## 23.1 Storage Formats: JSONL, Parquet, Tokenized `.bin` Memmaps

### 🧭 The Problem First
Training reads billions of tokens repeatedly. Re-tokenizing raw text every epoch wastes CPU; loading everything into RAM doesn't scale.

### 💡 Intuition / Instinct
Use different formats for different stages:
- **JSONL** (one JSON document per line): the *raw/clean text* stage. Human-readable, appendable, easy to stream.
- **Parquet** (columnar, compressed): large *metadata-rich* corpora (fast column filtering, 3–10× smaller).
- **Tokenized binary shards** (`uint16`/`uint32` arrays): the *training* stage. Memory-mapped: the OS pages in only what you read, so reads are nearly zero-copy.

### 🖼️ Visual Mental Model

```text
 raw HTML/PDF → JSONL {text, meta} → (filter, dedup) → tokenize → shard_00000.bin ... shard_00123.bin
                                                                   + index.json {shards, token counts, tokenizer hash}
```

### 📐 The Math, Gently
Bytes per token: uint16 (V ≤ 65,535) = 2 bytes; uint32 = 4. 10B tokens × 2 bytes = 20 GB. The Llama 3 vocab (128K) needs uint32 (or a packed 17-bit layout).

### 🛠️ Build It From Scratch

```python
# nanoforge/data/formats.py
import json, numpy as np, os

def read_jsonl(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            line = line.strip()
            if line: yield json.loads(line)

def write_jsonl(path, docs):
    with open(path, "w", encoding="utf-8") as f:
        for d in docs: f.write(json.dumps(d, ensure_ascii=False) + "\n")

def token_dtype(vocab_size): return np.uint16 if vocab_size < 2**16 else np.uint32

class ShardWriter:
    """Accumulates token ids and writes fixed-size shards + an index."""
    def __init__(self, out_dir, vocab_size, shard_tokens=100_000_000, prefix="train"):
        os.makedirs(out_dir, exist_ok=True)
        self.dir, self.prefix, self.n, self.dtype = out_dir, prefix, shard_tokens, token_dtype(vocab_size)
        self.buf = np.empty(shard_tokens, dtype=self.dtype); self.fill = 0; self.shards = []
    def add(self, ids):
        ids = np.asarray(ids, dtype=self.dtype); i = 0
        while i < len(ids):
            k = min(self.n - self.fill, len(ids) - i)
            self.buf[self.fill:self.fill + k] = ids[i:i + k]; self.fill += k; i += k
            if self.fill == self.n: self._flush()
    def _flush(self):
        if self.fill == 0: return
        path = os.path.join(self.dir, f"{self.prefix}_{len(self.shards):05d}.bin")
        self.buf[:self.fill].tofile(path); self.shards.append({"path": path, "tokens": int(self.fill)}); self.fill = 0
    def close(self, meta=None):
        self._flush()
        with open(os.path.join(self.dir, f"{self.prefix}_index.json"), "w") as f:
            json.dump({"shards": self.shards, "dtype": np.dtype(self.dtype).name, **(meta or {})}, f, indent=1)
```

### 🔬 Experiment & Observe
Write 1M documents as JSONL vs Parquet (`pyarrow.parquet.write_table`) and compare the file sizes and the time to read one column. Memmap a 2 GB `.bin` and time random 1K-token reads: microseconds.

### ⚠️ Failure Modes & Debugging
- **uint16 overflow:** a V > 65,535 tokenizer silently wraps the ids. Assert `max(ids) < np.iinfo(dtype).max`.
- Endianness when moving shards between systems (NumPy's default is native; x86/ARM are both little-endian, so this is usually fine).
- Record a tokenizer hash in the index so you never mix shards tokenized with different tokenizers.

### 🧠 Expert Insight
nanoGPT/llm.c use flat uint16 `.bin` shards; Megatron uses indexed `.bin` + `.idx` files with document boundaries; MosaicML Streaming (MDS) and WebDataset serve shards from object storage.

### ✅ Check Your Instinct
1. Why memmap instead of loading into RAM?
2. Storage for 50B tokens with a 100K vocab?

<details><summary>Answers</summary>

1. Datasets exceed RAM; memmap pages in on demand with near-zero overhead.
2. uint32: 200 GB.
</details>

### 📌 Recap Card
- JSONL for text, Parquet for large metadata, `.bin` shards for training.
- Choose uint16/uint32 by vocab size.
- Keep an index with a tokenizer hash.

> **Core intuition:** *Tokenize once, then stream raw integers straight from disk.*

## 23.2 Sharding and Deterministic Shuffling

### 🧭 The Problem First
Data is often sorted (by source, date or topic). Training on sorted data makes the model drift with each new topic (catastrophic interference). But a global shuffle of 10 TB won't fit in memory, and you need **reproducibility** and **exact resumption** after crashes.

### 💡 Intuition / Instinct
A two-level shuffle:
1. **Offline:** shuffle documents *before* sharding (external shuffle: assign each document to a random bucket file, then shuffle within each bucket).
2. **Online:** each epoch, permute the *shard order* and the *sample order within a shard* with a seeded RNG, where the seed is derived from (base_seed, epoch). Given (seed, epoch, step), you can recompute exactly which samples come next, so resumption is exact.

### 🖼️ Visual Mental Model

```text
 epoch e: shard order = perm(seed, e)            [s7, s2, s9, ...]
          within shard: window order = perm(seed, e, shard)
 resume at step k: skip k·B samples deterministically (no re-reading)
```

### 📐 The Math, Gently
Number of windows per shard = ⌊tokens / T⌋ (non-overlapping). Global sample index → (shard, window) by cumulative counts. Deterministic mapping means `sample(i)` is a pure function of (seed, epoch, i).

### 🛠️ Build It From Scratch

```python
# nanoforge/data/shuffle.py
import numpy as np, json, os, random

def external_shuffle(jsonl_paths, out_dir, n_buckets=64, seed=0):
    """Scatter docs into random buckets, then shuffle each bucket in memory."""
    os.makedirs(out_dir, exist_ok=True); rng = random.Random(seed)
    outs = [open(os.path.join(out_dir, f"bucket_{i:03d}.jsonl"), "w", encoding="utf-8") for i in range(n_buckets)]
    for p in jsonl_paths:
        for line in open(p, encoding="utf-8"): outs[rng.randrange(n_buckets)].write(line)
    for o in outs: o.close()
    for i in range(n_buckets):
        path = os.path.join(out_dir, f"bucket_{i:03d}.jsonl")
        lines = open(path, encoding="utf-8").readlines(); rng.shuffle(lines)
        open(path, "w", encoding="utf-8").writelines(lines)

class DeterministicSampler:
    """Maps a global step to (shard_idx, offset) windows deterministically."""
    def __init__(self, index_path, block_size, seed=0):
        idx = json.load(open(index_path)); self.shards = idx["shards"]; self.T = block_size; self.seed = seed
        self.windows = [s["tokens"] // (block_size + 1) for s in self.shards]
        self.total = sum(self.windows)
    def epoch_order(self, epoch):
        rng = np.random.default_rng([self.seed, epoch])
        pairs = [(si, w) for si in rng.permutation(len(self.shards)) for w in rng.permutation(self.windows[si])]
        return pairs                                      # list of (shard, window) for the whole epoch
```

(For huge datasets, don't materialize `pairs`; compute the permutation lazily per shard, as in 23.3.)

### 🔬 Experiment & Observe
Train on *sorted* data (all of domain A, then all of B) vs shuffled data. Plot the val loss on A: the sorted run shows a sharp rise when B starts (forgetting). Shuffled is smooth.

### ⚠️ Failure Modes & Debugging
- Every data-parallel rank using the same seed *and* the same data (duplicate batches across GPUs). Shard by rank (Ch 31).
- `random.shuffle` without a seed → an irreproducible run.

### 🧠 Expert Insight
Megatron precomputes shuffled sample-index files per epoch. Exact data-order resumption matters: a restart that replays or skips data changes the run and complicates debugging of loss spikes (Ch 27).

### ✅ Check Your Instinct
1. Why derive the seed from (base_seed, epoch)?

<details><summary>Answers</summary>

1. Each epoch gets a different order, yet any epoch's order is reproducible.
</details>

### 📌 Recap Card
- Offline external shuffle + online seeded permutations.
- Data order = f(seed, epoch, step), so resumption is exact.
- Never train on sorted data.

> **Core intuition:** *Randomness you can replay is the only randomness you want.*

## 23.3 Streaming Dataloaders and Multi-Worker Loading

### 🧭 The Problem First
Our `MemmapData.get_batch` runs in the main process. At high throughput, tokenization, indexing and host→GPU copies stall the GPU.

### 💡 Intuition / Instinct
Use PyTorch's `IterableDataset` + `DataLoader(num_workers=k, pin_memory=True)`. Workers prepare batches in parallel in background processes; pinned memory allows asynchronous copies to the GPU. Each worker must read a **disjoint** subset (split by worker id and by distributed rank), and each needs its own RNG seed.

### 🖼️ Visual Mental Model

```text
 worker0: shards 0,4,8...  ┐
 worker1: shards 1,5,9...  ├─▶ prefetch queue ─▶ pinned (B,T) ─non_blocking─▶ GPU
 worker2: shards 2,6,...   ┘
 (rank r of R: shards r, r+R, ... first; then split among workers)
```

### 📐 The Math, Gently
The required loader throughput = tokens/sec of the GPU. E.g. 200K tokens/s × 2 bytes is only 0.4 MB/s of token data (trivial for disk), so the bottleneck is Python overhead. Batching the reads matters more than raw I/O.

### 🛠️ Build It From Scratch

```python
# nanoforge/data/loader.py
import json, numpy as np, torch
from torch.utils.data import IterableDataset, DataLoader, get_worker_info

class TokenShardStream(IterableDataset):
    def __init__(self, index_path, block_size, seed=0, rank=0, world_size=1, start_step=0, micro_bs=1):
        idx = json.load(open(index_path))
        self.shards, self.dtype = idx["shards"], np.dtype(idx["dtype"])
        self.T, self.seed, self.rank, self.world = block_size, seed, rank, world_size
        self.skip = start_step * micro_bs                     # samples this rank already consumed
    def __iter__(self):
        wi = get_worker_info(); wid, nw = (wi.id, wi.num_workers) if wi else (0, 1)
        epoch, produced = 0, 0
        while True:
            rng = np.random.default_rng([self.seed, epoch])
            order = rng.permutation(len(self.shards))
            mine = order[self.rank::self.world][wid::nw]      # disjoint across ranks and workers
            for si in mine:
                data = np.memmap(self.shards[si]["path"], dtype=self.dtype, mode="r")
                n = (len(data) - 1) // self.T
                for w in np.random.default_rng([self.seed, epoch, si]).permutation(n):
                    produced += 1
                    if produced <= self.skip // max(nw, 1): continue   # fast-forward for resume (approximate per worker)
                    chunk = torch.from_numpy(data[w * self.T: w * self.T + self.T + 1].astype(np.int64))
                    yield chunk[:-1], chunk[1:]
            epoch += 1

def make_loader(index_path, block_size, micro_bs, seed=0, rank=0, world_size=1, num_workers=4, start_step=0):
    ds = TokenShardStream(index_path, block_size, seed, rank, world_size, start_step, micro_bs)
    return DataLoader(ds, batch_size=micro_bs, num_workers=num_workers, pin_memory=True,
                      persistent_workers=num_workers > 0, prefetch_factor=4 if num_workers > 0 else None)
```

```python
loader = iter(make_loader("data/processed/tinystories/train_index.json", 256, 32, num_workers=2))
x, y = next(loader); print(x.shape, y.shape, (x[:, 1:] == y[:, :-1]).all())
```

### 🔬 Experiment & Observe
Measure the tokens/sec of training with `num_workers` = 0, 2, 4, 8. Beyond the point where the GPU is saturated, more workers don't help. Watch `nvidia-smi` GPU utilization: aim for > 90%.

### ⚠️ Failure Modes & Debugging
- On Windows, DataLoader workers use *spawn*: the dataset must be picklable and the script must use `if __name__ == "__main__":`.
- Workers that don't split the shards → every worker yields the same data (duplicated batches).
- Opening a memmap in `__init__` and sharing it across processes can leak file handles. Open it in `__iter__`.

### 🧠 Expert Insight
At frontier scale, data loading is its own service (tokenize on the fly from object storage, or pre-tokenized shards with a deterministic global sampler). Loader *stalls* are a real source of lost MFU (Ch 24).

### ✅ Check Your Instinct
1. Why must each worker read a disjoint subset?
2. What does `pin_memory` enable?

<details><summary>Answers</summary>

1. Otherwise batches are duplicated, wasting compute and biasing training.
2. Page-locked host memory for fast asynchronous (non-blocking) GPU transfers.
</details>

### 📌 Recap Card
- IterableDataset + workers + pinned memory.
- Disjoint shards per rank and per worker.
- Open memmaps inside `__iter__`; beware Windows spawn.

> **Core intuition:** *Keep the GPU fed: prepare the next meal while it's still eating.*

## 23.4 Sequence Packing and Document Masking

### 🧭 The Problem First
Documents vary in length (50 to 50,000 tokens). Padding every sequence to T wastes compute on pad tokens. Concatenating documents (as we did with EOT separators) wastes nothing, but tokens can then attend *across* document boundaries to unrelated text.

### 💡 Intuition / Instinct
- **Packing:** concatenate documents separated by `<|endoftext|>` and cut the stream into T-length windows. Zero padding waste. The model learns that after EOT a new, unrelated document begins. This is standard in pretraining.
- **Document masking:** additionally block attention across document boundaries, so each token only attends within its own document (a block-diagonal causal mask). Position ids can restart at each document. It's cleaner, and it matters more for long contexts.

### 🖼️ Visual Mental Model

```text
 packed window:  [doc A tokens ... EOT][doc B tokens ... EOT][doc C ...]
 causal mask:                    document mask:
 ■                               ■
 ■■                              ■■
 ■■■  (B sees A)                 ··■   (B starts fresh)
 ■■■■                            ··■■
```

### 📐 The Math, Gently
Padding waste = $1 - \frac{\sum \text{len}_i}{N_{seq}\cdot T}$. With lengths ~ Uniform[1, T], ~50% waste.
The document mask: $M_{ij} = [j \le i]\cdot[\text{doc}(i) = \text{doc}(j)]$.

### 🛠️ Build It From Scratch

```python
import torch
def doc_ids_from_eot(x, eot_id):
    """x: (B, T) token ids. Returns (B, T) document index, incrementing after each EOT."""
    is_eot = (x == eot_id).long()
    return torch.cumsum(is_eot, dim=1) - is_eot          # EOT belongs to the doc it ends

def document_causal_mask(doc_ids):
    """(B, T) -> bool mask (B, 1, T, T), True = attend."""
    T = doc_ids.size(1)
    same = doc_ids[:, :, None] == doc_ids[:, None, :]
    causal = torch.tril(torch.ones(T, T, dtype=torch.bool, device=doc_ids.device))
    return (same & causal)[:, None]

def position_ids_from_docs(doc_ids):
    """Restart positions at each document start."""
    B, T = doc_ids.shape
    start = torch.ones_like(doc_ids, dtype=torch.bool); start[:, 1:] = doc_ids[:, 1:] != doc_ids[:, :-1]
    idx = torch.arange(T, device=doc_ids.device).expand(B, T)
    last_start = torch.cummax(torch.where(start, idx, torch.zeros_like(idx)), dim=1).values
    return idx - last_start

x = torch.tensor([[5, 6, 0, 7, 8, 9, 0, 3]])            # eot_id = 0
d = doc_ids_from_eot(x, 0); print(d); print(position_ids_from_docs(d))
print(document_causal_mask(d)[0, 0].int())
# use with SDPA: F.scaled_dot_product_attention(q, k, v, attn_mask=document_causal_mask(d))
```

### 🔬 Experiment & Observe
Train micro on TinyStories with plain packing vs document masking. The val loss is similar at T = 256 (stories are short and EOT carries the signal), and the difference grows with longer T and more heterogeneous documents.

### ⚠️ Failure Modes & Debugging
- Passing a boolean `attn_mask` to SDPA disables the fastest FlashAttention kernel on many versions. Use FlexAttention or FlashAttention's `varlen` API for speed (Ch 29).
- Forgetting to mask the loss on padding if you *do* pad (`ignore_index=-100`).

### 🧠 Expert Insight
- **Krell et al. (2021):** packing without cross-contamination.
- **Llama 3 (2024):** used an intra-document attention mask, which was important for very long sequences.
- **Zhao et al. (2024), "Analysing The Impact of Sequence Composition on Language Model Pre-Training":** document masking improves in-context learning.

</details>

### 📌 Recap Card

> **Core intuition:** *Fill every seat on the bus, but don't let strangers read each other's mail.*

## 23.5 Custom Data: PDFs, Code Repos, Chat Logs, CSV/Tables → Text

### 🧭 The Problem First
Your Capstone data is probably not neat text: PDFs of papers or manuals, a code repository, exported chat logs, spreadsheets. Each needs a conversion strategy that preserves meaning.

### 💡 Intuition / Instinct
Convert everything into **clean, self-describing text documents**:
- **PDFs:** extract the text per page, fix hyphenation across line breaks, drop the headers/footers repeated on every page, keep the reading order. Scanned PDFs need OCR.
- **Code:** one document per file with a path header (`# file: src/utils.py`), filtered by extension, excluding vendored/generated/minified files; optionally concatenate repository files in dependency order.
- **Chats:** render them with a consistent role template (plain text for pretraining, chat tokens for SFT; Ch 37).
- **Tables/CSV:** serialize rows as natural language or markdown tables (with the header repeated), chunked so each chunk keeps its context.

### 🖼️ Visual Mental Model

```text
 manual.pdf ─pypdf─▶ pages ─dehyphenate, drop repeated headers─▶ "## Page 3\n..."
 repo/ ─walk─▶ *.py ─filter─▶ "# file: src/x.py\n<code>"
 chat.json ─▶ "User: ...\nAssistant: ..."
 sales.csv ─▶ "| region | month | revenue |\n|---|---|---|\n| EU | Jan | 1.2M |"
```

### 📐 The Math, Gently
Repeated-line detection for PDF headers: a line appearing on > 50% of pages is boilerplate.

### 🛠️ Build It From Scratch

```python
# nanoforge/data/converters.py
import csv, json, os, re
from collections import Counter

def pdf_to_text(path):
    from pypdf import PdfReader
    pages = [p.extract_text() or "" for p in PdfReader(path).pages]
    line_freq = Counter(l.strip() for p in pages for l in set(p.split("\n")) if l.strip())
    boiler = {l for l, c in line_freq.items() if len(pages) > 3 and c / len(pages) > 0.5}
    out = []
    for i, p in enumerate(pages):
        lines = [l for l in p.split("\n") if l.strip() not in boiler and not re.fullmatch(r"\s*\d+\s*", l)]
        text = "\n".join(lines)
        text = re.sub(r"(\w)-\n(\w)", r"\1\2", text)          # de-hyphenate
        text = re.sub(r"(?<![.\n:])\n(?=[a-z])", " ", text)     # join wrapped lines
        out.append(text)
    return "\n\n".join(out)

CODE_EXT = {".py", ".js", ".ts", ".java", ".c", ".cpp", ".h", ".go", ".rs", ".rb", ".md", ".sh", ".sql"}
SKIP_DIRS = {".git", "node_modules", "venv", ".venv", "dist", "build", "__pycache__", "vendor"}
def repo_to_docs(root, max_bytes=200_000):
    for d, dirs, files in os.walk(root):
        dirs[:] = [x for x in dirs if x not in SKIP_DIRS]
        for f in files:
            p = os.path.join(d, f)
            if os.path.splitext(f)[1] not in CODE_EXT or os.path.getsize(p) > max_bytes: continue
            src = open(p, encoding="utf-8", errors="ignore").read()
            lines = src.split("\n")
            if lines and max(map(len, lines)) > 1000: continue          # likely minified/generated
            yield {"text": f"# file: {os.path.relpath(p, root)}\n{src}", "source": "code", "path": p}

def chat_to_text(messages, user="User", assistant="Assistant"):
    names = {"user": user, "assistant": assistant, "system": "System"}
    return "\n".join(f"{names.get(m['role'], m['role'])}: {m['content'].strip()}" for m in messages)

def csv_to_markdown_chunks(path, rows_per_chunk=30, title=None):
    rows = list(csv.reader(open(path, encoding="utf-8")))
    header, body = rows[0], rows[1:]
    head = "| " + " | ".join(header) + " |\n|" + "---|" * len(header)
    for i in range(0, len(body), rows_per_chunk):
        lines = ["| " + " | ".join(r) + " |" for r in body[i:i + rows_per_chunk]]
        yield (f"## {title}\n" if title else "") + head + "\n" + "\n".join(lines)
```

### ⚠️ Failure Modes & Debugging

- Secrets in code repos (API keys): run PII/secret redaction (Ch 22.3).

## 23.6 A Reusable `prepare_data.py` for Any Corpus

### 🧭 The Problem First
We now have a dozen pipeline pieces. We need one command that takes raw inputs to training-ready shards, reproducibly, with a report.

### 💡 Intuition / Instinct
A staged pipeline with a config: **convert → normalize → filter → dedup → PII → split → tokenize → shard → report**. Each stage logs its counts. Split *after* dedup. The output is a directory with train/val shard indexes and a `report.json`.

### 🖼️ Visual Mental Model

```text
 inputs (pdf/code/jsonl/csv/txt)
   → convert → normalize → quality filter → exact+near dedup → PII redact
   → split (doc-level, 99/1) → tokenize (+EOT) → shards + index + report.json
```

### 📐 The Math, Gently
Report the retention at every stage: $r_k = N_k / N_0$. Log documents, bytes and tokens.

### 🛠️ Build It From Scratch

```python
# scripts/prepare_data.py
import argparse, glob, hashlib, json, os, random
from nanoforge.data.clean import normalize_text
from nanoforge.data.filters import gopher_quality
from nanoforge.data.dedup import exact_dedup, near_dedup
from nanoforge.data.pii import redact_pii
from nanoforge.data.converters import pdf_to_text, repo_to_docs, csv_to_markdown_chunks
from nanoforge.data.formats import read_jsonl, ShardWriter
from nanoforge.tokenizer.regex_bpe import RegexBPE

def load_inputs(pattern):
    for p in glob.glob(pattern, recursive=True):
        ext = os.path.splitext(p)[1].lower()
        if ext == ".jsonl": yield from read_jsonl(p)
        elif ext == ".txt": yield {"text": open(p, encoding="utf-8", errors="ignore").read(), "source": p}
        elif ext == ".pdf": yield {"text": pdf_to_text(p), "source": p}
        elif ext == ".csv": yield from ({"text": c, "source": p} for c in csv_to_markdown_chunks(p, title=os.path.basename(p)))
        elif os.path.isdir(p): yield from repo_to_docs(p)

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--inputs", required=True); ap.add_argument("--tokenizer", required=True)
    ap.add_argument("--out", required=True); ap.add_argument("--val_frac", type=float, default=0.01)
    ap.add_argument("--skip_quality", action="store_true"); ap.add_argument("--near_dedup", action="store_true")
    ap.add_argument("--seed", type=int, default=0)
    a = ap.parse_args(); rep = {}
    docs = list(load_inputs(a.inputs)); rep["input_docs"] = len(docs)
    for d in docs: d["text"] = normalize_text(d["text"])
    docs = [d for d in docs if d["text"]]; rep["after_normalize"] = len(docs)
    if not a.skip_quality:
        docs = [d for d in docs if gopher_quality(d["text"])[0]]; rep["after_quality"] = len(docs)
    docs = exact_dedup(docs); rep["after_exact_dedup"] = len(docs)
    if a.near_dedup: docs = near_dedup(docs); rep["after_near_dedup"] = len(docs)
    pii = {}
    for d in docs:
        d["text"], c = redact_pii(d["text"])
        for k, v in c.items(): pii[k] = pii.get(k, 0) + v
    rep["pii_redactions"] = pii
    random.Random(a.seed).shuffle(docs)
    n_val = max(1, int(len(docs) * a.val_frac)); splits = {"val": docs[:n_val], "train": docs[n_val:]}
    tok = RegexBPE().load(a.tokenizer); eot = tok.special_tokens["<|endoftext|>"]
    tok_hash = hashlib.sha1(open(a.tokenizer, "rb").read()).hexdigest()[:12]
    for name, ds in splits.items():
        w = ShardWriter(a.out, tok.vocab_size, prefix=name); ntok = nbytes = 0
        for d in ds:
            ids = tok.encode_ordinary(d["text"]) + [eot]; w.add(ids); ntok += len(ids); nbytes += len(d["text"].encode())
        w.close({"tokenizer": a.tokenizer, "tokenizer_hash": tok_hash})
        rep[f"{name}_docs"], rep[f"{name}_tokens"], rep[f"{name}_bytes_per_token"] = len(ds), ntok, nbytes / max(ntok, 1)
    json.dump(rep, open(os.path.join(a.out, "report.json"), "w"), indent=1); print(json.dumps(rep, indent=1))

if __name__ == "__main__": main()
```

### ⚠️ Failure Modes & Debugging
- Holding all documents in memory doesn't scale past a few GB. For large corpora, process in streaming chunks per stage (e.g. datatrove), with near-dedup as a separate signature pass.
- Changing the tokenizer without re-running the pipeline: the tokenizer hash in the index catches it; check it in the trainer.

### 🧠 Expert Insight
Production pipelines (datatrove, Dolma toolkit, NeMo Curator) are exactly this staged design, distributed over many machines with per-stage statistics and sample dumps for human review.
