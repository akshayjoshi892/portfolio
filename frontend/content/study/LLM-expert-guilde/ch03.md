## 3.1 Vectors as Arrows and as Feature Lists; Norms and Distances

### 🧭 The Problem First
Computers can't compare words like "king" and "queen" directly. We need a representation where "similar things" are "close". Numbers alone (word IDs 17 and 942) carry no notion of closeness.

### 💡 Intuition / Instinct
A vector has two faces:
1. **A list of features:** `[size, furriness, danger]`, so a cat is `[0.3, 0.9, 0.2]`.
2. **An arrow/point in space:** the same numbers are coordinates.

Once things are points, "similar" means "nearby" and "different" means "far apart". Every embedding in an LLM (typically 768–16,384 dimensions) is a point in a huge space where directions carry meaning.

### 🖼️ Visual Mental Model

```text
 furriness
    ▲
 1.0│   • cat (0.3,0.9)    • dog (0.5,0.8)
    │
 0.5│
    │                               • shark (0.8,0.0)
    └──────────────────────────────▶ size
      cat–dog distance small; cat–shark distance large
```

### 📐 The Math, Gently
- **L2 norm (length):** $\|v\|_2 = \sqrt{\sum_i v_i^2}$
- **Euclidean distance:** $d(a, b) = \|a - b\|_2$
- **L1 norm:** $\|v\|_1 = \sum_i |v_i|$

Example: cat $= (0.3, 0.9)$, dog $= (0.5, 0.8)$, so $d = \sqrt{0.2^2 + 0.1^2} = \sqrt{0.05} = 0.224$.
Cat to shark $(0.8, 0.0)$: $\sqrt{0.25 + 0.81} = 1.03$.

### 🛠️ Build It From Scratch

```python
import numpy as np
animals = {"cat": [0.3, 0.9, 0.2], "dog": [0.5, 0.8, 0.3], "shark": [0.8, 0.0, 0.9]}
V = {k: np.array(v) for k, v in animals.items()}

def l2(v): return np.sqrt((v ** 2).sum())
def dist(a, b): return l2(a - b)

for a in V:
    for b in V:
        if a < b: print(f"{a:5s}-{b:5s}: {dist(V[a], V[b]):.3f}")
print(np.linalg.norm(V["cat"]), l2(V["cat"]))      # same

# all pairwise distances, vectorized: ||a-b||^2 = ||a||^2 + ||b||^2 - 2 a.b
X = np.stack(list(V.values()))                       # (N, 3)
sq = (X**2).sum(1)
D = np.sqrt(np.maximum(sq[:, None] + sq[None, :] - 2 * X @ X.T, 0))
print(D.round(3))
```

### 🔬 Experiment & Observe
- Add "wolf" `[0.6, 0.7, 0.7]`. **Predict** its nearest neighbour: dog.
- Scale all features by 10: distances scale by 10, but the *rankings* are unchanged.

### ⚠️ Failure Modes & Debugging
- **Features on different scales** dominate distance (e.g. price in dollars vs rating 1–5). Normalize features.
- **Negative values under sqrt** from floating-point error in the vectorized formula. Clamp with `np.maximum(…, 0)`.

### 🧠 Expert Insight
In high dimensions, raw Euclidean distance is dominated by vector length. That is why LLMs mostly compare with **dot products / cosine similarity** (Section 3.2) and **normalize** vectors (LayerNorm/RMSNorm, Ch 10).

### 📌 Recap Card
- Vector = feature list = point.
- Similar ⇒ close.
- $\|a-b\|^2 = \|a\|^2 + \|b\|^2 - 2a\cdot b$.

> **Core intuition:** *Meaning becomes geometry: similar things live nearby.*

## 3.2 The Dot Product as Similarity: the Seed of Attention

### 🧭 The Problem First
Attention must answer, for every pair of tokens, "how relevant is token j to token i?". We need a fast, differentiable relevance score.

### 💡 Intuition / Instinct
The dot product $a \cdot b$ measures **how much two arrows point the same way, scaled by their lengths**.
- Same direction → large positive.
- Perpendicular → 0 (unrelated).
- Opposite → negative.

Think of a flashlight (a) and a mirror (b): the dot product is how much light the mirror catches.

### 🖼️ Visual Mental Model

```text
  a ──▶        a ──▶        a ──▶
  b ──▶        b ↑          b ◀──
  a·b > 0      a·b = 0      a·b < 0
  (aligned)    (orthogonal) (opposed)
```

### 📐 The Math, Gently
$$ a \cdot b = \sum_i a_i b_i = \|a\|\|b\|\cos\theta $$
**Cosine similarity:** $\cos\theta = \frac{a\cdot b}{\|a\|\|b\|} \in [-1, 1]$.
Example: $a = (1, 2)$, $b = (2, 1)$: $a\cdot b = 4$, $\|a\| = \|b\| = \sqrt5$, so $\cos = 0.8$ (θ ≈ 37°).
**Projection** of $a$ onto $b$: $\frac{a\cdot b}{\|b\|^2} b = \frac{4}{5}(2,1) = (1.6, 0.8)$.

### 🛠️ Build It From Scratch

```python
import numpy as np
def dot(a, b): return sum(x * y for x, y in zip(a, b))
def cosine(a, b): return dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))
a, b = np.array([1., 2.]), np.array([2., 1.])
print(dot(a, b), a @ b, cosine(a, b))                 # 4.0 4.0 0.8

# a toy "attention" score table: which key best matches each query?
queries = np.array([[1., 0.], [0., 1.]])              # (2, 2)
keys    = np.array([[0.9, 0.1], [0.1, 0.9], [0.7, 0.7]])  # (3, 2)
scores = queries @ keys.T                              # (2, 3): every query · every key
print(scores)
print("best key per query:", scores.argmax(1))         # [0 1]

# random high-dim vectors are nearly orthogonal
d = 1024
u, v = np.random.randn(d), np.random.randn(d)
print(f"cosine of random {d}-d vectors: {cosine(u, v):.3f}")   # ~ ±0.03
```

### 🔬 Experiment & Observe
- Increase `d` from 2 → 10,000 and plot the |cosine| of random pairs. It shrinks like $1/\sqrt{d}$. **Instinct:** in high dimensions there is room for *huge* numbers of nearly independent directions (features).
- Dot products of random vectors grow like $\sqrt d$ in magnitude. This is exactly why attention divides by $\sqrt{d}$ (Ch 17).

### ⚠️ Failure Modes & Debugging
- **Dot product dominated by norms**: one very long vector wins every comparison. Normalize, or use cosine.
- **Cosine of a zero vector** → division by zero. Add an epsilon.

### 🧠 Expert Insight
- Attention score $= q \cdot k / \sqrt{d}$ is a scaled dot product (Vaswani et al., 2017).
- Embedding search in RAG (Ch 46) uses cosine similarity.
- **Elhage et al. (2022), "Toy Models of Superposition":** networks exploit near-orthogonality to store more features than dimensions.

3. *(Coding)* Write a batched cosine-similarity matrix for (N, d) inputs.

<details><summary>Answers</summary>

3. `Xn = X / norm(X, axis=1, keepdims=True); S = Xn @ Xn.T`.

</details>

### 📌 Recap Card
- $a\cdot b = \|a\|\|b\|\cos\theta$: alignment × lengths.
- Cosine removes the lengths.
- `Q @ K.T` = all pairwise similarities.
- Random high-dim vectors are nearly orthogonal.

> **Core intuition:** *A dot product asks "how much do these point the same way?", and attention is built on that question.*

## 3.3 Matrices as Transformations: Rotate, Scale, Project

### 🧭 The Problem First
A neural layer computes $y = Wx$. If you see $W$ as "a grid of numbers", you can't reason about what the layer does. If you see it as "a transformation of space", you can.

### 💡 Intuition / Instinct
A matrix is a **machine that moves every point in space in a consistent (linear) way**: it can stretch, rotate, shear, flip, or squash dimensions. **The columns of W tell you where the basis vectors land.** A linear layer in an LLM re-expresses the representation in new coordinates where the next computation becomes easier.

### 🖼️ Visual Mental Model

```text
 W = [[2, 0],      e1=(1,0) → (2,0)   stretch x by 2
      [0, 1]]      e2=(0,1) → (0,1)

 W = [[0,-1],      e1 → (0,1)          rotate 90°
      [1, 0]]      e2 → (-1,0)

 W = [[1, 0],      e2 → (0,0)          project onto x-axis (information lost!)
      [0, 0]]
```

### 📐 The Math, Gently
$y_i = \sum_j W_{ij} x_j$, which is also $y = x_1 \cdot W_{:,1} + x_2 \cdot W_{:,2}$ (a combination of the columns).
Rotation by θ: $R = \begin{bmatrix}\cos\theta & -\sin\theta\\ \sin\theta & \cos\theta\end{bmatrix}$.
Example: rotating $(1, 0)$ by 90° gives $(0, 1)$. This exact 2×2 rotation, applied to pairs of dimensions, *is* RoPE (Ch 18).

### 🛠️ Build It From Scratch

```python
import numpy as np
def rot(theta):
    return np.array([[np.cos(theta), -np.sin(theta)], [np.sin(theta), np.cos(theta)]])

pts = np.array([[1, 0], [0, 1], [1, 1]], dtype=float)   # (N, 2)
R = rot(np.pi / 2)
print((pts @ R.T).round(3))        # rows are rotated points; (N,2)@(2,2)
S = np.diag([2.0, 0.5])
print(pts @ S.T)                   # stretch x, squash y
P = np.array([[1., 0.], [0., 0.]])
print(pts @ P.T)                   # projection: y info destroyed

# rotations preserve lengths and dot products
a, b = np.random.randn(2), np.random.randn(2)
print(np.isclose(a @ b, (R @ a) @ (R @ b)))       # True

# a linear layer in PyTorch is exactly y = x W^T + b
import torch
lin = torch.nn.Linear(2, 3)
x = torch.randn(5, 2)
print(torch.allclose(lin(x), x @ lin.weight.T + lin.bias))   # True
```

### 🔬 Experiment & Observe
- Plot a grid of points before and after a random 2×2 matrix (use matplotlib). Lines stay lines, and the origin stays fixed: that's *linearity*.
- Compose two rotations: `rot(a) @ rot(b) == rot(a+b)`. **Predict** it first.

### ⚠️ Failure Modes & Debugging
- `nn.Linear` stores `weight` as `(out, in)` and computes `x @ W.T`. Confusing the orientation is common when loading weights (GPT-2's Conv1D stores the transpose; Ch 20).
- **Row vs column vectors:** in code, batches are rows, so `X @ W.T` rather than `W @ x`.

### 🧠 Expert Insight
Without nonlinearities, stacking linear layers collapses into one matrix ($W_2 W_1 x$). Nonlinearities (Ch 9) are what let depth add power. In transformers, $W_Q, W_K, W_V$ are learned transformations that put tokens into "question", "label" and "content" coordinate systems.

### ✅ Check Your Instinct
1. What does a matrix with a zero column do?
2. Why does $W_2 W_1 x$ equal a single linear layer?
3. *(Coding)* Construct a matrix that reflects across the y-axis.

**Predict:** determinant of a rotation matrix?

<details><summary>Answers</summary>

1. Ignores the corresponding input dimension.
2. Matrix multiplication is associative: $(W_2W_1)x$.
3. `[[-1, 0], [0, 1]]`.

Predict: 1 (area preserved, no flip).
</details>

### 📌 Recap Card
- Matrix = linear transformation; columns = images of basis vectors.
- Rotations preserve lengths and angles; projections destroy information.
- `nn.Linear`: $y = xW^T + b$.
- Linear∘linear = linear → nonlinearity needed.

> **Core intuition:** *A matrix moves all of space at once; a layer re-expresses meaning in new coordinates.*

## 3.4 Matrix Multiplication Four Ways

### 🧭 The Problem First
`A @ B` appears thousands of times per forward pass. Different "views" of matmul explain different things: attention as a weighted average, LoRA as a sum of outer products, GPU tiling for speed.

### 💡 Intuition / Instinct
$C = AB$ with $A: (m, k)$, $B: (k, n)$:
1. **Dot-product view:** $C_{ij}$ = row i of A · column j of B ("every pair's similarity").
2. **Column view:** each column of C is a combination of A's columns.
3. **Row view:** each row of C is a combination of B's rows. *This is attention:* output row = weighted mixture of value rows.
4. **Outer-product view:** $C = \sum_{r} A_{:,r} B_{r,:}$, a sum of k rank-1 matrices. *This is LoRA's world.*

### 🖼️ Visual Mental Model

```text
 Row view (attention):
   weights (T×T)      V (T×D)          out (T×D)
   [0.7 0.3 0 ]       v1 ─────         0.7·v1 + 0.3·v2
   [0.2 0.5 0.3]  @   v2 ─────   =     0.2·v1 + 0.5·v2 + 0.3·v3
   [0.1 0.1 0.8]      v3 ─────         ...
```

### 📐 The Math, Gently
$C_{ij} = \sum_{r=1}^k A_{ir} B_{rj}$. Cost: $m \cdot n \cdot k$ multiply-adds, i.e. $2mnk$ FLOPs.
Example: $(1024 × 4096) @ (4096 × 4096)$ gives $2 · 1024 · 4096 · 4096 ≈ 34$ GFLOPs. This FLOP counting is the basis of the $6ND$ rule (Ch 26).

### 🛠️ Build It From Scratch

```python
import numpy as np
A = np.random.randn(3, 4); B = np.random.randn(4, 2)
C_ref = A @ B

C1 = np.array([[A[i] @ B[:, j] for j in range(2)] for i in range(3)])  # dot-product view
C2 = np.stack([A @ B[:, j] for j in range(2)], axis=1)                  # column view
C3 = np.stack([sum(A[i, r] * B[r] for r in range(4)) for i in range(3)])# row view
C4 = sum(np.outer(A[:, r], B[r]) for r in range(4))                     # outer-product view
for C in (C1, C2, C3, C4): print(np.allclose(C, C_ref))

# row view = attention-like weighted average
W = np.array([[0.7, 0.3, 0.0], [0.2, 0.5, 0.3], [0.1, 0.1, 0.8]])       # rows sum to 1
Vv = np.array([[1., 0.], [0., 1.], [1., 1.]])
print(W @ Vv)            # each output is a mixture of value rows

def flops(m, k, n): return 2 * m * k * n
print(f"{flops(1024, 4096, 4096)/1e9:.1f} GFLOPs")

# batched matmul: (B, m, k) @ (B, k, n) -> (B, m, n)
Ab, Bb = np.random.randn(8, 3, 4), np.random.randn(8, 4, 5)
print((Ab @ Bb).shape)
```

### 🔬 Experiment & Observe
- Time `A @ B` for n = 256, 512, 1024, 2048. Time grows ~8× per doubling ($n^3$).
- In the attention example, set one row to `[1, 0, 0]`: the output copies $v_1$ exactly. **Attention can "copy" a token.**

### ⚠️ Failure Modes & Debugging
- Inner dimensions must match: `(m,k) @ (k,n)`. The error message shows the shapes; read them.
- `*` is element-wise, `@` is matmul. Mixing them up with broadcasting can silently produce the wrong shape.

### 🧠 Expert Insight
GPUs compute matmuls in tiles (blocks of the outer-product/dot view) using tensor cores. Matrix sizes that are multiples of 64/128 run much faster. Karpathy's famous nanoGPT speedup from padding the vocab 50257 → 50304 exploits exactly this.

### 📌 Recap Card
- Four views: dots, columns, rows, outer products.
- Attention = row view (mixtures of value rows).

- Shapes: `(m,k)@(k,n)→(m,n)`; batched on the leading dims.

> **Core intuition:** *A matmul is many weighted mixtures happening at once.*

## 3.5 Rank and Low-Rank Structure (Preview: LoRA)

### 🧭 The Problem First
A 4096×4096 weight matrix has 16.7M numbers. Fine-tuning all of them for a small task is expensive. Is all that freedom needed?

### 💡 Intuition / Instinct
The **rank** of a matrix is the number of truly independent directions it can output. A rank-r matrix squeezes everything through an r-dimensional "bottleneck". Many useful changes to a model are low-rank: "shift the style a bit" does not need 4096 independent directions. So write the change as $\Delta W = BA$ with $B: (d, r)$, $A: (r, d)$ and small r, and you store $2dr$ numbers instead of $d^2$.

### 🖼️ Visual Mental Model

```text
  x (d) ──▶ [A: r×d] ──▶ (r) ──▶ [B: d×r] ──▶ (d)
            compress        bottleneck        expand
  d=4096, r=8:  full 16.7M params  vs  low-rank 65K params (0.4%)
```

### 📐 The Math, Gently
$\text{rank}(BA) \le r$. The parameter ratio is $\frac{2dr}{d^2} = \frac{2r}{d}$.
Example: $u = (1, 2)$, $v = (3, 4)$ give $uv^T = \begin{bmatrix}3&4\\6&8\end{bmatrix}$. Row 2 = 2 × row 1, so rank 1.

### 🛠️ Build It From Scratch

```python
import numpy as np
d, r = 512, 8
B = np.random.randn(d, r); A = np.random.randn(r, d)
dW = B @ A
print(dW.shape, np.linalg.matrix_rank(dW))          # (512, 512) 8
print("full params", d*d, "low-rank params", 2*d*r)

# applying low-rank update efficiently: never materialize dW
x = np.random.randn(16, d)
y1 = x @ dW.T
y2 = (x @ A.T) @ B.T                                  # (16,r) then (16,d): cheap
print(np.allclose(y1, y2))
```

### 🔬 Experiment & Observe
Time `x @ dW.T` vs `(x @ A.T) @ B.T` for d = 4096: the low-rank path is ~250× fewer FLOPs.

### ⚠️ Failure Modes & Debugging
- Materializing $BA$ defeats the purpose during training.
- Initializing both A and B randomly makes $\Delta W \neq 0$ at the start. LoRA initializes $B = 0$ so the model starts unchanged (Ch 38).

### 🧠 Expert Insight
- **Hu et al. (2021), LoRA:** fine-tuning updates have low "intrinsic rank".
- **Aghajanyan et al. (2020), "Intrinsic Dimensionality Explains the Effectiveness of Language Model Fine-Tuning".**
- MLA (DeepSeek-V2, 2024) compresses the KV cache with low-rank projections.

### ✅ Check Your Instinct
1. Max rank of a (100, 5) @ (5, 100) product?
2. Parameter savings for d = 8192, r = 16?
3. *(Coding)* Build a rank-2 matrix and verify it.

<details><summary>Answers</summary>

1. 5.
2. $2·16/8192 ≈ 0.39\%$ of full.
3. `np.linalg.matrix_rank(np.random.randn(10,2)@np.random.randn(2,10))` gives 2.
</details>

### 📌 Recap Card
- Rank = number of independent output directions.
- Low-rank = bottleneck = few parameters.
- $\Delta W = BA$ is the basis of LoRA.
- Apply as $(xA^T)B^T$.

> **Core intuition:** *Most useful changes need only a few directions.*

## 3.6 SVD, Orthogonality, and High-Dimensional Surprises

### 🧭 The Problem First
How do we find the "most important directions" of a matrix or a dataset (to compress, visualize, or analyze embeddings)? And why do high-dimensional spaces behave so strangely?

### 💡 Intuition / Instinct
**SVD says every matrix is: rotate → stretch along axes → rotate.** $W = U \Sigma V^T$. The singular values in $\Sigma$ rank how much each direction matters. Keep the top-k and you get the best rank-k approximation. That is how we compress, and how PCA finds the main axes of embedding clouds.

High-dimensional surprises:
1. Random vectors are nearly orthogonal (3.2).
2. Almost all the volume of a high-dimensional ball is near its surface.
3. You can pack exponentially many *almost*-orthogonal directions, which is why models can store more "features" than they have dimensions (superposition).

### 🖼️ Visual Mental Model

```text
 unit circle ──V^T (rotate)──▶ circle ──Σ (stretch)──▶ ellipse ──U (rotate)──▶ tilted ellipse
 singular values = lengths of the ellipse's axes
```

### 📐 The Math, Gently
$W = U\Sigma V^T$, with $U, V$ orthogonal ($U^TU = I$) and $\Sigma = \text{diag}(\sigma_1 \ge \sigma_2 \ge \dots)$.
Best rank-k approximation (Eckart–Young): $W_k = \sum_{i\le k} \sigma_i u_i v_i^T$, with error $\|W - W_k\|_F^2 = \sum_{i>k}\sigma_i^2$.
Example: $W = \text{diag}(3, 1)$ gives $\sigma = (3, 1)$. The rank-1 approximation keeps the 3; the relative error is $1/(9+1) = 10\%$ of the squared norm.

### 🛠️ Build It From Scratch

```python
import numpy as np
np.random.seed(0)
# a matrix that is "mostly" rank 3 plus noise
W = np.random.randn(100, 3) @ np.random.randn(3, 80) + 0.05 * np.random.randn(100, 80)
U, S, Vt = np.linalg.svd(W, full_matrices=False)
print("top singular values:", S[:6].round(2))     # 3 big, then tiny

for k in [1, 2, 3, 10]:
    Wk = (U[:, :k] * S[:k]) @ Vt[:k]
    err = np.linalg.norm(W - Wk) / np.linalg.norm(W)
    print(f"rank {k:2d}: relative error {err:.4f}")

# PCA of points = SVD of centered data
X = np.random.randn(500, 50) @ np.random.randn(50, 50)
Xc = X - X.mean(0)
_, S2, Vt2 = np.linalg.svd(Xc, full_matrices=False)
proj2d = Xc @ Vt2[:2].T                            # (500, 2) for plotting
print(proj2d.shape, "explained var:", (S2[:2]**2).sum() / (S2**2).sum())

# volume near the surface: fraction of a d-ball within radius 0.99
for d in [2, 10, 100, 1000]:
    print(d, f"inner fraction {(0.99**d):.4f}")
```

### 🔬 Experiment & Observe
- Plot `S` on a log scale for a trained model's weight matrix (you'll do this for GPT-2 in Ch 20). Trained weights often have heavy-tailed spectra.
- Increase the noise 0.05 → 1.0: the gap between the top 3 and the rest disappears.

### ⚠️ Failure Modes & Debugging
- Forgetting to center data before PCA: the first component just points to the mean.
- `full_matrices=True` on large matrices wastes memory.

### 🧠 Expert Insight
- SVD-based weight compression and initialization (PiSSA, 2024) initialize LoRA from the top singular vectors.
- Orthogonal matrices underlie RoPE (rotations) and the Muon optimizer (orthogonalized updates).
- Embedding spaces are *anisotropic* (Ethayarajh, 2019): vectors cluster in a narrow cone, which affects cosine similarity.

### ✅ Check Your Instinct
1. What does a large gap in singular values tell you?
2. Why center before PCA?
3. *(Coding)* Compress a 256×256 grayscale image with rank-20 SVD and report the storage ratio.

**Predict:** in 1000-d, what fraction of a unit ball's volume lies in the outer 1% shell?

<details><summary>Answers</summary>

1. The matrix is approximately low-rank; a few directions dominate.
2. Otherwise the top direction captures the mean offset instead of the variance.
3. Storage $20(256+256+1)$ vs $256^2$, ≈ 15.7%.

</details>

### 📌 Recap Card
- SVD: rotate, stretch, rotate.
- Top-k singular vectors give the best rank-k approximation.
- PCA = SVD of centered data.
- High-dim: near-orthogonality, mass near the surface, superposition.

> **Core intuition:** *Every matrix has a few directions that matter most; SVD finds them.*
