## 11.1 The Chain Rule of Probability: Text as a Sequence of Guesses

### 🧭 The Problem First
We want a probability distribution over *all possible texts*. There are more possible 100-character strings than atoms in the universe, so we can't list them.

### 💡 Intuition / Instinct
Factor the problem: the probability of a text = the probability of the first char × the probability of the second given the first × ... (Ch 1.1). Now we only need a model of **"what comes next, given what came before"**. The whole art of language modelling is *how much of the past you use and how cleverly*.

### 🖼️ Visual Mental Model

```text
 P("hello") = P(h) · P(e|h) · P(l|he) · P(l|hel) · P(o|hell)
 bigram approximation:  P(h) · P(e|h) · P(l|e) · P(l|l) · P(o|l)   (only 1 char of memory)
```

### 📐 The Math, Gently
Exact: $P(x_{1:T}) = \prod_t P(x_t\mid x_{<t})$.
**n-gram (Markov) approximation:** $P(x_t\mid x_{<t}) \approx P(x_t\mid x_{t-n+1:t-1})$. A bigram (n = 2) conditions on 1 previous token.
We add special **boundary tokens** (e.g. `.` or `<BOS>`/`<EOS>`) so the model knows where sequences start and end.

### 🛠️ Build It From Scratch

```python
text = open("data/raw/shakespeare.txt").read()
chars = sorted(set(text)); V = len(chars)
stoi = {c: i for i, c in enumerate(chars)}; itos = {i: c for c, i in stoi.items()}
print(V, repr("".join(chars)))
print(text[:200])
```

### 🔬 Experiment & Observe
Before modelling, **look at the data** (Karpathy's first rule). Count the characters; note the newline structure (speaker names, blank lines) and upper vs lower case.

### ⚠️ Failure Modes & Debugging
An encoding mismatch (reading without `encoding="utf-8"` on Windows) gives mojibake. Always `open(path, encoding="utf-8")`.

### 🧠 Expert Insight
Markov (1913) analyzed letter sequences in Pushkin's *Eugene Onegin*: the first n-gram language model, over 100 years before GPT.

### ✅ Check Your Instinct
1. How many conditional distributions does a character bigram model need?

<details><summary>Answers</summary>

1. V (one per previous character), each over V outcomes, so a V×V table.
</details>

### 📌 Recap Card
- The chain rule factorizes text into next-token predictions.
- n-grams truncate the history to n−1 tokens.
- Look at your data first.

> **Core intuition:** *Language modelling = choosing how much of the past to remember.*

## 11.2 A Bigram Model by Counting

### 🧭 The Problem First
What's the simplest possible way to estimate $P(\text{next} \mid \text{current})$?

### 💡 Intuition / Instinct
**Count.** Go through the text and tally how often each character follows each other character. Normalize each row. This *is* the maximum-likelihood estimate (Ch 5.3). It's the "look it up in the book of past experience" model.

### 🖼️ Visual Mental Model

```text
          next →   a    b    ...  e    ...
 current  t      [ 12   0   ...  983  ... ]   → normalize row → P(·|t)
   ↓      h      [ 710  1   ...  2210 ... ]
```

### 📐 The Math, Gently
$$\hat P(j\mid i) = \frac{N_{ij}}{\sum_k N_{ik}}$$
Loss: the average NLL over all bigrams in held-out text.

### 🛠️ Build It From Scratch

```python
import torch
data = torch.tensor([stoi[c] for c in text], dtype=torch.long)
n = int(0.9 * len(data)); train, val = data[:n], data[n:]

N = torch.zeros((V, V), dtype=torch.float64)
N.index_put_((train[:-1], train[1:]), torch.ones(len(train) - 1, dtype=torch.float64), accumulate=True)
P = N / N.sum(1, keepdim=True)

def nll(P, d):
    p = P[d[:-1], d[1:]]
    return -(p.log()).mean().item()
print("train NLL:", nll(P, train))
print("val NLL  :", nll(P, val))              # may be inf! (see 11.3)

# sampling
g = torch.Generator().manual_seed(42)
ix = stoi["\n"]; out = []
for _ in range(300):
    ix = torch.multinomial(P[ix].float(), 1, generator=g).item(); out.append(itos[ix])
print("".join(out))
```

### 🔬 Experiment & Observe
- The train NLL is ~2.45 nats (PPL ≈ 11.6), versus the uniform baseline ln 65 = 4.17.
- Visualize `P` as a heatmap: vowels follow consonants, and newlines follow punctuation.
- The val NLL may be `inf`: some bigram in val never appeared in train.

### ⚠️ Failure Modes & Debugging
- `inf` validation loss from zero-probability events → smoothing (next section).
- Dividing by a zero row sum (a character that never appears as "current") gives NaN.

### 🧠 Expert Insight
Counting-based n-gram LMs (with smoothing) powered speech recognition and machine translation until ~2014. KenLM is the classic toolkit, and n-gram statistics are still used in data filtering (Ch 22) and contamination detection (Ch 35).

### ✅ Check Your Instinct
1. Why does counting equal MLE?
2. *(Coding)* Print the 5 most likely characters after `"q"`.

<details><summary>Answers</summary>

1. The categorical MLE is normalized counts (Ch 5.3).
2. `torch.topk(P[stoi['q']], 5)`, which is almost certainly dominated by 'u'.
</details>

### 📌 Recap Card
- Bigram = V×V count table, row-normalized.
- MLE by counting.
- Evaluate on held-out text.

> **Core intuition:** *The simplest model of language is a lookup table of what followed what.*

## 11.3 Smoothing and the Zero-Probability Problem

### 🧭 The Problem First
One unseen bigram in validation makes the whole loss infinite, since $-\log 0 = \infty$. Real text is full of rare events.

### 💡 Intuition / Instinct
**Pretend you've seen everything a little.** Add-k (Laplace) smoothing adds a pseudo-count k to every cell, reserving some probability mass for the unseen. Bigger k means more uniform and less confident. This is a *prior*: "before seeing data, I believed every character was possible."

Smarter methods (Kneser–Ney) back off to shorter contexts: if you've never seen "xq", use how often q appears in general (or, better, in how many different contexts it appears).

### 🖼️ Visual Mental Model

```text
 counts row "q":  u:120  a:0  b:0 ...      →  +1 each →  u:121 a:1 b:1 ...
 P(u|q) = 0.9999 → 0.65,   P(a|q) = 0 → 0.005
```

### 📐 The Math, Gently
$$\hat P_k(j\mid i) = \frac{N_{ij} + k}{\sum_l N_{il} + kV}$$
Interpolation: $P(j\mid i) = \lambda \hat P(j\mid i) + (1-\lambda)\hat P(j)$.

### 🛠️ Build It From Scratch

```python
def smoothed(N, k): return (N + k) / (N + k).sum(1, keepdim=True)
for k in [0.0, 0.01, 0.1, 1, 10, 100]:
    Pk = smoothed(N, k) if k > 0 else P
    print(f"k={k:6}: train {nll(Pk, train):.4f}  val {nll(Pk, val):.4f}")

unigram = N.sum(0) / N.sum()
for lam in [0.9, 0.99, 0.999]:
    Pi = lam * P + (1 - lam) * unigram[None, :]
    print(f"interp lambda={lam}: val {nll(Pi, val):.4f}")
```

### 🔬 Experiment & Observe
The train loss rises monotonically with k (less fitting). The val loss is finite for any k > 0 and U-shaped, with a best k around 0.1–1. **You just did hyperparameter tuning on a validation set.**

### ⚠️ Failure Modes & Debugging
- Tuning k on the *test* set leaks information. Use val for tuning and test once, at the end.
- Huge k makes everything uniform, and the loss approaches ln V.

### 🧠 Expert Insight
**Chen & Goodman (1998)** is the classic smoothing survey (Kneser–Ney wins). Neural LMs need no explicit smoothing because softmax never outputs exactly 0, but **label smoothing** and weight decay play analogous roles.

### ✅ Check Your Instinct
1. What does add-k correspond to in Bayesian terms?
2. Why does the train loss increase with k?

<details><summary>Answers</summary>

1. A symmetric Dirichlet prior over each row.
2. Probability mass moves away from the observed events.
</details>

### 📌 Recap Card
- Zero probabilities give infinite loss.
- Add-k or interpolation reserves mass for the unseen.
- Tune on val, never on test.

> **Core intuition:** *Never be absolutely certain something is impossible.*

## 11.4 The Same Bigram as a Neural Net: Counting vs Learning Are One Idea

### 🧭 The Problem First
Counting doesn't scale to long contexts (the table explodes) and doesn't generalize between similar contexts. We need a *learned* model. But first, let's see that learning recovers counting exactly.

### 💡 Intuition / Instinct
A neural bigram: one-hot(current char) × W → logits → softmax. Since one-hot × W just *selects a row* of W, W is a table of logits, and gradient descent on cross-entropy converges to the log of the counts (up to a per-row constant). **Counting and learning are the same model found two different ways.** Weight decay on W plays the role of smoothing (it pulls logits toward uniform).

### 🖼️ Visual Mental Model

```text
 one_hot(i) (V,) @ W (V,V) = W[i]  (logits)  → softmax → P(·|i)
 after training: softmax(W[i]) ≈ counts[i] / sum(counts[i])
```

### 📐 The Math, Gently
At the optimum: $\text{softmax}(W_i)_j = N_{ij}/\sum_k N_{ik}$, so $W_{ij} = \log N_{ij} + c_i$.
L2 on W: logits pushed toward 0 → a flatter distribution ≈ smoothing.

### 🛠️ Build It From Scratch

```python
# nanoforge/models/bigram.py
import torch, torch.nn as nn, torch.nn.functional as F

class BigramLM(nn.Module):
    def __init__(self, V):
        super().__init__()
        self.logits_table = nn.Embedding(V, V)              # row lookup == one_hot @ W
        nn.init.zeros_(self.logits_table.weight)            # start uniform: loss = ln V
    def forward(self, idx, targets=None):                   # idx: (B, T)
        logits = self.logits_table(idx)                     # (B, T, V)
        loss = None
        if targets is not None:
            B, T, V = logits.shape
            loss = F.cross_entropy(logits.view(B * T, V), targets.view(B * T))
        return logits, loss
```

```python
from nanoforge.models.bigram import BigramLM
torch.manual_seed(0)
model = BigramLM(V); opt = torch.optim.AdamW(model.parameters(), lr=0.1, weight_decay=0.0)
def get_batch(d, B=64, T=32):
    ix = torch.randint(0, len(d) - T - 1, (B,))
    x = torch.stack([d[i:i + T] for i in ix]); y = torch.stack([d[i + 1:i + T + 1] for i in ix])
    return x, y                                             # (B, T), (B, T)
for step in range(3001):
    x, y = get_batch(train); _, loss = model(x, y)
    opt.zero_grad(); loss.backward(); opt.step()
    if step % 1000 == 0: print(step, loss.item())
learned = F.softmax(model.logits_table.weight, -1).double()
print("max |learned - counted| prob:", (learned - smoothed(N, 0.01)).abs().max().item())
print("val NLL learned:", nll(learned, val))
```

### 🔬 Experiment & Observe
The learned probabilities match the (lightly smoothed) counts to ~1e-2, and the val NLL is essentially the same (~2.47). Add `weight_decay=0.01` and watch it act like more smoothing.

### ⚠️ Failure Modes & Debugging
- `logits.view(B*T, V)` needs contiguous memory; use `.reshape` if unsure.
- Note that `get_batch` shifts the targets by exactly one. An off-by-one here is a classic bug (the model predicts the *current* token, the loss goes to ~0, and generation is garbage).

### 🧠 Expert Insight
The `(B, T)` → `(B, T, V)` logits → flatten → cross-entropy pattern is *exactly* what GPT uses. Only the middle changes: `logits_table(idx)` becomes a stack of transformer blocks that let each position see its context.

### ✅ Check Your Instinct
1. What does `nn.Embedding(V, V)` compute on index i?
2. Why init to zeros?
3. *(Coding)* Check that the initial loss is ln V ≈ 4.17.

<details><summary>Answers</summary>

1. Row i of the weight matrix, i.e. one-hot(i) @ W.
2. Uniform predictions give the ln V baseline (the sanity check).
3. Print the loss at step 0.
</details>

### 📌 Recap Card
- Neural bigram = embedding table of logits.
- Gradient descent recovers the count-based MLE.
- Weight decay ≈ smoothing.
- `(B,T)` → `(B,T,V)` → CE: the GPT interface.

> **Core intuition:** *Learning and counting are the same thing for a lookup table; learning just generalizes to richer models.*

## 11.5 N-grams and the Curse of Context Length

### 🧭 The Problem First
One character of context is not enough ("q" → "u" is easy, but "th" vs "wh" needs more). Why not use trigrams, 10-grams, 100-grams?

### 💡 Intuition / Instinct
The table size is $V^{n}$. For characters (V = 65): a 5-gram needs 1.16 billion cells. For words (V = 50K): a trigram needs 1.25×10¹⁴. Almost all cells are empty (**data sparsity**), and the table can't generalize: seeing "the cat sat" tells a count table *nothing* about "the dog sat". **We need a model that shares knowledge between similar contexts.** That's what embeddings (Ch 12) provide.

### 🖼️ Visual Mental Model

```text
 n:           2        3          4            5
 table size:  4.2K     275K       17.9M        1.16B    (V = 65)
 fraction of contexts seen in 1M chars: falls toward 0 fast
```

### 📐 The Math, Gently
Number of contexts = $V^{n-1}$. With N training tokens, the average count per context ≈ $N / V^{n-1}$. For n = 5 and N = 10⁶, that's 10⁶/1.8×10⁷ ≈ 0.06, so almost every context is unseen.

### 🛠️ Build It From Scratch

```python
from collections import defaultdict, Counter
import math

def ngram_model(tokens, n):
    counts = defaultdict(Counter)
    for i in range(n - 1, len(tokens)):
        counts[tuple(tokens[i - n + 1:i])][tokens[i]] += 1
    return counts

def ngram_nll(counts, tokens, n, V, k=0.1):
    total = 0.0
    for i in range(n - 1, len(tokens)):
        c = counts.get(tuple(tokens[i - n + 1:i]), Counter())
        p = (c[tokens[i]] + k) / (sum(c.values()) + k * V)
        total -= math.log(p)
    return total / (len(tokens) - n + 1)

tr, va = text[:n], text[n:n + 100_000]
for order in [1, 2, 3, 4, 5, 6, 8]:
    m = ngram_model(tr, order)
    print(f"n={order}: contexts={len(m):8d}  train={ngram_nll(m, tr[:100000], order, V):.3f}  val={ngram_nll(m, va, order, V):.3f}")
```

### 🔬 Experiment & Observe
The train NLL drops toward 0 as n grows (memorization). The val NLL improves until n ≈ 4–5, then *worsens*: unseen contexts fall back to near-uniform. The classic overfitting U-curve, caused by sparsity.

### ⚠️ Failure Modes & Debugging
Memory explodes with n on big corpora. Production n-gram systems use pruning, hashing and suffix arrays.

### 🧠 Expert Insight
- **"Infini-gram" (Liu et al., 2024):** unbounded-n n-grams over trillions of tokens using suffix arrays. They are surprisingly strong when combined with neural LMs, but can't generalize to paraphrases.
- **Bengio et al. (2003)** explicitly framed the neural LM as the cure for the curse of dimensionality.

### ✅ Check Your Instinct
1. Why does the val loss get worse for large n?
2. What property would a better model need?

<details><summary>Answers</summary>

1. Most val contexts are unseen, so the model falls back to smoothing (near-uniform).
2. Sharing statistical strength between *similar* contexts: distributed representations.
</details>

### 📌 Recap Card
- Table size grows as $V^{n-1}$.
- Sparsity: most long contexts are unseen.
- Counting can't generalize across similar contexts.

> **Core intuition:** *Exact memory of contexts doesn't scale; we need a notion of similar contexts.*

## 11.6 Train/Val/Test Splits and Measuring Loss Honestly

### 🧭 The Problem First
A model's loss on its own training data tells you nothing about how well it generalizes. Worse, sloppy evaluation (noisy, leaky or biased) leads you to wrong conclusions.

### 💡 Intuition / Instinct
- **Train:** fit the parameters.
- **Val:** choose hyperparameters and decide when to stop.
- **Test:** report the final number, touched *once*.

For text, split **contiguously or by document**, not by random characters. Random character splits put almost-identical contexts in both sets, and val looks artificially good. Estimate the loss over **many batches** (average), because a single batch is noisy.

### 🖼️ Visual Mental Model

```text
 [============ train 90% ============][== val 5% ==][= test 5% =]
 split on document boundaries; dedup across splits
```

### 📐 The Math, Gently
The standard error of an estimated loss from $n$ tokens with per-token loss std $s$ is ≈ $s/\sqrt{n}$ (tokens are correlated, so the real error is larger). For s = 2 nats and n = 10⁴ tokens, ±0.02. To detect a 0.01 difference, you need ≥ 10⁵ eval tokens.

### 🛠️ Build It From Scratch

```python
# nanoforge/eval/loss.py
import torch

@torch.no_grad()
def estimate_loss(model, splits, get_batch, eval_iters=200, **batch_kw):
    """Average loss over eval_iters random batches for each split."""
    out = {}
    model.eval()
    for name, data in splits.items():
        losses = torch.zeros(eval_iters)
        for k in range(eval_iters):
            x, y = get_batch(data, **batch_kw)
            _, loss = model(x, y)
            losses[k] = loss.item()
        out[name] = losses.mean().item()
    model.train()
    return out
```

```python
# nanoforge/data/simple.py  (reused through Ch 20)
import torch
def get_batch(data, B=32, T=64, device="cpu"):
    ix = torch.randint(0, len(data) - T - 1, (B,))
    x = torch.stack([data[i:i + T] for i in ix])
    y = torch.stack([data[i + 1:i + T + 1] for i in ix])
    return x.to(device), y.to(device)
```

### 🔬 Experiment & Observe
Evaluate the neural bigram with `eval_iters` = 1, 10, 200 several times and look at the spread. With 1 iteration the estimate jumps around by ±0.05; with 200 it is stable to ±0.005.

### ⚠️ Failure Modes & Debugging
- Leakage from duplicated passages across splits (common with scraped data; Ch 21).
- Comparing val losses computed with different T (context length) or tokenizers.
- Forgetting `model.eval()` leaves dropout on during eval.

### 🧠 Expert Insight
Frontier evals include held-out *domains*, not just held-out samples, to measure true generalization, plus contamination checks against benchmark test sets (Ch 35).

### ✅ Check Your Instinct
1. Why split by document, not randomly?
2. How many eval tokens are needed to resolve a 0.01-nat difference with s = 2?

<details><summary>Answers</summary>

1. Random splits leak nearly identical contexts into val, making it optimistic.
2. ~(2/0.005)² ≈ 1.6×10⁵, for a 2σ margin (more because of correlation).
</details>

### 📌 Recap Card
- Train/val/test, split by document.
- Average the loss over many batches.
- Touch the test set once.

> **Core intuition:** *A number you can't trust is worse than no number.*
