## 40.1 Deriving DPO From the RLHF Objective

### 🧭 The Problem First
PPO-RLHF needs four models (policy, reference, reward, value), online generation and delicate tuning. Is there a closed-form shortcut?

### 💡 Intuition / Instinct
The KL-regularized RLHF objective has a **known optimal policy**: the reference policy re-weighted by the exponentiated reward. Invert that relationship: the reward can be *expressed* through the policy's log-ratio to the reference. Plug that into the Bradley–Terry preference loss, and the reward model disappears. You directly train the policy so that its log-ratio is higher on chosen than on rejected responses. **"Your language model is secretly a reward model."**

### 🖼️ Visual Mental Model

```text
 RLHF:  max E[r] − β KL(π || π_ref)
   → optimal π*(y|x) ∝ π_ref(y|x) · exp(r(x,y)/β)
   → r(x,y) = β log(π*(y|x)/π_ref(y|x)) + β log Z(x)
   → Bradley–Terry on r_w − r_l : Z(x) cancels!
   → loss = −log σ( β[log π/π_ref (y_w) − log π/π_ref (y_l)] )
```

### 📐 The Math, Gently
Step 1: $\max_\pi\ \mathbb{E}_{y\sim\pi}[r(x,y)] - \beta\,D_{KL}(\pi\|\pi_{ref})$ has solution $\pi^*(y\mid x) = \frac{1}{Z(x)}\pi_{ref}(y\mid x)e^{r(x,y)/\beta}$ (Gibbs distribution; proof: rewrite the objective as $-\beta D_{KL}(\pi\|\pi^*) + \text{const}$).
Step 2: $r(x,y) = \beta\log\frac{\pi^*(y\mid x)}{\pi_{ref}(y\mid x)} + \beta\log Z(x)$.
Step 3: Bradley–Terry: $P(y_w\succ y_l) = \sigma(r_w - r_l)$, where $\log Z(x)$ cancels.
DPO loss: $\mathcal{L}_{DPO} = -\mathbb{E}\left[\log\sigma\left(\beta\log\frac{\pi_\theta(y_w)}{\pi_{ref}(y_w)} - \beta\log\frac{\pi_\theta(y_l)}{\pi_{ref}(y_l)}\right)\right]$.
Gradient: it upweights $\nabla\log\pi(y_w)$ and downweights $\nabla\log\pi(y_l)$, weighted by $\sigma(\hat r_l - \hat r_w)$, i.e. more when the model currently ranks the pair *wrongly*.

### ⚠️ Failure Modes & Debugging
DPO is *offline*: it learns from a fixed dataset of pairs, often generated by other models. A distribution mismatch with the current policy limits it (hence online/iterative DPO variants).

### 🧠 Expert Insight
- **Rafailov et al. (2023), "Direct Preference Optimization: Your Language Model is Secretly a Reward Model".**
- Zephyr (2023) and Tülu 2/3 popularized DPO for open models.
- **Xu et al. (2024), "Is DPO Superior to PPO for LLM Alignment?":** well-tuned PPO can still win, especially with online data.

### ✅ Check Your Instinct
1. Why does the partition function Z(x) cancel?
2. What role does β play?

<details><summary>Answers</summary>

1. Both responses share the same prompt x, so β log Z(x) appears in both implicit rewards and cancels in their difference.
2. The strength of the KL constraint: smaller β lets the policy deviate more from the reference.
</details>

### 📌 Recap Card
- The optimal KL-regularized policy ∝ π_ref · exp(r/β).
- Implicit reward = β log(π/π_ref).
- DPO = Bradley–Terry on implicit rewards; no RM, no sampling.

> **Core intuition:** *Skip the judge: train the model so its own likelihood ratios agree with human preferences.*

## 40.2 Implementing DPO

### 🧭 The Problem First
Turn the loss into a training loop with correct masking and a frozen reference model.

### 💡 Intuition / Instinct
For each pair: compute the summed log-probs of the chosen and rejected responses (response tokens only) under the policy and under the frozen reference. Implicit rewards = β·(policy − ref). Loss = −logσ(chosen − rejected). Precompute the reference log-probs once to save compute.

### 🖼️ Visual Mental Model

```text
 batch: [chosen_1, rejected_1, chosen_2, rejected_2, ...]
 π_θ  → logp sums  ┐
 π_ref→ logp sums  ┴─▶ margins → −log σ(β·Δ) → backward (policy only)
```

### 📐 The Math, Gently
Metrics to log: reward accuracy = mean[$\hat r_w > \hat r_l$], reward margin = mean[$\hat r_w - \hat r_l$], and the chosen/rejected log-probs separately.
Typical settings: β = 0.1 (0.01–0.5), lr 5e-7 to 5e-6 (full fine-tuning; higher with LoRA), 1–3 epochs.

### 🛠️ Build It From Scratch

```python
# nanoforge/posttrain/dpo.py
import copy, random, torch, torch.nn.functional as F
from torch.nn.utils.rnn import pad_sequence

def build_pair_tensors(fmt, rec, max_len):
    p = fmt.prompt_for_generation(rec["prompt"])
    out = []
    for resp in (rec["chosen"], rec["rejected"]):
        r = fmt.tok.encode_ordinary(resp) + [fmt.end]
        ids = (p + r)[:max_len]; mask = ([0] * len(p) + [1] * len(r))[:max_len]
        out.append((torch.tensor(ids), torch.tensor(mask)))
    return out

def batch_logps(model, ids, mask):
    """Sum of log-probs over response tokens. ids/mask: (B, T)."""
    logits, _ = model(ids[:, :-1], all_logits=True)
    logp = F.log_softmax(logits.float(), -1).gather(-1, ids[:, 1:, None]).squeeze(-1)
    return (logp * mask[:, 1:]).sum(-1), mask[:, 1:].sum(-1)

def collate(pairs, pad_id):
    seqs = [s for pr in pairs for s in pr]                   # chosen, rejected interleaved
    ids = pad_sequence([s[0] for s in seqs], batch_first=True, padding_value=pad_id)
    mask = pad_sequence([s[1] for s in seqs], batch_first=True, padding_value=0)
    return ids, mask

@torch.no_grad()
def precompute_ref(ref, data, pad_id, device, B=8):
    out = []
    for i in range(0, len(data), B):
        ids, mask = collate(data[i:i + B], pad_id)
        lp, _ = batch_logps(ref, ids.to(device), mask.to(device).float())
        out.extend(lp.view(-1, 2).tolist())
    return out

def dpo_loss(pc, pr, rc, rr, beta=0.1, variant="dpo", label_smoothing=0.0):
    """pc/pr: policy logp chosen/rejected; rc/rr: reference. Returns loss, metrics."""
    logits = (pc - rc) - (pr - rr)                           # log-ratio margin
    if variant == "dpo":
        loss = -(1 - label_smoothing) * F.logsigmoid(beta * logits) - label_smoothing * F.logsigmoid(-beta * logits)
    elif variant == "ipo":
        loss = (logits - 1 / (2 * beta)) ** 2                # 40.3
    else: raise ValueError(variant)
    rw, rl = beta * (pc - rc).detach(), beta * (pr - rr).detach()
    return loss.mean(), {"acc": (rw > rl).float().mean().item(), "margin": (rw - rl).mean().item(),
                         "logp_chosen": pc.mean().item(), "logp_rejected": pr.mean().item()}

def train_dpo(policy, ref, fmt, records, device, beta=0.1, lr=1e-6, epochs=1, B=4, max_len=768, variant="dpo"):
    pad = fmt.tok.special_tokens["<|pad|>"]
    data = [build_pair_tensors(fmt, r, max_len) for r in records]
    ref_lp = precompute_ref(ref.eval(), data, pad, device)
    opt = torch.optim.AdamW([p for p in policy.parameters() if p.requires_grad], lr=lr, weight_decay=0.0)
    idx = list(range(len(data))); policy.train(); step = 0
    for ep in range(epochs):
        random.shuffle(idx)
        for i in range(0, len(idx) - B + 1, B):
            bi = idx[i:i + B]
            ids, mask = collate([data[j] for j in bi], pad)
            with torch.autocast("cuda", dtype=torch.bfloat16, enabled=device == "cuda"):
                lp, _ = batch_logps(policy, ids.to(device), mask.to(device).float())
            lp = lp.view(-1, 2); rl = torch.tensor([ref_lp[j] for j in bi], device=device)
            loss, m = dpo_loss(lp[:, 0], lp[:, 1], rl[:, 0], rl[:, 1], beta, variant)
            opt.zero_grad(); loss.backward(); torch.nn.utils.clip_grad_norm_(policy.parameters(), 1.0); opt.step()
            if step % 20 == 0: print(f"dpo step {step} loss {loss.item():.4f} {m}")
            step += 1
    return policy
```

With LoRA (Ch 38), the reference is just the base with the adapters disabled, so you don't need a second model copy (set the LoRA scale to 0, or unmerge, for the reference pass).

### 🔬 Experiment & Observe
Train DPO on your preference pairs (Ch 39.1) from the SFT checkpoint with β ∈ {0.05, 0.1, 0.5}. Track the reward accuracy (train and held-out) and the judge win-rate vs SFT (Ch 36). Compare with your PPO results from Ch 39: similar gains for far less complexity.

### ⚠️ Failure Modes & Debugging
- Forgetting to mask the prompt tokens → the loss includes identical prompt log-probs (they cancel in theory, but add noise).
- A reference ≠ the SFT starting point → the implicit reward is miscalibrated.
- Overfitting: the train reward accuracy → 100% and the outputs degrade. Use 1 epoch, a low lr, a higher β.

### 🧠 Expert Insight
HF TRL's `DPOTrainer` implements the same computation. **Tülu 3** found DPO with length-normalized log-probs and careful data mixing worked well; see also **online DPO / iterative DPO** (Xiong et al., 2024), which regenerates pairs from the current policy.

1. Why can the reference log-probs be precomputed?
2. What does reward accuracy measure in DPO?

<details><summary>Answers</summary>

1. The reference is frozen; its log-probs on the fixed dataset never change.
2. The fraction of pairs where the implicit reward of the chosen response exceeds that of the rejected one.
</details>

### 📌 Recap Card
- Summed response log-probs, policy and reference.
- Loss = −logσ(β·[Δchosen − Δrejected]).
- Precompute the reference; log accuracy, margin and the separate log-probs.

> **Core intuition:** *Widen the gap between what people chose and what they rejected, relative to where you started.*

## 40.3 IPO, KTO, ORPO, SimPO: What Each Fixes

### 🧭 The Problem First
DPO has known issues:
- (a) It can **overfit** deterministic preferences: the logistic loss pushes the margin to infinity.
- (b) It needs **paired** data.
- (c) It needs a **reference model** (memory and compute).
- (d) The chosen log-prob often *decreases* (the "likelihood displacement"), and the length bias persists.

### 💡 Intuition / Instinct

| Method | Idea | Fixes |
|---|---|---|
| **IPO** | Regress the margin to a finite target 1/(2β) (a squared loss) | overfitting of deterministic prefs (a) |
| **KTO** | Prospect-theory loss on *unpaired* good/bad labels vs a reference point | needs only thumbs up/down (b) |
| **ORPO** | SFT loss + an odds-ratio penalty; no reference, one stage | removes the reference + SFT stage (c) |
| **SimPO** | Reward = *length-normalized* log-prob (no reference) + a target margin γ | reference-free, length bias (c, d) |
| **DPO + NLL** (RPO) | Add an SFT loss on the chosen responses | likelihood displacement (d) |

### 🖼️ Visual Mental Model

```text
 DPO:   −log σ(β·Δ)                (Δ → ∞ keeps reducing the loss)
 IPO:   (Δ − 1/(2β))²              (stops at a target margin)
 SimPO: −log σ(β/|y_w| log π(y_w) − β/|y_l| log π(y_l) − γ)
 ORPO:  NLL(y_w) − λ log σ(log odds(y_w) − log odds(y_l)),  odds(y) = p/(1−p) with p = exp(mean token logp)
 KTO:   desirable: 1 − σ(β(r − z_ref)); undesirable: 1 − σ(β(z_ref − r)), r = log π/π_ref
```

### 📐 The Math, Gently
- IPO: $\mathcal{L} = \left(h_\theta - \frac{1}{2\beta}\right)^2$, with $h = \log\frac{\pi(y_w)\pi_{ref}(y_l)}{\pi(y_l)\pi_{ref}(y_w)}$.
- SimPO: $\mathcal{L} = -\log\sigma\left(\frac{\beta}{|y_w|}\log\pi(y_w) - \frac{\beta}{|y_l|}\log\pi(y_l) - \gamma\right)$, with typical β ≈ 2–2.5, γ ≈ 0.5–1.5.
- ORPO: $\mathcal{L} = \mathcal{L}_{NLL}(y_w) + \lambda\,\mathcal{L}_{OR}$, $\mathcal{L}_{OR} = -\log\sigma\left(\log\frac{\text{odds}(y_w)}{\text{odds}(y_l)}\right)$, λ ≈ 0.1.
- KTO: uses a batch-level reference point $z_{ref} = \max(0, \widehat{KL}(\pi\|\pi_{ref}))$ and separate weights for desirable/undesirable examples.

### 🛠️ Build It From Scratch

```python
# nanoforge/posttrain/pref_losses.py
import torch, torch.nn.functional as F

def ipo_loss(pc, pr, rc, rr, beta=0.1):
    h = (pc - rc) - (pr - rr); return ((h - 1 / (2 * beta)) ** 2).mean()

def simpo_loss(pc, pr, len_c, len_r, beta=2.0, gamma=1.0):
    return -F.logsigmoid(beta * pc / len_c - beta * pr / len_r - gamma).mean()

def orpo_loss(pc, pr, len_c, len_r, nll_chosen, lam=0.1):
    """pc/pr: summed logp; convert to mean-token prob p, then log-odds."""
    def log_odds(lp, n):
        mean_lp = lp / n
        return mean_lp - torch.log1p(-torch.exp(mean_lp).clamp(max=1 - 1e-6))
    return nll_chosen + lam * (-F.logsigmoid(log_odds(pc, len_c) - log_odds(pr, len_r))).mean()

def kto_loss(policy_lp, ref_lp, desirable: torch.Tensor, kl_ref, beta=0.1, w_d=1.0, w_u=1.0):
    """Unpaired: policy_lp/ref_lp summed logps per example; desirable: bool tensor; kl_ref: scalar estimate (detached)."""
    r = policy_lp - ref_lp
    z = kl_ref.clamp(min=0).detach()
    loss_d = w_d * (1 - torch.sigmoid(beta * (r - z)))
    loss_u = w_u * (1 - torch.sigmoid(beta * (z - r)))
    return torch.where(desirable, loss_d, loss_u).mean()
```

To use them, reuse `batch_logps` from 40.2, which also returns the response lengths.

### 🔬 Experiment & Observe
Run DPO, IPO, SimPO and ORPO (from the *base* model for ORPO, since it includes SFT) on the same data. Compare the judge win-rates, the average response length and the chosen log-prob trends. Typical observations: DPO lengthens responses; SimPO controls length; IPO is more robust with small, clean datasets; ORPO saves a stage.

### ⚠️ Failure Modes & Debugging
- The SimPO/ORPO hyperparameters (β, γ, λ) differ greatly from DPO's. Don't reuse DPO's β.
- The KTO reference point estimated on tiny batches is noisy. Use larger batches or an EMA.

### 🧠 Expert Insight
- **Azar et al. (2023), IPO.** **Ethayarajh et al. (2024), KTO.** **Hong et al. (2024), ORPO.** **Meng et al. (2024), SimPO.** **Pang et al. (2024), iterative RPO (DPO + NLL).**
- **Razin et al. (2024), "Unintentional Unalignment":** likelihood displacement in DPO.
- No method dominates universally; data quality and on-policy freshness matter more.
