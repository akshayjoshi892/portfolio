## 17.1 Attention as a Soft Dictionary Lookup

### 🧭 The Problem First
At each position, the model needs information from *some* earlier tokens, and which ones depends on the content. In "The trophy didn't fit in the suitcase because **it** was too big", "it" needs "trophy". The MLP LM gave fixed per-position weights (no selection); the RNN squeezed everything into one vector (a bottleneck).

### 💡 Intuition / Instinct
Think of a Python dictionary: `d[query]` returns the value whose key *exactly* matches. **Attention is a soft, differentiable dictionary:** compare the query with *every* key, score the similarity, turn the scores into weights with softmax, and return the **weighted average of all values**. Nothing is a hard miss; everything is blended by relevance, and because it's differentiable the model can *learn* what to look for.

### 🖼️ Visual Mental Model

```text
 hard dict:   query "trophy?" → exact key match → value

 soft attention:
   query q ──· k1 "The"      score 0.1 ─┐
            · k2 "trophy"    score 3.2 ─┤ softmax → weights [0.02, 0.85, 0.05, 0.08]
            · k3 "suitcase"  score 0.9 ─┤
            · k4 "because"   score 1.1 ─┘
   output = 0.02·v1 + 0.85·v2 + 0.05·v3 + 0.08·v4   ≈ mostly "trophy"'s information
```

### 📐 The Math, Gently
For a query $q$ and pairs $(k_j, v_j)$:
$$\alpha_j = \frac{e^{q\cdot k_j}}{\sum_l e^{q\cdot k_l}},\qquad \text{out} = \sum_j \alpha_j v_j$$
Worked example (2-d): q = (1, 0); keys k₁ = (1, 0), k₂ = (0, 1); values v₁ = (10, 0), v₂ = (0, 10).
Scores [1, 0] → weights [0.731, 0.269] → out = (7.31, 2.69).
Scale q by 5 → scores [5, 0] → weights [0.993, 0.007] → out ≈ (9.93, 0.07). **Larger dot products → sharper, more "hard" lookups.**

### 🛠️ Build It From Scratch

```python
import torch, torch.nn.functional as F
def soft_lookup(q, K, V):                  # q: (d,), K: (n, d), V: (n, dv)
    scores = K @ q                          # (n,)  similarity to each key
    w = F.softmax(scores, dim=0)            # (n,)  attention weights
    return w @ V, w                          # (dv,) weighted average of values
K = torch.tensor([[1., 0.], [0., 1.]]); V = torch.tensor([[10., 0.], [0., 10.]])
for s in [1, 5, 20]:
    out, w = soft_lookup(torch.tensor([1., 0.]) * s, K, V)
    print(f"scale {s:2d}: weights {w.numpy().round(3)} out {out.numpy().round(2)}")
```

### 🔬 Experiment & Observe
As the query scale grows, the soft lookup approaches a hard lookup. A model can learn to be sharp (copying one token) or diffuse (averaging many) simply by scaling its queries/keys.

### ⚠️ Failure Modes & Debugging
If all scores are equal, you get a uniform average: attention "sees" nothing specific. A randomly initialized model starts close to this.

### 🧠 Expert Insight
- **Bahdanau, Cho & Bengio (2014):** attention for translation (RNN encoder-decoder with additive scoring).
- **Graves et al. (2014), Neural Turing Machines:** content-based addressing.
- **Vaswani et al. (2017):** made attention the whole model.

### ✅ Check Your Instinct
1. What happens with a single key?
2. How can the model make attention sharper?

<details><summary>Answers</summary>

1. Its weight is 1; the output is that value.
2. By increasing the magnitude of the q·k scores (larger or more aligned queries/keys).
</details>

### 📌 Recap Card
- Attention = similarity → softmax → weighted average of values.
- Soft, differentiable, content-addressed.
- Score scale controls sharpness.

> **Core intuition:** *Every token asks a question, and gets back a relevance-weighted blend of the answers.*

## 17.2 Queries, Keys and Values: What I Seek, What I Offer, What I Give

### 🧭 The Problem First
If we used the raw token vectors for everything (q = k = v = x), a token would mostly attend to itself (x·x is large), and it couldn't separately control *what it looks for* vs *how it's found* vs *what it passes on*.

### 💡 Intuition / Instinct
Each token vector x is projected three ways by learned matrices:
- **Query** $q = xW_Q$: "what am I looking for?" (e.g. "it" seeks a noun antecedent)
- **Key** $k = xW_K$: "what do I contain / how should I be found?" (e.g. "trophy" advertises "I'm a noun, an object")
- **Value** $v = xW_V$: "what information do I hand over if selected?"

A library analogy: your query is your search phrase, keys are the catalogue entries, and values are the actual book contents. The catalogue entry is *not* the book, and separating them is powerful.

### 🖼️ Visual Mental Model

```text
 X (T, C) ──W_Q──▶ Q (T, d)   "seeking"
          ──W_K──▶ K (T, d)   "advertising"
          ──W_V──▶ V (T, d)   "content"
 scores = Q Kᵀ (T, T): row i = how much token i wants each token j
```

### 📐 The Math, Gently
$Q = XW_Q,\ K = XW_K,\ V = XW_V$, with $W_\ast \in \mathbb{R}^{C\times d}$.
$S = QK^\top = XW_QW_K^\top X^\top$. The matrix $W_QW_K^\top$ is a learned *bilinear similarity*: it lets the model define "relevance" in any way, not just raw similarity.

### 🛠️ Build It From Scratch

```python
torch.manual_seed(0)
T, C, d = 5, 16, 8
X = torch.randn(T, C)
W_Q, W_K, W_V = (torch.randn(C, d) / C**0.5 for _ in range(3))
Q, K, V = X @ W_Q, X @ W_K, X @ W_V             # (T, d) each
S = Q @ K.T                                      # (T, T) all pairwise scores
A = F.softmax(S, dim=-1)                         # (T, T) each row sums to 1
out = A @ V                                      # (T, d) row view of matmul (Ch 3.4)
print(A.sum(-1), out.shape)

# with q = k = x: self-similarity dominates the diagonal
A_raw = F.softmax(X @ X.T, -1); print("diag mass (q=k=x):", A_raw.diag().mean().item())
print("diag mass (learned proj):", A.diag().mean().item())
```

### 🔬 Experiment & Observe
With q = k = x, the diagonal carries almost all the attention (self-lookup). With separate random projections it doesn't, and after training, the projections encode useful relations (Ch 48 induction heads).

### ⚠️ Failure Modes & Debugging
Mixing up the softmax axis: the softmax must run over **keys** (last dim) so each query's weights sum to 1. A softmax over queries is a silent, disastrous bug.

### 🧠 Expert Insight
Anthropic's circuits framework splits a head into a **QK circuit** ($W_QW_K^\top$: *where* to attend) and an **OV circuit** ($W_VW_O$: *what* to move). Thinking in these two circuits is the key to interpretability (Ch 48).

### ✅ Check Your Instinct
1. Which projection determines what information moves?
2. Over which axis is the softmax taken?

<details><summary>Answers</summary>

1. The value projection (and then the output projection).
2. The key axis (last dimension of the (T, T) scores).
</details>

### 📌 Recap Card
- Q: seeking; K: advertising; V: content.
- $QK^\top$ = learned relevance.
- Softmax over keys.

> **Core intuition:** *Separate what you ask for, how you're found, and what you give.*

## 17.3 Scaled Dot-Product Attention: Why Divide by √d

### 🧭 The Problem First
With d = 64 or 128, raw dot products are large. The softmax then saturates into near one-hot weights at initialization, gradients through the softmax vanish, and training starts badly.

### 💡 Intuition / Instinct
If q and k have unit-variance components, $q\cdot k$ is a sum of d terms with variance d, so its std is √d (Ch 3.2, 5.1). Dividing by √d brings the scores back to unit variance regardless of head size, which keeps the softmax in its "soft", trainable regime.

### 🖼️ Visual Mental Model

```text
 d=64, unscaled scores std ≈ 8 → softmax ≈ one-hot → gradient ≈ 0
 scaled by 1/√64  std ≈ 1 → softmax spread out → healthy gradients
```

### 📐 The Math, Gently
$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V$$
$\text{Var}(q\cdot k) = \sum_{i=1}^d \text{Var}(q_ik_i) = d$ for independent unit-variance components.
Softmax Jacobian: $\partial p_i/\partial s_j = p_i(\delta_{ij} - p_j)$, which goes to 0 when p is one-hot. Saturated softmax means no learning.

### 🛠️ Build It From Scratch

```python
def attention(q, k, v, mask=None, scale=True):
    """q,k,v: (..., T, d). mask: broadcastable bool (..., T, T), True = keep."""
    d = q.size(-1)
    s = q @ k.transpose(-2, -1)                          # (..., T, T)
    if scale: s = s / d ** 0.5
    if mask is not None: s = s.masked_fill(~mask, float("-inf"))
    a = F.softmax(s, dim=-1)
    return a @ v, a

for d in [16, 64, 256]:
    q, k, v = torch.randn(1, 32, d), torch.randn(1, 32, d), torch.randn(1, 32, d)
    for sc in [False, True]:
        _, a = attention(q, k, v, scale=sc)
        ent = -(a * a.clamp_min(1e-12).log()).sum(-1).mean()
        print(f"d={d:3d} scaled={sc!s:5}: max weight {a.max(-1).values.mean():.2f}, entropy {ent:.2f} (uniform={torch.log(torch.tensor(32.)):.2f})")
```

### 🔬 Experiment & Observe
Unscaled attention at d = 256 has max weights near 1 (saturated) and near-zero entropy; scaled attention stays spread out. Measure the gradient norm w.r.t. q in each case: the unscaled one is tiny.

### ⚠️ Failure Modes & Debugging
- Forgetting the scale (or scaling by d instead of √d) makes training slower or unstable.
- During training, the attention logits can *grow* anyway, so entropy collapses and the loss spikes. QK-norm and logit soft-capping address this (Ch 27, 32).

### 🧠 Expert Insight
- Vaswani et al. (2017) Section 3.2.1 explains the √d choice exactly like this.
- µP (Ch 26) argues for 1/d scaling for width-transferable hyperparameters.
- Gemma 2 adds attention **logit soft-capping** (tanh(s/c)·c).

### ✅ Check Your Instinct
1. Std of q·k for d = 128 with unit-variance components?
2. Why does a saturated softmax stop learning?

<details><summary>Answers</summary>

1. √128 ≈ 11.3.
2. Its Jacobian $p_i(\delta_{ij}-p_j)$ → 0 when p is one-hot.
</details>

### 📌 Recap Card
- Dot products grow like √d.
- Divide by √d to keep the scores unit-variance.
- A saturated softmax kills gradients.

> **Core intuition:** *Scale the scores so the softmax starts out curious, not certain.*

## 17.4 Causal Masking: No Peeking at the Future

### 🧭 The Problem First
We train on all T positions in parallel: position t predicts token t+1. If position t can attend to positions > t, it can just *read the answer*. The training loss goes to ~0, and generation (where the future doesn't exist) is garbage.

### 💡 Intuition / Instinct
Before the softmax, set the scores for future keys to −∞, so their weights become exactly 0. The mask is a lower-triangular matrix. It turns a parallel computation into one that is *equivalent* to T separate left-to-right predictions, which is why transformers train in parallel but generate autoregressively.

### 🖼️ Visual Mental Model

```text
 keys →   t1  t2  t3  t4
 q t1   [ ✓   ✗   ✗   ✗ ]
 q t2   [ ✓   ✓   ✗   ✗ ]
 q t3   [ ✓   ✓   ✓   ✗ ]
 q t4   [ ✓   ✓   ✓   ✓ ]      lower-triangular (causal) mask
```

### 📐 The Math, Gently
$M_{ij} = 0$ if $j \le i$, $-\infty$ otherwise; $A = \text{softmax}(S/\sqrt d + M)$. Since $e^{-\infty} = 0$, the future weights are exactly zero. The first position attends only to itself.

### 🛠️ Build It From Scratch

```python
T, d = 4, 8
q, k, v = torch.randn(T, d), torch.randn(T, d), torch.randn(T, d)
causal = torch.tril(torch.ones(T, T, dtype=torch.bool))
out, a = attention(q, k, v, mask=causal)
print(a.round(decimals=2))                     # upper triangle exactly 0

# Leak test: changing a FUTURE token must not change earlier outputs
v2 = v.clone(); v2[3] += 100; k2 = k.clone(); k2[3] += 100
out2, _ = attention(q, k2, v2, mask=causal)
print("positions 0-2 unchanged:", torch.allclose(out[:3], out2[:3]))   # True
```

### 🔬 Experiment & Observe
Remove the mask in your GPT (Ch 20) and train: the train loss plummets toward 0 within a few hundred steps, and samples are garbage. This is the classic "too good to be true" bug. **The leak test above belongs in your test suite.**

### ⚠️ Failure Modes & Debugging
- Mask orientation reversed (`triu` instead of `tril`).
- Using a large negative value like −1e4 in fp16 (it overflows its own range), or −inf on fully masked rows (NaN). With causal masks, every row has at least the diagonal, so −inf is safe.
- Padding masks must be *combined* with the causal mask (logical AND).

### 🧠 Expert Insight
- Encoder models (BERT) use bidirectional attention (no causal mask) with a masked-LM objective.
- Prefix-LMs (T5-style variants) are bidirectional over the prompt and causal over the output.
- **Document masking:** when packing several documents into one sequence, also block attention across document boundaries (Ch 23).

### ✅ Check Your Instinct
1. What does the first row of the causal attention matrix look like?
2. Why does removing the mask make the train loss collapse?

<details><summary>Answers</summary>

1. [1, 0, 0, ...]: the first token attends only to itself.
2. Each position can see (and copy) the token it's supposed to predict.
</details>

### 📌 Recap Card
- A −∞ mask on future keys gives zero weight.
- Lower-triangular = causal.
- Leak test: future changes must not affect past outputs.

> **Core intuition:** *In training, the model must be blindfolded to everything it would not know at generation time.*

## 17.5 The Averaging Trick: From Loops to a Matmul

### 🧭 The Problem First
A naive implementation loops over positions: for each t, average over positions ≤ t. That's slow. We want the whole causal averaging in one GPU-friendly operation.

### 💡 Intuition / Instinct
"Average of all previous tokens" = multiply by a lower-triangular matrix whose rows are normalized. `tril(ones)` with row normalization gives uniform causal averaging. Replace the uniform weights with *learned, data-dependent* weights (softmax of scores with a −∞ mask) and you have attention. **Attention = data-dependent weighted averaging, as a matmul.**

### 🖼️ Visual Mental Model

```text
 uniform:  [1   0   0 ]      attention: [1    0    0  ]
           [.5 .5   0 ]  →              [.2  .8    0  ]   (weights learned from content)
           [.33 .33 .33]                [.1  .6   .3  ]
 out = W @ X   (row view: each output is a mixture of earlier rows)
```

### 📐 The Math, Gently
Uniform: $W = \text{softmax}(M)$ where M is 0 on/below the diagonal and −∞ above, giving rows of $1/(i+1)$.
Attention: $W = \text{softmax}(QK^\top/\sqrt d + M)$.

### 🛠️ Build It From Scratch

```python
torch.manual_seed(1337)
B, T, C = 4, 8, 2
x = torch.randn(B, T, C)

# v1: loops
xbow = torch.zeros(B, T, C)
for b in range(B):
    for t in range(T):
        xbow[b, t] = x[b, :t + 1].mean(0)

# v2: matmul with normalized tril
w = torch.tril(torch.ones(T, T)); w = w / w.sum(1, keepdim=True)
xbow2 = w @ x                                          # (T,T) @ (B,T,C) -> (B,T,C)

# v3: softmax with -inf mask (the attention form)
wei = torch.zeros(T, T).masked_fill(torch.tril(torch.ones(T, T)) == 0, float("-inf"))
xbow3 = F.softmax(wei, -1) @ x
print(torch.allclose(xbow, xbow2, atol=1e-6), torch.allclose(xbow, xbow3, atol=1e-6))

# v4: single-head self-attention: data-dependent weights
head = 16
key, query, value = (torch.nn.Linear(C, head, bias=False) for _ in range(3))
k, q, v = key(x), query(x), value(x)                   # (B, T, h)
wei = q @ k.transpose(-2, -1) * head ** -0.5           # (B, T, T)
wei = wei.masked_fill(torch.tril(torch.ones(T, T)) == 0, float("-inf"))
out = F.softmax(wei, -1) @ v                           # (B, T, h)
print(out.shape)
```

### 🔬 Experiment & Observe
Time v1 vs v2 for T = 512: the matmul is orders of magnitude faster. Print `F.softmax(wei, -1)[0]` for v4: unlike the uniform version, the weights vary by content.

### ⚠️ Failure Modes & Debugging
Broadcasting the (T, T) weights across (B, T, C) works by matmul broadcasting; check the shapes when you add heads (B, H, T, T).

### 🧠 Expert Insight
This progression is the heart of Karpathy's "Let's build GPT" lecture. It shows that attention is a generalization of simple averaging, and why it's so hardware-friendly.

### ✅ Check Your Instinct
1. What does `tril(ones)` normalized per row compute?
2. What turns uniform averaging into attention?

<details><summary>Answers</summary>

1. The causal running mean of all previous tokens.
2. Replacing the constant scores with data-dependent scores $qk^\top/\sqrt d$.
</details>

### 📌 Recap Card
- Causal averaging = lower-triangular matmul.
- Attention = learned, content-dependent causal averaging.
- One matmul replaces the loops.

> **Core intuition:** *Attention is averaging the past, but letting the content decide the weights.*

## 17.6 Self-Attention vs Cross-Attention

### 🧭 The Problem First
Sometimes the tokens asking the questions and the tokens being searched come from *different* sequences: translating French to English, a text decoder reading image patches, or retrieval-augmented reading.

### 💡 Intuition / Instinct
- **Self-attention:** Q, K and V all come from the same sequence (tokens attend to each other). GPT uses only this.
- **Cross-attention:** Q comes from sequence A, K and V from sequence B. A asks, B answers. This is used in the original encoder–decoder transformer, Whisper, and some multimodal models (Flamingo).

The math is identical; only the sources change. The (T_A, T_B) score matrix doesn't need to be square, and it usually needs no causal mask (B is fully available).

### 🖼️ Visual Mental Model

```text
 self:  X ─▶ Q,K,V          (T×T scores)
 cross: X_dec ─▶ Q
        X_enc ─▶ K,V        (T_dec × T_enc scores)
```

### 📐 The Math, Gently
$\text{CrossAttn}(X_A, X_B) = \text{softmax}\!\left(\frac{(X_AW_Q)(X_BW_K)^\top}{\sqrt d}\right)X_BW_V$, output shape $(T_A, d)$.

### 🛠️ Build It From Scratch

```python
class CrossAttention(torch.nn.Module):
    def __init__(self, C_q, C_kv, d):
        super().__init__()
        self.q = torch.nn.Linear(C_q, d, bias=False)
        self.k = torch.nn.Linear(C_kv, d, bias=False)
        self.v = torch.nn.Linear(C_kv, d, bias=False)
    def forward(self, xa, xb, mask=None):                 # xa (B,Ta,Cq), xb (B,Tb,Ckv)
        return attention(self.q(xa), self.k(xb), self.v(xb), mask=mask)[0]   # (B,Ta,d)
ca = CrossAttention(32, 48, 16)
print(ca(torch.randn(2, 5, 32), torch.randn(2, 9, 48)).shape)   # (2, 5, 16)
```

### 🔬 Experiment & Observe
Build a toy "lookup" task: B holds 10 (key-token, value-token) pairs, A holds a query token, and the target is the matching value. A single cross-attention layer learns to solve it nearly perfectly. It is a differentiable dictionary, literally.

### ⚠️ Failure Modes & Debugging
Padding in B must be masked (a mask of shape (B, 1, T_b), broadcast over T_a).

### 🧠 Expert Insight
- The original Transformer (2017) was an encoder–decoder with cross-attention.
- Decoder-only models (GPT) won for general LLMs because concatenating everything into one sequence with self-attention is simpler and scales well.
- Multimodal LLMs mostly project image features into the token sequence (Ch 34) rather than using cross-attention.

### ✅ Check Your Instinct
1. Shape of the cross-attention scores for T_a = 5, T_b = 9?
2. Does cross-attention need a causal mask?

<details><summary>Answers</summary>

1. (5, 9).
2. Usually no; the source sequence is fully visible.
</details>

### 📌 Recap Card
- Self: Q, K, V from one sequence. Cross: Q from A, K/V from B.
- Same math, rectangular scores.
- Decoder-only LLMs use self-attention only.

> **Core intuition:** *Self-attention is a conversation within a sequence; cross-attention is one sequence interviewing another.*
