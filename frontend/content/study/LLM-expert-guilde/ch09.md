## 9.1 Why Initialization Matters: Exploding and Vanishing Activations

### 🧭 The Problem First
Stack 50 layers initialized with `randn` weights. The outputs are either ~10³⁰ or ~10⁻³⁰. Gradients do the same thing in reverse. Training fails before it begins.

### 💡 Intuition / Instinct
Each layer *multiplies* the signal's scale by some factor. Over L layers: factor^L. Unless the factor is ≈ 1, the signal explodes or vanishes exponentially. It's like a game of telephone where each person either whispers or shouts. Good init makes each layer **preserve the signal's variance**.

### 🖼️ Visual Mental Model

```text
 std of activations by layer:
  W ~ N(0,1):     1 → 22 → 500 → 11,000 → ... (explodes)
  W ~ N(0,0.01):  1 → 0.2 → 0.04 → 0.008 → ... (vanishes)
  W ~ N(0,1/n):   1 → 1 → 1 → 1 → ...         (preserved ✓)
```

### 📐 The Math, Gently
For $y = \sum_{i=1}^{n} w_i x_i$ with independent zero-mean terms: $\text{Var}(y) = n\,\text{Var}(w)\,\text{Var}(x)$.
To keep $\text{Var}(y) = \text{Var}(x)$ we need $\text{Var}(w) = 1/n$.
Example: n = 512 and Var(w) = 1 give Var(y) = 512 (std ×22.6 per layer).

### 🛠️ Build It From Scratch

```python
import torch
torch.manual_seed(0)
def forward_stats(std_fn, n=512, L=20, act=lambda x: x):
    x = torch.randn(1000, n); stds = []
    for _ in range(L):
        W = torch.randn(n, n) * std_fn(n)
        x = act(x @ W); stds.append(x.std().item())
    return [f"{s:.2e}" for s in stds[::4]]
print("N(0,1)     :", forward_stats(lambda n: 1.0))
print("N(0,0.01)  :", forward_stats(lambda n: 0.01))
print("N(0,1/n)   :", forward_stats(lambda n: n ** -0.5))
```

### 🔬 Experiment & Observe
Add `act=torch.relu` to the 1/n version: the std *halves* in variance every layer (it slowly vanishes). ReLU zeroes half the inputs, so the variance law must account for the activation, which leads us to Kaiming.

### ⚠️ Failure Modes & Debugging
Symptoms of bad init: a first-step loss far above ln V, NaN in the first steps, or gradients of ~0 in early layers. **Always print the initial loss.**

### 🧠 Expert Insight
Normalization layers (Ch 10) and residual connections make modern nets much less sensitive to init, but at scale init still matters for stability. GPT-2, T5 and µP (Ch 26) all specify careful inits.

### ✅ Check Your Instinct
1. Var(w) needed for fan-in 4096?
2. Why exponential behaviour?

<details><summary>Answers</summary>

1. 1/4096 (std 0.0156).
2. Per-layer factors multiply across L layers.
</details>

### 📌 Recap Card
- Each layer scales variance by $n\,\text{Var}(w)$.
- Keep the factor ≈ 1 to preserve the signal.
- Check the initial loss.

> **Core intuition:** *Every layer must neither shout nor whisper.*

## 9.2 Xavier/Glorot and Kaiming/He, Derived

### 🧭 The Problem First
The 1/n rule ignores the activation function and the backward pass. We need rules for real networks.

### 💡 Intuition / Instinct
- **Xavier (Glorot, 2010):** balance the forward (fan-in) and backward (fan-out) variance for linear/tanh-like activations: $\text{Var}(w) = 2/(n_{in} + n_{out})$.
- **Kaiming (He, 2015):** ReLU zeroes half the signal, halving the variance, so double the weights' variance to compensate: $\text{Var}(w) = 2/n_{in}$.

### 🖼️ Visual Mental Model

```text
 activation   gain    init Var(w)
 linear/tanh  1       1/n_in   (≈ Xavier)
 ReLU         √2      2/n_in   (Kaiming)
 GELU/SiLU    ~√2     ~2/n_in
```

### 📐 The Math, Gently
For ReLU with symmetric pre-activations $z$: $\mathbb{E}[\text{relu}(z)^2] = \frac12\text{Var}(z)$. So
$\text{Var}(z^{(l+1)}) = n\,\text{Var}(w)\,\frac12\text{Var}(z^{(l)})$, and setting this to 1 gives $\text{Var}(w) = 2/n$.

### 🛠️ Build It From Scratch

```python
import torch, math
def kaiming_normal_(W, gain=math.sqrt(2)):    # W: (out, in) like nn.Linear
    fan_in = W.shape[1]
    with torch.no_grad(): W.normal_(0, gain / math.sqrt(fan_in))
    return W
def xavier_normal_(W):
    fan_out, fan_in = W.shape
    with torch.no_grad(): W.normal_(0, math.sqrt(2.0 / (fan_in + fan_out)))
    return W

x = torch.randn(1000, 512)
for name, init in [("xavier", xavier_normal_), ("kaiming", kaiming_normal_)]:
    h = x
    for _ in range(30): h = torch.relu(h @ init(torch.empty(512, 512)).T)
    print(f"{name:8s} relu net std after 30 layers: {h.std():.3e}")
```

### 🔬 Experiment & Observe
Kaiming keeps the std ≈ 1–2 after 30 ReLU layers; Xavier with ReLU decays toward zero (each layer loses about half the variance).

### ⚠️ Failure Modes & Debugging
- PyTorch's default `nn.Linear` init is Kaiming-*uniform* with a=√5, which gives std ≈ $1/\sqrt{3n}$. That's fine for shallow nets but not "variance-preserving" for deep ReLU stacks. LLM codebases override it.
- Using fan-out instead of fan-in (confusing (out, in) ordering).

### 🧠 Expert Insight
Transformers typically use a small fixed std (GPT-2: 0.02) plus **scaled residual init**: the output projections feeding the residual stream are scaled by $1/\sqrt{2L}$, so the sum of 2L residual branches doesn't grow the stream's variance (Ch 20). µP generalizes this to width scaling (Ch 26).

### ✅ Check Your Instinct
1. Kaiming std for fan-in 768?
2. Why does ReLU need a factor of 2?

<details><summary>Answers</summary>

1. √(2/768) ≈ 0.051.
2. It zeroes half the pre-activations, halving the second moment.
</details>

### 📌 Recap Card
- Xavier: $2/(n_{in}+n_{out})$; Kaiming: $2/n_{in}$ for ReLU.
- Transformers: std 0.02 + residual scaling by $1/\sqrt{2L}$.

> **Core intuition:** *Init compensates for what the activation throws away.*

## 9.3 Activations: Sigmoid, tanh, ReLU, Dead Neurons, GELU, SiLU

### 🧭 The Problem First
Without nonlinearities, deep nets collapse to one linear map (Ch 3.3). But which nonlinearity? Sigmoid and tanh saturate and kill gradients; ReLU can die.

### 💡 Intuition / Instinct
- **Sigmoid/tanh:** smooth squashes. Their gradient is at most 0.25 (sigmoid) or 1 (tanh), and ≈ 0 when saturated. Deep stacks → vanishing gradients.
- **ReLU:** $\max(0, x)$. Gradient 1 for positive inputs, which is great for depth. But a neuron that is always negative gets gradient 0 forever: a **dead ReLU**.
- **GELU:** $x\,\Phi(x)$, a smooth ReLU that lets small negative values leak through probabilistically ("keep x with probability Φ(x)"). Used in GPT-2/BERT.
- **SiLU/Swish:** $x\,\sigma(x)$, similar to GELU and cheaper. Used in Llama (inside SwiGLU).

### 🖼️ Visual Mental Model

```text
       ReLU            GELU / SiLU           tanh
        /               _/                  ___
       /              _/                  /
  ____/          ___.'                ___/
                 (small negative dip)
```

### 📐 The Math, Gently
- $\sigma'(x) = \sigma(1-\sigma) \le 0.25$
- $\tanh'(x) = 1 - \tanh^2 x$
- $\text{GELU}(x) = x\Phi(x) \approx 0.5x(1 + \tanh[\sqrt{2/\pi}(x + 0.044715x^3)])$
- $\text{SiLU}(x) = x\sigma(x)$, with $\text{SiLU}'(x) = \sigma(x)(1 + x(1-\sigma(x)))$

Example: through 10 sigmoid layers the gradient factor is at most $0.25^{10} ≈ 10^{-6}$.

### 🛠️ Build It From Scratch

```python
import torch, math
def gelu_tanh(x): return 0.5 * x * (1 + torch.tanh(math.sqrt(2 / math.pi) * (x + 0.044715 * x**3)))
def gelu_exact(x): return x * 0.5 * (1 + torch.erf(x / math.sqrt(2)))
def silu(x): return x * torch.sigmoid(x)
x = torch.linspace(-4, 4, 9)
print("gelu diff:", (gelu_tanh(x) - torch.nn.functional.gelu(x)).abs().max().item())
print("silu diff:", (silu(x) - torch.nn.functional.silu(x)).abs().max().item())

# dead ReLU demo: large negative bias
torch.manual_seed(0)
lin = torch.nn.Linear(10, 100); lin.bias.data.fill_(-5.0)
h = torch.relu(lin(torch.randn(1000, 10)))
print("fraction of dead neurons:", ((h > 0).float().mean(0) == 0).float().mean().item())

# gradient flow through depth for different activations
for name, act in [("sigmoid", torch.sigmoid), ("tanh", torch.tanh), ("relu", torch.relu), ("gelu", torch.nn.functional.gelu)]:
    x = torch.randn(256, 256, requires_grad=True); h = x
    for _ in range(20):
        W = torch.randn(256, 256) * (2 / 256) ** 0.5
        h = act(h @ W)
    h.sum().backward()
    print(f"{name:8s} input-grad std after 20 layers: {x.grad.std():.2e}")
```

### 🔬 Experiment & Observe
Sigmoid's gradient vanishes to ~1e-10; ReLU/GELU stay healthy. Train the spiral MLP with each: the ranking is usually GELU ≈ SiLU ≥ ReLU >> sigmoid.

### ⚠️ Failure Modes & Debugging
- **Dead ReLUs** from high learning rates or negative biases: log the fraction of units that never fire.
- Using the tanh-GELU approximation at load time when the model was trained with exact GELU (or vice versa) causes small but real output drift. GPT-2 uses the tanh approximation (`gelu(approximate='tanh')`).

### 🧠 Expert Insight
- **Nair & Hinton (2010):** ReLU. **Hendrycks & Gimpel (2016):** GELU. **Ramachandran et al. (2017):** Swish.
- Modern LLMs use gated variants (next section). Some (e.g. OLMo, Gemma) have also used GeGLU or squared-ReLU variants (Primer, 2021).

### ✅ Check Your Instinct

2. What's a dead ReLU?
3. *(Coding)* Measure the fraction of dead ReLUs during spiral training at lr 1e-3 vs 1e-1.

<details><summary>Answers</summary>

1. 0.25 at x = 0.
2. A unit whose pre-activation is negative for every input, so it gets zero gradient forever.
3. High lr kills many more units.
</details>

### 📌 Recap Card
- Sigmoid/tanh saturate → vanishing gradients.
- ReLU has gradient 1 but can die.
- GELU/SiLU are smooth and slightly leaky; they are the transformer defaults.

> **Core intuition:** *An activation is a gate; it must let gradients through most of the time.*

## 9.4 Gated Activations: GLU and SwiGLU

### 🧭 The Problem First
A standard FFN applies one fixed nonlinearity to each hidden unit. Can the network *learn* how much of each feature to let through, depending on the input?

### 💡 Intuition / Instinct
**Gating:** compute two projections of the input, a *value* and a *gate*, and multiply them elementwise. The gate decides, per feature and per token, how much of the value passes. It's like a mixing desk where one hand sets the signal and the other sets the volume fader, both depending on the song. Multiplicative interactions are more expressive than additive ones.

SwiGLU (used in Llama, PaLM, Mistral, Qwen...) = SiLU(gate) ⊙ value, followed by a down projection.

### 🖼️ Visual Mental Model

```text
 x (B,T,C) ─┬─▶ W_gate (C→H) ─▶ SiLU ─┐
            │                          ⊙ ─▶ W_down (H→C) ─▶ (B,T,C)
            └─▶ W_up   (C→H) ─────────┘
 H ≈ (8/3)·C (so params ≈ standard 4C FFN: 3·C·H = 8C² ✓)
```

### 📐 The Math, Gently
$$\text{SwiGLU}(x) = W_{down}\big(\text{SiLU}(xW_{gate}) \odot xW_{up}\big)$$
Params: $3CH$. With $H = \frac83 C$: $8C^2$, the same as a standard FFN with $H = 4C$ ($2 · 4C^2$).
Example: C = 4096 gives H = 10,923, which Llama rounds to 11,008 (a multiple of 256).

### 🛠️ Build It From Scratch

```python
import torch, torch.nn as nn, torch.nn.functional as F

class SwiGLU(nn.Module):
    def __init__(self, C, hidden=None, multiple_of=64):
        super().__init__()
        H = hidden or int(8 * C / 3)
        H = multiple_of * ((H + multiple_of - 1) // multiple_of)   # round up for GPU efficiency
        self.w_gate = nn.Linear(C, H, bias=False)
        self.w_up   = nn.Linear(C, H, bias=False)
        self.w_down = nn.Linear(H, C, bias=False)
    def forward(self, x):                       # (B, T, C)
        return self.w_down(F.silu(self.w_gate(x)) * self.w_up(x))   # (B, T, C)

class GeluFFN(nn.Module):
    def __init__(self, C):
        super().__init__()
        self.fc, self.proj = nn.Linear(C, 4 * C), nn.Linear(4 * C, C)
    def forward(self, x): return self.proj(F.gelu(self.fc(x), approximate="tanh"))

C = 256
for m in (SwiGLU(C), GeluFFN(C)):
    print(type(m).__name__, sum(p.numel() for p in m.parameters()), m(torch.randn(2, 5, C)).shape)
```

### 🔬 Experiment & Observe
In Ch 32 you'll swap GeluFFN → SwiGLU in your GPT and measure the validation loss at equal parameters. Shazeer reports consistent small wins (~1–2% lower loss/perplexity).

### ⚠️ Failure Modes & Debugging
- Forgetting to shrink H to 8/3·C adds 50% more FFN params, which makes the comparison unfair.
- Mixing up gate and up when loading pretrained weights (Llama's `w1`, `w3`, `w2` naming: w1 = gate, w3 = up, w2 = down).

### 🧠 Expert Insight
**Shazeer (2020), "GLU Variants Improve Transformer":** his famous conclusion attributes the success "to divine benevolence". Gating appears everywhere: LSTM gates (Ch 14), Mamba's gates (Ch 34), MoE routers (Ch 33).

### ✅ Check Your Instinct
1. Why 8/3·C?
2. What does the gate do?

<details><summary>Answers</summary>

1. To match the parameter count of the 4C GELU FFN (three matrices instead of two).
2. It multiplicatively scales each hidden feature, per token.
</details>

### 📌 Recap Card
- GLU = value ⊙ activation(gate).
- SwiGLU = the Llama-family FFN.
- H ≈ 8C/3 for parameter parity.

> **Core intuition:** *Gates let the network decide, per token, which features to amplify.*

## 9.5 Activation and Gradient Statistics Dashboards

### 🧭 The Problem First
Training "doesn't work" and the loss is the only clue. You need X-ray vision into each layer.

### 💡 Intuition / Instinct
Log, per layer: activation mean/std, % saturated or dead units, gradient std, and the **update-to-data ratio** ($\text{lr}\cdot|\text{grad}| / |\text{weight}|$). A healthy network has similar statistics across layers and update ratios around ~1e-3.

### 🖼️ Visual Mental Model

```text
 layer  act_std  dead%  grad_std  upd/data
 0      0.98     2%     1.1e-3    1.2e-3   ✓
 1      1.02     3%     1.0e-3    1.0e-3   ✓
 2      0.03    71%     2.0e-6    3.0e-6   ✗ dead layer
```

### 📐 The Math, Gently
Update ratio $r = \frac{\text{std}(\eta\,g)}{\text{std}(W)}$. $r \approx 10^{-3}$ is healthy; $r \gg 10^{-2}$ means the lr is too high; $r \ll 10^{-4}$ means the layer is barely learning.

### 🛠️ Build It From Scratch

```python
# nanoforge/diagnostics.py
import torch

class ActivationStats:
    """Attach forward hooks to modules; record output mean/std/dead fraction."""
    def __init__(self, model, types=(torch.nn.ReLU, torch.nn.GELU, torch.nn.Tanh)):
        self.stats, self.handles = {}, []
        for name, m in model.named_modules():
            if isinstance(m, types):
                self.handles.append(m.register_forward_hook(self._hook(name)))
    def _hook(self, name):
        def fn(module, inp, out):
            o = out.detach()
            self.stats[name] = dict(mean=o.mean().item(), std=o.std().item(),
                                    zero=(o == 0).float().mean().item(),
                                    sat=(o.abs() > 0.97).float().mean().item())
        return fn
    def remove(self):
        for h in self.handles: h.remove()

def update_ratios(model, lr):
    out = {}
    for n, p in model.named_parameters():
        if p.grad is not None and p.dim() >= 2:
            out[n] = (lr * p.grad.std() / (p.data.std() + 1e-12)).item()
    return out
```

Use it:

```python
from nanoforge.nn import MLP
from nanoforge.diagnostics import ActivationStats, update_ratios
import torch, torch.nn.functional as F
m = MLP(2, 64, 3, n_layers=4); st = ActivationStats(m)
x, y = torch.randn(256, 2), torch.randint(0, 3, (256,))
loss = F.cross_entropy(m(x), y); loss.backward()
for k, v in st.stats.items(): print(k, {a: round(b, 3) for a, b in v.items()})
for k, v in update_ratios(m, 3e-3).items(): print(k, f"{v:.1e}")
```

### 🔬 Experiment & Observe
Deliberately break init (std = 1.0 weights) and watch the dashboard: tanh saturation near 100%, or ReLU activations exploding. Fix it with Kaiming and watch the stats normalize.

### ⚠️ Failure Modes & Debugging
- Hooks keep running forever unless removed, which adds memory and slows things down.
- Logging every step is expensive; log every N steps.

### 🧠 Expert Insight
Frontier training dashboards track per-layer grad norms, activation RMS, attention entropy, logit max, and update ratios. Loss spikes are often preceded by a rising logit max or attention-entropy collapse (Ch 27).
