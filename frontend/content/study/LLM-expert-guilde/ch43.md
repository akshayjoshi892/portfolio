## 43.1 Prefill vs Decode: Two Different Workloads

### 🧭 The Problem First
Time your Llama-mini on a 1,000-token prompt followed by 200 generated tokens. The 1,000 prompt tokens take perhaps 30 ms. The 200 generated tokens take perhaps 2 seconds. That's ~33,000 tokens/s for the prompt and ~100 tokens/s for generation, on the same model and the same GPU. Why is there a 300× difference?

### 💡 Intuition / Instinct
Generation has two phases:
- **Prefill:** process the whole prompt in one forward pass. Every weight matrix is multiplied by a (T × C) block of activations. Each weight read from memory is reused T times. This is a big matmul: **compute-bound**, like training.
- **Decode:** produce one token at a time. Every weight matrix is multiplied by a *single row* (1 × C). Each weight is read from HBM, used for one multiply-add per row, and thrown away. This is a matrix–vector product: **memory-bound**. The tensor cores sit mostly idle, waiting for bytes.

A rule of thumb that follows: **at batch size 1, decode speed ≈ memory bandwidth ÷ model size in bytes.** A 7B model in bf16 (14 GB) on a GPU with 1 TB/s bandwidth can't exceed ~70 tokens/s, no matter how many TFLOPs the GPU has.

This single fact explains most of inference engineering:
- **Batching** (Ch 45) serves many users per weight read.
- **Quantization** (Ch 44) makes the weights smaller, so each read is cheaper.
- **Speculative decoding** (43.2) checks several tokens per weight read.
- The **KV cache** (Ch 30) is also read every step, so long contexts slow decode down too.

### 🖼️ Visual Mental Model

```text
 PREFILL (T = 1000)                         DECODE (T = 1, repeated 200×)
 X: (1000 × C) ─┐                            x: (1 × C) ─┐
                ├─ matmul ─▶ (1000 × C)                  ├─ mat-vec ─▶ (1 × C)
 W: (C × C) ────┘                            W: (C × C) ─┘
 FLOPs per weight byte ≈ 1000               FLOPs per weight byte ≈ 1
 ▶ compute-bound (tensor cores busy)        ▶ memory-bound (waiting on HBM)

 timeline:  [██ prefill ██][▌][▌][▌][▌][▌][▌][▌][▌] ... one thin step per token
             TTFT ◀──────▶  TPOT ◀▶
```

### 📐 The Math, Gently
**Arithmetic intensity** (Ch 28.2) is FLOPs per byte moved. For a linear layer with a (C × C) weight in bf16 (2 bytes/param) and T rows of input:

$$\text{intensity} \approx \frac{2TC^2 \text{ FLOPs}}{2C^2 \text{ bytes}} = T \ \text{FLOPs/byte}$$

An A100 has ~312 TFLOP/s of bf16 compute and ~2 TB/s of bandwidth, so its **ridge point** is ~156 FLOPs/byte. Below it, you're memory-bound. Decode with batch B has intensity ≈ B, so single-user decode (B = 1) runs at under 1% of peak compute.

Decode time per token, lower bound:

$$t_{token} \gtrsim \frac{N_{params}\cdot b_w + \text{KV bytes}(T)}{\text{bandwidth}}$$

where $b_w$ is bytes per weight. Two terms, two levers: shrink the weights (quantization) or make each read produce more tokens (batching, speculation).

The two latency metrics that users feel:
- **TTFT** (time to first token) ≈ the prefill time: grows with prompt length.
- **TPOT** (time per output token) ≈ the decode step time: grows with model size and context length.

### 🛠️ Build It From Scratch
A benchmark that separates the two phases, using the Llama model (Ch 32) and `KVCache` (Ch 30):

```python
# nanoforge/serve/bench.py
import time, torch
from nanoforge.models.kv_cache import KVCache

def sync(device):
    if device.type == "cuda": torch.cuda.synchronize()

@torch.no_grad()
def bench_prefill_decode(model, prompt_len=512, new_tokens=128, B=1, warmup=2):
    cfg, dev = model.cfg, next(model.parameters()).device
    dtype = next(model.parameters()).dtype
    D = cfg.n_embd // cfg.n_head
    ids = torch.randint(0, cfg.vocab_size, (B, prompt_len), device=dev)
    res = {}
    for trial in range(warmup + 1):
        cache = KVCache(cfg.n_layer, B, cfg.n_kv_head, prompt_len + new_tokens, D, dev, dtype)
        sync(dev); t0 = time.perf_counter()
        logits, _ = model(ids, cache=cache)                     # prefill: (B, T) in one pass
        sync(dev); t1 = time.perf_counter()
        nxt = logits[:, -1].argmax(-1, keepdim=True)
        for _ in range(new_tokens):                             # decode: one token per pass
            logits, _ = model(nxt, cache=cache)
            nxt = logits[:, -1].argmax(-1, keepdim=True)
        sync(dev); t2 = time.perf_counter()
        res = {"ttft_ms": 1e3 * (t1 - t0), "tpot_ms": 1e3 * (t2 - t1) / new_tokens,
               "prefill_tok_s": B * prompt_len / (t1 - t0), "decode_tok_s": B * new_tokens / (t2 - t1)}
    return res

def decode_roofline(n_params, bytes_per_param, bandwidth_gb_s, kv_bytes=0):
    """Upper bound on single-stream decode speed (tokens/s)."""
    return bandwidth_gb_s * 1e9 / (n_params * bytes_per_param + kv_bytes)

if __name__ == "__main__":
    from nanoforge.models.llama import Llama, LlamaConfig, LLAMA_CONFIGS
    dev = "cuda" if torch.cuda.is_available() else "cpu"
    m = Llama(LlamaConfig(**LLAMA_CONFIGS["mini"])).to(dev).eval()
    if dev == "cuda": m = m.to(torch.bfloat16)
    for B in (1, 8, 32):
        print(B, bench_prefill_decode(m, B=B))
    print("7B bf16 on 1 TB/s ceiling:", decode_roofline(7e9, 2, 1000), "tok/s")
```

### 🔬 Experiment & Observe
1. Run the benchmark for B ∈ {1, 8, 32}. Watch `tpot_ms` barely move as B grows while `decode_tok_s` rises almost linearly. That's the memory-bound regime: extra rows are nearly free.
2. Increase `prompt_len` from 128 to 4,096. TTFT grows roughly linearly (then quadratically, once attention dominates). TPOT grows too, because each step reads a longer KV cache.
3. Compare your measured B = 1 decode speed with `decode_roofline(model.num_params(), 2, <your GPU bandwidth>)`. For tiny models, you'll be far below the ceiling: kernel-launch overhead dominates (fix: CUDA graphs, Ch 29.3).

### ⚠️ Failure Modes & Debugging
- **Forgetting `torch.cuda.synchronize()`:** CUDA is asynchronous, so un-synchronized timers measure launch time, not work.
- **Measuring the first call:** it includes allocation and kernel autotuning. Always warm up.
- **Huge prompts stall other users:** one 32k-token prefill can block a batch of decodes for a second. Production engines use **chunked prefill**: split the prompt into chunks (e.g. 512 tokens) and interleave them with decode steps. Your `LlamaAttention` already supports it, because a cache with `pos > 0` plus T > 1 takes the explicit offset-mask path.

### 🧠 Expert Insight
- **Pope et al. (2022), "Efficiently Scaling Transformer Inference":** the canonical analysis of prefill/decode costs and partitioning.
- **Agrawal et al. (2024), Sarathi-Serve:** chunked prefills to avoid decode stalls.
- **Zhong et al. (2024), DistServe** and **Patel et al. (2024), Splitwise:** run prefill and decode on *different* GPUs (disaggregation), since they want different hardware. Many large deployments now do this.

### 📌 Recap Card
- Prefill: a big matmul, compute-bound, sets TTFT.
- Decode: a mat-vec per token, memory-bound, sets TPOT.
- Decode speed ≈ bandwidth ÷ bytes read per step.
- Levers: batch more, read fewer bytes, verify more tokens per read.

> **Core intuition:** *During decode, the GPU isn't thinking slowly; it's waiting for weights to arrive. Make every trip to memory count.*

## 43.2 Speculative Decoding With a Draft Model, and Its Correctness Proof

### 🧭 The Problem First
Decode is memory-bound, so a forward pass over 5 tokens costs almost the same as over 1. But we can't process 5 *future* tokens at once, because we don't know them yet. Or can we guess them?

### 💡 Intuition / Instinct
Hire a fast intern (a small **draft model**) and an expensive expert (the **target model**):
1. The intern quickly writes the next k tokens (k cheap decode steps).
2. The expert reads all k guesses in **one** forward pass, which costs about the same as generating one token, and gets its own probabilities at every position.
3. Walk through the guesses left to right. Keep each guess the expert "agrees with" (probabilistically); at the first disagreement, the expert replaces the token with its own choice and the rest are discarded.
4. If all k are accepted, the expert's pass also gives a free (k+1)-th token.

Easy text ("the United States of", closing brackets, repeated names) is guessed right most of the time, so you get several tokens per expensive pass. The remarkable part: with the right acceptance rule, **the output distribution is exactly the target model's**. This is not an approximation; the samples are statistically indistinguishable from running the target alone.

### 🖼️ Visual Mental Model

```text
 context: "The cat sat on the"
 draft proposes (k=4):     mat   .    It   was
 target verifies in ONE pass:
   p(mat)=0.62 q(mat)=0.55  → accept (p ≥ q)
   p(.)  =0.40 q(.)  =0.70  → accept with prob 0.40/0.70 ... coin flip: accept
   p(It) =0.05 q(It) =0.30  → accept with prob 0.17 ... coin flip: REJECT
        → resample from norm(max(0, p − q)) → "The"
 output this round: "mat . The"   (3 tokens for 1 target pass + 4 cheap draft passes)
```

### 📐 The Math, Gently
Let $p$ be the target's next-token distribution and $q$ the draft's, at the same position. The draft samples $x \sim q$.

**Rule:** accept $x$ with probability $\min\!\left(1, \frac{p(x)}{q(x)}\right)$. If rejected, sample from the **residual** distribution

$$r(x) = \frac{\max(0,\ p(x) - q(x))}{\sum_{x'} \max(0,\ p(x') - q(x'))}$$

**Proof that the output is distributed as $p$.** The probability that the final token is $x$ is:

$$P(x) = \underbrace{q(x)\min\!\left(1,\tfrac{p(x)}{q(x)}\right)}_{\text{drafted and accepted}} + \underbrace{P(\text{reject})\cdot r(x)}_{\text{rejected, then resampled}}$$

The first term is $\min(q(x), p(x))$. The total acceptance probability is $\beta = \sum_x \min(p(x), q(x))$, so $P(\text{reject}) = 1 - \beta$. Because $\sum_x \max(0, p-q) = \sum_x (p - \min(p,q)) = 1 - \beta$, the residual is $r(x) = \max(0,p(x)-q(x))/(1-\beta)$. So:

$$P(x) = \min(p(x), q(x)) + \max(0,\ p(x) - q(x)) = p(x) \quad \blacksquare$$

(Check both cases: if $p \ge q$, it's $q + (p - q) = p$; if $p < q$, it's $p + 0 = p$.) By induction over positions, the whole sequence is distributed as the target's.

**Speedup.** If each draft token is accepted independently with rate α (α = β on average), the expected number of tokens per round is

$$\mathbb{E}[\text{tokens}] = \frac{1 - \alpha^{k+1}}{1 - \alpha}$$

With α = 0.8 and k = 4: (1 − 0.8⁵)/0.2 ≈ 3.4 tokens per target pass. If a draft step costs a fraction c of a target step, the wall-clock speedup is roughly $\mathbb{E}[\text{tokens}] / (1 + kc)$. With c = 0.05, that's 3.4 / 1.2 ≈ 2.8×.

**Greedy special case:** with temperature 0, both $p$ and $q$ are one-hot. Acceptance becomes "does the draft's argmax equal the target's argmax?", and the residual is the target's argmax. The output is bit-for-bit the target's greedy output.

### 🛠️ Build It From Scratch
The trick for efficiency is **cache rollback**: both models keep KV caches, and rejected tokens are "forgotten" simply by moving `cache.pos` back. Stale entries beyond `pos` are overwritten next time.

```python
# nanoforge/serve/speculative.py
import torch, torch.nn.functional as F
from nanoforge.models.kv_cache import KVCache

def to_probs(logits, temperature):
    """(B, V) logits -> probabilities; temperature 0 means a one-hot argmax."""
    if temperature == 0:
        return F.one_hot(logits.argmax(-1), logits.size(-1)).float()
    return F.softmax(logits.float() / temperature, -1)

def new_cache(model, T_max, B=1):
    cfg, p = model.cfg, next(model.parameters())
    return KVCache(cfg.n_layer, B, cfg.n_kv_head, T_max, cfg.n_embd // cfg.n_head, p.device, p.dtype)

@torch.no_grad()
def speculative_generate(target, draft, idx, max_new_tokens, k=4, temperature=1.0, eos_id=None, generator=None):
    """idx: (1, T) prompt. Samples exactly from `target`, using `draft` to propose k tokens per round.
    Invariant: each cache holds K/V for seq[:, :cache.pos]; we always feed seq[:, cache.pos:]."""
    assert idx.size(0) == 1, "batch size 1 for clarity"
    T_max = idx.size(1) + max_new_tokens + k + 1
    tc, dc = new_cache(target, T_max), new_cache(draft, T_max)
    seq, n_rounds, n_accepted = idx, 0, 0
    while seq.size(1) - idx.size(1) < max_new_tokens:
        L = seq.size(1)
        # 1) draft proposes k tokens autoregressively (cheap)
        x, drafts, qs = seq[:, dc.pos:], [], []
        for _ in range(k):
            logits, _ = draft(x, cache=dc)                          # (1, 1, V): last position only
            q = to_probs(logits[:, -1], temperature)                # (1, V)
            d = torch.multinomial(q, 1, generator=generator)        # (1, 1)
            drafts.append(d); qs.append(q); x = d
        drafts = torch.cat(drafts, 1)                               # (1, k)
        # 2) target scores all k proposals in ONE pass
        logits, _ = target(torch.cat([seq[:, tc.pos:], drafts], 1), cache=tc, all_logits=True)
        ps = [to_probs(logits[:, -(k + 1) + i], temperature) for i in range(k + 1)]   # k+1 × (1, V)
        # 3) accept / reject left to right
        accepted, extra = 0, None
        for i in range(k):
            tok = drafts[0, i]
            p_t, q_t = ps[i][0, tok], qs[i][0, tok]
            u = torch.rand((), device=seq.device, generator=generator)
            if u < torch.clamp(p_t / q_t.clamp_min(1e-20), max=1.0):
                accepted += 1
            else:
                resid = (ps[i] - qs[i]).clamp_min(0)
                resid = resid / resid.sum() if resid.sum() > 0 else ps[i]
                extra = torch.multinomial(resid, 1, generator=generator)
                break
        if extra is None:                                           # all k accepted: free bonus token
            extra = torch.multinomial(ps[k], 1, generator=generator)
        seq = torch.cat([seq, drafts[:, :accepted], extra], 1)
        # 4) roll back both caches to the last token both have validly processed
        tc.pos = L + accepted
        dc.pos = min(dc.pos, L + accepted)
        n_rounds += 1; n_accepted += accepted
        if eos_id is not None and (seq[0, L:] == eos_id).any():
            cut = L + int((seq[0, L:] == eos_id).nonzero()[0]) + 1
            seq = seq[:, :cut]; break
    seq = seq[:, :idx.size(1) + max_new_tokens]
    stats = {"rounds": n_rounds, "accept_rate": n_accepted / max(1, n_rounds * k),
             "tokens_per_round": (seq.size(1) - idx.size(1)) / max(1, n_rounds)}
    return seq, stats
```

Why `dc.pos = min(dc.pos, L + accepted)`? The draft processed `seq[:L]` plus drafts 1..k−1 (it never fed draft k). If all k were accepted, it still needs to see draft k, so its pos stays at L + k − 1, and next round it feeds the two unprocessed tokens. Otherwise it rolls back to L + accepted.

**Verify correctness empirically** (the proof says the distribution must match):

```python

import torch
from nanoforge.models.llama import Llama, LlamaConfig
from nanoforge.serve.speculative import speculative_generate
from nanoforge.sampling import generate

def test_greedy_exact():
    torch.manual_seed(0)
    tgt = Llama(LlamaConfig(vocab_size=64, n_layer=2, n_head=4, n_kv_head=2, n_embd=64, block_size=128)).eval()
    drf = Llama(LlamaConfig(vocab_size=64, n_layer=1, n_head=2, n_kv_head=1, n_embd=32, block_size=128)).eval()
    p = torch.randint(0, 64, (1, 8))
    ref = generate(tgt, p, 30, 128, temperature=0)
    out, _ = speculative_generate(tgt, drf, p, 30, k=4, temperature=0)
    assert torch.equal(ref, out)

def test_first_token_distribution():
    torch.manual_seed(0)
    tgt = Llama(LlamaConfig(vocab_size=8, n_layer=1, n_head=2, n_kv_head=1, n_embd=16, block_size=32)).eval()
    drf = Llama(LlamaConfig(vocab_size=8, n_layer=1, n_head=2, n_kv_head=1, n_embd=16, block_size=32)).eval()

```

### ⚠️ Failure Modes & Debugging
- **The draft and target tokenizers differ:** token-level verification is impossible. They must share a vocabulary.
- **Forgetting to apply the same sampling transforms to p and q** (temperature, top-k, top-p): the exactness proof holds for whatever distributions you actually sample from, so both must be the post-filter distributions.
- **Batching:** different sequences accept different numbers of tokens, so caches go ragged. Production engines handle this with per-sequence cache positions (paged KV, Ch 45.2).
- **Big k with a weak draft** wastes compute: if α is low (say 0.4), use k = 1–2 or skip speculation.
- **Off-by-one cache bugs** show up as outputs that diverge from the non-speculative greedy output. The greedy-exact test above catches them.

### 🧠 Expert Insight
- **Leviathan, Kalman & Matias (2023)** and **Chen et al. (2023, DeepMind):** speculative decoding/sampling, proposed independently with the same rejection scheme.
- **Stern et al. (2018), blockwise parallel decoding:** the greedy precursor.
- **Li et al. (2024), EAGLE / EAGLE-2/3:** the draft is a tiny head that reads the *target's own hidden states*, giving very high acceptance; widely deployed.
- **Tree speculation (SpecInfer, 2024):** verify a *tree* of candidate continuations in one pass using a tree-shaped attention mask, raising tokens per round.
- Speculative decoding helps most at **small batch sizes**. At large batches, decode becomes compute-bound and the "free" verification compute disappears.

</details>

### 📌 Recap Card
- Draft k tokens cheaply → verify in one target pass → accept with min(1, p/q) → resample from the residual on rejection.
- Exact: the samples come from the target distribution. Greedy mode reproduces the target's greedy output bit for bit.
- Tokens per round = (1 − α^{k+1})/(1 − α); tune k to α.
- Needs a shared tokenizer and careful cache rollback.

> **Core intuition:** *Guessing is cheap and checking is parallel. Let a small model guess, and let the big model check many guesses at once.*

## 43.3 Medusa, Lookahead & Constrained Generation

### 🧭 The Problem First
A separate draft model is extra weight to train, store and keep in sync with the target. Can we speculate *without* a second model? And separately: your application needs valid JSON, or one of five labels, and a model that's "usually right" about format still breaks your parser 2% of the time. Can we make invalid outputs impossible?

### 💡 Intuition / Instinct
**Draft-free speculation.** Anything that produces cheap guesses can act as the draft, and the target's verification still keeps (greedy) outputs exact:
- **Prompt lookup decoding:** in summarization, RAG and code editing, outputs often copy spans from the input. Find the last few generated tokens earlier in the context and propose whatever followed them. It costs zero model compute.
- **Medusa heads:** add a few extra small heads on the target's final hidden state; head i predicts the token i+1 positions ahead. One forward pass yields the next token *and* k guesses beyond it.
- **Lookahead decoding:** run Jacobi-style parallel iterations to harvest n-grams from the model's own trajectory, then verify them.

**Constrained generation.** The model outputs a distribution, but *you* choose which tokens are allowed. At every step, mask out (set to −∞) every token that would make the output an invalid prefix of your format. If the format is a regex or grammar, the output is guaranteed to match it. The model still chooses *among valid options*, so it keeps its intelligence.

### 🖼️ Visual Mental Model

```text
 PROMPT LOOKUP:   context "... def load_config(path): ... "     generated so far "... load_"
                  match "load_" earlier → propose "config(path):" → target verifies in one pass

 MEDUSA:          h_T ──▶ lm_head   → token t+1
                      ├─▶ head_1   → guess t+2
                      ├─▶ head_2   → guess t+3
                      └─▶ head_3   → guess t+4        (verify next step, keep the agreeing prefix)

 CONSTRAINED:     format: {"label": "(pos|neg|neutral)"}
                  so far: {"label": "ne      allowed next: g, u, ...   (everything else → −∞)
```

### 📐 The Math, Gently
**Constrained decoding as conditioning.** Masking and renormalizing samples from

$$\tilde p(x_t \mid x_{<t}) \propto p(x_t \mid x_{<t})\ \mathbb{1}[x_{\le t} \text{ is a valid prefix}]$$

This is *locally* renormalized, which is not the same as sampling from $p(\text{sequence} \mid \text{sequence is valid})$ globally: the model may be steered down a prefix where all valid continuations are unlikely. In practice, it works well when the format is natural for the model (show it the format in the prompt too).

**Token/character mismatch.** Grammars are defined over characters, but the model emits multi-character tokens. A token is allowed if appending its string keeps the text a valid prefix. Checking all V tokens naively costs O(V) per step; production libraries precompile the grammar into a token-level automaton (an index from each grammar state to its allowed token set).

**Medusa's training loss:** freeze (or lightly tune) the base, and train head i with cross-entropy against the token at position t + i + 1: $\mathcal{L} = \sum_i \lambda_i\, \text{CE}(\text{head}_i(h_t), x_{t+i+1})$, with decaying weights λ_i (later heads are harder).

### 🛠️ Build It From Scratch
**1. Prompt lookup decoding** (greedy, exact): a draft function that searches the context, plugged into a verify loop.

```python
# nanoforge/serve/lookup.py
import torch

def prompt_lookup_draft(seq, ngram=3, k=8):
    """seq: 1-D LongTensor. Find the most recent earlier occurrence of the last `ngram` tokens; propose what followed."""
    if seq.numel() <= ngram: return seq.new_empty(0)
    tail = seq[-ngram:]
    windows = seq[:-1].unfold(0, ngram, 1)                     # (N, ngram), excluding the final position
    hits = (windows == tail).all(1).nonzero().flatten()
    if hits.numel() == 0: return seq.new_empty(0)
    start = int(hits[-1]) + ngram
    return seq[start:start + k]

@torch.no_grad()
def lookup_generate(model, idx, max_new_tokens, ngram=3, k=8):
    """Greedy decoding with prompt-lookup drafts. Output equals plain greedy decoding (no cache, for clarity)."""
    seq, passes = idx[0], 0
    while seq.numel() - idx.size(1) < max_new_tokens:
        d = prompt_lookup_draft(seq, ngram, k)
        logits, _ = model(torch.cat([seq, d])[None, -model.cfg.block_size:], all_logits=True)
        passes += 1
        preds = logits[0, -(d.numel() + 1):].argmax(-1)       # target's greedy choice at each position
        n = 0
        while n < d.numel() and preds[n] == d[n]: n += 1       # longest agreeing prefix
        seq = torch.cat([seq, d[:n], preds[n:n + 1]])          # accepted drafts + one target token
    return seq[None, :idx.size(1) + max_new_tokens], passes
```

**2. Medusa heads:** each head is a residual block plus a projection to the vocabulary.

```python
# nanoforge/serve/medusa.py
import torch, torch.nn as nn, torch.nn.functional as F

class MedusaHeads(nn.Module):
    def __init__(self, C, V, n_heads=3):
        super().__init__()
        self.blocks = nn.ModuleList([nn.Linear(C, C) for _ in range(n_heads)])
        self.heads = nn.ModuleList([nn.Linear(C, V, bias=False) for _ in range(n_heads)])
        for b in self.blocks: nn.init.zeros_(b.weight); nn.init.zeros_(b.bias)   # start as identity
    def forward(self, h):                                       # h: (B, T, C) final normed hidden states
        return [head(h + F.silu(blk(h))) for blk, head in zip(self.blocks, self.heads)]  # n × (B, T, V)

def final_hidden(model, idx):
    """Run the Llama trunk and return normed hidden states (B, T, C)."""
    x = model.tok_emb(idx)
    for i, layer in enumerate(model.layers): x = layer(x, model.rope_cos, model.rope_sin)
    return model.norm(x)

def medusa_loss(model, medusa, idx, decay=0.8):
    with torch.no_grad(): h = final_hidden(model, idx)           # base frozen
    loss = 0.0
    for i, logits in enumerate(medusa(h)):
        shift = i + 2                                            # head i predicts x_{t+i+2}
        tgt = idx[:, shift:]
        lg = logits[:, :-shift]
        loss = loss + decay ** i * F.cross_entropy(lg.reshape(-1, lg.size(-1)).float(), tgt.reshape(-1))
    return loss
```

Initializing the head blocks to zero means each head starts as a copy of "the next token" predictor and learns the offset from there; tying each head's projection to `model.lm_head.weight` is a common trick to save parameters. At inference, the target's own head gives token t+1 and the Medusa heads propose t+2..t+k+1, verified on the next pass exactly like `lookup_generate`.

**3. Constrained decoding with a regex.** The `regex` package can test whether a string is a *partial* match (a valid prefix), which is exactly what we need.

```python
# nanoforge/serve/constrained.py
import regex, torch

class RegexConstraint:
    def __init__(self, pattern, tok, vocab_size):
        self.pat = regex.compile(pattern)
        special = set(tok.special_tokens.values())
        # precompute each token's string once; special/unused ids get None and are never allowed
        self.tok_strs = [None if (i in special or i >= len(tok.vocab)) else tok.decode([i]) for i in range(vocab_size)]
    def valid_prefix(self, text):
        return self.pat.fullmatch(text, partial=True) is not None
    def complete(self, text):
        return self.pat.fullmatch(text) is not None

@torch.no_grad()
def constrained_generate(model, tok, prompt_ids, constraint, max_new_tokens=64, temperature=0.0,
                         eos_id=None, scan=256, generator=None):
    """Only tokens that keep the output a valid prefix of the pattern are allowed.
    Checks the `scan` most likely tokens first (fast), falling back to the full vocabulary."""
    idx = torch.tensor([prompt_ids], device=next(model.parameters()).device)
    out_text, out_ids = "", []
    for _ in range(max_new_tokens):
        logits, _ = model(idx[:, -model.cfg.block_size:])
        logits = logits[0, -1].float()
        order = torch.argsort(logits, descending=True).tolist()
        allowed = []
        for cands in (order[:scan], order[scan:]):
            for t in cands:
                if t == eos_id:
                    if constraint.complete(out_text): allowed.append(t)
                elif constraint.tok_strs[t] and constraint.valid_prefix(out_text + constraint.tok_strs[t]):
                    allowed.append(t)
            if allowed: break
        if not allowed: break                                   # dead end (should not happen for sane patterns)
        mask = torch.full_like(logits, float("-inf")); mask[allowed] = 0
        l = logits + mask
        nxt = int(l.argmax()) if temperature == 0 else int(torch.multinomial(torch.softmax(l / temperature, -1), 1, generator=generator))
        if nxt == eos_id: break
        out_ids.append(nxt); out_text += constraint.tok_strs[nxt]
        idx = torch.cat([idx, torch.tensor([[nxt]], device=idx.device)], 1)
        if eos_id is None and constraint.complete(out_text) and not any(
                constraint.valid_prefix(out_text + s) for s in (" ", "\n", "a", "0")):
            break                                              # pattern closed and cannot grow further
    return out_text, out_ids

# Example: force a sentiment label in a JSON object
# c = RegexConstraint(PATTERN, tok, model.cfg.vocab_size); text, _ = constrained_generate(model, tok, ids, c, eos_id=im_end)
PATTERN = r'\{"label": "(positive|negative|neutral)", "confidence": 0\.[0-9]{1,2}\}'
```

Two cautions baked into the code: the `scan` shortcut is only an optimization (it falls back to the full vocabulary), and with a byte-level BPE, a single token can decode to an incomplete UTF-8 sequence (shown as `�`). For ASCII formats like JSON that's harmless; for general text, check validity on bytes rather than decoded strings.

### ⚠️ Failure Modes & Debugging
- **Over-tight constraints hurt quality:** if the prompt doesn't show the format, the model may be forced into a low-probability prefix and produce garbage *inside* valid syntax. Always describe the format in the prompt as well.
- **Token boundary traps:** a pattern that expects `"` followed by `,` may be unreachable if the tokenizer only has a merged `",` token and your check forbids it mid-way. Checking the full string `out_text + token_str` against the partial match (as above) handles merged tokens correctly.
- **Slow masks:** Python regex checks over 50k tokens per step are slow. Precompile to a token-level FSM (as Outlines, XGrammar and llguidance do) for production.
- **Medusa heads trained on different data** than the one you serve on get low acceptance; train them on the target's own outputs (self-distillation) when possible.

### 🧠 Expert Insight
- **Saxena (2023), prompt lookup decoding:** a few lines of code; now built into Hugging Face `generate` and vLLM (`ngram` speculation).
- **Cai et al. (2024), Medusa:** multiple decoding heads with tree attention for verification.
- **Fu et al. (2024), Lookahead decoding:** Jacobi iterations plus n-gram pools, no draft model.
- **Willard & Louf (2023), Outlines:** regex/JSON-schema constrained generation via an FSM index over the vocabulary. **XGrammar (2024)** and **llguidance** made context-free grammar constraints nearly free. Most serving stacks now expose "structured outputs" this way.
- **Multi-token prediction (Gloeckle et al., 2024; DeepSeek-V3):** training the base model with extra future-token heads improves quality *and* provides built-in speculation heads.

<details><summary>Answers</summary>

1. The drafts are only proposals; the target's own greedy prediction at each position decides acceptance, so the output equals plain greedy decoding. A bad guess only costs speed.
2. It guarantees the output matches the format (syntax); it doesn't guarantee the content is correct, and it samples from a locally renormalized distribution rather than the true conditional over valid sequences.
3. So each head starts as the base next-token predictor (a sensible starting point) and training only has to learn the offset.

### 📌 Recap Card
- Any cheap guesser can be a draft: n-gram lookup, extra heads, Jacobi iterations.
- Verification keeps greedy outputs exact.
- Constrained decoding = mask invalid next tokens; guarantees syntax, not truth.
- Describe the format in the prompt too; precompile the grammar for speed.

> **Core intuition:** *The model proposes, the verifier (or the grammar) disposes. Keep the model's judgement, but only over the options you can accept.*
