## 48.1 Attention Visualization and Its Limits

### 🧭 The Problem First
Your model completes "The Eiffel Tower is in the city of" with "Paris". Which earlier tokens did it use? Attention weights look like the obvious answer: they're literally "how much each position looks at each other position". How far can you trust them?

### 💡 Intuition / Instinct
Attention patterns are the easiest thing to look at, and they *do* reveal real structure: heads that attend to the previous token, to the first token (sinks, Ch 47.3), to matching brackets, to the subject of the sentence. But three caveats keep them from being explanations:
1. **Weights aren't contributions.** A head can put 90% of its attention on a token whose value vector is nearly zero (a sink): high weight, no effect. What matters is roughly weight × ‖value · W_O‖.
2. **Information has already moved.** After layer 1, the residual stream at position 5 may already contain information copied from position 2. Attention from position 9 to position 5 in layer 6 may really be reading "token 2's information stored at position 5".
3. **Many heads, many layers.** Individual heads are one part of a distributed computation; a pattern tells you *where* a head reads, not *what* it does with it.

Use attention to form hypotheses, then test them *causally* (48.3): change something and measure the effect on the output.

### 🖼️ Visual Mental Model

```text
 query ↓ / key →   The  Eif  fel  Tower  is  in  the  city  of
 "of"             [.62  .01  .02  .15   .01 .02 .03  .09  .05]
                    ▲ sink: big weight, ~zero value → little effect
                                   ▲ "Tower": moderate weight, large value → real contribution
 effective contribution_j ≈ a_j · ‖v_j W_O‖
```

### 📐 The Math, Gently
For head h at query position i, the head's output written into the residual stream is

$$o_i^h = \sum_j a_{ij}^h\, v_j^h W_O^h$$

so the contribution of source position j has norm $a_{ij}^h\,\|v_j^h W_O^h\|$. Plotting this **value-weighted attention** instead of $a_{ij}$ removes most sink artefacts. It's still not a full attribution (it ignores the nonlinear effects downstream), but it's a much better picture of where information actually flows.

### 🛠️ Build It From Scratch
Hooks to capture per-layer residual streams and per-head attention (with value norms), without modifying the model code:

```python
# nanoforge/interp/hooks.py
import torch
from nanoforge.models.rope import apply_rope
from nanoforge.models.attention import repeat_kv

@torch.no_grad()
def run_with_cache(model, ids):
    """Returns logits and a cache: resid[l] = residual stream *after* block l (resid[-1] = embeddings),
    attn[l] = (H, T, T) attention weights, vnorm[l] = (H, T) norms of each position's v·W_O per head."""
    cache = {"resid": {}, "attn": {}, "vnorm": {}}
    m = model; x = m.tok_emb(ids[None]); cache["resid"][-1] = x[0].clone()
    T = ids.numel(); cos, sin = m.rope_cos[:T], m.rope_sin[:T]
    causal = torch.ones(T, T, dtype=torch.bool, device=ids.device).triu(1)
    for l, layer in enumerate(m.layers):
        a = layer.attn; h = layer.attn_norm(x); B = 1
        q = apply_rope(a.q_norm(a.wq(h).view(B, T, a.H, a.D)).transpose(1, 2), cos, sin)
        k = apply_rope(a.k_norm(a.wk(h).view(B, T, a.Hkv, a.D)).transpose(1, 2), cos, sin)
        v = a.wv(h).view(B, T, a.Hkv, a.D).transpose(1, 2)
        k, v = repeat_kv(k, a.H // a.Hkv), repeat_kv(v, a.H // a.Hkv)
        att = ((q @ k.transpose(-1, -2)) / a.D ** 0.5).masked_fill(causal, float("-inf")).softmax(-1)
        Wo = a.wo.weight.view(-1, a.H, a.D)                               # (C, H, D): per-head slices of W_O
        vo = torch.einsum("bhtd,chd->bhtc", v, Wo)                        # (1, H, T, C) each position's write per head
        cache["attn"][l], cache["vnorm"][l] = att[0], vo[0].norm(dim=-1)
        x = layer(x, m.rope_cos, m.rope_sin)                              # the real forward, for exact residuals
        cache["resid"][l] = x[0].clone()
    logits = m.lm_head(m.norm(x))
    return logits[0], cache

def plot_attention(att, tokens, title="", value_norms=None, path=None):
    """att: (T, T) for one head. If value_norms (T,) is given, plots value-weighted attention (rows renormalized)."""
    import matplotlib.pyplot as plt
    A = att.float().cpu()
    if value_norms is not None:
        A = A * value_norms.float().cpu()[None, :]; A = A / A.sum(-1, keepdim=True).clamp_min(1e-12)
    fig, ax = plt.subplots(figsize=(0.35 * len(tokens) + 2, 0.35 * len(tokens) + 1.5))
    ax.imshow(A, cmap="Blues", vmin=0, vmax=1)
    ax.set_xticks(range(len(tokens))); ax.set_xticklabels(tokens, rotation=90, fontsize=7)
    ax.set_yticks(range(len(tokens))); ax.set_yticklabels(tokens, fontsize=7)
    ax.set_xlabel("key (attended to)"); ax.set_ylabel("query"); ax.set_title(title)
    fig.tight_layout()
    if path: fig.savefig(path, dpi=150)
    return fig
```

A tiny head classifier that labels common patterns automatically:

```python
def classify_heads(cache, n_layers):
    """Scores each head on 'previous token', 'first token (sink)' and 'self' patterns (queries from position 8 on)."""
    out = {}
    for l in range(n_layers):
        A = cache["attn"][l][:, 8:, :]                                     # (H, T-8, T)
        T = cache["attn"][l].size(-1); q = torch.arange(8, T)
        out[l] = {"prev": A[:, torch.arange(len(q)), q - 1].mean(-1).tolist(),
                  "first": A[:, :, 0].mean(-1).tolist(),
                  "self": A[:, torch.arange(len(q)), q].mean(-1).tolist()}
    return out
```

2. Use `classify_heads` to find the strongest previous-token head and sink-heavy heads. For sink heads, compare raw vs value-weighted plots: the column at position 0 shrinks dramatically.

### ⚠️ Failure Modes & Debugging
- **Forgetting RoPE or GQA** when recomputing attention: patterns look plausible but differ from what the model actually used. Sanity check: the cached residual stream must equal the real forward pass (it does above, because we call the real `layer`).
- **Reading averages over heads:** they blur distinct mechanisms together. Look per head.
- **Tokenization artefacts:** a "word" may be three tokens, and attention between sub-tokens of one word is often uninteresting glue.

### 🧠 Expert Insight

- **Jain & Wallace (2019), "Attention is not Explanation"** and **Wiegreffe & Pinter (2019), "Attention is not not Explanation":** the classic debate; the modern consensus is to treat attention as a hypothesis generator.
- **Kobayashi et al. (2020):** norm-based analysis (attention × transformed value norm), the value-weighted view used above.
- **Elhage et al. (2021), "A Mathematical Framework for Transformer Circuits":** decomposes attention heads into QK (where to look) and OV (what to move) circuits; the foundation of 48.3.

## 48.2 Logit Lens and Linear Probes

### 🧭 The Problem First
The model predicts "Paris" at the last layer. At which layer did it "know" Paris? And does it internally represent things it never outputs directly, like whether a statement is true, or which language the text is in?

### 💡 Intuition / Instinct
- **Logit lens:** the residual stream is a shared bus (Ch 19.4) that every layer reads and writes, and the final layer reads it through `norm → lm_head`. So apply that same readout to the residual stream *after every layer* and see what the model "would say" if it stopped there. Typically the right answer emerges gradually through the middle layers and sharpens at the end.
- **Linear probes:** train a small linear classifier on the residual stream at some layer to predict a property (part of speech, sentiment, "is this token inside a code block", the document's domain). If a linear probe succeeds, the information is **linearly represented** there, meaning it's easy for later layers to use.
- **The catch:** a powerful enough probe can *learn* the task itself from rich features rather than *read* it. Use simple (linear) probes and compare against **control tasks** (the same probe on randomized labels, and on a randomly initialized model) to see how much is really in the representation.

### 🖼️ Visual Mental Model

```text
 layer:     emb   L0    L1    L2    L3    L4    L5    L6    L7
 lens top1: "of"  "the" "the" "Fr" "city" "Paris" "Paris" "Paris" "Paris"
 p(Paris):  .00   .00   .01   .03   .12   .41    .66    .79    .88
                                         ▲ the answer becomes linearly readable around here

 probe:  residual (C-dim) ─▶ [w·x + b] ─▶ property?   accuracy per layer vs a control-task baseline
```

### 📐 The Math, Gently
**Logit lens** at layer l: $\text{logits}_l = W_U\,\text{Norm}(r_l)$, where $r_l$ is the residual stream after block l and $W_U$ is the unembedding (lm_head). Measure $D_{KL}(p_{final}\,\|\,p_l)$ per layer. Because intermediate residuals aren't trained to be read this way, the lens can be biased in early layers; the **tuned lens** learns a small affine map per layer, $\text{logits}_l = W_U\,\text{Norm}(A_l r_l + b_l)$, trained to match the final distribution.

**Probe:** logistic regression $p(y=1 \mid r) = \sigma(w^\top r + b)$ trained with cross-entropy (+ weight decay). **Selectivity** = accuracy on the real task − accuracy on a control task with the same label distribution but random label assignments per token type (Hewitt & Liang, 2019). High accuracy with high selectivity is evidence the representation encodes the property.

### 🛠️ Build It From Scratch

```python
# nanoforge/interp/lens.py
import torch, torch.nn.functional as F
from nanoforge.interp.hooks import run_with_cache

@torch.no_grad()
def logit_lens(model, ids, tok=None, pos=-1, topk=5):
    """Per layer: top-k tokens and KL(final || layer) at position `pos`."""
    logits, cache = run_with_cache(model, ids)
    p_final = F.log_softmax(logits[pos].float(), -1)
    rows = []
    for l in sorted(cache["resid"]):
        lp = F.log_softmax(model.lm_head(model.norm(cache["resid"][l][pos])).float(), -1)
        kl = (p_final.exp() * (p_final - lp)).sum().item()
        top = lp.topk(topk).indices.tolist()
        rows.append({"layer": l, "kl_to_final": kl, "top": [tok.decode([t]) for t in top] if tok else top})
    return rows

@torch.no_grad()
def collect_resid(model, id_seqs, layer):
    """Stack residual vectors at `layer` for every position of every sequence -> (N, C)."""
    return torch.cat([run_with_cache(model, ids)[1]["resid"][layer].float() for ids in id_seqs])

def train_probe(X, y, n_classes, epochs=200, lr=1e-2, wd=1e-3, val_frac=0.2, seed=0):
    """Multinomial logistic regression on (N, C) features. Returns validation accuracy."""
    g = torch.Generator().manual_seed(seed); perm = torch.randperm(X.size(0), generator=g)
    n_val = int(val_frac * X.size(0)); va, tr = perm[:n_val], perm[n_val:]
    mu, sd = X[tr].mean(0), X[tr].std(0) + 1e-6
    Xn = (X - mu) / sd
    probe = torch.nn.Linear(X.size(1), n_classes)
    opt = torch.optim.AdamW(probe.parameters(), lr=lr, weight_decay=wd)
    for _ in range(epochs):
        loss = F.cross_entropy(probe(Xn[tr]), y[tr]); opt.zero_grad(); loss.backward(); opt.step()
    with torch.no_grad(): return (probe(Xn[va]).argmax(-1) == y[va]).float().mean().item()

def control_labels(token_ids, y, n_classes, seed=0):
    """Hewitt & Liang control task: each token *type* gets a fixed random label (same label distribution)."""
    g = torch.Generator().manual_seed(seed)
    types = token_ids.unique()
    probs = torch.bincount(y, minlength=n_classes).float(); probs /= probs.sum()
    mapping = {int(t): int(torch.multinomial(probs, 1, generator=g)) for t in types}
    return torch.tensor([mapping[int(t)] for t in token_ids])
```

**A probe task that works on any corpus:** "is this token inside a quotation / parenthesis / code block?", computed from the text itself. Label each position by scanning the decoded prefix, collect residuals at each layer, and train probes.

```python
def inside_parens_labels(tok, ids):
    depth, labels = 0, []
    for t in ids.tolist():
        s = tok.decode([t])
        labels.append(1 if depth > 0 else 0)                        # label = state *before* this token
        depth = max(0, depth + s.count("(") - s.count(")"))
    return torch.tensor(labels)
```

### ⚠️ Failure Modes & Debugging
- **Train/validation leakage:** positions from the same sequence are highly correlated. Split by *sequence*, not by position, for honest numbers (the simple random split above is optimistic; use it for quick looks only).
- **Class imbalance:** 95% "outside parentheses" means 95% accuracy for free. Report balanced accuracy or compare to the majority baseline.

- **Logit lens on models with untied embeddings or extra final layers** can be garbage in early layers; try the tuned lens.

## 48.3 Induction Heads and Circuits

### 🧭 The Problem First
Show a trained transformer a random sequence of tokens that it has never seen, then repeat it. On the second copy, its loss drops to near zero: it predicts each next token perfectly. A bigram model can't do that; nothing in the training data told it these tokens follow each other. What mechanism inside the model copies the sequence?

### 💡 Intuition / Instinct
The mechanism is an **induction head**, a two-head circuit spread across two layers:
1. A **previous-token head** (earlier layer) writes, into each position's residual stream, "the token before me was X".
2. The **induction head** (later layer), at the current token A, searches for earlier positions whose "previous token was A" (a key match on the information written by head 1), then copies *that* position's token B into the output: "last time A appeared, B came next, so predict B".

Pattern: `[A][B] ... [A] → predict [B]`. It's the model's built-in copy-and-paste, and it's thought to underlie much of in-context learning (few-shot prompting, copying names, following formats). Induction heads also appear suddenly during training, coinciding with a visible bump in the loss curve (a **phase change**).

**Circuits** = specific, verified sub-networks implementing an algorithm. Verification means **causal interventions**: ablate (zero or mean-replace) a head and show the behaviour breaks; patch activations from one input into another and show the behaviour transfers.

### 🖼️ Visual Mental Model

```text
 tokens:  ... [A] [B] ... ... [A]  → ?
 layer 1: previous-token head at [B] writes "prev = A" into [B]'s stream
 layer 2: induction head at the second [A]:
            query  "I am A"   ─┐  matches key "prev = A" at [B]
            value  copies "B" ─┴▶ output: predict B
 attention pattern on repeated random tokens: a stripe at offset −(L−1) (one after the earlier copy)
```

### 📐 The Math, Gently
Take a random sequence $s$ of length L and feed $[s; s]$. For a query position $i \ge L$ in the second copy, the induction target position is $i - L + 1$ (the token right after the earlier occurrence of the current token). The **induction score** of head h is

$$\text{score}_h = \frac{1}{L-1}\sum_{i=L}^{2L-2} a^h_{i,\ i-L+1}$$

With random tokens, only a copying mechanism can lower the loss on the second copy, so the per-token loss gap between halves is a clean behavioural measure. **Ablation effect** of head h = loss on the second half with head h's output zeroed − baseline loss. A true induction head has both a high score and a large ablation effect.

### 🛠️ Build It From Scratch

```python
# nanoforge/interp/induction.py
import contextlib, torch, torch.nn.functional as F
from nanoforge.interp.hooks import run_with_cache

def repeated_random_tokens(V, L, B=8, seed=0, lo=0):
    g = torch.Generator().manual_seed(seed)
    s = torch.randint(lo, V, (B, L), generator=g)
    return torch.cat([s, s], 1)                                   # (B, 2L)

@torch.no_grad()
def per_token_loss(model, x):
    logits, _ = model(x, all_logits=True)
    return F.cross_entropy(logits[:, :-1].float().reshape(-1, logits.size(-1)), x[:, 1:].reshape(-1),
                           reduction="none").view(x.size(0), -1)  # (B, 2L-1)

@torch.no_grad()
def induction_scores(model, x):
    """(n_layers, H) mean attention from each second-half position to (i - L + 1)."""
    L = x.size(1) // 2
    scores = []
    for b in range(x.size(0)):
        _, cache = run_with_cache(model, x[b])
        per_layer = []
        for l in range(len(model.layers)):
            A = cache["attn"][l]                                  # (H, 2L, 2L)
            i = torch.arange(L, 2 * L - 1)
            per_layer.append(A[:, i, i - L + 1].mean(-1))
        scores.append(torch.stack(per_layer))
    return torch.stack(scores).mean(0)

@contextlib.contextmanager
def ablate_heads(model, heads):
    """heads: list of (layer, head). Zeroes those heads' outputs by editing the input of W_O."""
    handles = []
    for l, h in heads:
        a = model.layers[l].attn
        def pre_hook(mod, inp, h=h, D=a.D):
            x = inp[0].clone(); x[..., h * D:(h + 1) * D] = 0; return (x,)
        handles.append(a.wo.register_forward_pre_hook(pre_hook))
    try: yield
    finally:
        for hd in handles: hd.remove()

def ablation_table(model, x, n_head):
    L = x.size(1) // 2
    base = per_token_loss(model, x)[:, L:].mean().item()
    rows = []
    for l in range(len(model.layers)):
        for h in range(n_head):
            with ablate_heads(model, [(l, h)]):
                rows.append({"layer": l, "head": h, "delta_loss": per_token_loss(model, x)[:, L:].mean().item() - base})
    return base, sorted(rows, key=lambda r: -r["delta_loss"])
```

Train a tiny attention-only-ish model where induction heads form quickly, to see the phase change yourself:

```python
# scripts/train_induction_toy.py
import torch
from nanoforge.models.llama import Llama, LlamaConfig
from nanoforge.interp.induction import repeated_random_tokens, per_token_loss, induction_scores

torch.manual_seed(0)
V, L = 64, 24
model = Llama(LlamaConfig(vocab_size=V, n_layer=2, n_head=4, n_kv_head=4, n_embd=64, block_size=2 * L))
opt = torch.optim.AdamW(model.parameters(), lr=3e-3)
for step in range(1501):
    x = repeated_random_tokens(V, L, B=32, seed=step + 1000)
    _, loss = model(x[:, :-1], targets=x[:, 1:].contiguous())
    opt.zero_grad(); loss.backward(); opt.step()
    if (step <= 300 and step % 20 == 0) or step % 250 == 0:     # fine-grained early: the jump is fast
        model.eval()
        pl = per_token_loss(model, repeated_random_tokens(V, L, B=16, seed=0))
        s = induction_scores(model, repeated_random_tokens(V, L, B=4, seed=1))
        print(f"step {step:4d}  loss 1st half {pl[:, :L-1].mean():.2f}  2nd half {pl[:, L:].mean():.2f}  "
              f"max induction score L1 {s[1].max():.2f}")
        model.train()
```

### 🔬 Experiment & Observe
1. Run the toy: the first-half loss stays at ≈ ln 64 ≈ 4.16 (random tokens are unpredictable), while the second-half loss drops sharply within a few dozen steps, at the same time as the layer-1 heads' induction scores jump toward 1. That's the phase change. (In our run the second-half loss went from 4.17 at step 0 to 1.4 at step 100 and 0.1 by step 160; the exact timing depends on the seed and learning rate.)
2. Run `ablation_table` on the trained toy: ablating the high-scoring layer-1 heads raises the second-half loss from ~0.01 to over 1 nat each. Then look at layer 0 with `classify_heads`. In our run there was *no* single crisp previous-token head: the "previous token" information was smeared across several layer-0 heads (redundancy), so ablating any one of them changed the loss by less than 0.07. Ablating **all** layer-0 heads together with `ablate_heads(model, [(0, h) for h in range(4)])` raised it to ~0.7: the first half of the circuit is real but distributed. This is a typical lesson: clean textbook circuits often show up as distributed ones in practice, and group ablations reveal what single ablations miss.
3. Repeat `induction_scores` and the half-loss comparison on your Llama-mini (trained on real text) using `repeated_random_tokens`. Real LMs trained on natural text develop induction heads too.

### ⚠️ Failure Modes & Debugging
- **Zero-ablation takes activations off-distribution** (a head's output is never exactly zero in normal operation), which can exaggerate effects. **Mean-ablation** (replace with the head's average output) is a gentler baseline.
- **Redundancy:** ablating one head may do nothing because another head compensates (backup heads). Ablate groups, too.
- **Random tokens from the full vocabulary** can include special tokens; use the `lo` argument to sample from the ordinary range.
- **Toy vs real:** in large models, circuits are messier and distributed. Treat clean toy circuits as existence proofs, not complete explanations.

- **Conmy et al. (2023), ACDC:** automated circuit discovery. **Attribution patching** (Nanda, 2023) approximates many patching experiments with gradients.

### ✅ Check Your Instinct
1. Why can't a bigram model lower the loss on the second copy of a random sequence?
2. What two pieces of evidence identify a head as an induction head?

<details><summary>Answers</summary>

1. The token pairs are random and were never seen in training, so no fixed token-to-token statistics predict them; only copying from the context can.
2. A high induction attention score (attending to the token after the previous occurrence) and a large loss increase on repeated sequences when the head is ablated (causal importance).
</details>

### 📌 Recap Card
- Induction = previous-token head (layer l) + induction head (layer > l): [A][B]…[A] → [B].
- Measure: attention score on repeated random tokens + ablation effect.
- Verify circuits causally; beware off-distribution ablations and redundancy.

> **Core intuition:** *"Last time I saw this, what came next?" is a two-head algorithm, and you can find it, break it, and watch the model forget how to copy.*

## 48.4 Sparse Autoencoders for Features, From Scratch

### 🧭 The Problem First
You'd like to say "neuron 1,337 means *legal citations*". But when you look at individual neurons (or residual dimensions), each one fires on a confusing mix of unrelated things. Why, and how do you find the model's real units of meaning?

### 💡 Intuition / Instinct
**Superposition:** the model needs to represent far more concepts than it has dimensions (C = 512 but thousands of features). Because any given text uses only a few concepts at once, the model can pack them as *almost-orthogonal directions* in a shared space, tolerating small interference. The price: every neuron participates in many features, so neurons are **polysemantic**.

A **sparse autoencoder (SAE)** tries to undo this. It maps an activation vector x (C-dim) to a much larger code f (F-dim, e.g. 8×C) where **only a few entries are non-zero**, then reconstructs x as a sum of those few dictionary directions:

$$x \approx \sum_i f_i\, d_i$$

Sparsity forces each dictionary direction $d_i$ to stand for something that appears on its own, which often turns out to be a human-interpretable **feature**: "Python code", "a date", "text in French", "a negation".

### 🖼️ Visual Mental Model

```text
 residual x (C=512) ─▶ encoder W_e, ReLU ─▶ f (F=4096, ~20 non-zero) ─▶ decoder W_d ─▶ x̂ (C=512)
                                            │
                                   each active f_i scales one dictionary direction d_i (a column of W_d)
 loss = ‖x − x̂‖²  +  λ · Σ_i f_i ‖d_i‖        (reconstruct well, using as few features as possible)
```

### 📐 The Math, Gently
Encoder and decoder (with a pre-encoder bias that centres the data):

$$f = \text{ReLU}\big(W_e (x - b_d) + b_e\big), \qquad \hat x = W_d f + b_d$$

Loss:

$$\mathcal{L} = \|x - \hat x\|_2^2 + \lambda \sum_i f_i\,\|W_{d,:,i}\|_2$$

Multiplying each feature's activation by its decoder column norm prevents the trivial cheat of shrinking f while growing $W_d$. Equivalently, constrain the columns to unit norm, as below.

**Metrics:**
- **L0:** average number of active features per token (sparsity; typically 10–100).
- **Explained variance:** $1 - \|x - \hat x\|^2 / \|x - \bar x\|^2$.
- **Loss recovered:** splice $\hat x$ back into the model in place of x and measure the LM loss: $\frac{L_{zero} - L_{SAE}}{L_{zero} - L_{orig}}$, where $L_{zero}$ zero-ablates the layer's residual. This is what matters: does the SAE keep what the model *uses*?
- **Dead features:** never activate on a large sample; resample or use auxiliary losses.

### 🛠️ Build It From Scratch

```python
# nanoforge/interp/sae.py
import torch, torch.nn as nn, torch.nn.functional as F

class SparseAutoencoder(nn.Module):
    def __init__(self, C, F_):
        super().__init__()
        self.W_e = nn.Parameter(torch.empty(F_, C)); self.b_e = nn.Parameter(torch.zeros(F_))
        self.W_d = nn.Parameter(torch.empty(C, F_)); self.b_d = nn.Parameter(torch.zeros(C))
        nn.init.kaiming_uniform_(self.W_d); self.normalize_decoder()
        with torch.no_grad(): self.W_e.copy_(self.W_d.T)            # tied init: encoder = decoder transpose
    @torch.no_grad()
    def normalize_decoder(self): self.W_d.div_(self.W_d.norm(dim=0, keepdim=True).clamp_min(1e-8))
    def encode(self, x): return F.relu((x - self.b_d) @ self.W_e.T + self.b_e)
    def decode(self, f): return f @ self.W_d.T + self.b_d
    def forward(self, x):
        f = self.encode(x); return self.decode(f), f

def train_sae(acts, F_mult=8, l1=5e-3, steps=5000, B=4096, lr=3e-4, seed=0, log_every=500):
    """acts: (N, C) residual activations (float32). Normalizes them to unit mean norm first."""
    torch.manual_seed(seed)
    scale = acts.norm(dim=1).mean(); X = acts / scale
    sae = SparseAutoencoder(X.size(1), F_mult * X.size(1)).to(X.device)
    with torch.no_grad(): sae.b_d.copy_(X.median(0).values)       # geometric-median-ish init for the centre
    opt = torch.optim.Adam(sae.parameters(), lr=lr)
    fired = torch.zeros(sae.W_e.size(0), device=X.device)
    for step in range(steps):
        x = X[torch.randint(0, X.size(0), (B,), device=X.device)]
        x_hat, f = sae(x)
        mse = (x - x_hat).pow(2).sum(-1).mean()
        loss = mse + l1 * f.sum(-1).mean()                         # decoder columns are unit norm
        opt.zero_grad(); loss.backward()
        with torch.no_grad():                                      # remove the gradient component that changes column norms
            sae.W_d.grad -= (sae.W_d.grad * sae.W_d).sum(0, keepdim=True) * sae.W_d
        opt.step(); sae.normalize_decoder()
        fired += (f > 0).float().sum(0)
        if step % log_every == 0:
            ev = 1 - (x - x_hat).pow(2).sum() / (x - x.mean(0)).pow(2).sum()
            print(f"step {step} mse {mse:.4f} L0 {(f > 0).float().sum(-1).mean():.1f} "
                  f"expl.var {ev:.3f} dead {(fired == 0).float().mean():.2%}")
            fired.zero_()
    sae.act_scale = scale
    return sae

@torch.no_grad()
def loss_recovered(model, sae, layer, batches):
    """Splice SAE reconstructions into the residual stream after `layer`; compare LM losses."""
    def run(mode):
        def hook(mod, inp, out):
            if mode == "zero": return torch.zeros_like(out)
            if mode == "sae":
                x = out.float() / sae.act_scale
                return (sae(x)[0] * sae.act_scale).to(out.dtype)
        h = model.layers[layer].register_forward_hook(hook) if mode != "orig" else None
        tot = sum(model(x[:, :-1], targets=x[:, 1:].contiguous())[1].item() for x in batches) / len(batches)
        if h: h.remove()
        return tot
    L_orig, L_sae, L_zero = run("orig"), run("sae"), run("zero")
    return {"orig": L_orig, "sae": L_sae, "zero": L_zero, "recovered": (L_zero - L_sae) / (L_zero - L_orig)}

@torch.no_grad()
def top_activating_contexts(model, sae, layer, id_seqs, feature, tok, k=10, width=12):
    """The k (sequence, position) contexts where `feature` fires most strongly, as text snippets."""
    from nanoforge.interp.hooks import run_with_cache
    hits = []
    for si, ids in enumerate(id_seqs):
        r = run_with_cache(model, ids)[1]["resid"][layer].float() / sae.act_scale
        acts = sae.encode(r)[:, feature]
        for p in acts.topk(min(3, acts.numel())).indices.tolist():
            hits.append((acts[p].item(), si, p))
    hits.sort(reverse=True)
    out = []
    for a, si, p in hits[:k]:
        ids = id_seqs[si]
        left = tok.decode(ids[max(0, p - width):p].tolist()); cur = tok.decode(ids[p:p + 1].tolist())
        out.append(f"{a:6.2f}  {left}[[{cur}]]")
    return out
```

### ⚠️ Failure Modes & Debugging
- **Dead features** (never fire): common with a large F. Resample them to point at poorly reconstructed inputs, or use newer architectures (TopK SAEs choose exactly k active features, which avoids tuning λ).
- **Shrinkage:** the L1 penalty pulls activations toward zero, so reconstructions are systematically too small. Gated/JumpReLU/TopK SAEs reduce it.
- **Great MSE, poor loss recovered:** the SAE reconstructs directions the model doesn't use and loses ones it does. Always report loss recovered.
- **Over-interpreting top activations:** a feature's top examples can look clean while its weaker activations mean something else. Check activations across the whole range.

### 🧠 Expert Insight
- **Elhage et al. (2022), "Toy Models of Superposition":** why and when superposition happens.
- **Bricken et al. (2023), "Towards Monosemanticity"** and **Cunningham et al. (2023):** SAEs recover interpretable features from real LMs.
- **Templeton et al. (2024), "Scaling Monosemanticity":** millions of features from a production model, including abstract and safety-relevant ones, used to steer the model.
- **Gao et al. (2024), TopK SAEs** and **Rajamanoharan et al. (2024), JumpReLU (Gemma Scope):** better sparsity/fidelity trade-offs; open SAE suites for open models enable research without training your own.
- **Transcoders and crosscoders (2024–2025):** replace MLPs, or span several layers, to trace features through computation ("attribution graphs") rather than only reading one layer.

### ✅ Check Your Instinct
1. Why are individual neurons often polysemantic?
2. Why is "loss recovered" a better metric than reconstruction MSE alone?

<details><summary>Answers</summary>

1. Superposition: the model represents more sparse features than it has dimensions by using non-orthogonal directions, so each neuron takes part in many features.
2. It measures whether the reconstruction preserves what the model downstream actually relies on; small MSE can still destroy important low-variance directions.
</details>

### 📌 Recap Card
- Superposition → polysemantic neurons.
- SAE: wide ReLU code + unit-norm decoder + L1 → sparse, often interpretable features.
- Report L0, explained variance, loss recovered, dead features; read top-activating contexts.

> **Core intuition:** *The model packs many concepts into few dimensions. A sparse dictionary unpacks them back into things you can name.*

## 48.5 Activation Steering

### 🧭 The Problem First
You want your model to be more formal, or to stay on topic, or to stop mentioning a competitor, without retraining. If concepts are directions in the residual stream (48.2, 48.4), can you just *push* the activations along a direction?

### 💡 Intuition / Instinct
Yes, often surprisingly well. **Activation steering** adds a vector to the residual stream at one layer during generation:
1. Find a direction v for the concept: e.g. the mean activation on formal texts minus the mean on casual texts (**contrastive activation addition**), or an SAE feature's decoder direction (48.4), or a probe's weight vector (48.2).
2. At inference, add α·v to the residual stream at layer l for every position (or only for generated positions).
3. Tune α: too small does nothing, too large breaks fluency.

Steering is both a control tool and an interpretability test: if adding the "French" direction makes the model write French, that direction is causally used for "French". Removing a direction (projecting it out) tests whether the model *needs* it, e.g. the "refusal direction" found in chat models.

### 🖼️ Visual Mental Model

```text
 residual at layer l:  x ──▶ x + α·v ──▶ layers l+1..L ──▶ output shifts toward the concept
 v = mean(acts | formal prompts) − mean(acts | casual prompts)
 α:   0 ──── 4 ──── 8 ──── 16
      no change   subtle   strong   gibberish
```

### 📐 The Math, Gently
**Difference of means:** $v = \frac{1}{|P|}\sum_{p\in P} r_l(p) - \frac{1}{|N|}\sum_{n \in N} r_l(n)$ over the residual at layer l (usually averaged over the last token, or all tokens, of each prompt). Normalize v and choose α relative to the typical residual norm at that layer, e.g. α = c · mean‖r_l‖ with c ∈ [0.1, 1].

**Directional ablation:** remove a concept everywhere by projecting it out of the residual stream, $x \leftarrow x - (x\cdot \hat v)\,\hat v$, at every layer. If a behaviour disappears, the direction is necessary for it.

### 🛠️ Build It From Scratch

```python
# nanoforge/interp/steer.py
import contextlib, torch
from nanoforge.interp.hooks import run_with_cache

@torch.no_grad()
def mean_resid(model, id_seqs, layer, last_only=False):
    vs = []
    for ids in id_seqs:
        r = run_with_cache(model, ids)[1]["resid"][layer].float()
        vs.append(r[-1] if last_only else r.mean(0))
    return torch.stack(vs).mean(0)

@torch.no_grad()
def steering_vector(model, pos_seqs, neg_seqs, layer, last_only=False):
    """Returns (unit direction, typical residual norm at that layer)."""
    v = mean_resid(model, pos_seqs, layer, last_only) - mean_resid(model, neg_seqs, layer, last_only)
    norm = torch.stack([run_with_cache(model, s)[1]["resid"][layer].float().norm(dim=-1).mean() for s in pos_seqs]).mean()
    return v / v.norm(), norm.item()

@contextlib.contextmanager
def steer(model, layer, direction, alpha):
    """Adds alpha * direction to the output of block `layer` at every position."""
    d = direction.to(next(model.parameters()).dtype)
    h = model.layers[layer].register_forward_hook(lambda mod, inp, out: out + alpha * d.to(out.device))
    try: yield
    finally: h.remove()

@contextlib.contextmanager
def ablate_direction(model, direction):
    """Projects `direction` out of the residual stream after every block."""
    u = direction / direction.norm()
    def hook(mod, inp, out):
        uu = u.to(out.dtype).to(out.device); return out - (out @ uu)[..., None] * uu
    hs = [blk.register_forward_hook(hook) for blk in model.layers]
    try: yield
    finally:
        for h in hs: h.remove()
```

### 🔬 Experiment & Observe
1. Build 50 positive/negative text pairs for a concept in your domain (formal vs casual, technical vs lay, on-topic vs off-topic). Compute v at each layer and steer. Which layer works best? Usually a middle layer.
2. Sweep α and measure two things on 50 prompts: a concept score (a judge or a classifier probe) and fluency (perplexity of the output under the unsteered model). Plot the trade-off curve.
3. Compare the difference-of-means direction with the decoder direction of the SAE feature that best matches the concept (highest cosine similarity with v). Do they steer similarly?
4. Try `ablate_direction` on the concept direction: does the model lose the ability to produce the concept even when asked?

### ⚠️ Failure Modes & Debugging
- **Confounded contrast sets:** if "formal" examples are also longer or about different topics, v encodes those differences too. Match pairs as closely as possible (same content, different style).
- **Steering at every position including the prompt** can distort the model's reading of the prompt; try steering only generated positions (check `out.size(1) == 1` in the hook when using a KV cache).
- **α in absolute units:** residual norms grow with depth, so a fixed α means different things at different layers. Scale by the layer's typical norm.
- **Treating steering as a safety guarantee:** it shifts behaviour on average; it doesn't prevent specific outputs. It complements training and system-level controls (Ch 42.4).

### 🧠 Expert Insight
- **Turner et al. (2023), ActAdd;** **Rimsky et al. (2024), Contrastive Activation Addition;** **Zou et al. (2023), Representation Engineering:** steering with activation differences.
- **Li et al. (2023), Inference-Time Intervention:** steering along truthfulness directions found by probes improved TruthfulQA scores.
- **Arditi et al. (2024), "Refusal in LLMs is mediated by a single direction":** ablating one direction removed refusal behaviour in many chat models, a striking result for both interpretability and safety (safety training can be shallow).
- **Templeton et al. (2024):** clamping SAE features ("Golden Gate Claude") produced strong, specific behaviour changes, showing features are causally used.

### ✅ Check Your Instinct
1. Why scale the steering coefficient by the residual norm of the layer?
2. What does it show if projecting out a direction removes a behaviour?

<details><summary>Answers</summary>

1. Residual norms differ greatly across layers; the effect of adding α·v depends on its size relative to the existing activations.
2. That the direction is causally necessary for the behaviour (not just correlated with it), at least in the way the model normally computes it.
</details>

### 📌 Recap Card
- Direction from contrast means, probes or SAE features.
- Add α·v at a middle layer; scale α by the residual norm; sweep for the fluency trade-off.
- Project directions out to test necessity.
- Steering is a tool and a test, not a guarantee.

> **Core intuition:** *If a concept is a direction, you can nudge the model along it, and by nudging, prove that the direction means what you think.*
