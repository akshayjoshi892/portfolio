## 15.1 Characters vs Words vs Subwords: The Trade-off Triangle

### 🧭 The Problem First
With characters, "internationalization" is 20 tokens: sequences get long, attention costs O(T²), and the model must learn spelling from scratch. With words, the vocabulary explodes (millions of words and names in many languages), and any unseen word becomes `<UNK>`.

### 💡 Intuition / Instinct
**Subwords** sit in the middle: common words are single tokens ("the"), rare words split into meaningful pieces ("inter" + "national" + "ization"), and *anything* can be spelled out from smaller pieces, down to bytes. Think of it as a dictionary of frequent chunks, built from data.

| Unit | Vocab | Seq length | Unknown words | Learns spelling? |
|---|---|---|---|---|
| Character/byte | 256 | very long | never | must learn |
| Word | 100K–1M+ | short | `<UNK>` | no |
| Subword (BPE) | 32K–256K | medium | never (byte fallback) | partially |

### 🖼️ Visual Mental Model

```text
 "unbelievably"
 chars:    u n b e l i e v a b l y        (12 tokens)
 words:    unbelievably  or <UNK>         (1 token / unknown)
 subwords: un believ ably                  (3 tokens)
```

### 📐 The Math, Gently
Compute per sequence ∝ number of tokens (and attention ∝ tokens²). Compression ratio = bytes/token. Typical English BPE: ~4 bytes/token, so it is 4× shorter than bytes: 4× cheaper in linear parts and 16× in attention for the same text.

### 🛠️ Build It From Scratch

```python
text = "The unbelievably international tokenizer tokenizes internationalization."
print("chars:", len(text), "| words:", len(text.split()), "| bytes:", len(text.encode("utf-8")))
import tiktoken                                     # comparison only
enc = tiktoken.get_encoding("gpt2")
ids = enc.encode(text); print("gpt2 BPE:", len(ids), [enc.decode([i]) for i in ids])
```

### 🔬 Experiment & Observe
Tokenize a sentence in English, Hindi, and code with GPT-2's tokenizer. Hindi uses many more tokens per character (Ch 16.5). That is a fairness and cost issue.

### ⚠️ Failure Modes & Debugging
Different tokenizers make per-token metrics incomparable (Ch 5.6). Use bits-per-byte.

### 🧠 Expert Insight
- **Sennrich et al. (2016):** BPE for neural MT.
- GPT-2 (2019): byte-level BPE, 50,257 tokens.
- Llama 3: 128K tokens; Gemma: 256K. The trend is larger vocabularies for multilingual efficiency.

## 15.2 Unicode, UTF-8 and Bytes

### 🧭 The Problem First
Text isn't "characters". It's Unicode code points (~150K of them) encoded as bytes. A tokenizer that works on code points has an enormous base alphabet. One that ignores encoding breaks on emoji and non-Latin scripts.

### 💡 Intuition / Instinct
**Unicode** assigns each symbol a number (a code point): 'A' = 65, 'é' = 233, '中' = 20013, '😀' = 128512. **UTF-8** encodes each code point as 1–4 bytes: ASCII takes 1 byte, most European and Hindi characters 2–3, emoji 4. If we tokenize *bytes*, the base alphabet is exactly 256, and **every possible string is representable**.

### 🖼️ Visual Mental Model

```text
 'A'  → U+0041  → [0x41]                  1 byte
 'é'  → U+00E9  → [0xC3, 0xA9]            2 bytes
 'क'  → U+0915  → [0xE0, 0xA4, 0x95]      3 bytes
 '😀' → U+1F600 → [0xF0,0x9F,0x98,0x80]   4 bytes
```

### 📐 The Math, Gently
UTF-8 prefixes: `0xxxxxxx` (1 byte), `110xxxxx 10xxxxxx` (2), `1110xxxx` + 2 continuation bytes (3), `11110xxx` + 3 continuation bytes (4). Continuation bytes always start with `10`, so the encoding is self-synchronizing.

### 🛠️ Build It From Scratch

```python
for ch in ["A", "é", "क", "中", "😀"]:

    print(ch, hex(ord(ch)), list(b), [f"{x:08b}" for x in b])

s = "héllo 😀"
bs = list(s.encode("utf-8")); print(bs, len(s), len(bs))
print(bytes(bs).decode("utf-8"))
# decoding a partial sequence fails -> use errors="replace"
print(bytes(bs[:-1]).decode("utf-8", errors="replace"))   # ends with U+FFFD �
```

### 🔬 Experiment & Observe
Decode the byte-token output of a model mid-emoji: you get `�`. Streaming decoders must buffer incomplete UTF-8 sequences (Ch 45).

### ⚠️ Failure Modes & Debugging
- `errors="strict"` crashes on partial bytes during streaming. Use `errors="replace"` for display.
- Unicode normalization (NFC vs NFD): "é" can be 1 or 2 code points. Normalize consistently (Ch 21).

### 🧠 Expert Insight
GPT-2's byte-level BPE maps each of the 256 bytes to a printable Unicode character so its merges file is readable. Our implementation works directly with integer bytes, which is simpler and equivalent.

> **Core intuition:** *Bytes are the universal alphabet: everything is 256 symbols underneath.*

## 15.3 The BPE Algorithm: Merge the Most Frequent Pair

### 🧭 The Problem First
We have 256 byte tokens. How do we *automatically* discover useful longer chunks from data?

### 💡 Intuition / Instinct
**Greedy compression:** find the most frequent adjacent pair of tokens in the corpus, make it a new token, replace every occurrence, and repeat until the vocabulary is the size you want. Frequent pairs like "t"+"h" → "th", then "th"+"e" → "the", then " "+"the" → " the". It's data compression that builds a dictionary of the corpus's most common chunks.

### 🖼️ Visual Mental Model

```text
 corpus: "aaabdaaabac"
 1: most frequent pair (a,a) → Z   : "ZabdZabac"
 2: (Z,a) → Y                       : "YbdYbac"
 3: (Y,b) → X                       : "XdXac"
 merges = [(a,a)→Z, (Z,a)→Y, (Y,b)→X]   ← the tokenizer IS this ordered list
```

### 📐 The Math, Gently
Each merge replaces n occurrences of a pair, reducing the sequence length by n. Vocab size = 256 + number of merges. The order of merges matters: encoding replays them in the same order.

### 🛠️ Build It From Scratch

```python
def get_pair_counts(ids, counts=None):
    counts = {} if counts is None else counts
    for a, b in zip(ids, ids[1:]):
        counts[(a, b)] = counts.get((a, b), 0) + 1
    return counts

def merge(ids, pair, new_id):
    out, i = [], 0
    while i < len(ids):
        if i < len(ids) - 1 and ids[i] == pair[0] and ids[i + 1] == pair[1]:
            out.append(new_id); i += 2
        else:
            out.append(ids[i]); i += 1
    return out

text = "aaabdaaabac"
ids = list(text.encode("utf-8"))
merges = {}
for k in range(3):
    counts = get_pair_counts(ids)
    pair = max(counts, key=counts.get)
    new_id = 256 + k
    ids = merge(ids, pair, new_id); merges[pair] = new_id
    print(f"merge {pair} -> {new_id}: {ids}")
```

### 🔬 Experiment & Observe
Run 20 merges on the first 10K characters of Shakespeare and print each new token as a string. You'll see "e ", "th", " the", "ou", "ing"...

### ⚠️ Failure Modes & Debugging
- Ties in pair counts: break them deterministically (e.g. the first seen, or the lowest pair), or the tokenizer won't be reproducible.
- Overlapping pairs: "aaa" with (a,a) → "Za", not "ZZ". The left-to-right scan handles this.

### 🧠 Expert Insight
Gage (1994) invented BPE as a data-compression algorithm; Sennrich et al. (2016) adapted it for NLP. The tokenizer's "training" is just this counting loop, with no gradients.

## 15.4 Implementing Train / Encode / Decode

### 🧭 The Problem First
We need a real tokenizer class: train it on a corpus, save it, encode new text by replaying the merges, and decode ids back to text exactly.

### 💡 Intuition / Instinct
- **Train:** the merge loop, recording `merges[(a,b)] = new_id` and building `vocab[id] = bytes`.
- **Encode:** start from bytes; repeatedly find the pair in the current sequence with the *lowest merge rank* (earliest learned) and merge it, until no mergeable pairs remain.
- **Decode:** concatenate `vocab[id]` bytes and decode UTF-8.

### 🖼️ Visual Mental Model

```text
 encode("the"):  [t,h,e] → pairs {(t,h):rank 3, (h,e):rank 9} → merge (t,h) → [th,e]
                 → pairs {(th,e): rank 12} → merge → [the] → done
```

### 📐 The Math, Gently
Encoding greedily by merge rank reproduces what training would have produced for that text.
Round trip: `decode(encode(s)) == s` for all s (byte-level guarantees this).

### 🛠️ Build It From Scratch

```python
# nanoforge/tokenizer/bpe.py
import json

def get_pair_counts(ids, counts=None):
    counts = {} if counts is None else counts
    for pair in zip(ids, ids[1:]):
        counts[pair] = counts.get(pair, 0) + 1
    return counts

def merge(ids, pair, new_id):
    out, i, n = [], 0, len(ids)
    a, b = pair
    while i < n:
        if i < n - 1 and ids[i] == a and ids[i + 1] == b:
            out.append(new_id); i += 2
        else:
            out.append(ids[i]); i += 1
    return out

class BasicBPE:
    """Byte-level BPE on raw text (no pre-tokenization). See RegexBPE for the GPT-style version."""
    def __init__(self):
        self.merges = {}                                # (int, int) -> int
        self.vocab = {i: bytes([i]) for i in range(256)}
        self.special_tokens = {}                        # str -> int

    def train(self, text, vocab_size, verbose=False):
        assert vocab_size >= 256
        ids = list(text.encode("utf-8"))
        for k in range(vocab_size - 256):
            counts = get_pair_counts(ids)
            if not counts: break
            pair = max(counts, key=lambda p: (counts[p], -p[0], -p[1]))   # deterministic ties
            new_id = 256 + k
            ids = merge(ids, pair, new_id)
            self.merges[pair] = new_id
            self.vocab[new_id] = self.vocab[pair[0]] + self.vocab[pair[1]]
            if verbose and k % 100 == 0:
                print(f"merge {k}: {pair} -> {self.vocab[new_id]!r} ({counts[pair]} occurrences)")

    def encode(self, text):
        ids = list(text.encode("utf-8"))
        while len(ids) >= 2:
            counts = get_pair_counts(ids)
            pair = min(counts, key=lambda p: self.merges.get(p, float("inf")))   # earliest merge
            if pair not in self.merges: break
            ids = merge(ids, pair, self.merges[pair])
        return ids

    def decode(self, ids):
        inv_special = {v: k for k, v in self.special_tokens.items()}
        parts = [inv_special[i].encode("utf-8") if i in inv_special else self.vocab[i] for i in ids]
        return b"".join(parts).decode("utf-8", errors="replace")

    def save(self, path):
        with open(path, "w", encoding="utf-8") as f:
            json.dump({"type": type(self).__name__,
                       "merges": [[a, b, i] for (a, b), i in self.merges.items()],
                       "special_tokens": self.special_tokens,
                       "pattern": getattr(self, "pattern", None)}, f)

    def load(self, path):
        with open(path, encoding="utf-8") as f: d = json.load(f)
        self.merges = {(a, b): i for a, b, i in d["merges"]}
        self.vocab = {i: bytes([i]) for i in range(256)}
        for (a, b), i in sorted(self.merges.items(), key=lambda kv: kv[1]):
            self.vocab[i] = self.vocab[a] + self.vocab[b]
        self.special_tokens = d.get("special_tokens", {})
        return self

    @property
    def vocab_size(self): return 256 + len(self.merges) + len(self.special_tokens)
```

## 15.5 Regex Pre-tokenization (GPT-2/GPT-4 Style)

### 🧭 The Problem First
Naive BPE creates tokens like "dog." , "dog!" and "dog?" as separate entries, and merges across spaces and punctuation. The vocabulary is wasted on combinations, and the same word gets different tokens depending on the punctuation next to it.

### 💡 Intuition / Instinct
**Split the text into chunks first** (words with their leading space, numbers, punctuation runs, whitespace), and only allow merges *within* chunks. Then " dog" is a token regardless of what follows. GPT-4's pattern also splits numbers into chunks of at most 3 digits, which makes arithmetic more consistent.

### 🖼️ Visual Mental Model

```text
 "Hello world!! It's 12345."
 GPT-4 split: ["Hello", " world", "!!", " It", "'s", " ", "123", "45", "."]
 BPE runs inside each chunk independently
```

### 📐 The Math, Gently
Pair counts are now summed over chunks. Identical chunks can be counted once with a multiplicity, which is a big speedup: `Counter(chunks)`.

### 🛠️ Build It From Scratch

```python
# nanoforge/tokenizer/regex_bpe.py
import regex as re
from collections import Counter
from nanoforge.tokenizer.bpe import BasicBPE, get_pair_counts, merge

GPT2_PATTERN = r"""'(?:[sdmt]|ll|ve|re)| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+"""
GPT4_PATTERN = r"""'(?i:[sdmt]|ll|ve|re)|[^\r\n\p{L}\p{N}]?+\p{L}+|\p{N}{1,3}| ?[^\s\p{L}\p{N}]++[\r\n]*|\s*[\r\n]|\s+(?!\S)|\s+"""

class RegexBPE(BasicBPE):
    def __init__(self, pattern=GPT4_PATTERN):
        super().__init__()
        self.pattern = pattern
        self._re = re.compile(pattern)

    def train(self, text, vocab_size, verbose=False):
        chunk_counts = Counter(self._re.findall(text))                  # unique chunks + multiplicity
        chunks = [list(c.encode("utf-8")) for c in chunk_counts]
        freqs = list(chunk_counts.values())
        for k in range(vocab_size - 256):
            counts = {}
            for ids, f in zip(chunks, freqs):
                for p in zip(ids, ids[1:]):
                    counts[p] = counts.get(p, 0) + f
            if not counts: break
            pair = max(counts, key=lambda p: (counts[p], -p[0], -p[1]))
            new_id = 256 + k
            chunks = [merge(ids, pair, new_id) if len(ids) > 1 else ids for ids in chunks]
            self.merges[pair] = new_id
            self.vocab[new_id] = self.vocab[pair[0]] + self.vocab[pair[1]]
            if verbose and k % 200 == 0:
                print(f"{k}: {self.vocab[new_id]!r} x{counts[pair]}")

    def _encode_chunk(self, b):
        ids = list(b)
        while len(ids) >= 2:
            counts = get_pair_counts(ids)
            pair = min(counts, key=lambda p: self.merges.get(p, float("inf")))
            if pair not in self.merges: break
            ids = merge(ids, pair, self.merges[pair])
        return ids

    def encode_ordinary(self, text):
        out = []
        for chunk in self._re.findall(text):
            out.extend(self._encode_chunk(chunk.encode("utf-8")))
        return out

    def encode(self, text, allowed_special="all"):
        if not self.special_tokens or allowed_special == "none":
            return self.encode_ordinary(text)
        special_pat = "(" + "|".join(re.escape(s) for s in self.special_tokens) + ")"
        out = []
        for part in re.split(special_pat, text):
            if part in self.special_tokens: out.append(self.special_tokens[part])
            elif part: out.extend(self.encode_ordinary(part))
        return out

    def register_special_tokens(self, tokens):
        """tokens: list of strings; assigned ids after the merges."""
        base = 256 + len(self.merges)
        for i, t in enumerate(tokens):
            self.special_tokens[t] = base + i

    def load(self, path):
        super().load(path)
        import json
        with open(path, encoding="utf-8") as f: d = json.load(f)
        if d.get("pattern"): self.pattern = d["pattern"]; self._re = re.compile(self.pattern)
        return self
```

## 15.6 Making It Fast: Incremental Pair Counts and Priority Queues

### 🧭 The Problem First
Our training recounts every pair after every merge: O(merges × corpus). For 50K merges on gigabytes of text, that takes days.

### 💡 Intuition / Instinct
A merge only changes pair counts **near the merged positions**. Keep a global pair-count table plus an index of *which chunks contain each pair*, and update only the affected chunks. Use a max-heap keyed by count to find the best pair in O(log n) (with lazy invalidation of stale entries).

### 🖼️ Visual Mental Model

```text
 merge (t,h)→X in chunk "the":   pairs before (t,h),(h,e)  after (X,e)
 update: count[(t,h)] -= f, count[(h,e)] -= f, count[(X,e)] += f   (only this chunk)
```

### 📐 The Math, Gently
Each merge costs O(occurrences of the pair) instead of O(corpus). Total ≈ O(corpus × average merges touching each position), which is typically 100–1000× faster.

### 🛠️ Build It From Scratch

```python
# nanoforge/tokenizer/fast_train.py
import heapq
from collections import Counter, defaultdict

def train_bpe_fast(chunk_counts: Counter, vocab_size: int):
    """chunk_counts: Counter of pre-tokenized chunks (str). Returns merges dict {(a,b): new_id}."""
    words = [list(w.encode("utf-8")) for w in chunk_counts]
    freqs = list(chunk_counts.values())
    pair_counts = Counter()
    where = defaultdict(set)                                   # pair -> set of word indices
    for wi, (w, f) in enumerate(zip(words, freqs)):
        for p in zip(w, w[1:]):
            pair_counts[p] += f; where[p].add(wi)
    heap = [(-c, p) for p, c in pair_counts.items()]
    heapq.heapify(heap)
    merges = {}
    for k in range(vocab_size - 256):
        while heap:
            negc, p = heapq.heappop(heap)
            if pair_counts.get(p, 0) == -negc and -negc > 0: break   # valid, not stale
        else:
            break
        new_id = 256 + k; merges[p] = new_id
        a, b = p
        for wi in list(where[p]):
            w, f = words[wi], freqs[wi]
            for q in zip(w, w[1:]):                            # remove old pairs of this word
                pair_counts[q] -= f
            i, out = 0, []
            while i < len(w):
                if i < len(w) - 1 and w[i] == a and w[i + 1] == b: out.append(new_id); i += 2
                else: out.append(w[i]); i += 1
            words[wi] = out
            for q in zip(out, out[1:]):                        # add new pairs
                pair_counts[q] += f; where[q].add(wi)
                heapq.heappush(heap, (-pair_counts[q], q))
        del pair_counts[p]; where.pop(p, None)
    return merges
```

```python
import time, regex as re
from collections import Counter
from nanoforge.tokenizer.regex_bpe import GPT4_PATTERN, RegexBPE
from nanoforge.tokenizer.fast_train import train_bpe_fast

t = time.time(); m = train_bpe_fast(cc, 2048); print("fast:", time.time() - t, "s")

print("same merges:", list(m.items())[:50] == list(slow.merges.items())[:50])
```
