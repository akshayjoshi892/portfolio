## 14.1 Recurrence: A Memory That Updates Each Step

### 🧭 The Problem First
The MLP LM has separate weights per position and a fixed window (Ch 12.6). We want a model that shares weights across positions and can, in principle, use unbounded history.

### 💡 Intuition / Instinct
Read like a human: keep a **running summary** (the hidden state h) in your head. At each new character, update the summary using the *same rule*: $h_t = f(h_{t-1}, x_t)$. Then predict the next character from $h_t$. Same weights at every step, unbounded context, constant memory.

### 🖼️ Visual Mental Model

```text
  x1      x2      x3      x4
  │       │       │       │
  ▼       ▼       ▼       ▼
 [f]─h1─▶[f]─h2─▶[f]─h3─▶[f]─h4
  │       │       │       │
  ▼       ▼       ▼       ▼
 ŷ2      ŷ3      ŷ4      ŷ5        (same f, same weights, every step)
```

### 📐 The Math, Gently
$$h_t = \tanh(x_t W_{xh} + h_{t-1}W_{hh} + b_h),\qquad \text{logits}_t = h_t W_{hy} + b_y$$
The parameters are independent of the sequence length.

(See 14.2.)

### 🔬 Experiment & Observe
Before training, predict: will the RNN beat the MLP LM's ~2.0 val loss on Shakespeare? (It should reach ~1.6–1.7 with enough hidden units.)

### ⚠️ Failure Modes & Debugging
The hidden state has to *compress the entire past* into H numbers: a bottleneck.

### 🧠 Expert Insight
Elman (1990) "Finding Structure in Time"; Karpathy's "The Unreasonable Effectiveness of Recurrent Neural Networks" (2015) made char-RNNs famous.

### ✅ Check Your Instinct
1. What does the hidden state represent?

<details><summary>Answers</summary>

1. A fixed-size summary of everything read so far that's useful for prediction.
</details>

### 📌 Recap Card
- $h_t = f(h_{t-1}, x_t)$ with shared weights.
- Unbounded context, constant memory, fixed-size bottleneck.

> **Core intuition:** *An RNN reads one token at a time, carrying a compressed memory forward.*

## 14.2 A Vanilla RNN From Scratch; Backprop Through Time

### 🧭 The Problem First
How do we train a model whose computation loops over time?

### 💡 Intuition / Instinct
**Unroll** the loop over T steps into a long feed-forward graph where the same weights appear T times. Then ordinary backprop applies (Ch 6). Shared weights receive the *sum* of gradients from every time step. This is **backpropagation through time (BPTT)**. For long texts, truncate: unroll only T steps and carry the hidden state forward *detached* (truncated BPTT).

### 🖼️ Visual Mental Model

```text
 forward: h0 → h1 → h2 → ... → hT        (W_hh used T times)
 backward: dL/dW_hh = Σ_t (contribution at step t)   (sum over its T uses)
```

### 📐 The Math, Gently
$\frac{\partial L}{\partial W_{hh}} = \sum_t \frac{\partial L}{\partial h_t}\frac{\partial h_t}{\partial W_{hh}}$, and $\frac{\partial L}{\partial h_t}$ includes contributions from all future steps through $\frac{\partial h_{t+1}}{\partial h_t} = \text{diag}(1 - h_{t+1}^2)\,W_{hh}^\top$.

### 🛠️ Build It From Scratch

```python
# nanoforge/models/rnn.py
import torch, torch.nn as nn, torch.nn.functional as F

class RNNCell(nn.Module):
    def __init__(self, d_in, H):
        super().__init__()
        self.xh = nn.Linear(d_in, H); self.hh = nn.Linear(H, H, bias=False)
        nn.init.orthogonal_(self.hh.weight)                # helps gradient flow
    def forward(self, x, h): return torch.tanh(self.xh(x) + self.hh(h))

class CharRNN(nn.Module):
    def __init__(self, V, d_emb=64, H=512, cell="rnn"):
        super().__init__()
        self.H, self.cell_type = H, cell
        self.emb = nn.Embedding(V, d_emb)
        self.cell = RNNCell(d_emb, H) if cell == "rnn" else LSTMCell(d_emb, H)
        self.head = nn.Linear(H, V)
    def init_state(self, B, device):
        z = torch.zeros(B, self.H, device=device)
        return z if self.cell_type == "rnn" else (z, z.clone())
    def forward(self, idx, targets=None, state=None):     # idx: (B, T)
        B, T = idx.shape
        state = state if state is not None else self.init_state(B, idx.device)
        x = self.emb(idx)                                  # (B, T, d)
        outs = []
        for t in range(T):                                 # the recurrence: inherently sequential
            state = self.cell(x[:, t], state)
            outs.append(state if self.cell_type == "rnn" else state[0])
        hs = torch.stack(outs, 1)                          # (B, T, H)
        logits = self.head(hs)                             # (B, T, V)
        loss = None
        if targets is not None:
            loss = F.cross_entropy(logits.reshape(B * T, -1), targets.reshape(B * T))
        self.last_state = state
        return logits, loss

class LSTMCell(nn.Module):                                 # defined in 14.4
    def __init__(self, d_in, H):
        super().__init__()
        self.W = nn.Linear(d_in + H, 4 * H)
        with torch.no_grad(): self.W.bias[H:2 * H].fill_(1.0)   # forget-gate bias = 1
        self.H = H
    def forward(self, x, state):
        h, c = state
        i, f, g, o = self.W(torch.cat([x, h], -1)).chunk(4, -1)
        i, f, o, g = torch.sigmoid(i), torch.sigmoid(f), torch.sigmoid(o), torch.tanh(g)
        c = f * c + i * g                                  # the "conveyor belt"
        h = o * torch.tanh(c)
        return h, c
```

```python
# scripts/train_rnn.py
import torch
from nanoforge.models.rnn import CharRNN
from nanoforge.data.simple import get_batch
from nanoforge.eval.loss import estimate_loss
from nanoforge.sampling import generate
from nanoforge.utils import set_seed, get_device
set_seed(0); dev = get_device()
text = open("data/raw/shakespeare.txt", encoding="utf-8").read()
chars = sorted(set(text)); V = len(chars); stoi = {c: i for i, c in enumerate(chars)}; itos = {i: c for c, i in stoi.items()}
data = torch.tensor([stoi[c] for c in text]); n = int(0.9 * len(data)); tr, va = data[:n], data[n:]
for cell in ["rnn", "lstm"]:
    model = CharRNN(V, H=512, cell=cell).to(dev)
    opt = torch.optim.AdamW(model.parameters(), lr=2e-3)
    for step in range(3001):
        x, y = get_batch(tr, B=64, T=128, device=dev)
        _, loss = model(x, y)
        opt.zero_grad(); loss.backward()
        gn = torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)     # essential for RNNs
        opt.step()
        if step % 1000 == 0:
            L = estimate_loss(model, {"train": tr, "val": va}, get_batch, eval_iters=20, B=64, T=128, device=dev)
            print(f"{cell} step {step} {L} gradnorm {gn:.2f}")
    s = generate(model, torch.zeros(1, 1, dtype=torch.long, device=dev), 300, block_size=256, temperature=0.8)
    print("".join(itos[i] for i in s[0].tolist()))
```

### 🔬 Experiment & Observe
- The vanilla RNN reaches ~1.7 val loss; the LSTM ~1.55. Both beat the MLP LM (~2.0).
- Time per step vs the MLP LM: the Python loop over T is *slow*, and it can't be parallelized over time.

### ⚠️ Failure Modes & Debugging
- Without gradient clipping, the loss suddenly spikes to NaN (exploding gradients).
- Carrying the state across batches without `.detach()` makes backprop go back through *all* history → memory explosion and "trying to backward through the graph a second time".

### 🧠 Expert Insight
Werbos (1990) BPTT. cuDNN's fused RNN kernels make recurrence faster, but they're still sequential in T, and that is the fundamental limit.

### ✅ Check Your Instinct
1. Why must shared-weight gradients be summed?
2. Why is gradient clipping crucial here?

<details><summary>Answers</summary>

1. The weight appears at every step (multiple paths → sum).
2. Repeated multiplication by $W_{hh}$ can make gradients explode.
</details>

### 📌 Recap Card
- Unroll + backprop = BPTT.
- Truncate and detach the state for long streams.
- Clip gradients.

> **Core intuition:** *Unroll the loop, and recurrence is just a very deep network with shared weights.*

## 14.3 Vanishing and Exploding Gradients, Felt on Real Numbers

### 🧭 The Problem First
The RNN *can* use long context in theory. In practice, it forgets anything beyond ~10–20 steps. Why?

### 💡 Intuition / Instinct
The gradient from step t+k back to step t passes through k copies of the Jacobian $\text{diag}(\tanh')\,W_{hh}^\top$. If its largest singular value is below 1, the signal shrinks exponentially (vanishes); above 1, it grows exponentially (explodes). Long-range credit assignment dies either way. It is the Ch 4.3 chain-of-multiplications problem, in time.

### 🖼️ Visual Mental Model

```text
 ||∂L/∂h_t|| for t going back in time:
 σ_max=0.9:  1.0  0.35  0.12  0.04  ...  (vanishes: the model can't learn long dependencies)
 σ_max=1.1:  1.0  2.6   6.7   17    ...  (explodes: training unstable → clip)
```

### 📐 The Math, Gently
$\left\|\frac{\partial h_{t+k}}{\partial h_t}\right\| \le \prod_{j}\|\text{diag}(1 - h_j^2)\|\,\|W_{hh}\| \le \sigma_{max}(W_{hh})^k$.
Example: σ = 0.9 and k = 50 give $0.9^{50} ≈ 0.005$.

### 🛠️ Build It From Scratch

```python
import torch
torch.manual_seed(0)
H, T = 128, 100
for scale in [0.5, 0.9, 1.0, 1.1, 1.5]:
    W = torch.nn.init.orthogonal_(torch.empty(H, H)) * scale
    h0 = torch.zeros(1, H, requires_grad=True); h = h0; hs = []
    for t in range(T):
        h = torch.tanh(h @ W + 0.1 * torch.randn(1, H)); hs.append(h)
    hs[-1].sum().backward()
    print(f"scale {scale}: |dL/dh0| = {h0.grad.norm():.2e}")
```

### 🔬 Experiment & Observe
Build a synthetic "copy" task: the first token is a random digit, then 50 noise tokens, then the model must output the first digit. The vanilla RNN fails (chance accuracy); the LSTM succeeds more often. That is long-range memory tested directly.

### ⚠️ Failure Modes & Debugging
Clipping fixes explosion, **not** vanishing. Vanishing requires architectural changes (gates, residuals, attention).

### 🧠 Expert Insight
**Hochreiter (1991)** (diploma thesis) and **Bengio, Simard & Frasconi (1994)** identified the problem. **Pascanu et al. (2013)** analyzed it and popularized gradient clipping.

### ✅ Check Your Instinct
1. Does clipping solve vanishing gradients?
2. Why orthogonal init for $W_{hh}$?

<details><summary>Answers</summary>

1. No, only explosion.
2. All its singular values are 1, so it preserves norms (at least initially).
</details>

### 📌 Recap Card
- Gradients through time multiply Jacobians → exponential vanish/explode.
- Clip for explosion; change the architecture for vanishing.

> **Core intuition:** *A signal passed through a hundred hands arrives either as a whisper or a scream.*

## 14.4 LSTM/GRU Gates as Learned Valves

### 🧭 The Problem First
We need a memory that can hold information for hundreds of steps *without* the gradient vanishing.

### 💡 Intuition / Instinct
The LSTM adds a **cell state** c, a conveyor belt where information is modified only by *addition* and gated *multiplication* ($c_t = f\odot c_{t-1} + i\odot g$). Three learned valves:
- **forget gate f:** how much old memory to keep;
- **input gate i:** how much new information to write;
- **output gate o:** how much memory to expose.

If f ≈ 1 and i ≈ 0, the cell carries information unchanged indefinitely, and gradients flow back along it without shrinking. It is the same trick as residual connections (Ch 10.3), invented 18 years earlier.

The **GRU** simplifies this to two gates (update, reset) with no separate cell.

### 🖼️ Visual Mental Model

```text
 c_{t-1} ──(×f)──(+)────────────▶ c_t ──tanh──(×o)──▶ h_t
                  ▲
          i ⊙ g (new candidate)
```

### 📐 The Math, Gently
$[i, f, g, o] = [x_t; h_{t-1}]W + b$; $i, f, o = \sigma(\cdot)$; $g = \tanh(\cdot)$;
$c_t = f\odot c_{t-1} + i\odot g$; $h_t = o\odot\tanh(c_t)$.
$\partial c_t/\partial c_{t-1} = \text{diag}(f)$: if f ≈ 1, the gradient survives.
Forget-gate bias init = 1 → σ(1) = 0.73: remember by default (Jozefowicz et al., 2015).

### 🛠️ Build It From Scratch
`LSTMCell` is already in `nanoforge/models/rnn.py` (14.2). Verify it against `nn.LSTMCell` by copying the weights (PyTorch's gate order is i, f, g, o; the same as ours).

```python
import torch
from nanoforge.models.rnn import LSTMCell
torch.manual_seed(0)
d, H = 8, 16
mine, ref = LSTMCell(d, H), torch.nn.LSTMCell(d, H)
with torch.no_grad():
    ref.weight_ih.copy_(mine.W.weight[:, :d]); ref.weight_hh.copy_(mine.W.weight[:, d:])
    ref.bias_ih.copy_(mine.W.bias); ref.bias_hh.zero_()
x, h, c = torch.randn(4, d), torch.randn(4, H), torch.randn(4, H)
h1, c1 = mine(x, (h, c)); h2, c2 = ref(x, (h, c))
print(torch.allclose(h1, h2, atol=1e-6), torch.allclose(c1, c2, atol=1e-6))
```

### 🔬 Experiment & Observe
Run the copy task with gaps of 10, 50, 100 for RNN vs LSTM. The LSTM handles far longer gaps. Log the mean forget-gate values: they go toward 1 on the "memory" units.

### ⚠️ Failure Modes & Debugging
- A forget bias of 0 leads to faster forgetting and slower learning.
- Gate order mismatches when loading pretrained weights.

### 🧠 Expert Insight
**Hochreiter & Schmidhuber (1997), LSTM.** **Cho et al. (2014), GRU.** LSTMs powered Google Translate (2016) and ELMo (2018). **xLSTM (Beck et al., 2024)** revisits the LSTM with exponential gating and matrix memory, competitive with transformers at moderate scale.

### ✅ Check Your Instinct
1. Why does the cell state preserve gradients?
2. What does the output gate control?

<details><summary>Answers</summary>

1. Its update is additive with a multiplicative forget factor near 1, so $\partial c_t/\partial c_{t-1} ≈ I$.
2. How much of the cell is revealed to the hidden state/output.
</details>

### 📌 Recap Card
- Additive cell state + learned gates.
- Forget ≈ 1 → long memory, stable gradients.
- Init the forget bias to 1.

> **Core intuition:** *Gates learn when to remember, when to write, and when to speak.*

## 14.5 Why Recurrence Lost: Sequential Bottlenecks and Long-Range Problems

### 🧭 The Problem First
LSTMs worked. Why did the field abandon them for transformers almost overnight after 2017?

### 💡 Intuition / Instinct
Three decisive problems:
1. **No parallelism over time:** step t needs step t−1. GPUs are idle while the loop runs. Transformers process all T positions at once in training.
2. **Fixed-size bottleneck:** the whole past must be squeezed into H numbers. Attention can look directly at *any* past token at full resolution.
3. **Long paths:** information from 500 tokens ago has to survive 500 updates. In attention the path length is **1**.

The trade-off: attention costs O(T²) compute and a KV cache that grows with T (Ch 30), while an RNN has O(1) memory per step at inference. That trade-off is exactly why SSMs/Mamba (Ch 34) are trying to bring recurrence back.

### 🖼️ Visual Mental Model

```text
                      RNN/LSTM            Transformer
 training parallelism  O(T) sequential     O(1) sequential steps (parallel)
 path length t→t+k     k                   1
 memory at inference   O(1) state          O(T) KV cache
 compute per sequence  O(T·H²)             O(T²·C + T·C²)
```

### 📐 The Math, Gently
Sequential operations per layer: RNN O(T), attention O(1) (Vaswani et al., 2017, Table 1). With T = 1024 on a GPU, that's 1024 dependent small matmuls vs a few big ones.

### 🛠️ Build It From Scratch

```python
import time, torch
from nanoforge.models.rnn import CharRNN
dev = "cuda" if torch.cuda.is_available() else "cpu"
m = CharRNN(65, H=512, cell="lstm").to(dev)
for T in [64, 256, 1024]:
    x = torch.randint(0, 65, (32, T), device=dev)
    t0 = time.time(); m(x, x)[1].backward()
    if dev == "cuda": torch.cuda.synchronize()
    print(f"T={T}: {time.time() - t0:.3f}s per step")   # grows ~linearly; transformer is far flatter (Ch 20)
```

### 🔬 Experiment & Observe
In Ch 20, repeat this timing with your GPT. At T = 1024 the transformer step is much faster on a GPU, despite doing *more* FLOPs, because the work is parallel.

### ⚠️ Failure Modes & Debugging
"My LSTM is slow on GPU": that's expected; recurrence is latency-bound. Use the cuDNN `nn.LSTM` for speed if you must.

### 🧠 Expert Insight
- **Vaswani et al. (2017), "Attention Is All You Need":** Table 1 is exactly this comparison.
- **Gu & Dao (2023), Mamba:** recurrence with *parallel scan* training and a selective (input-dependent) state, which removes problem 1 and eases problem 2 (Ch 34).

### ✅ Check Your Instinct
1. Name the three reasons transformers won.
2. What is the RNN's advantage at inference?

<details><summary>Answers</summary>

1. Training parallelism, no fixed bottleneck (direct access), path length 1.
2. Constant memory and compute per generated token.
</details>

### 📌 Recap Card
- RNNs: sequential, bottlenecked, long paths.
- Transformers: parallel, direct access, but O(T²) and a growing cache.
- Modern SSMs revisit recurrence with parallel training.

> **Core intuition:** *Recurrence summarizes the past; attention re-reads it. Re-reading won, for now.*
