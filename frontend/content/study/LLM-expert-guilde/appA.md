# Appendix A — Glossary

> Each entry gives a short definition and the chapter(s) where the idea is developed. Terms are alphabetical; symbols and numbers come first.

---

### Symbols & numbers

- **6ND** — The approximate number of training FLOPs for a dense transformer with N parameters trained on D tokens (2ND forward, 4ND backward). (Ch 19.6, 26.3)
- **α (LoRA alpha)** — Scaling hyperparameter for a LoRA update; the update is multiplied by α/r. (Ch 38.2)
- **β (DPO/KL coefficient)** — Strength of the penalty that keeps a policy close to its reference model. (Ch 39.4, 40.1)
- **τ (temperature)** — Divisor applied to logits before the softmax; higher values flatten the distribution. (Ch 13.2, 42.2, 46.2)
- **√d scaling** — Dividing attention scores by the square root of the head dimension to keep their variance near 1. (Ch 17.3)

### A

- **Ablation** — Removing or disabling a component to measure its causal contribution. (Ch 20.6, 48.3)
- **Absmax quantization** — Symmetric quantization where the scale is set by the largest absolute value. (Ch 38.4, 44.1)
- **Accumulation (gradient)** — Summing gradients over several micro-batches before one optimizer step, to emulate a larger batch. (Ch 24.4)
- **Activation** — The output of a layer or nonlinearity for a given input; also the nonlinearity itself (ReLU, GELU…). (Ch 9.3)
- **Activation checkpointing** — Recomputing activations during the backward pass instead of storing them, trading compute for memory. (Ch 28.4)
- **Activation steering** — Adding a direction to the residual stream at inference time to change behaviour. (Ch 48.5)
- **Adafactor** — A memory-efficient optimizer that factorizes second-moment estimates. (Ch 8.8)
- **Adam** — Optimizer combining momentum with per-parameter adaptive step sizes and bias correction. (Ch 8.5)
- **AdamW** — Adam with weight decay decoupled from the gradient update. (Ch 8.6)
- **Advantage** — How much better an action was than expected; the signal policy-gradient methods weight updates by. (Ch 39.4, 41.2)
- **Agent** — A model running in a loop that chooses actions (tool calls), observes results and continues toward a goal. (Ch 47.2)
- **ALiBi** — Attention with Linear Biases: a position method that adds a distance-proportional penalty to attention scores. (Ch 18.6)
- **All-reduce** — Collective operation that sums (or averages) tensors across devices and gives every device the result. (Ch 31.1)
- **Alignment** — Training a model to behave according to intended goals and values (helpful, honest, harmless). (Ch 37–42)
- **Arithmetic intensity** — FLOPs performed per byte of memory moved; determines whether an operation is compute- or memory-bound. (Ch 28.2, 43.1)
- **Attention** — A mechanism where each position computes a weighted average of other positions' values, with weights from query–key similarity. (Ch 17)
- **Attention sink** — A token (usually the first) that receives large attention weight while contributing little, acting as a no-op target. (Ch 47.3)
- **Autocast** — Automatic execution of selected operations in lower precision (fp16/bf16) during mixed-precision training. (Ch 25.2)
- **Autograd** — Automatic differentiation: computing gradients by recording operations and applying the chain rule backward. (Ch 6)
- **Autoregressive** — Generating a sequence one element at a time, each conditioned on all previous elements. (Ch 1.1, 11.1)
- **AWQ** — Activation-aware Weight Quantization: scales salient input channels before quantizing weights. (Ch 44.4)

### B

- **Backpropagation** — Computing gradients of a loss with respect to all parameters by applying the chain rule backward through the computation graph. (Ch 4.4, 6.2)
- **Backprop through time (BPTT)** — Backpropagation unrolled across the time steps of a recurrent network. (Ch 14.2)
- **Batch size** — Number of sequences (or tokens) processed per optimizer step. (Ch 8.2, 26.5)
- **BatchNorm** — Normalization using statistics across the batch dimension; ill-suited to variable-length sequences. (Ch 10.1)
- **Beam search** — Decoding that keeps the k most probable partial sequences at each step. (Ch 13.4)
- **BF16 (bfloat16)** — 16-bit float with fp32's exponent range and a short mantissa; the default training precision on modern GPUs. (Ch 25.1)
- **Bias correction** — Adam's rescaling of moment estimates to remove their bias toward zero in early steps. (Ch 8.5)
- **Bias–variance trade-off** — The tension between underfitting (high bias) and overfitting (high variance). (Ch 10.5)
- **Bigram model** — A model predicting the next token from only the current token. (Ch 11.2)
- **Bits per byte (bpb)** — Cross-entropy normalized per byte of text; comparable across tokenizers. (Ch 35.1)
- **Block table** — Per-sequence list mapping logical KV positions to physical cache blocks in PagedAttention. (Ch 45.2)
- **BM25** — A classic lexical relevance score based on term frequency, inverse document frequency and length normalization. (Ch 46.3)
- **BOS / EOS** — Special tokens marking the beginning and end of a sequence. (Ch 16.3)
- **BPE (Byte-Pair Encoding)** — Tokenization that repeatedly merges the most frequent adjacent pair of symbols. (Ch 15.3)
- **Bradley–Terry model** — A model of pairwise preferences: P(A beats B) = σ(r_A − r_B). (Ch 36.2, 39.1)
- **Broadcasting** — NumPy/PyTorch rules for combining arrays of different shapes by virtually expanding size-1 dimensions. (Ch 2.2)
- **Byte-level BPE** — BPE over raw UTF-8 bytes, so any string can be encoded without unknown tokens. (Ch 16.1)

### C

- **Calibration (quantization)** — Running sample data through a model to collect statistics for choosing quantization parameters. (Ch 44.3–44.4)
- **Calibration (probabilistic)** — Agreement between predicted confidence and actual accuracy. (Ch 7, 36)
- **Capacity factor** — In MoE, the maximum number of tokens each expert may process relative to an even split. (Ch 33.3)
- **Catastrophic forgetting** — Loss of previously learned abilities when training on new data. (Ch 37.4)
- **Causal mask** — Mask preventing positions from attending to later positions. (Ch 17.4)
- **Chain rule (calculus)** — The derivative of a composition is the product of local derivatives. (Ch 4.3)
- **Chain rule (probability)** — A joint probability factorizes into a product of conditionals; the basis of language modeling. (Ch 11.1)
- **Chain-of-thought (CoT)** — Intermediate reasoning text generated before a final answer. (Ch 41.4)
- **Chat template** — The exact token format for roles and turns in a conversation. (Ch 37.2)
- **Checkpoint** — A saved snapshot of model, optimizer, scheduler, RNG and data state. (Ch 25.3)
- **Chinchilla scaling** — The finding that compute-optimal training uses roughly 20 tokens per parameter. (Ch 26.2)
- **Chunked prefill** — Splitting a long prompt's prefill into pieces interleaved with decode steps. (Ch 43.1, 45.1)
- **Chunking (RAG)** — Splitting documents into passages for indexing and retrieval. (Ch 46.2)
- **Circuit** — A verified subnetwork implementing a specific computation. (Ch 48.3)
- **Clipping (gradient)** — Rescaling gradients whose norm exceeds a threshold. (Ch 24.3)
- **Clipping (PPO)** — Limiting the policy ratio to [1−ε, 1+ε] in the objective to keep updates small. (Ch 39.4)
- **Common Crawl** — A large public web crawl used as the base of most pretraining corpora. (Ch 21.1)
- **Compute-bound** — Limited by arithmetic throughput rather than memory bandwidth. (Ch 28.2)
- **Constitutional AI** — Alignment using written principles for self-critique and AI-generated preferences. (Ch 42.3)
- **Constrained decoding** — Masking invalid tokens so outputs follow a grammar or format. (Ch 43.3)
- **Contamination** — Evaluation data appearing in training data, inflating scores. (Ch 35.4)
- **Context window** — Maximum number of tokens a model processes at once. (Ch 20.1, 32.2)
- **Continuous batching** — Scheduling that adds and removes sequences from the batch at every decode step. (Ch 45.1)
- **Contrastive loss (InfoNCE)** — A loss that pulls matched pairs together and pushes other pairs apart. (Ch 46.2)
- **Control task** — A probing baseline with random labels per token type, used to measure probe selectivity. (Ch 48.2)
- **Critic (value model)** — A network estimating expected return, used to compute advantages. (Ch 39.4)
- **Cross-attention** — Attention where queries come from one sequence and keys/values from another. (Ch 17.6)
- **Cross-encoder** — A model that reads query and passage together to score relevance. (Ch 46.3)
- **Cross-entropy** — Expected negative log-probability of the true distribution under the model; the LM training loss. (Ch 5.5, 7.3)
- **CUDA graph** — A recorded sequence of GPU kernels replayed with a single launch to cut overhead. (Ch 29.3)
- **Curse of dimensionality (context)** — The exponential growth of n-gram tables with context length. (Ch 11.5)

### D

- **Data parallelism (DDP)** — Replicating the model on every device and splitting the batch across them. (Ch 31.1)
- **Dead neuron** — A ReLU unit that never activates, so it never receives gradient. (Ch 9.3)
- **Decode (phase)** — Token-by-token generation after the prompt; memory-bound. (Ch 43.1)
- **Deduplication** — Removing exact or near-duplicate documents from a corpus. (Ch 21.5)
- **Dense retrieval** — Retrieval by similarity of learned embedding vectors. (Ch 46.2)
- **Distillation** — Training a student model to imitate a teacher's outputs or distributions. (Ch 42.2)
- **Document masking** — Preventing attention across document boundaries in packed sequences. (Ch 23.4)
- **DoRA** — Weight-decomposed LoRA: separates magnitude and direction of weight updates. (Ch 38.4)
- **DoReMi** — A method that learns domain mixture weights using a proxy model. (Ch 22.5)
- **Double descent** — Test error falling, rising, then falling again as model size or training grows. (Ch 10.5)
- **DPO (Direct Preference Optimization)** — Preference tuning with a closed-form loss derived from the RLHF objective, without a reward model. (Ch 40)
- **Draft model** — A small model proposing tokens for speculative decoding. (Ch 43.2)
- **Dropout** — Randomly zeroing activations during training as regularization. (Ch 10.4)

### E

- **Early stopping** — Halting training when validation performance stops improving. (Ch 10.6)
- **Einsum** — Einstein-summation notation for expressing tensor contractions. (Ch 2.4)
- **Embedding** — A learned vector representing a token (or text) as coordinates of meaning. (Ch 12.2)
- **Entropy** — Expected surprise of a distribution, in bits or nats. (Ch 5.4)
- **Epoch** — One full pass over the training data. (Ch 27.4)
- **Evaluation harness** — A fixed, versioned pipeline for running all evals the same way on every checkpoint. (Ch 36.3)
- **Expert (MoE)** — One of several parallel feed-forward networks selected by a router. (Ch 33.1)

### F

- **Faithfulness (RAG)** — Whether every claim in an answer is supported by the retrieved sources. (Ch 46.4)
- **Feature (interpretability)** — A direction in activation space corresponding to an interpretable concept. (Ch 48.4)
- **FFN (feed-forward network)** — The per-position MLP inside each transformer block. (Ch 19.3)
- **Fine-tuning** — Continuing training of a pretrained model on new data. (Ch 37)
- **FlashAttention** — An exact attention algorithm that tiles computation in fast on-chip memory to avoid materializing the attention matrix. (Ch 29.2)
- **FLOP / FLOPs** — A floating-point operation / a count of them (FLOP/s for throughput). (Ch 19.6, 28.2)
- **FP8** — 8-bit floating-point formats (E4M3, E5M2) for training and inference on recent GPUs. (Ch 25.1, 44.2)
- **FSDP** — Fully Sharded Data Parallel: shards parameters, gradients and optimizer states across devices. (Ch 31.2)
- **Function calling** — A model emitting structured requests for a runtime to execute tools. (Ch 47.1)

### G

- **GAE** — Generalized Advantage Estimation: an exponentially weighted mix of TD errors. (Ch 39.4)
- **Gated activation (GLU)** — An activation where one projection gates another elementwise. (Ch 9.4)
- **GELU** — Gaussian Error Linear Unit, a smooth ReLU-like activation. (Ch 9.3)
- **Glitch token** — A token that was rare or absent in training, causing strange behaviour. (Ch 16.6)
- **Goodput** — The request rate a server sustains while meeting its latency SLOs. (Ch 45.3)
- **GPTQ** — Post-training quantization that rounds weights column by column with second-order error compensation. (Ch 44.4)
- **GQA (Grouped-Query Attention)** — Attention where groups of query heads share key/value heads. (Ch 30.3)
- **Gradient** — The vector of partial derivatives; points in the direction of steepest ascent. (Ch 4.2)
- **Gradient check** — Comparing analytic gradients with finite-difference estimates. (Ch 4.5)
- **Gradient noise scale** — A measure of gradient variance that suggests the critical batch size. (Ch 26.5)
- **Greedy decoding** — Always picking the most probable next token. (Ch 13.1)
- **GRPO** — Group Relative Policy Optimization: policy gradients with advantages normalized within a group of samples, no critic. (Ch 41.2)
- **GRU** — Gated Recurrent Unit, a simplified gated RNN. (Ch 14.4)
- **GGUF** — The single-file model format used by llama.cpp, with metadata and block-quantized tensors. (Ch 44.5)

### H

- **Hallucination** — Fluent output not supported by facts or sources. (Ch 46.1)
- **Hard negative** — A retrieval negative that looks relevant but isn't; improves contrastive training. (Ch 46.2)
- **Head (attention)** — One of several parallel attention computations with its own projections. (Ch 18.1)
- **Hessian** — Matrix of second derivatives; in GPTQ, the layer-wise matrix 2XXᵀ. (Ch 4.6, 44.4)
- **HBM** — High-bandwidth memory: the GPU's main memory. (Ch 28.1)
- **HNSW** — A graph-based approximate nearest-neighbour index. (Ch 46.2)
- **Hybrid retrieval** — Combining lexical (BM25) and dense retrieval. (Ch 46.3)
- **Hyperparameter** — A setting chosen rather than learned (LR, batch size, depth…). (Ch 26.5)

### I

- **IDF** — Inverse document frequency: rarer terms get higher weight. (Ch 46.3)
- **In-context learning** — Learning a task from examples in the prompt without weight updates. (Ch 48.3)
- **Induction head** — An attention head that completes [A][B]…[A] → [B] by copying from earlier context. (Ch 48.3)
- **Inference** — Running a trained model to produce outputs. (Ch 1.3, 43)
- **Initialization** — The choice of initial parameter values (Xavier, Kaiming, scaled residual). (Ch 9.2, 20.3)
- **Instruction hierarchy** — Training a model to prioritize system over user over tool instructions. (Ch 42.4)
- **INT4 / INT8** — 4- and 8-bit integer formats for quantized weights or activations. (Ch 44.2)
- **IVF index** — Inverted-file ANN index: cluster vectors, then search only the nearest clusters. (Ch 46.2)

### J–K

- **Jacobian** — Matrix of partial derivatives of a vector function. (Ch 4.4)
- **Jailbreak** — An input crafted to bypass a model's safety behaviour. (Ch 42.4)
- **Kaiming (He) initialization** — Variance-preserving init for ReLU-family activations. (Ch 9.2)
- **Kernel (GPU)** — A function executed on the GPU; fused kernels combine several operations. (Ch 29.1)
- **Kernel fusion** — Merging operations into one kernel to avoid memory round trips. (Ch 29.1)
- **KL divergence** — The expected extra log-loss of using one distribution in place of another; asymmetric. (Ch 5.5)
- **KTO** — Kahneman–Tversky Optimization: preference tuning from unpaired good/bad labels. (Ch 40.3)
- **KV cache** — Stored keys and values of past tokens, reused during generation. (Ch 30.1)

### L

- **Label smoothing** — Mixing the target one-hot with a uniform distribution. (Ch 7.3, 40.1)
- **Latency** — Time for a request or token: see TTFT and TPOT. (Ch 45.3)
- **Layer** — One transformer block, or more generally one stage of a network. (Ch 19)
- **LayerNorm** — Normalization across features of each position, with learned scale and shift. (Ch 10.2)
- **Learning rate** — The step size of gradient descent. (Ch 8.1)
- **Learning-rate schedule** — How the LR changes over training (warmup, cosine, WSD). (Ch 24.2)
- **Likelihood** — Probability of observed data under model parameters. (Ch 5.3)
- **Linear attention** — Attention approximations that avoid the quadratic T×T matrix via kernel feature maps. (Ch 34.1)
- **Linear probe** — A linear classifier trained on internal activations to test what information they contain. (Ch 48.2)
- **LLM-as-judge** — Using a language model to grade or compare outputs. (Ch 36.2)
- **LLM.int8()** — Mixed-precision INT8 matmul that keeps outlier channels in fp16. (Ch 44.3)
- **Logit** — An unnormalized score; softmax turns logits into probabilities. (Ch 5.2)
- **Logit lens** — Reading intermediate residual streams through the final norm and unembedding. (Ch 48.2)
- **Log-sum-exp trick** — Subtracting the max before exponentiating for numerical stability. (Ch 7.4)
- **Long context** — Techniques for handling sequences beyond the training length (RoPE scaling, windows, memory). (Ch 32.2, 47.3)
- **LoRA** — Low-Rank Adaptation: training a small low-rank update instead of full weights. (Ch 38)
- **Loss landscape** — The loss as a function of parameters: minima, saddles, flat vs sharp regions. (Ch 4.6)
- **Loss masking** — Excluding some tokens (e.g. prompts, tool results) from the loss. (Ch 37.2, 47.1)
- **Loss scaling** — Multiplying the loss to prevent fp16 gradient underflow. (Ch 25.2)
- **Loss spike** — A sudden jump in training loss, often an instability. (Ch 27.2)
- **LSTM** — Long Short-Term Memory: a gated RNN with a separate cell state. (Ch 14.4)

### M

- **Mamba** — A state-space model with input-dependent (selective) parameters. (Ch 34.2)
- **Maximum likelihood (MLE)** — Choosing parameters that maximize the probability of the data. (Ch 5.3)
- **Medusa** — Extra decoding heads that predict several future tokens for self-speculation. (Ch 43.3)
- **Memory-bound** — Limited by memory bandwidth rather than compute. (Ch 28.2, 43.1)
- **MFU** — Model FLOPs Utilization: achieved model FLOP/s divided by hardware peak. (Ch 24.5)
- **MinHash** — A hashing scheme that estimates Jaccard similarity for near-duplicate detection. (Ch 21.5)
- **Min-p sampling** — Keeping tokens whose probability is at least a fraction of the top token's. (Ch 13.4)
- **Mixed precision** — Training with low-precision compute and higher-precision master weights/accumulators. (Ch 25.2)
- **Mixture of Experts (MoE)** — Layers with many experts where a router activates only a few per token. (Ch 33)
- **MLP** — Multi-layer perceptron: stacked linear layers and nonlinearities. (Ch 7.2)
- **Model card** — Documentation of a model's intended use, training, evaluation and limitations. (Ch 50.4)
- **Model collapse** — Degradation from recursively training on generated data; tails vanish first. (Ch 42.1)
- **Momentum** — Accumulating a moving average of gradients to smooth and accelerate optimization. (Ch 8.3)
- **MQA (Multi-Query Attention)** — All query heads share one key/value head. (Ch 30.3)
- **MRR** — Mean Reciprocal Rank of the first relevant result. (Ch 46.4)
- **µP (Maximal Update Parametrization)** — A parametrization that keeps optimal hyperparameters stable across widths. (Ch 26.6)
- **Multi-head attention (MHA)** — Several attention heads in parallel, concatenated and projected. (Ch 18)
- **Muon** — An optimizer that orthogonalizes momentum updates for matrix parameters. (Ch 8.8)

### N

- **N-gram** — A sequence of n tokens; n-gram models predict from the previous n−1 tokens. (Ch 11.5)
- **Nats** — Units of information using the natural logarithm (1 nat ≈ 1.44 bits). (Ch 5.4)
- **NF4** — 4-bit NormalFloat: quantization levels at quantiles of a normal distribution. (Ch 38.4)
- **Normalization** — Rescaling activations to stabilize training (BatchNorm, LayerNorm, RMSNorm). (Ch 10)
- **Nucleus sampling** — See top-p sampling. (Ch 13.3)

### O

- **Off-policy / on-policy** — Training on data from a different policy vs the current one. (Ch 39–41, 50.3)
- **One-hot vector** — A vector with a single 1 marking a category. (Ch 12.1)
- **Online softmax** — Computing softmax incrementally over blocks with running max and sum. (Ch 29.2)
- **Optimizer state** — Per-parameter buffers (e.g. Adam's moments) that must be stored and checkpointed. (Ch 8.5, 28.3)
- **ORPO** — Odds-Ratio Preference Optimization: combines SFT and preference loss without a reference model. (Ch 40.3)
- **Outlier features** — Systematic large-magnitude activation channels in large transformers. (Ch 44.3)
- **Overfitting** — Fitting training data at the expense of generalization. (Ch 10.5)
- **Over-refusal** — Declining benign requests because they superficially resemble harmful ones. (Ch 42.3)
- **Overtraining** — Training beyond compute-optimal tokens per parameter to get a smaller model for inference. (Ch 26, 50.1)

### P

- **Packing** — Concatenating documents into fixed-length training sequences. (Ch 23.4)
- **PagedAttention** — Managing the KV cache in fixed-size blocks with per-sequence block tables. (Ch 45.2)
- **Parameter** — A learned number in the model (weights, biases, embeddings). (Ch 1.3)
- **Parquet** — A columnar file format for tabular data. (Ch 23.1)
- **pass@k** — Probability that at least one of k samples solves a problem. (Ch 35.3)
- **Perplexity** — exp(cross-entropy): the effective number of choices per token. (Ch 5.6)
- **PII** — Personally identifiable information; detected and redacted in data pipelines. (Ch 22.3)
- **Pipeline parallelism** — Splitting layers across devices and streaming micro-batches through them. (Ch 31.4)
- **Policy** — In RL, the model's distribution over actions (tokens) given a state (context). (Ch 39.3)
- **Policy gradient** — Updating a policy in the direction that increases expected reward. (Ch 39.3)
- **Positional encoding** — Information added so attention can distinguish token order. (Ch 18.3–18.6)
- **Post-norm / pre-norm** — Normalization after vs before each sublayer's residual addition. (Ch 19.2)
- **Post-training** — Everything after pretraining: SFT, preference tuning, RL. (Ch 37–42)
- **PPO** — Proximal Policy Optimization: clipped policy-gradient RL used in classic RLHF. (Ch 39.4)
- **Preemption** — Temporarily removing a running sequence to free KV memory. (Ch 45.2)
- **Prefill** — Processing the prompt in one parallel forward pass; compute-bound. (Ch 43.1)
- **Prefix caching** — Reusing KV-cache blocks for shared prompt prefixes. (Ch 45.2)
- **Pretraining** — Large-scale next-token training on broad text. (Ch 24–27)
- **Prompt injection** — Instructions hidden in untrusted content that try to hijack a model. (Ch 42.4, 47.2)
- **Prompt lookup decoding** — Speculating tokens by copying n-gram continuations from the context. (Ch 43.3)
- **PTQ / QAT** — Post-training quantization vs quantization-aware training. (Ch 44.1)

### Q

- **QK-norm** — Normalizing queries and keys before the dot product to prevent logit growth. (Ch 27.3)
- **QLoRA** — LoRA on top of a 4-bit (NF4) quantized frozen base model. (Ch 38.4)
- **Quantization** — Representing values with fewer bits by mapping them onto a grid. (Ch 44)
- **Query, key, value (Q, K, V)** — The three projections in attention: what I seek, what I offer, what I give. (Ch 17.2)

### R

- **RAG** — Retrieval-Augmented Generation: retrieving documents and conditioning generation on them. (Ch 46)
- **Rank (matrix)** — The dimension of a matrix's column space. (Ch 3.5)
- **Recall@k** — Fraction of queries with a relevant item in the top k results. (Ch 46.4)
- **Red-teaming** — Systematically attacking a model to find failures. (Ch 42.4)
- **Regression gate** — A check that blocks a new checkpoint if evals regress significantly. (Ch 50.3)
- **Rejection sampling (fine-tuning)** — Sampling many outputs, keeping the good ones, and training on them. (Ch 41.3)
- **ReLU** — max(0, x). (Ch 9.3)
- **Repetition penalty** — Reducing logits of tokens already generated. (Ch 13.4)
- **Reranker** — A second-stage model that reorders retrieved candidates. (Ch 46.3)
- **Residual connection** — Adding a sublayer's input to its output, x + f(x). (Ch 10.3)
- **Residual stream** — The running sum of all block outputs that layers read from and write to. (Ch 19.4)
- **Reward hacking** — A policy exploiting flaws in the reward signal. (Ch 39.5)
- **Reward model** — A model scoring outputs by predicted human preference. (Ch 39.2)
- **RLHF** — Reinforcement Learning from Human Feedback. (Ch 39)
- **RLVR** — RL with verifiable rewards (programs check correctness). (Ch 41.1)
- **RMSNorm** — Normalization by root-mean-square only (no mean subtraction, no bias). (Ch 10.2)
- **RNN** — Recurrent neural network: a hidden state updated at each time step. (Ch 14)
- **Roofline model** — Performance bound set by min(peak compute, bandwidth × arithmetic intensity). (Ch 28.2)
- **RoPE** — Rotary Position Embedding: rotating queries and keys by position-dependent angles. (Ch 18.5)
- **RoPE scaling** — Methods (PI, NTK, YaRN) for extending RoPE beyond the training length. (Ch 32.2)
- **Router** — The gating network that assigns tokens to experts in MoE. (Ch 33.2)
- **RRF** — Reciprocal Rank Fusion of several ranked lists. (Ch 46.3)
- **RTN** — Round-to-nearest quantization without error compensation. (Ch 44.4)

### S

- **SAE (sparse autoencoder)** — An overcomplete autoencoder with a sparsity penalty, used to find interpretable features. (Ch 48.4)
- **Sampling** — Drawing the next token from the model's distribution. (Ch 13)
- **Scaled dot-product attention** — softmax(QKᵀ/√d)V. (Ch 17.3)
- **Scaling law** — A power-law relationship between loss and parameters, data or compute. (Ch 26)
- **Selective scan** — Mamba's input-dependent recurrent computation. (Ch 34.2)
- **Self-attention** — Attention where queries, keys and values come from the same sequence. (Ch 17.6)
- **Self-instruct** — Generating instruction data by prompting a model with seed tasks. (Ch 37.3)
- **Sequence-level distillation** — Training a student on teacher-generated outputs. (Ch 42.2)
- **SFT** — Supervised Fine-Tuning on (prompt, response) examples. (Ch 37)
- **SGD** — Stochastic gradient descent on mini-batches. (Ch 8.2)
- **Sharding** — Splitting data or model state into pieces across files or devices. (Ch 23.2, 31.2)
- **SiLU (Swish)** — x·σ(x). (Ch 9.3)
- **SimPO** — Reference-free preference optimization using length-normalized log-probabilities. (Ch 40.3)
- **Sliding-window attention** — Attention restricted to a fixed number of recent tokens. (Ch 32.3)
- **SLO** — Service-level objective, e.g. a p99 latency target. (Ch 45.3)
- **SmoothQuant** — Migrating activation outliers into weights with per-channel scales before INT8 quantization. (Ch 44.3)
- **Softmax** — exp(zᵢ)/Σⱼexp(zⱼ): turns scores into a probability distribution. (Ch 5.2)
- **Sparse attention** — Attention over a subset of positions (e.g. sliding windows). (Ch 32.3)
- **Special tokens** — Reserved tokens for control (BOS, EOS, PAD, chat roles, tool calls). (Ch 16.3)
- **Speculative decoding** — Drafting several tokens cheaply and verifying them in one target pass, preserving the target distribution. (Ch 43.2)
- **SSE (Server-Sent Events)** — An HTTP streaming format used to stream tokens. (Ch 45.4)
- **SSM (state-space model)** — A sequence model based on linear dynamical systems (S4, Mamba). (Ch 34.2)
- **Stride** — Memory step between consecutive elements along a tensor dimension. (Ch 2.1)
- **Superposition** — Representing more features than dimensions using non-orthogonal directions. (Ch 48.4)
- **SVD** — Singular value decomposition: A = UΣVᵀ. (Ch 3.6)
- **SwiGLU** — A gated FFN: (SiLU(xW₁) ⊙ xW₃)W₂. (Ch 9.4)
- **Synthetic data** — Training data generated by models. (Ch 42.1)

### T

- **t-SNE / PCA** — Dimensionality-reduction methods for visualizing embeddings. (Ch 12.5)
- **Teacher forcing** — Training on ground-truth previous tokens rather than the model's own outputs; how every LM in this book is trained. (Ch 11–14)
- **Tensor** — An n-dimensional array. (Ch 2.1)
- **Tensor cores** — GPU units specialized for matrix multiply-accumulate. (Ch 28.1)
- **Tensor parallelism** — Splitting individual weight matrices across devices. (Ch 31.3)
- **Test-time compute** — Spending more inference computation (longer reasoning, more samples) to improve answers. (Ch 41.4)
- **Throughput** — Tokens (or requests) processed per second across all users. (Ch 45.3)
- **Tied embeddings** — Sharing weights between the input embedding and the output projection. (Ch 19.5)
- **Token** — The unit a model reads and writes: a subword, byte or character. (Ch 15)
- **Tokenizer** — The mapping between text and token ids. (Ch 15–16)
- **Tool use** — A model invoking external functions through a structured protocol. (Ch 47.1)
- **Top-k sampling** — Sampling from only the k most probable tokens. (Ch 13.3)
- **Top-p (nucleus) sampling** — Sampling from the smallest set of tokens whose probabilities sum to p. (Ch 13.3)
- **TPOT** — Time Per Output Token during decode. (Ch 43.1, 45.3)
- **Transformer** — Architecture built from attention and feed-forward blocks with residuals and normalization. (Ch 19–20)
- **Triton** — A Python-embedded language for writing GPU kernels. (Ch 29.4)
- **TTFT** — Time To First Token, dominated by queueing and prefill. (Ch 43.1, 45.3)
- **Tuned lens** — A logit lens with a learned affine map per layer. (Ch 48.2)

### U–V

- **Unembedding** — The final projection from the residual stream to vocabulary logits (lm_head). (Ch 19.5, 48.2)
- **Unigram LM tokenizer** — A tokenizer that prunes a large vocabulary by likelihood (SentencePiece). (Ch 16.2)
- **UTF-8** — Variable-length byte encoding of Unicode. (Ch 15.2)
- **Value-weighted attention** — Attention weights multiplied by the norm of each position's transformed value. (Ch 48.1)
- **Vanishing / exploding gradients** — Gradients shrinking or growing exponentially through depth or time. (Ch 9.1, 14.3)
- **Vector database / index** — Storage and search for embedding vectors. (Ch 46.2)
- **Vectorization** — Replacing Python loops with array operations. (Ch 2.3)
- **Vocabulary** — The set of tokens a tokenizer can produce. (Ch 16.4)

### W–Z

- **Warmup** — Gradually increasing the learning rate at the start of training. (Ch 24.2)
- **Weight decay** — Shrinking weights toward zero each step as regularization. (Ch 8.6, 10.6)
- **Weight-only quantization** — Quantizing weights while keeping activations in high precision (W4A16, W8A16). (Ch 44.2)
- **WordPiece** — A subword tokenizer choosing merges by likelihood gain. (Ch 16.2)
- **WSD schedule** — Warmup-Stable-Decay learning-rate schedule. (Ch 24.2)
- **Xavier (Glorot) initialization** — Variance-preserving init for tanh/linear layers. (Ch 9.2)
- **YaRN** — A RoPE scaling method that interpolates frequencies non-uniformly and rescales attention. (Ch 32.2)
- **Zero-point** — The integer code representing real 0.0 in asymmetric quantization. (Ch 44.1)
- **ZeRO** — Sharding optimizer states (stage 1), gradients (2) and parameters (3) across data-parallel ranks. (Ch 31.2)
- **Z-loss** — A penalty on log-sum-exp of logits that stabilizes training. (Ch 27.3)
