## 41.1 Verifiable Rewards (Math, Code)

### 🧭 The Problem First
Learned reward models can be hacked (Ch 39.5). For many tasks, though, correctness can be *checked*: the math answer equals the reference, the code passes its tests, the output parses as valid JSON.

### 💡 Intuition / Instinct
Use a **program** as the reward: 1 if correct, 0 otherwise (plus small format rewards). It's binary, objective and unhackable in its core signal (though format loopholes still exist). This is RLVR (RL with verifiable rewards). The model explores different solution paths, and correct ones get reinforced. Over time, it learns the *strategies* that lead to correct answers, such as checking its work and trying alternatives.

### 🖼️ Visual Mental Model

```text
 prompt: "What is 17 × 23? Put the final answer in <answer></answer>."
 samples: "...<answer>391</answer>" → reward 1   "...<answer>381</answer>" → reward 0
 format check: missing tags → reward 0 (or −0.5)
```

### 📐 The Math, Gently
Total reward = $R_{correct}\in\{0,1\}$ + $\lambda_{fmt}R_{format}$ (e.g. 0.1–0.2 for the correct tag structure). Keep the format weight small so it can't dominate.

### 🛠️ Build It From Scratch

```python
# nanoforge/posttrain/verifiers.py
import re
from nanoforge.eval.generative import run_code_tests

ANSWER_RE = re.compile(r"<answer>\s*(.*?)\s*</answer>", re.S)

def format_reward(text):
    has_think = "<think>" in text and "</think>" in text and text.index("<think>") < text.index("</think>")
    has_ans = len(ANSWER_RE.findall(text)) == 1
    return 0.5 * has_think + 0.5 * has_ans

def math_reward(text, gold, tol=1e-6):
    m = ANSWER_RE.findall(text)
    if len(m) != 1: return 0.0
    pred = m[0].replace(",", "").replace("$", "").strip()
    try: return float(abs(float(pred) - float(gold)) <= tol * max(1, abs(float(gold))))
    except ValueError: return float(pred == str(gold).strip())

def code_reward(text, tests):
    m = re.search(r"```python\n(.*?)```", text, re.S)
    return float(bool(m) and run_code_tests(m.group(1) + "\n\n" + tests))    # SANDBOX in real use

def combined_reward(text, item, fmt_w=0.1):
    base = math_reward(text, item["answer"]) if item["type"] == "math" else code_reward(text, item["tests"])
    return base + fmt_w * format_reward(text)
```

### ⚠️ Failure Modes & Debugging
- Reward loopholes: multiple `<answer>` tags (hence "exactly one"), answers hidden in `<think>`, printing the expected output instead of computing it in code.
- Verifier bugs (number parsing) create false negatives that silently cap learning. Test the verifier heavily.

- **DeepSeek-R1 (2025):** rule-based accuracy + format rewards only, with no neural RM, which avoided reward hacking at scale.
- **OpenAI o1 (2024):** large-scale RL for reasoning (few public details).

## 41.2 GRPO: Group-Relative Advantages Without a Critic

### 🧭 The Problem First
PPO's value network doubles the memory and is hard to train for sparse, end-of-sequence rewards. Can we get a good baseline more simply?

### 💡 Intuition / Instinct
For each prompt, **sample a group of G responses** (e.g. 8–16). Score them all. The advantage of each response = (its reward − the group mean) / the group std. The group *is* the baseline: a response is reinforced only if it beats its siblings on the same prompt. Apply this sequence-level advantage to every token of that response, use PPO-style clipped ratios, and add a KL term to the reference. No value network at all.

### 🖼️ Visual Mental Model

```text
 prompt → 8 samples → rewards [1,0,0,1,1,0,0,0] → mean .375, std .48
 advantages [+1.3, −.78, −.78, +1.3, +1.3, −.78, −.78, −.78]
 all-correct or all-wrong group → advantages 0 → no learning signal (skip)
```

### 📐 The Math, Gently
$\hat A_i = \frac{r_i - \text{mean}(r_{1..G})}{\text{std}(r_{1..G}) + \epsilon}$ for every token of response i.
$\mathcal{L} = -\frac{1}{G}\sum_i\frac{1}{|o_i|}\sum_t\left[\min(\rho_{i,t}\hat A_i,\ \text{clip}(\rho_{i,t}, 1\pm\epsilon)\hat A_i) - \beta D_{KL,t}\right]$
KL estimator (k3, unbiased and non-negative): $D_{KL,t} = \frac{\pi_{ref}}{\pi_\theta} - \log\frac{\pi_{ref}}{\pi_\theta} - 1$ (per token, using the log-probs of the sampled token).
Variants: **Dr. GRPO** removes the per-sequence length normalization and the std division (which bias toward short correct and long wrong answers); **DAPO** uses asymmetric clipping ("clip-higher"), dynamic sampling (drop zero-variance groups) and token-level loss averaging.

### 🛠️ Build It From Scratch

```python
# nanoforge/posttrain/grpo.py
import copy, random, torch, torch.nn.functional as F
from torch.nn.utils.rnn import pad_sequence
from nanoforge.sampling import generate

def token_logps(model, ids):
    logits, _ = model(ids[:, :-1], all_logits=True)
    return F.log_softmax(logits.float(), -1).gather(-1, ids[:, 1:, None]).squeeze(-1)   # (B, T-1)

class GRPOTrainer:
    def __init__(self, policy, ref, fmt, reward_fn, device, G=8, lr=1e-6, beta=0.04, clip_lo=0.2, clip_hi=0.28,
                 max_new=256, temperature=1.0, mu=1, token_level=True):
        self.pi, self.ref, self.fmt, self.reward_fn, self.dev = policy, ref.eval(), fmt, reward_fn, device
        for p in self.ref.parameters(): p.requires_grad_(False)
        self.opt = torch.optim.AdamW([p for p in policy.parameters() if p.requires_grad], lr=lr, weight_decay=0.0)
        self.G, self.beta, self.lo, self.hi, self.max_new, self.temp, self.mu, self.token_level = G, beta, clip_lo, clip_hi, max_new, temperature, mu, token_level

    @torch.no_grad()
    def sample_group(self, item):
        p = self.fmt.prompt_for_generation([{"role": "user", "content": item["prompt"]}])
        x = torch.tensor([p] * self.G, device=self.dev)
        out = generate(self.pi, x, self.max_new, self.pi.cfg.block_size, temperature=self.temp, eos_id=self.fmt.end)
        resps = [o[len(p):].tolist() for o in out]
        resps = [r[:r.index(self.fmt.end) + 1] if self.fmt.end in r else r for r in resps]     # cut after EOS
        texts = [self.fmt.tok.decode(r) for r in resps]
        rewards = torch.tensor([self.reward_fn(t, item) for t in texts], dtype=torch.float)
        return p, resps, texts, rewards

    def step(self, items):
        batch = []
        for it in items:
            p, resps, texts, R = self.sample_group(it)
            if R.std() < 1e-6: continue                                   # dynamic sampling: no signal
            adv = (R - R.mean()) / (R.std() + 1e-4)
            for r, a in zip(resps, adv): batch.append((p, r, a.item()))
        if not batch: return {"skipped": True}
        seqs = [torch.tensor(p + r) for p, r, _ in batch]
        ids = pad_sequence(seqs, batch_first=True, padding_value=0).to(self.dev)
        mask = torch.zeros_like(ids, dtype=torch.float)
        for i, (p, r, _) in enumerate(batch): mask[i, len(p):len(p) + len(r)] = 1
        m = mask[:, 1:]; A = torch.tensor([a for *_, a in batch], device=self.dev)[:, None]
        with torch.no_grad():
            old = token_logps(self.pi, ids); ref = token_logps(self.ref, ids)
        for _ in range(self.mu):                                           # mu=1 => ratio≈1, pure on-policy
            lp = token_logps(self.pi, ids)
            ratio = torch.exp(lp - old)
            surr = torch.min(ratio * A, ratio.clamp(1 - self.lo, 1 + self.hi) * A)
            kl = torch.exp(ref - lp) - (ref - lp) - 1
            per_tok = -(surr - self.beta * kl)
            if self.token_level: loss = (per_tok * m).sum() / m.sum()      # DAPO-style token averaging
            else: loss = ((per_tok * m).sum(1) / m.sum(1).clamp_min(1)).mean()   # original per-sequence average
            self.opt.zero_grad(); loss.backward(); torch.nn.utils.clip_grad_norm_(self.pi.parameters(), 1.0); self.opt.step()
        return {"loss": loss.item(), "kl": ((kl * m).sum() / m.sum()).item(), "n_seqs": len(batch),
                "resp_len": m.sum(1).mean().item()}
```

### ⚠️ Failure Modes & Debugging
- All groups zero-variance (too hard or too easy) → no learning. Curate the difficulty so that the pass rate is ~20–80%.
- Entropy collapse (every sample identical) → exploration dies. Use a higher temperature, clip-higher, or an entropy bonus.
- The generation cost dominates. Use a fast inference engine with the KV cache (Ch 30, 45) for the rollouts.

- **DeepSeek-R1 (2025):** GRPO at scale; R1-Zero learned reasoning from a base model with RL only.

## 41.3 Rejection Sampling / Best-of-n Fine-Tuning

### 🧭 The Problem First
RL is complex and unstable. Is there a simpler way to improve from verifiable or RM-scored samples?

### 💡 Intuition / Instinct
**Generate many, keep the best, fine-tune on them (repeat).** For each prompt, sample n responses, keep the correct (or top-RM-scored) ones, and run SFT on that filtered set. This is also called RFT (rejection-sampling fine-tuning), STaR (self-taught reasoner), or expert iteration. It's a crude but robust policy improvement that captures much of RL's gain for far less complexity. Best-of-n can also be used purely at *inference* (Ch 41.4).

### 🖼️ Visual Mental Model

```text
 round k: model_k → sample n=16 per prompt → verify → keep correct (dedup) → SFT → model_{k+1}
```

### 📐 The Math, Gently
Best-of-n under a reward r gives an implicit policy with $D_{KL}(\pi_{BoN}\|\pi) ≈ \log n - \frac{n-1}{n}$ (Stiennon et al., 2020). So n = 16 is a ≈ 1.8-nat "move", comparable to a modest RL step.

### 🛠️ Build It From Scratch

```python
# nanoforge/posttrain/rft.py
import json, torch
def rejection_sample_dataset(model, fmt, tasks, reward_fn, device, n=16, max_new=256, temperature=1.0, keep_per_prompt=2):
    from nanoforge.sampling import generate
    out = []
    for t in tasks:
        p = fmt.prompt_for_generation([{"role": "user", "content": t["prompt"]}])
        x = torch.tensor([p] * n, device=device)
        gens = generate(model, x, max_new, model.cfg.block_size, temperature=temperature, eos_id=fmt.end)
        texts = {fmt.tok.decode([i for i in g[len(p):].tolist() if i != fmt.end]).strip() for g in gens}   # dedup
        good = [s for s in texts if reward_fn(s, t) >= 1.0][:keep_per_prompt]
        out += [{"messages": [{"role": "user", "content": t["prompt"]}, {"role": "assistant", "content": g}]} for g in good]
    return out
# then: write to jsonl and run sft_train (Ch 37) from the current model; repeat 2-3 rounds
```

### 🔬 Experiment & Observe
Run 3 rounds of RFT on arithmetic and compare the held-out accuracy with GRPO at a similar number of generated samples. RFT is often competitive in early rounds and plateaus sooner (it ignores the negative examples).

### ⚠️ Failure Modes & Debugging
- Only easy problems yield correct samples, so the data skews easy. Balance by difficulty.
- Correct answers with wrong reasoning (lucky guesses) get reinforced. Use process checks where possible.

### 🧠 Expert Insight
- **Zelikman et al. (2022), STaR.** **Yuan et al. (2023), RFT for math.** **Dong et al. (2023), RAFT.**
- Llama 2/3 used rejection sampling heavily in post-training. DeepSeek-R1 used rejection-sampled reasoning traces for a later SFT stage.

### 📌 Recap Card

> **Core intuition:** *Learn from your own best attempts.*

## 41.4 Chain-of-Thought, Test-Time Compute, Training for Reasoning

### 🧭 The Problem First
A model answering "17 × 23 = ?" in one token must compute everything in one forward pass: a fixed amount of computation per token. Hard problems need more computation.

### 💡 Intuition / Instinct
**Chain-of-thought (CoT):** letting the model write intermediate steps turns *tokens into computation*. Each generated token is another forward pass that can build on the previous ones. **Test-time compute** scales this:
1. **Longer reasoning:** RL-trained models learn to think longer on hard problems (DeepSeek-R1's "aha moment": self-verification and backtracking emerge).
2. **Parallel sampling + selection:** best-of-n with a verifier, majority vote (self-consistency), or a reward model.
3. **Search:** tree search guided by process reward models.

The key discovery: for a fixed budget, spending compute at inference time can beat spending it on a larger model, especially for reasoning.

### 🖼️ Visual Mental Model

```text
 accuracy
   │            ╱‾‾‾‾ RL-trained reasoning model (scales with thinking tokens)
   │        ╱‾‾
   │    ╱‾‾        ── majority vote@k
   │ ╱‾
   └────────────────────── test-time compute (tokens per problem, log)
```

### 📐 The Math, Gently
Self-consistency: sample k answers and return the mode. If each sample is independently correct with probability p > the largest wrong-answer probability, the majority vote accuracy → 1 as k grows (a Condorcet-style argument). In practice samples are correlated, so the gains saturate.

### 🛠️ Build It From Scratch

```python
from collections import Counter
from nanoforge.posttrain.verifiers import ANSWER_RE
def majority_vote(model, fmt, prompt, k=16, device="cpu", max_new=256):
    from nanoforge.sampling import generate
    import torch
    p = fmt.prompt_for_generation([{"role": "user", "content": prompt}])
    gens = generate(model, torch.tensor([p] * k, device=device), max_new, model.cfg.block_size, temperature=0.8, eos_id=fmt.end)
    answers = [ANSWER_RE.findall(fmt.tok.decode(g[len(p):].tolist())) for g in gens]
    votes = Counter(a[0].strip() for a in answers if len(a) == 1)
    return votes.most_common(1)[0][0] if votes else None

def best_of_n(model, fmt, prompt, scorer, n=16, device="cpu", max_new=256):
    """scorer(text)->float, e.g. a reward model or verifier."""
    from nanoforge.sampling import generate
    import torch
    p = fmt.prompt_for_generation([{"role": "user", "content": prompt}])
    gens = generate(model, torch.tensor([p] * n, device=device), max_new, model.cfg.block_size, temperature=0.8, eos_id=fmt.end)
    texts = [fmt.tok.decode(g[len(p):].tolist()) for g in gens]
    return max(texts, key=scorer)
```

### 🔬 Experiment & Observe
On held-out arithmetic, plot accuracy vs k ∈ {1, 2, 4, 8, 16, 32} for majority voting, for (a) the SFT model and (b) the GRPO model. Also plot the GRPO model's accuracy against its average thinking length across checkpoints. You'll see both test-time scaling curves in miniature.

### ⚠️ Failure Modes & Debugging
- CoT without any correctness pressure can produce plausible but wrong reasoning ("unfaithful CoT"). Evaluate the final answers.
- Overthinking: RL models may produce very long outputs even for easy problems. Add length-aware rewards or budget controls.

### 🧠 Expert Insight
- **Wei et al. (2022), Chain-of-Thought prompting.** **Wang et al. (2022), Self-Consistency.**
- **Snell et al. (2024), "Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Model Parameters".**
- **Lightman et al. (2023):** process reward models for step-level verification.
- **DeepSeek-R1 (2025)** and **OpenAI o1/o3:** RL-trained long reasoning.

### ✅ Check Your Instinct
1. Why does CoT add computation?
2. When does majority voting stop helping?

<details><summary>Answers</summary>

### 📌 Recap Card
- Tokens = computation; CoT lets the model think.
- Test-time scaling: longer reasoning, parallel sampling + voting/verifiers, search.
- RL on verifiable rewards teaches models to use that compute well.

> **Core intuition:** *Give the model room to think, and teach it that thinking pays.*
