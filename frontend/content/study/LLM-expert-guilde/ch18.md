## 18.1 Multiple Heads as Parallel Specialists

### 🧭 The Problem First
One attention head produces one set of weights per query, one "question". But a token often needs several things at once: its syntactic head, the previous token, the subject of the sentence, a matching bracket.

### 💡 Intuition / Instinct
Run H attention heads **in parallel**, each with its own smaller Q/K/V projections (head size D = C/H). Each head is a specialist asking a different question. Concatenate their outputs and mix them with an output projection $W_O$. Same total compute as one big head, but H different attention patterns.

### 🖼️ Visual Mental Model

```text
 X (B,T,C) ─┬─ head 1 (D) : "previous token"
            ├─ head 2 (D) : "subject of verb"
            ├─ ...
            └─ head H (D) : "matching quote"
           concat (B,T,H·D=C) ─▶ W_O ─▶ (B,T,C)
```

### 📐 The Math, Gently
$\text{head}_h = \text{Attn}(XW_Q^h, XW_K^h, XW_V^h)$, $\text{MHA}(X) = [\text{head}_1;\dots;\text{head}_H]W_O$.
Params: $4C^2$ (Q, K, V, O each C×C). FLOPs per token (projections): $8C^2$. Scores: $2TC$ per token for QKᵀ plus $2TC$ for AV.

### 🛠️ Build It From Scratch

```python
import torch, torch.nn as nn, torch.nn.functional as F
class NaiveMHA(nn.Module):
    """H separate heads (clear but slow) — for understanding."""
    def __init__(self, C, H, T_max):
        super().__init__()
        D = C // H
        self.heads = nn.ModuleList([nn.ModuleDict(dict(q=nn.Linear(C, D, bias=False), k=nn.Linear(C, D, bias=False),
                                                      v=nn.Linear(C, D, bias=False))) for _ in range(H)])
        self.o = nn.Linear(C, C)
        self.register_buffer("mask", torch.tril(torch.ones(T_max, T_max, dtype=torch.bool)))
    def forward(self, x):
        B, T, C = x.shape; outs = []
        for h in self.heads:
            q, k, v = h["q"](x), h["k"](x), h["v"](x)
            s = (q @ k.transpose(-2, -1)) / q.size(-1) ** 0.5
            s = s.masked_fill(~self.mask[:T, :T], float("-inf"))
            outs.append(F.softmax(s, -1) @ v)
        return self.o(torch.cat(outs, -1))
print(NaiveMHA(64, 4, 32)(torch.randn(2, 10, 64)).shape)
```

### 🔬 Experiment & Observe
After training (Ch 20), visualize each head's attention pattern on a sentence. You'll find heads attending to the previous token, heads attending to the first token (an "attention sink"), and heads tracking matching punctuation.

### ⚠️ Failure Modes & Debugging
C must be divisible by H. Too many heads (tiny D, like 8) hurts each head's expressiveness; the typical D is 64–128.

### 🧠 Expert Insight
- **Voita et al. (2019), Michel et al. (2019):** many heads can be pruned; a few specialized heads do most of the work.
- **Olsson et al. (2022):** *induction heads* (Ch 48) emerge in multi-head, multi-layer models and drive in-context learning.

### ✅ Check Your Instinct
1. Params of an MHA with C = 768?
2. Why not one big head?

<details><summary>Answers</summary>

1. 4·768² ≈ 2.36M (+ biases).
2. One head gives one weighting per query; multiple heads can attend to different things simultaneously.
</details>

### 📌 Recap Card
- H heads of size D = C/H, in parallel.
- Concatenate → $W_O$.
- Params $4C^2$; each head specializes.

> **Core intuition:** *Many small attentions ask many different questions at once.*

## 18.2 Efficient Batched MHA With Reshapes (B, H, T, D)

### 🧭 The Problem First
The naive version launches H small matmuls. GPUs want *one* large batched matmul.

### 💡 Intuition / Instinct
Compute Q, K, V for all heads with **one** C → 3C linear layer, then *reshape* C into (H, D) and move H next to B so that heads behave like extra batch entries (Ch 2.4). All heads compute in one batched matmul. Then undo the reshape and apply $W_O$.

### 🖼️ Visual Mental Model

```text
 x (B,T,C) ─c_attn─▶ (B,T,3C) ─split─▶ q,k,v (B,T,C)
   ─view(B,T,H,D)─▶ ─transpose(1,2)─▶ (B,H,T,D)
   scores (B,H,T,T) ─mask,softmax─▶ @ v ─▶ (B,H,T,D)
   ─transpose(1,2).contiguous().view(B,T,C)─▶ c_proj ─▶ (B,T,C)
```

### 📐 The Math, Gently
One (C, 3C) matmul has the same FLOPs as three (C, C) ones, but gives better GPU utilization. Batched matmul over (B·H) independent (T, D) × (D, T) products.

### 🛠️ Build It From Scratch

```python
# nanoforge/models/attention.py (append)
import math, torch, torch.nn as nn, torch.nn.functional as F

class CausalSelfAttention(nn.Module):
    def __init__(self, n_embd, n_head, block_size, dropout=0.0, bias=True, use_flash=True):
        super().__init__()
        assert n_embd % n_head == 0
        self.n_head, self.n_embd, self.dropout, self.use_flash = n_head, n_embd, dropout, use_flash
        self.c_attn = nn.Linear(n_embd, 3 * n_embd, bias=bias)    # q,k,v for all heads
        self.c_proj = nn.Linear(n_embd, n_embd, bias=bias)        # W_O
        self.c_proj.RESIDUAL_SCALE = True                          # marker for scaled init (Ch 20)
        self.attn_drop, self.resid_drop = nn.Dropout(dropout), nn.Dropout(dropout)
        self.register_buffer("mask", torch.tril(torch.ones(block_size, block_size, dtype=torch.bool))
                             .view(1, 1, block_size, block_size), persistent=False)

    def forward(self, x):                                          # (B, T, C)
        B, T, C = x.shape
        q, k, v = self.c_attn(x).split(self.n_embd, dim=2)         # 3 x (B, T, C)
        H, D = self.n_head, C // self.n_head
        q = q.view(B, T, H, D).transpose(1, 2)                     # (B, H, T, D)
        k = k.view(B, T, H, D).transpose(1, 2)
        v = v.view(B, T, H, D).transpose(1, 2)
        if self.use_flash:
            y = F.scaled_dot_product_attention(q, k, v, dropout_p=self.dropout if self.training else 0.0, is_causal=True)
        else:
            att = (q @ k.transpose(-2, -1)) / math.sqrt(D)         # (B, H, T, T)
            att = att.masked_fill(~self.mask[:, :, :T, :T], float("-inf"))
            att = self.attn_drop(F.softmax(att, dim=-1))
            y = att @ v                                            # (B, H, T, D)
        y = y.transpose(1, 2).contiguous().view(B, T, C)           # (B, T, C)
        return self.resid_drop(self.c_proj(y))
```

```python
torch.manual_seed(0)
m = CausalSelfAttention(64, 4, 32)
x = torch.randn(2, 10, 64)
m.use_flash = False; a = m(x); m.use_flash = True; b = m(x)
print(torch.allclose(a, b, atol=1e-5))        # manual == fused SDPA
```

### 🔬 Experiment & Observe
Time NaiveMHA vs CausalSelfAttention (manual) vs SDPA at T = 1024 on GPU. SDPA (FlashAttention under the hood, Ch 29) is fastest and uses far less memory, because it never materializes the (B, H, T, T) matrix.

### ⚠️ Failure Modes & Debugging
- `view(B, H, T, D)` instead of `view(B, T, H, D).transpose(1, 2)` scrambles tokens across heads (Ch 2.4). The equality test catches it.
- Forgetting `.contiguous()` before `.view` raises an error.

### 🧠 Expert Insight
`F.scaled_dot_product_attention` (PyTorch 2.0+) dispatches to FlashAttention-2, memory-efficient attention, or the math fallback. Use it by default; keep the manual path for teaching and debugging (e.g. to extract attention maps).

### ✅ Check Your Instinct
1. Why one c_attn of size 3C?
2. Shape of the attention scores?

<details><summary>Answers</summary>

1. One large matmul is more efficient than three small ones.
2. (B, H, T, T).
</details>

### 📌 Recap Card
- Fused QKV projection, split, reshape to (B, H, T, D).
- Heads act as a batch dimension.
- Use SDPA; keep the manual path for inspection.

> **Core intuition:** *Make heads a batch dimension, and the GPU does them all at once.*

## 18.3 Why Attention Is Permutation-Invariant and Needs Position

### 🧭 The Problem First
Shuffle the words of a sentence: "dog bites man" vs "man bites dog". Without positional information, self-attention computes the *same* set of outputs, just permuted. Word order is lost.

### 💡 Intuition / Instinct
Attention is a *set* operation: scores depend only on content, and the weighted sum doesn't care where things are. (The causal mask adds *some* order information, since tokens see different numbers of predecessors, but that's weak and indirect.) We must inject position explicitly, either by *adding* position vectors to the inputs, or by making the *scores* depend on relative distance.

### 🖼️ Visual Mental Model

```text
 no position:  attn(["dog","bites","man"]) = permute(attn(["man","bites","dog"]))
 with position: token vector = content + where-am-I signal
```

### 📐 The Math, Gently
For a permutation matrix P: $\text{Attn}(PX) = P\,\text{Attn}(X)$ (permutation equivariance) without a mask or position information.

### 🛠️ Build It From Scratch

```python
torch.manual_seed(0)
m = CausalSelfAttention(16, 2, 8); m.use_flash = False
m.mask.fill_(True)                                   # remove causal mask to show pure equivariance
x = torch.randn(1, 5, 16); perm = torch.tensor([3, 0, 4, 1, 2])
print(torch.allclose(m(x)[:, perm], m(x[:, perm]), atol=1e-6))   # True: order doesn't matter
```

### 🔬 Experiment & Observe
Train your GPT (Ch 20) with the position embedding removed. The loss is noticeably worse, but not catastrophic: the causal mask leaks some positional information (Haviv et al., 2022, "Transformer Language Models without Positional Encodings Still Learn Positional Information").

### ⚠️ Failure Modes & Debugging
Forgetting to add position (e.g. a bug in `forward`) doesn't crash; it just quietly hurts quality. Test that swapping two input tokens changes the outputs at later positions.

### 🧠 Expert Insight
NoPE (no positional encoding) works partially in causal models and has shown decent length generalization in some studies (Kazemnejad et al., 2023), but explicit schemes (RoPE) remain standard.

### ✅ Check Your Instinct
1. Why is attention permutation-equivariant?

<details><summary>Answers</summary>

1. Scores and sums depend only on content pairs, not on indices.
</details>

### 📌 Recap Card
- Attention ignores order by itself.
- The causal mask leaks weak order information.
- Explicit position encoding is needed.

> **Core intuition:** *Attention reads a bag of tokens unless you tell it where each one sits.*

## 18.4 Sinusoidal and Learned Positional Embeddings

### 🧭 The Problem First
How do we encode "position t" as a vector the model can use?

### 💡 Intuition / Instinct
- **Learned (GPT-2):** a table `wpe[t]` of size (T_max, C), learned like word embeddings and *added* to the token embeddings. Simple and effective, but it can't handle positions beyond T_max.
- **Sinusoidal (original Transformer):** fixed sines and cosines at geometrically spaced frequencies, like the hands of a clock running at many speeds. Low dimensions tick fast (fine position); high dimensions tick slowly (coarse position). Nearby positions get similar vectors, and a shift by k is a *linear transformation* (a rotation), so relative offsets are easy to compute.

### 🖼️ Visual Mental Model

```text
 dim pair 0 (fast):  ∿∿∿∿∿∿∿∿∿∿∿∿   period ~6 tokens
 dim pair 8 (mid):   ∿   ∿   ∿   ∿   period ~600
 dim pair 31 (slow): ─────────╮     period ~60,000
 position = the reading of all clock hands together
```

### 📐 The Math, Gently
$PE(t, 2i) = \sin(t/10000^{2i/C})$, $PE(t, 2i+1) = \cos(t/10000^{2i/C})$.
Each (sin, cos) pair is a point on a circle rotating with angle $\omega_i t$. Shifting by k rotates each pair by $\omega_i k$, which is a linear map independent of t. **This rotation idea is the seed of RoPE.**

### 🛠️ Build It From Scratch

```python
def sinusoidal_pe(T, C, base=10000.0):
    pos = torch.arange(T, dtype=torch.float32)[:, None]             # (T, 1)
    i = torch.arange(0, C, 2, dtype=torch.float32)[None, :]         # (1, C/2)
    ang = pos / base ** (i / C)                                      # (T, C/2)
    pe = torch.zeros(T, C); pe[:, 0::2] = torch.sin(ang); pe[:, 1::2] = torch.cos(ang)
    return pe

pe = sinusoidal_pe(128, 64)
sim = F.normalize(pe, dim=-1) @ F.normalize(pe, dim=-1).T
print("similarity of pos 10 to 9,10,11,50:", sim[10, [9, 10, 11, 50]].numpy().round(3))

class LearnedPE(nn.Module):
    def __init__(self, T_max, C): super().__init__(); self.wpe = nn.Embedding(T_max, C)
    def forward(self, T, device): return self.wpe(torch.arange(T, device=device))   # (T, C)
```

### 🔬 Experiment & Observe
Plot `pe` as a heatmap (T × C): stripes of decreasing frequency across the dimensions. Plot the `sim` matrix: a band around the diagonal. Nearby positions are similar, and similarity decays with distance.

### ⚠️ Failure Modes & Debugging
- Learned PE with T > T_max: index error. Crop the context in `generate` (Ch 13.5).
- Adding PE to embeddings with a very different scale: one signal drowns out the other.

### 🧠 Expert Insight
GPT-2/3 used learned absolute embeddings. Absolute schemes generalize poorly beyond the training length, which is why RoPE/ALiBi (relative) took over.

### ✅ Check Your Instinct
1. Why multiple frequencies?
2. Weakness of learned absolute PE?

<details><summary>Answers</summary>

1. To encode both fine and coarse position uniquely (like digits in a number).
2. No extrapolation beyond the trained length; each position must be learned separately.
</details>

### 📌 Recap Card
- Learned: a table, simple, bounded length.
- Sinusoidal: multi-frequency clocks; shifts are rotations.
- Both *added* to the token embeddings.

> **Core intuition:** *Position is a set of clocks at different speeds.*

## 18.5 RoPE: Rotating Queries and Keys

### 🧭 The Problem First
Language mostly cares about **relative** position ("the word 2 before me"), not absolute index 1,047. Additive absolute embeddings mix position into content and extrapolate poorly.

### 💡 Intuition / Instinct
**Rotary Position Embedding:** don't add anything. Instead, **rotate** each query and key vector by an angle proportional to its position, pair of dimensions by pair, at multiple frequencies (like the sinusoidal clocks). The dot product of two rotated vectors depends only on the *difference* of their angles, so $q_m\cdot k_n$ depends on the content and on $m - n$. **Relative position falls out of the geometry automatically.** Values are not rotated, so content passes through clean.

### 🖼️ Visual Mental Model

```text
 2D pair of a query at position m: rotate by m·θ
 2D pair of a key   at position n: rotate by n·θ
 dot(R_m q, R_n k) = dot(q, R_{n-m} k)      ← only the offset matters
```

### 📐 The Math, Gently
For each pair $(x_{2i}, x_{2i+1})$ with frequency $\theta_i = \text{base}^{-2i/D}$ (base = 10000):
$$\begin{bmatrix}x'_{2i}\\x'_{2i+1}\end{bmatrix} = \begin{bmatrix}\cos m\theta_i & -\sin m\theta_i\\ \sin m\theta_i & \cos m\theta_i\end{bmatrix}\begin{bmatrix}x_{2i}\\x_{2i+1}\end{bmatrix}$$
Key property: $R_m^\top R_n = R_{n-m}$, so $(R_mq)^\top(R_nk) = q^\top R_{n-m}k$.
Worked 2D example: q = k = (1, 0), θ = 90°. At m = 1, n = 1: both rotate to (0, 1), dot = 1. At m = 1, n = 2: k → (−1, 0), dot = 0. At m = 5, n = 6: the same offset gives the same dot, 0 ✓.

### 🛠️ Build It From Scratch

```python
# nanoforge/models/rope.py
import torch

def rope_cache(T, D, base=10000.0, device=None, dtype=torch.float32):
    """cos/sin tables of shape (T, D/2)."""
    inv_freq = 1.0 / (base ** (torch.arange(0, D, 2, device=device, dtype=torch.float32) / D))  # (D/2,)
    t = torch.arange(T, device=device, dtype=torch.float32)
    freqs = torch.outer(t, inv_freq)                                  # (T, D/2)
    return freqs.cos().to(dtype), freqs.sin().to(dtype)

def apply_rope(x, cos, sin):
    """x: (B, H, T, D) with interleaved pairs (x0,x1),(x2,x3)...; cos/sin: (T, D/2)."""
    x1, x2 = x[..., 0::2], x[..., 1::2]                               # (B,H,T,D/2) each
    cos, sin = cos[None, None], sin[None, None]
    out = torch.stack([x1 * cos - x2 * sin, x1 * sin + x2 * cos], dim=-1)   # (B,H,T,D/2,2)
    return out.flatten(-2).type_as(x)                                 # (B,H,T,D)
```

```python
from nanoforge.models.rope import rope_cache, apply_rope
torch.manual_seed(0)
D = 16; cos, sin = rope_cache(64, D)
q, k = torch.randn(1, 1, 1, D), torch.randn(1, 1, 1, D)
def score(m, n):
    qm = apply_rope(q.expand(1, 1, 64, D).clone(), cos, sin)[..., m, :]
    kn = apply_rope(k.expand(1, 1, 64, D).clone(), cos, sin)[..., n, :]
    return (qm * kn).sum().item()
print(score(3, 1), score(10, 8), score(40, 38))   # equal: depends only on m-n = 2
print("norm preserved:", torch.allclose(apply_rope(q.expand(1,1,64,D), cos, sin).norm(dim=-1), q.norm(dim=-1).expand(1,1,64)))
```

### ⚠️ Failure Modes & Debugging
- **Interleaved vs half-split pairing:** Llama's HF implementation pairs dimension i with i + D/2 (`rotate_half`), while the original and Meta's reference implementation interleave. Loading weights with the wrong convention silently breaks the model. Match the checkpoint's convention.
- Computing cos/sin in bf16 at large positions loses precision. Compute the tables in fp32.
- Applying RoPE to V: wrong; only Q and K are rotated.

### 🧠 Expert Insight
- **Su et al. (2021), RoFormer: "Enhanced Transformer with Rotary Position Embedding".**
- Used by GPT-NeoX, PaLM, Llama, Mistral, Qwen, Gemma, DeepSeek...
- Its frequency structure enables context extension by rescaling (Position Interpolation, NTK-aware, YaRN; Ch 32).
- Base values: 10,000 (Llama 2) → 500,000 (Llama 3) for longer contexts.

### ✅ Check Your Instinct
1. Why does RoPE give relative position?
2. Why aren't values rotated?
3. *(Coding)* Implement the `rotate_half` convention and show it equals interleaved RoPE after permuting the dimensions.

<details><summary>Answers</summary>

1. The rotations compose: $R_m^\top R_n = R_{n-m}$, so the dot product depends only on the offset.
2. Position only needs to affect *where* to attend (the scores), not the content that's moved.
3. Permute the dimensions `[0,2,4,...,1,3,5,...]`, apply the half-split version, then invert the permutation.
</details>

### 📌 Recap Card
- Rotate the q/k pairs by position × frequency.
- The dot product depends only on the relative offset.
- The norm is preserved; values are untouched.
- Watch the pairing convention and fp32 tables.

> **Core intuition:** *Encode position as an angle; relative position becomes the difference of angles.*

## 18.6 ALiBi: A Linear Distance Penalty

### 🧭 The Problem First
Can we get relative position and good length extrapolation with *zero* extra parameters and trivial compute?

### 💡 Intuition / Instinct
**ALiBi** adds a penalty to each attention score proportional to the distance: $s_{ij} \mathrel{-}= m_h\cdot(i - j)$. Each head gets a different slope $m_h$ (geometric: 1/2, 1/4, 1/8, ...), so some heads look far and others only near. There's no position embedding at all. Because the bias is a simple linear function of distance, it extends naturally to unseen lengths.

### 🖼️ Visual Mental Model

```text
 bias for one head (slope 0.5):
   [ 0                ]
   [-0.5  0           ]
   [-1.0 -0.5  0      ]
   [-1.5 -1.0 -0.5  0 ]   added to QKᵀ/√d before the softmax → recency preference
```

### 📐 The Math, Gently
$\text{softmax}(q_ik_j^\top/\sqrt d - m_h(i - j))$, with slopes $m_h = 2^{-8h/H}$ for h = 1..H.
For H = 8: slopes 1/2, 1/4, ..., 1/256.

### 🛠️ Build It From Scratch

```python
def alibi_slopes(H):
    return torch.tensor([2 ** (-8 * (h + 1) / H) for h in range(H)])          # (H,)
def alibi_bias(H, T):
    pos = torch.arange(T)
    dist = (pos[:, None] - pos[None, :]).clamp(min=0).float()                  # (T, T), i - j for j <= i
    return -alibi_slopes(H)[:, None, None] * dist[None]                        # (H, T, T)
b = alibi_bias(4, 5); print(b[0]); print(b[3])
# use: att = q @ k.transpose(-2,-1) / sqrt(D) + alibi_bias(H, T)[None]; then the causal mask, softmax
```

### 🔬 Experiment & Observe
Train small models with learned PE, RoPE and ALiBi at T = 256, then evaluate at T = 512 and 1024. ALiBi degrades most gracefully; learned PE can't run past 256 at all; RoPE degrades without scaling tricks (Ch 32).

### ⚠️ Failure Modes & Debugging
- ALiBi biases are incompatible with some fused kernels unless they support a bias argument (FlashAttention-2 supports ALiBi slopes).
- The strong recency bias can hurt tasks that need precise long-range retrieval.

### 🧠 Expert Insight
**Press et al. (2021), "Train Short, Test Long".** Used by BLOOM and MPT. RoPE dominates today, largely because RoPE + scaling handles long-context retrieval better.

### ✅ Check Your Instinct
1. Why different slopes per head?
2. Why does ALiBi extrapolate?

<details><summary>Answers</summary>

1. To give heads different effective ranges (local to global).
2. The bias is a simple function of distance that extends to any length, with no untrained embeddings.
</details>

### 📌 Recap Card
- ALiBi: score −= slope × distance.
- Per-head geometric slopes; no parameters.
- Good extrapolation, strong recency bias.

> **Core intuition:** *Make far-away tokens pay a distance tax.*
