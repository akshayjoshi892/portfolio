## 5.1 Random Variables, Distributions, Expectation and Variance

### 🧭 The Problem First
The next word is not deterministic: after "I like", many words are plausible. A model that outputs one "answer" cannot express this uncertainty. We need a language for "how likely is each possibility?".

### 💡 Intuition / Instinct
A **random variable** is a quantity whose value is uncertain. A **distribution** assigns a probability to each possible value, and the probabilities sum to 1. Think of it as *spreading one unit of belief* across the options.
- **Expectation** = the long-run average (the center of mass of belief).
- **Variance** = how spread out the belief is.

### 🖼️ Visual Mental Model

```text
  P(next word | "I like")
   pizza   ███████   0.35
   you     █████     0.25
   to      ████      0.20
   cats    ██        0.10
   other   ██        0.10     total = 1.00
```

### 📐 The Math, Gently
- Discrete: $\sum_x P(x) = 1$, $P(x) \ge 0$.
- $\mathbb{E}[X] = \sum_x x P(x)$, $\text{Var}[X] = \mathbb{E}[(X - \mathbb{E}X)^2] = \mathbb{E}[X^2] - (\mathbb{E}X)^2$.
- Linearity: $\mathbb{E}[aX + bY] = a\mathbb{E}X + b\mathbb{E}Y$. For independent variables, $\text{Var}[X + Y] = \text{Var}X + \text{Var}Y$.

Example (die): $\mathbb{E} = 3.5$, $\mathbb{E}[X^2] = 91/6$, $\text{Var} = 91/6 - 12.25 = 2.917$.
**Key fact for initialization (Ch 9):** summing $n$ independent unit-variance terms gives variance $n$, i.e. std $\sqrt n$.

### 🛠️ Build It From Scratch

```python
import numpy as np
rng = np.random.default_rng(0)
vals = np.arange(1, 7); p = np.ones(6) / 6
E = (vals * p).sum(); Var = ((vals - E) ** 2 * p).sum()
print(E, Var)                                         # 3.5 2.9167

samples = rng.choice(vals, size=100_000, p=p)
print(samples.mean(), samples.var())                  # ≈ 3.5, 2.917 (law of large numbers)

# variance of a sum grows linearly -> std grows with sqrt(n)
for n in [1, 10, 100, 1000]:
    s = rng.normal(size=(10_000, n)).sum(1)
    print(n, f"std={s.std():.2f}  sqrt(n)={np.sqrt(n):.2f}")

# categorical sampling from scratch (inverse CDF)
def sample_categorical(p, rng):
    u = rng.random(); c = 0.0
    for i, pi in enumerate(p):
        c += pi
        if u < c: return i
    return len(p) - 1
probs = [0.35, 0.25, 0.2, 0.1, 0.1]
counts = np.bincount([sample_categorical(probs, rng) for _ in range(20000)], minlength=5)
print(counts / counts.sum())
```

### 🔬 Experiment & Observe
Watch the empirical frequencies converge to `probs` as the sample count grows. The error shrinks like $1/\sqrt{N}$, so it takes 100× more samples for 10× more precision. This same law governs how noisy your loss estimates are (eval batches, Ch 35).

### ⚠️ Failure Modes & Debugging
- Probabilities that don't sum to 1 (after manual edits like top-k): renormalize.
- `np.random.choice` raises an error if the probabilities don't sum to 1 within tolerance.

### 🧠 Expert Insight
`torch.multinomial` implements categorical sampling on GPU. Every token an LLM writes is one draw from a categorical distribution over ~32K–256K tokens.

### 📌 Recap Card
- Distribution = one unit of belief spread over outcomes.
- $\mathbb{E}$ is the average, Var is the spread.
- Sums of n independent terms: std ∝ √n.
- Sampling error ∝ 1/√N.

> **Core intuition:** *A prediction should be a distribution of belief, not a single answer.*

## 5.2 Categorical Distributions and Softmax: Scores into Beliefs

### 🧭 The Problem First
A neural network outputs arbitrary real numbers (logits): negative, huge, whatever. We need to turn them into a valid distribution: positive and summing to 1, *differentiably*.

### 💡 Intuition / Instinct
**Softmax** exponentiates (making everything positive and amplifying differences), then normalizes. Logits are "log-odds scores": adding 1 to a logit multiplies that option's relative odds by $e ≈ 2.72$. Softmax is a *soft* version of argmax: the biggest score wins most, but not all, of the belief.

**Temperature** $\tau$ divides the logits: small τ gives a sharp (near-argmax) distribution, large τ gives a flat (near-uniform) one.

### 🖼️ Visual Mental Model

```text
 logits [2.0, 1.0, 0.1]
   │ exp
   ▼
 [7.39, 2.72, 1.11] sum 11.22
   │ normalize
   ▼
 [0.66, 0.24, 0.10]         τ=0.5 → [0.86, 0.12, 0.02]    τ=5 → [0.40, 0.33, 0.27]
```

### 📐 The Math, Gently
$$\text{softmax}(z)_i = \frac{e^{z_i/\tau}}{\sum_j e^{z_j/\tau}}$$
- Shift invariance: $\text{softmax}(z + c) = \text{softmax}(z)$.
- Log-softmax: $\log p_i = z_i - \log\sum_j e^{z_j}$ (the log-sum-exp, LSE).
- Ratio: $p_i/p_j = e^{z_i - z_j}$, so only *differences* of logits matter.

### 🛠️ Build It From Scratch

```python
import numpy as np
def softmax(z, tau=1.0, axis=-1):
    z = np.asarray(z, dtype=np.float64) / tau
    z = z - z.max(axis=axis, keepdims=True)
    e = np.exp(z)
    return e / e.sum(axis=axis, keepdims=True)

def logsumexp(z, axis=-1):
    m = z.max(axis=axis, keepdims=True)
    return (m + np.log(np.exp(z - m).sum(axis=axis, keepdims=True))).squeeze(axis)

def log_softmax(z, axis=-1):
    return z - np.expand_dims(logsumexp(z, axis), axis)

z = np.array([2.0, 1.0, 0.1])
for tau in [0.1, 0.5, 1, 2, 5, 100]:
    print(f"tau={tau:5}: {softmax(z, tau).round(3)}")
print(np.exp(log_softmax(z)), softmax(z))
print(logsumexp(np.array([1000., 1000.])))            # 1000.693, no overflow
```

### 🔬 Experiment & Observe
- As τ→0 you get one-hot at the argmax; as τ→∞ you get uniform. **This is exactly the temperature knob of ChatGPT-style sampling** (Ch 13).
- Add 1 to one logit and verify that its odds against the others increase by e.

### ⚠️ Failure Modes & Debugging
- Computing `log(softmax(z))` separately can give `log(0) = -inf` for very negative logits. Use `log_softmax` directly (PyTorch `F.log_softmax`, `F.cross_entropy`).
- τ = 0 means division by zero; handle greedy decoding as a special case.

### 🧠 Expert Insight
- The final layer of every LLM outputs logits over the vocabulary; `F.cross_entropy` fuses log-softmax and NLL for stability.
- **Softmax bottleneck** (Yang et al., 2018): a low-dimensional logit layer limits which distributions are expressible.
- Large logits cause instability; **z-loss** (PaLM, 2022) penalizes $\text{LSE}^2$ to keep them small (Ch 27).

**Predict:** softmax([10, 0]) first entry?

### 📌 Recap Card
- Softmax: exponentiate, then normalize.
- Temperature controls sharpness.
- Shift invariant; use LSE for stability.
- Logits = log-odds scores.

> **Core intuition:** *Softmax is a soft, differentiable argmax that turns scores into beliefs.*

## 5.3 Likelihood and Maximum-Likelihood Estimation

### 🧭 The Problem First
We have data and a model with adjustable parameters. What does it mean for the parameters to be "good"? We need an objective.

### 💡 Intuition / Instinct
**Likelihood** = how probable the observed data is under the model. Good parameters make the actual data unsurprising. **Maximum likelihood (MLE):** choose the parameters that make the observed data most probable.

For a coin landing H, H, T, H: if p(H) = 0.1, this data is very unlikely. If p(H) = 0.75, it's quite likely. MLE picks 0.75 = 3/4, the observed frequency.

Because the probabilities of many data points multiply to tiny numbers, we take the log: products become sums. Minimizing negative log-likelihood (NLL) is *the* LLM loss.

### 🖼️ Visual Mental Model

```text
  L(p) for data HHTH = p^3 (1-p)
     │        .-─-.
     │      .'     '.
     │    .'         '.
     │___/_____________\___ p
     0        0.75        1       peak = MLE
```

### 📐 The Math, Gently
$$\mathcal{L}(\theta) = \prod_i P_\theta(x_i), \qquad \text{NLL}(\theta) = -\sum_i \log P_\theta(x_i)$$
Coin: $\log L = 3\log p + \log(1-p)$. Setting the derivative to zero: $3/p - 1/(1-p) = 0 \Rightarrow p = 3/4$.
For a categorical over V outcomes with counts $n_k$: $\hat p_k = n_k / N$. **The MLE of a bigram model is just normalized counts** (Ch 11).

### 🛠️ Build It From Scratch

```python
import numpy as np
data = np.array([1, 1, 0, 1])                 # H=1
ps = np.linspace(0.01, 0.99, 99)
nll = -(data.sum() * np.log(ps) + (len(data) - data.sum()) * np.log(1 - ps))
print("MLE by grid:", ps[nll.argmin()])        # 0.75

# MLE by gradient descent on a logit (unconstrained parameter)
import torch
z = torch.zeros(1, requires_grad=True)
x = torch.tensor(data, dtype=torch.float32)
opt = torch.optim.SGD([z], lr=0.5)
for _ in range(200):
    p = torch.sigmoid(z)
    loss = -(x * torch.log(p) + (1 - x) * torch.log(1 - p)).mean()
    opt.zero_grad(); loss.backward(); opt.step()
print("MLE by GD:", torch.sigmoid(z).item())   # ≈ 0.75
```

### 🔬 Experiment & Observe
Use only 1 data point (H). The MLE is p = 1, and the model will assign 0 probability to T forever. **Overfitting in its purest form.** Smoothing and priors (Ch 11) fix it.

### ⚠️ Failure Modes & Debugging
- Optimizing p directly lets it leave [0, 1]. Parameterize with logits + sigmoid/softmax.
- Summing rather than averaging the NLL couples the learning rate to the batch size.

### 🧠 Expert Insight
Pretraining is MLE over trillions of tokens. RLHF deliberately departs from MLE (it optimizes a reward), which is why it needs a KL leash back to the MLE model (Ch 39).

### ✅ Check Your Instinct

<details><summary>Answers</summary>

</details>

### 📌 Recap Card
- Likelihood = probability of the data under the model.
- MLE = maximize it = minimize NLL.
- The categorical MLE is normalized counts.
- Use logits to keep probabilities valid.

> **Core intuition:** *Good parameters make reality unsurprising.*

## 5.4 Entropy as Surprise; Bits vs Nats

### 🧭 The Problem First
How uncertain is a distribution? We need a single number for "how hard is this to predict?", to know the best possible loss for a task.

### 💡 Intuition / Instinct
**Surprise** of an outcome with probability p is $-\log p$: certain events (p = 1) are 0 surprise; rare events are very surprising. **Entropy** is the *average surprise*: the expected information you gain when the outcome is revealed. In bits, it's the minimum average number of yes/no questions needed to identify the outcome.

- Fair coin: 1 bit.
- A fair 8-sided die: 3 bits.
- A coin that always lands H: 0 bits.

### 🖼️ Visual Mental Model

```text
 H(p) for a coin
 1.0 │      .-'''-.
     │    .'       '.
 0.5 │  .'           '.
     │ /               \
 0.0 └──────────────────── p
     0       0.5        1
```

### 📐 The Math, Gently
$$H(P) = -\sum_x P(x)\log P(x)$$
Max entropy for V outcomes = $\log V$ (uniform). Base 2 gives bits; natural log gives nats.
Example: P = [0.5, 0.25, 0.25] gives $H = 0.5·1 + 0.25·2 + 0.25·2 = 1.5$ bits.

### 🛠️ Build It From Scratch

```python
import numpy as np
def entropy(p, base=2):
    p = np.asarray(p, dtype=float); p = p[p > 0]
    return -(p * np.log(p)).sum() / np.log(base)
print(entropy([0.5, 0.5]), entropy([0.5, 0.25, 0.25]), entropy([1.0]), entropy(np.ones(8)/8))

# entropy of English characters (unigram) from a text
text = open(__file__).read().lower()
chars, counts = np.unique(list(text), return_counts=True)
print(f"char unigram entropy: {entropy(counts/counts.sum()):.2f} bits/char (uniform over {len(chars)}: {np.log2(len(chars)):.2f})")
```

### 🔬 Experiment & Observe
Unigram entropy of English letters ≈ 4.1 bits/char; Shannon estimated ~1 bit/char when the full context is used. The gap (4.1 → ~1) is *everything context buys you*, and that is what language models exploit. A good modern LLM achieves under 1 bit/char on web text.

### ⚠️ Failure Modes & Debugging
- `0 * log 0` is NaN in code; define it as 0 (filter out zeros).
- Mixing bits and nats when comparing to papers.

### 🧠 Expert Insight
The **irreducible loss** term in scaling laws (Ch 26) is roughly the entropy of natural text: no model can do better than the true entropy of the data source.

### 📌 Recap Card
- Surprise = $-\log p$; entropy = expected surprise.
- Uniform maximizes entropy ($\log V$).
- Context lowers entropy; that is what LMs exploit.
- Entropy is the floor on achievable loss.

> **Core intuition:** *Entropy is how many yes/no questions the future costs you, on average.*

## 5.5 Cross-Entropy and KL Divergence

### 🧭 The Problem First
The *true* distribution of text, P, is unknown. Our model Q approximates it. How do we measure how wrong Q is, using only samples from P?

### 💡 Intuition / Instinct
**Cross-entropy H(P, Q):** the average surprise *your model* Q experiences when reality follows P. If Q = P, it equals the entropy H(P) (the best possible). Otherwise it is larger.
**KL divergence $D_{KL}(P\|Q) = H(P,Q) - H(P)$:** the *extra* surprise, i.e. the cost of believing Q when the truth is P. Always ≥ 0, zero only if Q = P.

Crucially, H(P, Q) = $\mathbb{E}_{x\sim P}[-\log Q(x)]$ only needs **samples** from P (real text) and **evaluations** of Q (our model). That is exactly the LLM loss: average $-\log Q(\text{true next token})$ over real data.

KL is **asymmetric**:
- $D_{KL}(P\|Q)$ (forward) punishes Q for assigning low probability where P has mass → *mass-covering*.
- $D_{KL}(Q\|P)$ (reverse) punishes Q for putting mass where P has none → *mode-seeking*.

### 🖼️ Visual Mental Model

```text
 H(P,Q)  = H(P)          +  KL(P||Q)
 [model   [irreducible      [what training
  loss]    uncertainty]      can remove]
```

### 📐 The Math, Gently
$$H(P,Q) = -\sum_x P(x)\log Q(x), \qquad D_{KL}(P\|Q) = \sum_x P(x)\log\frac{P(x)}{Q(x)}$$
For one-hot P (the true token y): $H(P,Q) = -\log Q(y)$, the standard CE loss.
Example: P = [0.5, 0.5], Q = [0.9, 0.1]:
$H(P,Q) = -0.5\ln0.9 - 0.5\ln0.1 = 0.053 + 1.151 = 1.204$ nats; $H(P) = 0.693$; KL = 0.511.
Reverse: $D_{KL}(Q\|P) = 0.9\ln1.8 + 0.1\ln0.2 = 0.529 - 0.161 = 0.368$. Different!

**Gradient of CE w.r.t. logits:** $\partial/\partial z_i = q_i - p_i$ (prediction − target), the cleanest gradient in ML.

### 🛠️ Build It From Scratch

```python
import numpy as np, torch, torch.nn.functional as F
def cross_entropy(p, q): return -(p * np.log(q)).sum()
def kl(p, q):
    p, q = np.asarray(p, float), np.asarray(q, float); m = p > 0
    return (p[m] * np.log(p[m] / q[m])).sum()
P, Q = np.array([0.5, 0.5]), np.array([0.9, 0.1])
print(cross_entropy(P, Q), kl(P, Q), kl(Q, P))       # 1.204 0.511 0.368

# CE with integer targets from logits, from scratch, vs PyTorch
logits = torch.randn(4, 6); y = torch.tensor([1, 0, 5, 2])
lse = torch.logsumexp(logits, dim=-1)                  # (B,)
ce_manual = (lse - logits[torch.arange(4), y]).mean()
print(ce_manual.item(), F.cross_entropy(logits, y).item())

# gradient = softmax - onehot
logits.requires_grad_(True)
F.cross_entropy(logits, y, reduction="sum").backward()
expected = F.softmax(logits.detach(), -1) - F.one_hot(y, 6)
print(torch.allclose(logits.grad, expected, atol=1e-6))  # True

# forward vs reverse KL fitting a single Gaussian-like Q to a bimodal P (discrete grid)
xs = np.linspace(-5, 5, 201)
P = np.exp(-(xs+2)**2) + np.exp(-(xs-2)**2); P /= P.sum()
def gauss(mu, s): g = np.exp(-(xs-mu)**2/(2*s*s)); return g / g.sum() + 1e-12
best_f = min(((kl(P, gauss(m, s)), m, s) for m in np.linspace(-3,3,61) for s in np.linspace(0.3,3,28)))
best_r = min(((kl(gauss(m, s), P + 1e-12), m, s) for m in np.linspace(-3,3,61) for s in np.linspace(0.3,3,28)))
print("forward KL fit (mu, s):", best_f[1:], "-> covers both modes")
print("reverse KL fit (mu, s):", best_r[1:], "-> picks one mode")
```

### 🔬 Experiment & Observe
The forward-KL fit lands at μ ≈ 0 with a wide σ (covering both bumps); the reverse-KL fit sits on one bump (μ ≈ ±2). **Instinct:** pretraining (forward KL/MLE) makes models *cover* all the ways people write; RL-style objectives (reverse KL) make them *mode-seek*, becoming more confident and less diverse. This is why RLHF'd models are less varied (Ch 39).

### ⚠️ Failure Modes & Debugging
- KL with Q = 0 where P > 0 is infinite. Add an epsilon or use log-space ops.
- `F.kl_div(input, target)` expects `input` as *log*-probabilities and computes KL(target‖input). Its argument order confuses everyone.

### 🧠 Expert Insight
- Pretraining loss = cross-entropy = forward KL + constant.
- RLHF objective: reward − β·KL(π‖π_ref) (Ch 39).
- Distillation: minimize KL between teacher and student distributions (Ch 42).
- **Hinton et al. (2015), "Distilling the Knowledge in a Neural Network".**

### 📌 Recap Card
- CE = model's average surprise on real data = the LLM loss.
- CE = entropy + KL; only the KL part is learnable.
- Gradient w.r.t. logits = softmax − one-hot.
- Forward KL covers modes; reverse KL seeks modes.

> **Core intuition:** *Cross-entropy measures how surprised your model is by reality; KL is the part of that surprise that is your fault.*

## 5.6 Perplexity: The Effective Branching Factor

### 🧭 The Problem First
"Loss 3.2 nats" is hard to feel. We want an interpretable metric.

### 💡 Intuition / Instinct
**Perplexity = e^loss.** It is the number of equally likely options the model is effectively choosing between at each step. PPL 20 means "as uncertain as picking among 20 equally likely words". A random model over V tokens has PPL = V.

### 🖼️ Visual Mental Model

```text
 loss (nats):  10.8   5.0   3.0   2.0   1.0   0
 perplexity:   50k    148   20    7.4   2.7   1
               random ─────────────────────▶ perfect
```

### 📐 The Math, Gently
$$\text{PPL} = \exp\left(-\frac1T\sum_t \log Q(x_t|x_{<t})\right)$$
It is the geometric mean of $1/Q(\text{true token})$. Example: probabilities 0.5, 0.25, 0.125 give mean NLL $= (0.693 + 1.386 + 2.079)/3 = 1.386$, so PPL = 4.

**Warning:** perplexity depends on the tokenizer. A tokenizer with longer tokens gives higher per-token PPL for the same model quality. Compare across tokenizers with **bits per byte** (Ch 35):
$$\text{BPB} = \frac{\text{total NLL (nats)}}{\ln 2 \cdot \text{number of bytes}}$$

### 🛠️ Build It From Scratch

```python
import numpy as np
def perplexity(true_token_probs):
    return float(np.exp(-np.mean(np.log(true_token_probs))))
print(perplexity([0.5, 0.25, 0.125]))              # 4.0
print(perplexity([1/50257] * 10))                  # 50257

def bits_per_byte(total_nll_nats, n_bytes):
    return total_nll_nats / (np.log(2) * n_bytes)
# a model with loss 3.0 nats/token and 4.2 bytes/token on average:
print(f"BPB = {bits_per_byte(3.0 * 1000, 4.2 * 1000):.3f}")
```

### 🔬 Experiment & Observe
Compute the Ch 1 toy model's perplexity: ~7 for the character bigram. You will watch this number fall as the book progresses.

### ⚠️ Failure Modes & Debugging
- Averaging perplexities across documents instead of averaging losses and then exponentiating.
- Comparing PPL across different tokenizers or datasets (meaningless).
- Including padding tokens in the average artificially lowers the loss.

### 🧠 Expert Insight
GPT-2 (1.5B) reported ~35 PPL on WikiText-103 (zero-shot); modern models achieve much lower. Frontier labs mostly track loss/BPB on held-out data plus downstream benchmarks (Ch 35), since PPL correlates with, but does not equal, usefulness.

### 📌 Recap Card
- PPL = e^(mean NLL) = effective number of choices.

> **Core intuition:** *Perplexity is how many doors the model is still hesitating between.*

## 5.7 Compression ⇔ Prediction: Why LLMs Are Compressors

### 🧭 The Problem First
Why should minimizing cross-entropy produce *intelligence*? It helps to see the loss as something concrete: file size.

### 💡 Intuition / Instinct
With **arithmetic coding**, a model that assigns probability q to the next symbol can encode it in $-\log_2 q$ bits. So *the total training loss (in bits) is literally the compressed size of the data under the model*. Better predictions mean a smaller file.

To compress text really well, you must capture its regularities: grammar, facts, arithmetic, reasoning patterns. **Compression forces understanding.** This is the deepest reason next-token prediction works.

### 🖼️ Visual Mental Model

```text
 text ──▶ [LLM gives q(next)] ──▶ arithmetic coder ──▶ bits ≈ Σ -log2 q(x_t)
 decoder runs the same LLM, reads bits ──▶ reconstructs text exactly
```

### 📐 The Math, Gently
Shannon's source coding theorem: the expected code length is ≥ H(P) bits per symbol, and using model Q it is ≈ H(P, Q). So compressed size = N · (cross-entropy in bits).
Example: 1 MB of text (10⁶ chars) at 1.0 bit/char becomes 125 KB. At 4.1 bits/char (unigram) it is 512 KB. gzip gets ~2.5–3 bits/char.

### 🛠️ Build It From Scratch

```python
import numpy as np, zlib
text = ("the quick brown fox jumps over the lazy dog. " * 200).encode()
print("raw bits/char:", 8)
print("zlib bits/char:", 8 * len(zlib.compress(text, 9)) / len(text))

# ideal code length under a simple adaptive order-1 (bigram) model with add-1 smoothing
counts = np.ones((256, 256))
bits, prev = 0.0, 32
for b in text:
    p = counts[prev, b] / counts[prev].sum()
    bits += -np.log2(p)
    counts[prev, b] += 1           # learn online, exactly as a decoder could
    prev = b
print("adaptive bigram bits/char:", bits / len(text))
```

### 🔬 Experiment & Observe
Replace `text` with a real book. The adaptive bigram beats raw bytes but loses to zlib on repetitive data (zlib captures long repeats). Transformers capture long-range structure, which is why they beat both.

### ⚠️ Failure Modes & Debugging
The compression analogy requires counting model size for a *fair* comparison (a huge model can memorize). This is the Minimum Description Length (MDL) principle behind the "prequential" view of training.
