## 19.1 Decoder Block Anatomy

### 🧭 The Problem First
Attention moves information *between* positions but applies only a weighted average (a linear mix) plus projections. We also need per-token nonlinear computation, normalization and residual paths, arranged so that stacking dozens of blocks stays trainable.

### 💡 Intuition / Instinct
Each block has two sub-layers, each wrapped as `x = x + sublayer(norm(x))`:
1. **Attention (communication):** tokens gather information from other tokens.
2. **MLP/FFN (computation):** each token processes what it gathered, independently.

"Communicate, then think", repeated N times.

### 🖼️ Visual Mental Model

```text
 x ──┬───────────────────────(+)──┬─────────────────────(+)──▶ x_out
     └─ LN ─ CausalSelfAttn ──┘   └─ LN ─ MLP (C→4C→C) ─┘
       (communication)              (computation)
```

### 📐 The Math, Gently
$x' = x + \text{Attn}(\text{LN}_1(x))$, $x_{out} = x' + \text{MLP}(\text{LN}_2(x'))$.
Params per block (GPT-2 style, with biases): attention $4C^2 + 4C$, MLP $8C^2 + 5C$, two LayerNorms $4C$, so ≈ $12C^2 + 13C$.

### 🛠️ Build It From Scratch

```python
# nanoforge/models/gpt.py (part 1)
import torch, torch.nn as nn, torch.nn.functional as F
from nanoforge.models.attention import CausalSelfAttention

class MLP(nn.Module):
    def __init__(self, n_embd, dropout=0.0, bias=True):
        super().__init__()
        self.c_fc = nn.Linear(n_embd, 4 * n_embd, bias=bias)
        self.c_proj = nn.Linear(4 * n_embd, n_embd, bias=bias)
        self.c_proj.RESIDUAL_SCALE = True
        self.drop = nn.Dropout(dropout)
    def forward(self, x):                                   # (B, T, C)
        return self.drop(self.c_proj(F.gelu(self.c_fc(x), approximate="tanh")))

class Block(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.ln_1 = nn.LayerNorm(cfg.n_embd, bias=cfg.bias)
        self.attn = CausalSelfAttention(cfg.n_embd, cfg.n_head, cfg.block_size, cfg.dropout, cfg.bias)
        self.ln_2 = nn.LayerNorm(cfg.n_embd, bias=cfg.bias)
        self.mlp = MLP(cfg.n_embd, cfg.dropout, cfg.bias)
    def forward(self, x):                                   # (B, T, C) -> (B, T, C)
        x = x + self.attn(self.ln_1(x))                     # communicate
        x = x + self.mlp(self.ln_2(x))                      # compute
        return x
```

### 🔬 Experiment & Observe
Count the parameters of one block for C = 768: expect ≈ 7.08M. **Predict it before running**: 12·768² + 13·768 = 7,087,872.

### ⚠️ Failure Modes & Debugging
- `nn.LayerNorm(..., bias=False)` needs PyTorch ≥ 2.1.
- Forgetting the residual (`x = self.attn(...)`) quietly destroys deep training (Ch 10.3).

### 🧠 Expert Insight
This block is essentially unchanged from GPT-2 (2019). Llama-style models swap LayerNorm→RMSNorm, GELU MLP→SwiGLU, learned PE→RoPE, and drop the biases (Ch 32). The skeleton is the same.

### ✅ Check Your Instinct
1. Which sub-layer mixes information across positions?
2. Params per block for C = 1024?

<details><summary>Answers</summary>

1. Attention (the MLP is per-token).
2. ≈ 12·1024² + 13·1024 ≈ 12.6M.
</details>

### 📌 Recap Card
- Block = x + Attn(LN(x)); x + MLP(LN(x)).
- Attention = communication; MLP = computation.
- ≈ 12C² params per block.

> **Core intuition:** *Each block: tokens talk, then each token thinks.*

## 19.2 Pre-Norm vs Post-Norm: Stability Explained

### 🧭 The Problem First
The original Transformer (2017) put LayerNorm *after* the residual addition (post-norm). Deep post-norm models are hard to train: they need careful LR warmup and can diverge.

### 💡 Intuition / Instinct
- **Post-norm:** `x = LN(x + f(x))`. The normalization sits *on* the residual highway, so every layer rescales the stream and the clean identity gradient path is broken.
- **Pre-norm:** `x = x + f(LN(x))`. The highway stays untouched from input to output; each branch reads a normalized copy. Gradients flow directly, so training is stable even at 100+ layers. A final LayerNorm is needed before the head, because the stream itself is never normalized.

### 🖼️ Visual Mental Model

```text
 post-norm:  x ─(+)─ LN ─(+)─ LN ─▶      the highway passes through LNs
 pre-norm:   x ─(+)────(+)────── LN_f ─▶ head   the highway is clean
               ↑ f(LN)   ↑ f(LN)
```

### 📐 The Math, Gently
Pre-norm: $\partial x_L/\partial x_l = I + \sum(\dots)$, so the identity path survives. Post-norm: each LN's Jacobian multiplies the path, and at init the gradient norms at the lower layers can be much larger than at the upper layers (Xiong et al., 2020), which requires warmup.

### 🛠️ Build It From Scratch

```python
class PostNormBlock(Block):
    def forward(self, x):
        x = self.ln_1(x + self.attn(x))
        x = self.ln_2(x + self.mlp(x))
        return x

def grad_norms_by_layer(block_cls, L=24, C=128):
    torch.manual_seed(0)
    from types import SimpleNamespace
    cfg = SimpleNamespace(n_embd=C, n_head=4, block_size=64, dropout=0.0, bias=True)
    blocks = nn.Sequential(*[block_cls(cfg) for _ in range(L)])
    x = torch.randn(8, 64, C); blocks(x).pow(2).mean().backward()
    return [round(b.attn.c_attn.weight.grad.norm().item(), 4) for b in blocks][::6]
print("pre-norm :", grad_norms_by_layer(Block))
print("post-norm:", grad_norms_by_layer(PostNormBlock))
```

### 🔬 Experiment & Observe
Train a 12-layer GPT on Shakespeare with each variant at lr 1e-3 *without warmup*. Pre-norm trains; post-norm often diverges or lags. Add warmup and post-norm recovers partially.

### ⚠️ Failure Modes & Debugging
With pre-norm, the residual stream's magnitude grows with depth (nothing normalizes it). The final `ln_f` is essential; forgetting it gives a poorly scaled head input.

### 🧠 Expert Insight
- **Xiong et al. (2020), "On Layer Normalization in the Transformer Architecture".** GPT-2 onward use pre-norm.
- Variants: **sandwich norm**, and **peri-norm/double norm** (Gemma 2 normalizes both the input and the output of the sub-layer); **DeepNorm** (2022) makes post-norm trainable at 1000 layers.

### ✅ Check Your Instinct
1. Why does pre-norm need a final LayerNorm?
2. Why is post-norm unstable at depth?

<details><summary>Answers</summary>

1. The residual stream is never normalized inside the blocks.
2. The LNs on the main path distort gradient flow; the gradient scales vary a lot across layers at init.
</details>

### 📌 Recap Card
- Pre-norm: `x + f(LN(x))`, clean highway, stable.
- Post-norm: `LN(x + f(x))`, needs warmup, unstable when deep.
- Pre-norm requires a final LN.

> **Core intuition:** *Normalize what you read, never the highway itself.*

## 19.3 The FFN as a Key–Value Memory

### 🧭 The Problem First
Two-thirds of the parameters are in the MLPs. What do they *do*?

### 💡 Intuition / Instinct
Read the MLP as a **memory lookup**:
- The rows of $W_{fc}$ (C → 4C) are 4C **keys**: patterns to detect in the token's representation.
- GELU gives an activation for each key: "how much does this pattern match?"
- The columns of $W_{proj}$ (4C → C) are **values**: what to *write* into the residual stream when that key fires.

So the MLP = "if the token looks like pattern k, add information v". Facts like "Paris → capital of France" are stored this way.

### 🖼️ Visual Mental Model

```text
 x ─▶ [k1·x, k2·x, ..., k_4C·x] ─GELU─▶ activations a_i ─▶ Σ a_i v_i ─▶ added to residual
      "does x match pattern i?"                           "write memory i"
```

### 📐 The Math, Gently
$\text{MLP}(x) = \sum_{i=1}^{4C}\text{GELU}(k_i\cdot x + b_i)\,v_i$.
It's like attention, but the keys and values are *learned parameters* rather than computed from the context, and there is an elementwise nonlinearity instead of a softmax.

### 🛠️ Build It From Scratch

```python
def top_memories(mlp, x, k=5):
    """Which hidden units ('memories') fire most for input vectors x (N, C)?"""
    with torch.no_grad():
        acts = F.gelu(mlp.c_fc(x), approximate="tanh")         # (N, 4C)
    return acts.topk(k, dim=-1)
# After training GPT (Ch 20): feed the residual stream at a token (e.g. after " king"),
# find the top units, then project their value vectors through the unembedding to see which tokens they promote:
#   logits = model.lm_head(model.transformer.ln_f(mlp.c_proj.weight[:, unit]))  -> topk tokens
```

### 🔬 Experiment & Observe
After Ch 20, pick a few MLP units and read their "value" vectors through the LM head (the logit lens, Ch 48). Some units promote coherent token sets (e.g. names, punctuation after a line end).

### ⚠️ Failure Modes & Debugging
Superposition: units often respond to *several* unrelated patterns, so single-unit interpretations can mislead. Sparse autoencoders help (Ch 48).

### 🧠 Expert Insight
- **Geva et al. (2021), "Transformer Feed-Forward Layers Are Key-Value Memories".**
- **Meng et al. (2022), ROME:** locate and *edit* facts by modifying mid-layer MLP weights.
- MoE (Ch 33) scales exactly this memory by using many MLPs and routing each token to a few.

### ✅ Check Your Instinct
1. In the key–value view, what are the columns of $W_{proj}$?
2. How does the MLP differ from attention?

<details><summary>Answers</summary>

1. Value vectors written to the residual stream when the matching hidden unit fires.
2. Its keys/values are fixed learned parameters (not from context), and it acts per token.
</details>

### 📌 Recap Card
- MLP = learned pattern detectors (keys) + write vectors (values).
- Stores much of the factual knowledge.
- Per-token, context-independent memory.

> **Core intuition:** *Attention looks things up in the context; the MLP looks things up in memory.*

## 19.4 The Residual Stream Mental Model

### 🧭 The Problem First
How should you *think* about information flow through 12–100 layers?

### 💡 Intuition / Instinct
Picture the residual stream as a **shared communication bus** (a whiteboard) running through the whole network, one vector per token. Every attention head and MLP **reads** from it (via the LayerNorm + input projections) and **writes** to it (by addition). Nothing is ever overwritten, only added. Different components communicate by writing to and reading from *subspaces* (directions) of this C-dimensional space.

Consequences:
- The final logits are a **sum of contributions** from every component (the embeddings, each head, each MLP) → direct logit attribution (Ch 48).
- A layer can read what *any* earlier layer wrote, so paths skip layers freely.
- Width C is the bandwidth of the bus. Features are crammed in via superposition.

### 🖼️ Visual Mental Model

```text
 token t's stream:  e_t + PE ──(+ head1.1)──(+ mlp1)──(+ head2.3)── ... ──▶ LN_f ─▶ logits
                     ↑ every component adds a vector; logits = W_U · LN(Σ contributions)
```

### 📐 The Math, Gently
$x_L = x_0 + \sum_{l}\left(\text{Attn}_l + \text{MLP}_l\right)$. Ignoring the final LN's nonlinearity (it is approximately linear, a per-token scale), $\text{logits} \approx \sum_{\text{components}} W_U\,c$.

### 🛠️ Build It From Scratch

```python
@torch.no_grad()
def residual_contributions(model, idx):
    """Return list of (name, contribution tensor (B,T,C)) for a GPT (Ch 20 structure)."""
    tr = model.transformer
    B, T = idx.shape
    x = tr.wte(idx) + tr.wpe(torch.arange(T, device=idx.device))
    contribs = [("embed", x.clone())]
    for i, blk in enumerate(tr.h):
        a = blk.attn(blk.ln_1(x)); x = x + a; contribs.append((f"attn{i}", a))
        m = blk.mlp(blk.ln_2(x));  x = x + m; contribs.append((f"mlp{i}", m))
    return contribs, x
# check: sum of contributions == final stream
#   cs, x = residual_contributions(model, idx); torch.allclose(sum(c for _, c in cs), x)
```

### 🔬 Experiment & Observe
After Ch 20, for a prompt, compute each component's contribution to the correct next token's logit ($W_U[\text{target}]\cdot\text{LN}_f\text{-scaled } c$). You'll find a few components responsible for most of the prediction.

### ⚠️ Failure Modes & Debugging
The final LayerNorm is nonlinear (it divides by the stream's norm). For exact attribution, freeze the LN scale computed on the full stream and apply it to each contribution.

### 🧠 Expert Insight
**Elhage et al. (2021), "A Mathematical Framework for Transformer Circuits":** the residual stream, QK/OV circuits and path expansion. This view underlies modern interpretability, model editing and steering (Ch 48).

### ✅ Check Your Instinct
1. Why can the logits be decomposed into per-component contributions?
2. What limits how much information the stream can carry?

<details><summary>Answers</summary>

1. The stream is a sum of additive writes, and the head is (nearly) linear.
2. Its width C (partially overcome by superposition).
</details>

### 📌 Recap Card
- The residual stream = a shared bus; components read and add.
- Output = the sum of all contributions.
- Width = bandwidth; subspaces = channels.

> **Core intuition:** *A transformer is a committee writing notes onto a shared whiteboard, token by token.*

## 19.5 Weight Tying Between Embeddings and the LM Head

### 🧭 The Problem First
The input embedding (V × C) and the output LM head (C → V) are the two largest matrices in small models. Do we need both?

### 💡 Intuition / Instinct
The input embedding maps token → vector; the output head scores vector → token. Both encode "what does token i mean in this space". **Tie them:** use the same matrix for both (the head computes $x\,W_E^\top$). This saves VC parameters and often improves quality in small models, since each token's vector gets gradients from both roles.

### 🖼️ Visual Mental Model

```text
 idx ─▶ W_E[idx] ─▶ ... blocks ... ─▶ LN_f ─▶ x @ W_Eᵀ ─▶ logits
         └──────────── same matrix ───────────┘
```

### 📐 The Math, Gently
GPT-2 small: V·C = 50257·768 = 38.6M saved (≈ 31% of 124M). Logit for token j: $x\cdot e_j$, a similarity between the final state and token j's embedding.

### 🛠️ Build It From Scratch

```python
# in GPT.__init__ (Ch 20):
#   self.lm_head = nn.Linear(C, V, bias=False)
#   self.transformer.wte.weight = self.lm_head.weight   # tie: same Parameter object
```

### 🔬 Experiment & Observe
Train the Ch 20 GPT tied vs untied at the same C. On small data, tied is usually equal or better with fewer parameters.

### ⚠️ Failure Modes & Debugging
- Tying by *copying* instead of sharing the Parameter object: they diverge during training.
- `state_dict` contains both names pointing to the same tensor; `safetensors` complains about shared tensors, so save carefully (Ch 25).
- Initialization: the tied matrix gets the embedding init; check the initial loss ≈ ln V.

### 🧠 Expert Insight
**Press & Wolf (2017)**, **Inan et al. (2017)**. GPT-2 and Gemma tie; Llama 2/3 7B+ don't (at large scale the parameter saving matters less). Llama 3.2 1B/3B tie again.

### ✅ Check Your Instinct
1. How many params does tying save for V = 32K, C = 2048?

<details><summary>Answers</summary>

1. 32,000 × 2,048 ≈ 65.5M.
</details>

### 📌 Recap Card
- One matrix for the input embedding and the output head.
- Saves VC params; helps small models.
- Share the Parameter; don't copy it.

> **Core intuition:** *Reading a token and predicting a token use the same dictionary.*

## 19.6 Parameter and FLOP Counting

### 🧭 The Problem First
To plan training (Ch 26) and check memory (Ch 28) you must compute the parameters and FLOPs of any configuration in your head.

### 💡 Intuition / Instinct
Almost all the params are $12LC^2$ (blocks) + $VC$ (embeddings). Almost all the FLOPs: every parameter participates in one multiply-add per token forward (**2 FLOPs/param/token**), backward costs 2× forward, so training ≈ **6 FLOPs/param/token**, plus attention's $T$-dependent term.

### 🖼️ Visual Mental Model

```text
 params N ≈ 12·L·C²  (+ V·C embeddings)
 forward FLOPs/token ≈ 2N + 2·L·T·C (attention scores + AV, causal ≈ half of 4LTC)
 train FLOPs/token   ≈ 6N + 6·L·T·C  (commonly just 6N)
```

### 📐 The Math, Gently
Per token, per layer: QKV proj $2·3C^2$, out proj $2C^2$, MLP $2·8C^2$, i.e. $24C^2$ forward = 2 × (12C² params) ✓. Attention scores: QKᵀ $2TC$ and AV $2TC$ (full; causal kernels can skip ~half).
GPT-2 small (L = 12, C = 768, V = 50257, T = 1024): N ≈ 85M (non-embedding) + 38.6M (embedding) = 124M. Training FLOPs per token ≈ 6·124M + 6·12·1024·768 ≈ 0.74G + 0.057G ≈ 0.8 GFLOPs.

### 🛠️ Build It From Scratch

```python
# nanoforge/models/flops.py
def gpt_params(L, C, V, T, tied=True, bias=True):
    per_block = 12 * C * C + (13 * C if bias else 4 * C)
    emb = V * C + T * C                      # wte + wpe
    head = 0 if tied else V * C
    final_ln = 2 * C if bias else C
    return L * per_block + emb + head + final_ln

def train_flops_per_token(L, C, V, T, N=None):
    N = N or gpt_params(L, C, V, T)
    return 6 * N + 6 * L * T * C            # Kaplan/PaLM-style estimate incl. attention

if __name__ == "__main__":
    print(f"GPT-2 small params: {gpt_params(12, 768, 50257, 1024)/1e6:.1f}M")   # ~124.4M
    f = train_flops_per_token(12, 768, 50257, 1024)
    print(f"train FLOPs/token: {f/1e9:.2f} GFLOPs; 10B tokens -> {f*1e10:.2e} FLOPs")
```

### 🔬 Experiment & Observe
Compare `gpt_params` with `sum(p.numel() for p in model.parameters())` for your Ch 20 model (tied weights are counted once). They should agree exactly.

### ⚠️ Failure Modes & Debugging
- Counting tied weights twice.
- Using 6N when T is large relative to C (long context): the attention FLOPs become significant when $T \gtrsim 12C$... more precisely when $6LTC$ is comparable to $6N ≈ 72LC^2$, i.e. $T \sim 12C$.

### 🧠 Expert Insight
- **Kaplan et al. (2020)** Table 1 gives the FLOP accounting; **Chowdhery et al. (2022, PaLM)** defined **MFU** (model FLOPs utilization) with this formula. You'll compute MFU in Ch 24.

### 📌 Recap Card
- N ≈ 12LC² + VC.
- Forward ≈ 2N FLOPs/token; training ≈ 6N.
- Attention adds ~6LTC per token in training.

> **Core intuition:** *Every parameter does one multiply-add per token forward, and three times that in training.*
