## 34.1 Linear Attention and the Kernel Trick

### 🧭 The Problem First
Softmax attention computes all T×T scores. Can we get attention-like behaviour at O(T) cost?

### 💡 Intuition / Instinct
Softmax attention: $\text{out}_i = \frac{\sum_j e^{q_i\cdot k_j}v_j}{\sum_j e^{q_i\cdot k_j}}$. Replace $e^{q\cdot k}$ with a **feature-map dot product** $\phi(q)\cdot\phi(k)$. Then, by associativity:
$\sum_j (\phi(q_i)\cdot\phi(k_j))v_j = \phi(q_i)^\top\underbrace{\sum_j \phi(k_j)v_j^\top}_{S\in\mathbb{R}^{d\times d}}$.
In causal form, $S_i = S_{i-1} + \phi(k_i)v_i^\top$ is an **RNN with a matrix state**! Training can be parallel (a cumulative sum), and inference is O(1) per token with a fixed-size state. The price: a fixed d×d memory can't store as much as a growing KV cache, so recall-intensive tasks suffer.

### 🖼️ Visual Mental Model

```text
 softmax attn:   (QKᵀ) V      → T×T matrix, O(T²)
 linear attn:    Q (KᵀV)      → d×d state,  O(T·d²)
 causal:  S_t = S_{t-1} + φ(k_t) v_tᵀ ;  out_t = φ(q_t)ᵀ S_t / (φ(q_t)ᵀ z_t),  z_t = z_{t-1} + φ(k_t)
```

### 📐 The Math, Gently
Feature maps: $\phi(x) = \text{elu}(x) + 1$ (Katharopoulos et al., 2020) keeps the features positive.
Memory: the state is d×d per head regardless of T, versus a KV cache of 2·T·d per head.

### 🛠️ Build It From Scratch

```python
import torch, torch.nn.functional as F
def phi(x): return F.elu(x) + 1
def linear_attention_parallel(q, k, v):            # (B, H, T, D) causal, O(T D^2) memory-heavy version
    q, k = phi(q), phi(k)
    kv = torch.einsum("bhtd,bhte->bhtde", k, v).cumsum(2)          # running sum of k v^T
    z = k.cumsum(2)                                                  # running normalizer
    num = torch.einsum("bhtd,bhtde->bhte", q, kv)
    den = torch.einsum("bhtd,bhtd->bht", q, z)[..., None]
    return num / (den + 1e-6)

def linear_attention_recurrent(q, k, v):
    B, H, T, D = q.shape; S = torch.zeros(B, H, D, D); z = torch.zeros(B, H, D); out = []
    for t in range(T):
        qt, kt, vt = phi(q[:, :, t]), phi(k[:, :, t]), v[:, :, t]
        S = S + kt[..., :, None] * vt[..., None, :]; z = z + kt
        out.append((qt[..., None, :] @ S).squeeze(-2) / ((qt * z).sum(-1, keepdim=True) + 1e-6))
    return torch.stack(out, 2)
q, k, v = (torch.randn(1, 2, 16, 8) for _ in range(3))
print(torch.allclose(linear_attention_parallel(q, k, v), linear_attention_recurrent(q, k, v), atol=1e-5))
```

### 🔬 Experiment & Observe
Train micro with linear attention replacing softmax attention. The val loss is worse than softmax on TinyStories, and much worse on associative recall ("key: A … value: 7 … what was A's value?"). The fixed state limits recall.

### ⚠️ Failure Modes & Debugging
- The naive parallel form materializes T×D×D, which is memory-heavy. Use a chunked algorithm (intra-chunk quadratic, inter-chunk recurrent).
- Numerical issues in the normalizer; many modern variants drop it and use normalization layers instead.

### 🧠 Expert Insight
- **Katharopoulos et al. (2020), "Transformers are RNNs".**
- Modern gated linear attention/RNN variants (RetNet, GLA, **RWKV**, **DeltaNet / Gated DeltaNet**) add decay and gating to the state update, and close much of the gap. Several recent hybrid models use them.

### ✅ Check Your Instinct
1. What makes linear attention an RNN?
2. Why is its recall weaker?

<details><summary>Answers</summary>

1. The causal sum $S_t = S_{t-1} + \phi(k_t)v_t^\top$ is a recurrent state update.
2. A fixed d×d state can't store an unbounded number of key–value associations precisely.
</details>

### 📌 Recap Card
- Replace $e^{q\cdot k}$ with $\phi(q)\cdot\phi(k)$ → reassociate → O(T).
- Causal linear attention = RNN with a matrix state.
- Cheap inference, weaker recall.

## 34.2 State-Space Models: S4 Intuition and Mamba's Selective Scan

### 🧭 The Problem First
RNNs are cheap at inference but hard to train in parallel; attention trains in parallel but is costly at inference. Can we have both, plus strong long-range modelling?

### 💡 Intuition / Instinct
A **state-space model (SSM)** is a *linear* recurrence from control theory: $h_t = \bar A h_{t-1} + \bar B x_t$, $y_t = C h_t$. Because it's linear, it can be computed as a **convolution** or a **parallel scan** for training (fast), and as a recurrence for inference (O(1) per token).
**S4:** structured A matrices (HiPPO) for excellent long-range memory, but the parameters are the same for every input (time-invariant), so it can't *choose* what to remember.
**Mamba:** makes the SSM parameters ($\Delta, B, C$) **input-dependent** ("selective"). Now the model can decide per token how strongly to write into or forget its state, like LSTM gates but with a linear recurrence that still admits a parallel scan. Add a hardware-aware scan kernel, gating and a short convolution, and you get a strong attention-free LM.

### 🖼️ Visual Mental Model

```text
 x_t ─▶ [Δ_t, B_t, C_t = f(x_t)] (selective)
 h_t = exp(Δ_t A) ⊙ h_{t-1} + Δ_t B_t x_t        (per channel, diagonal A)
 y_t = C_t · h_t
 Mamba block: x → Linear(expand) → conv1d → SiLU → selective SSM → ⊙ SiLU(gate) → Linear(down)
```

### 📐 The Math, Gently
Continuous: $h'(t) = Ah(t) + Bx(t)$. Zero-order-hold discretization with step Δ: $\bar A = e^{\Delta A}$, $\bar B ≈ \Delta B$.
Mamba uses a diagonal A (negative reals, so $\bar A \in (0, 1)$ is a decay). A large Δ means "reset and focus on the current input"; a small Δ means "keep the state, ignore the input".
The recurrence $h_t = a_t h_{t-1} + b_t$ is associative under $(a_1, b_1)\circ(a_2, b_2) = (a_1a_2,\ a_2b_1 + b_2)$, so a **parallel scan** computes all $h_t$ in O(log T) depth.

### 🛠️ Build It From Scratch

```python
# nanoforge/models/mamba_simple.py : readable (slow) selective SSM + Mamba block
import math, torch, torch.nn as nn, torch.nn.functional as F

def selective_scan_ref(x, delta, A, B, C, D):
    """x, delta: (b, l, d); A: (d, n); B, C: (b, l, n); D: (d,). Sequential reference."""
    b, l, d = x.shape; n = A.shape[1]
    dA = torch.exp(delta.unsqueeze(-1) * A)                     # (b, l, d, n) decay per step
    dBx = delta.unsqueeze(-1) * B.unsqueeze(2) * x.unsqueeze(-1) # (b, l, d, n)
    h = torch.zeros(b, d, n, device=x.device, dtype=x.dtype); ys = []
    for t in range(l):
        h = dA[:, t] * h + dBx[:, t]                            # selective recurrence
        ys.append((h * C[:, t].unsqueeze(1)).sum(-1))           # (b, d)
    return torch.stack(ys, 1) + x * D                           # skip term

class MambaBlock(nn.Module):
    def __init__(self, C, d_state=16, expand=2, d_conv=4):
        super().__init__()
        d_in = expand * C; self.d_in, self.n = d_in, d_state
        self.in_proj = nn.Linear(C, 2 * d_in, bias=False)
        self.conv = nn.Conv1d(d_in, d_in, d_conv, groups=d_in, padding=d_conv - 1)
        self.dt_rank = math.ceil(C / 16)
        self.x_proj = nn.Linear(d_in, self.dt_rank + 2 * d_state, bias=False)
        self.dt_proj = nn.Linear(self.dt_rank, d_in, bias=True)
        A = torch.arange(1, d_state + 1, dtype=torch.float32).repeat(d_in, 1)
        self.A_log = nn.Parameter(torch.log(A)); self.D = nn.Parameter(torch.ones(d_in))
        self.out_proj = nn.Linear(d_in, C, bias=False)
    def forward(self, x):                                          # (b, l, C)
        b, l, _ = x.shape
        xz = self.in_proj(x); xi, z = xz.chunk(2, -1)
        xi = F.silu(self.conv(xi.transpose(1, 2))[..., :l].transpose(1, 2))   # causal depthwise conv
        dbc = self.x_proj(xi)
        dt, Bm, Cm = dbc.split([self.dt_rank, self.n, self.n], -1)
        delta = F.softplus(self.dt_proj(dt))                        # (b, l, d_in) input-dependent step
        A = -torch.exp(self.A_log.float())                          # (d_in, n) negative -> decay
        y = selective_scan_ref(xi, delta, A, Bm, Cm, self.D)
        return self.out_proj(y * F.silu(z))

m = MambaBlock(64); print(m(torch.randn(2, 32, 64)).shape)
```

A Mamba LM = embeddings → [RMSNorm → MambaBlock + residual] × L → RMSNorm → head (no attention, no positional encoding: the recurrence encodes order).

### 🔬 Experiment & Observe
- Train a 6-layer Mamba LM on TinyStories and compare it with Llama-micro at equal params. Mamba is competitive on loss (this pure-Python scan is slow; the real `mamba_ssm` CUDA kernels are fast).
- An associative-recall probe: transformers are better at exact copying/retrieval from long contexts.

### ⚠️ Failure Modes & Debugging
- The sequential reference is O(l) Python steps. Fine for learning, too slow for real training; use `mamba-ssm` kernels (Linux + CUDA).
- Δ initialization matters (Mamba samples dt in [0.001, 0.1] via the `dt_proj` bias init); poor init gives a poor memory horizon.

### 🧠 Expert Insight
- **Gu et al. (2021), S4.** **Gu & Dao (2023), Mamba.** **Dao & Gu (2024), Mamba-2 (SSD):** connects SSMs and attention ("state space duality"), allowing matmul-friendly chunked algorithms.
- **Jelassi et al. (2024), "Repeat After Me":** transformers beat SSMs at copying, which motivates hybrids.

### ✅ Check Your Instinct
1. What makes Mamba "selective"?
2. Why can a linear recurrence be trained in parallel?

<details><summary>Answers</summary>

1. Δ, B, C depend on the input token, so the model chooses what to write, keep or forget.
2. The update is associative, so a parallel prefix scan computes all states.
</details>

### 📌 Recap Card
- SSM: linear recurrence; parallel scan for training, O(1) inference.
- Mamba: input-dependent Δ, B, C (selective) + gating + conv.
- Strong LM quality; weaker exact recall than attention.

> **Core intuition:** *A recurrent memory that learns, token by token, how much to forget.*

## 34.3 Hybrid Architectures

### 🧭 The Problem First
Attention excels at precise retrieval and in-context learning; SSMs and linear RNNs excel at efficient long-sequence processing. Can we combine them?

### 💡 Intuition / Instinct
Interleave them: mostly SSM/linear-attention layers (cheap, constant state) with a few full-attention layers (precise retrieval). Just as local/global attention mixes (Ch 32.3), a small fraction of attention layers recovers most of the retrieval ability, while the KV cache shrinks proportionally.

### 🖼️ Visual Mental Model

```text
 [Mamba][Mamba][Mamba][Attn][Mamba][Mamba][Mamba][Attn] ...   (e.g. 1 attention per 4-8 layers)
 KV cache only for the attention layers → several-× smaller
```

### 📐 The Math, Gently
With L layers and an attention fraction ρ: KV cache ∝ ρ·L·T, plus the SSM state ∝ (1−ρ)·L·d·n (constant in T).

### 🛠️ Build It From Scratch

```python
import torch.nn as nn
from nanoforge.nn import RMSNorm
from nanoforge.models.llama import LlamaBlock, LlamaConfig, llama_rope_cache
from nanoforge.models.mamba_simple import MambaBlock

class HybridLM(nn.Module):
    def __init__(self, cfg: LlamaConfig, attn_every=4):
        super().__init__()
        self.emb = nn.Embedding(cfg.vocab_size, cfg.n_embd)
        self.layers = nn.ModuleList()
        for i in range(cfg.n_layer):
            if (i + 1) % attn_every == 0: self.layers.append(LlamaBlock(cfg))
            else: self.layers.append(nn.ModuleDict(dict(norm=RMSNorm(cfg.n_embd), mix=MambaBlock(cfg.n_embd))))
        self.norm = RMSNorm(cfg.n_embd); self.head = nn.Linear(cfg.n_embd, cfg.vocab_size, bias=False)
        cos, sin = llama_rope_cache(cfg); self.register_buffer("cos", cos, persistent=False); self.register_buffer("sin", sin, persistent=False)
    def forward(self, idx, targets=None):
        x = self.emb(idx)
        for l in self.layers:
            x = l(x, self.cos, self.sin) if isinstance(l, LlamaBlock) else x + l["mix"](l["norm"](x))
        logits = self.head(self.norm(x))
        loss = None if targets is None else nn.functional.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1))
        return logits, loss
```

### 🔬 Experiment & Observe
Compare pure Llama, pure Mamba and a hybrid (attention every 4 layers) on TinyStories val loss *and* on a synthetic associative-recall task. The hybrid typically matches Llama on recall and matches or beats it on loss.

### ⚠️ Failure Modes & Debugging
Mixing layer types complicates caching (a KV cache for the attention layers, SSM states for the others) and parallelism; plan the inference engine support early.

### 🧠 Expert Insight
- **Lieber et al. (2024), Jamba:** Mamba + attention + MoE.
- **Waleffe et al. (2024), "An Empirical Study of Mamba-based Language Models" (NVIDIA):** hybrids beat pure transformers at 8B scale on many tasks.
- **Zamba, Samba, RecurrentGemma (Griffin)** and several 2025 models use hybrid linear-attention/SSM + attention designs.

### ✅ Check Your Instinct
1. Why include *some* attention layers?

<details><summary>Answers</summary>

1. They provide precise, content-addressed retrieval over the full context that fixed-state layers lack.
</details>

### 📌 Recap Card
- Mostly SSM/linear layers + a few attention layers.
- Near-transformer quality with a much smaller cache.
- Inference engines must support both kinds of state.

> **Core intuition:** *Let cheap memory handle the flow and a few attention layers handle the lookups.*

## 34.4 Multimodal Basics: Vision Encoders, Patches as Tokens, Projectors

### 🧭 The Problem First
Text-only LLMs can't see charts, screenshots or photos. How do you give a language model eyes without retraining it from scratch?

### 💡 Intuition / Instinct
Turn an image into a **sequence of vectors that live in the LLM's embedding space**, then prepend them to the text tokens:
1. **Patchify:** cut the image into 14×14 or 16×16 pixel patches; each patch is a "visual token".
2. **Vision encoder (ViT):** a transformer over the patches produces contextual patch embeddings (often a pretrained CLIP/SigLIP encoder, whose features are already aligned with language).
3. **Projector:** a small MLP maps the vision features into the LLM's hidden size.
4. **LLM:** processes `[image tokens][text tokens]` with ordinary self-attention.

Training: (a) train only the projector on image–caption pairs (alignment), then (b) fine-tune the projector + LLM on visual instruction data.

### 🖼️ Visual Mental Model

```text
 image 224×224 → 16×16 patches (196) → ViT → (196, 768) → MLP projector → (196, C_llm)
 LLM input: [<img> v1 ... v196 </img>] "What is in this chart?" → answer
```

### 📐 The Math, Gently
Number of patches = (H/p)·(W/p): 224/14 = 16 → 256 tokens; 336/14 = 24 → 576 tokens. High-resolution images are costly in context, hence tiling, pooling or token compression.
Patch embedding = a linear layer on the flattened p×p×3 pixels, equivalent to a Conv2d with kernel = stride = p.

### 🛠️ Build It From Scratch

```python
# nanoforge/models/vision.py
import torch, torch.nn as nn

class PatchEmbed(nn.Module):
    def __init__(self, img=224, patch=16, C=384):
        super().__init__(); self.proj = nn.Conv2d(3, C, patch, patch)
        self.pos = nn.Parameter(torch.zeros(1, (img // patch) ** 2, C)); nn.init.normal_(self.pos, std=0.02)
    def forward(self, x):                                          # (B, 3, H, W)
        return self.proj(x).flatten(2).transpose(1, 2) + self.pos  # (B, N_patches, C)

class TinyViT(nn.Module):
    def __init__(self, img=224, patch=16, C=384, L=6, H=6):
        super().__init__(); self.patch = PatchEmbed(img, patch, C)
        layer = nn.TransformerEncoderLayer(C, H, 4 * C, batch_first=True, norm_first=True, activation="gelu")
        self.enc = nn.TransformerEncoder(layer, L); self.norm = nn.LayerNorm(C)
    def forward(self, x): return self.norm(self.enc(self.patch(x)))    # bidirectional over patches

class VisionLanguageModel(nn.Module):
    """LLaVA-style: vision encoder -> MLP projector -> prepend to LLM token embeddings."""
    def __init__(self, vit, llm, vit_dim, llm_dim):
        super().__init__(); self.vit, self.llm = vit, llm
        self.projector = nn.Sequential(nn.Linear(vit_dim, llm_dim), nn.GELU(), nn.Linear(llm_dim, llm_dim))
    def forward(self, images, input_ids, targets=None):
        img = self.projector(self.vit(images))                      # (B, Np, C_llm)
        txt = self.llm.tok_emb(input_ids)                           # (B, T, C_llm)  (Llama from Ch 32)
        x = torch.cat([img, txt], 1)
        for i, layer in enumerate(self.llm.layers): x = layer(x, self.llm.rope_cos, self.llm.rope_sin)
        logits = self.llm.lm_head(self.llm.norm(x))[:, img.size(1):]  # predict text positions only
        loss = None
        if targets is not None:
            loss = nn.functional.cross_entropy(logits.reshape(-1, logits.size(-1)).float(), targets.reshape(-1), ignore_index=-100)
        return logits, loss
```

(The LLM's `block_size` must cover the image tokens + text tokens.)

### 🔬 Experiment & Observe
A toy multimodal task: generate synthetic images of coloured shapes with captions ("a red circle on the left"). Freeze a small Llama trained on text, train the TinyViT + projector on (image, caption) pairs, then ask "what colour is the circle?". Even at tiny scale, the model learns to ground colours and shapes.

### ⚠️ Failure Modes & Debugging
- Forgetting to exclude the image positions from the loss.
- Image tokens exceeding the LLM's context. Budget the tokens per image.
- Using a vision encoder trained without language alignment → slow, poor learning. Pretrained CLIP/SigLIP features help enormously.

### 🧠 Expert Insight
- **Dosovitskiy et al. (2020), ViT.** **Radford et al. (2021), CLIP.** **Zhai et al. (2023), SigLIP.**
- **Liu et al. (2023), LLaVA:** projector + visual instruction tuning.
- **Alayrac et al. (2022), Flamingo:** cross-attention adapters.
- **Chameleon (2024):** early-fusion *discrete* image tokens in one transformer.
- Qwen-VL / Llama 3.2 Vision / Gemma 3 use variants of these designs.
