## 4.1 The Derivative as Sensitivity

### 🧭 The Problem First
A model has a loss. We want to change each parameter to reduce it. But in which direction, and by how much? Randomly trying changes across billions of parameters is hopeless.

### 💡 Intuition / Instinct
The derivative answers: **"If I wiggle this input a tiny bit, how much does the output wiggle, and in which direction?"** It is a *sensitivity* or *exchange rate*: "1 unit of x buys f′(x) units of f".
If $f'(x) = 3$, nudging $x$ by 0.01 moves $f$ by about 0.03. If the derivative is negative, increasing x decreases f. To decrease a loss, move *against* the derivative.

### 🖼️ Visual Mental Model

```text
 f(x)
   │        ╱  slope = f'(x) (tangent line)
   │      ╱•
   │   .-'
   │_.'
   └──────────────▶ x
   zoom in far enough and every smooth curve looks like a straight line with slope f'(x)
```

### 📐 The Math, Gently
$$f'(x) = \lim_{h\to 0} \frac{f(x+h) - f(x)}{h}$$
Rules: $(x^n)' = nx^{n-1}$, $(e^x)' = e^x$, $(\ln x)' = 1/x$, $(fg)' = f'g + fg'$.
Example: $f(x) = x^2$ at $x = 3$ gives $f' = 6$. Check: $f(3.01) = 9.0601$, so $\Delta f / \Delta x = 0.0601 / 0.01 = 6.01$ ✓.

### 🛠️ Build It From Scratch

```python
def numeric_derivative(f, x, h=1e-5):
    return (f(x + h) - f(x - h)) / (2 * h)       # central difference: error O(h^2)

f = lambda x: x ** 2
print(numeric_derivative(f, 3.0))                 # ~6.0

import math
tests = {
    "x^3 at 2":  (lambda x: x**3, 2.0, 12.0),
    "exp at 1":  (math.exp, 1.0, math.e),
    "ln at 4":   (math.log, 4.0, 0.25),
    "sin at 0":  (math.sin, 0.0, 1.0),
}
for name, (fn, x, true) in tests.items():
    print(f"{name:10s} numeric={numeric_derivative(fn, x):.6f} true={true:.6f}")

# gradient descent on f(x) = (x-3)^2 using the derivative
x, lr = 0.0, 0.1
for step in range(30):
    grad = 2 * (x - 3)
    x -= lr * grad
print(f"min found at x={x:.4f}")                  # ~3.0
```

### 🔬 Experiment & Observe
- Try `h = 1e-12`: floating-point cancellation ruins the estimate. Try `h = 1e-1`: truncation error. The sweet spot for float64 is around 1e-5.
- In gradient descent, try `lr = 1.1`. **Predict:** divergence, because each step overshoots by more than it corrects.

### ⚠️ Failure Modes & Debugging
- **Non-differentiable points** (ReLU at 0): frameworks just pick a subgradient (0).
- **Numerical derivative in float32** is much noisier; use float64 for gradient checks.

### 🧠 Expert Insight
Numerical differentiation costs 2 function evaluations *per parameter*, which is impossible for 10⁹ parameters. Backprop (reverse-mode autodiff) computes *all* derivatives for about 2–3× the cost of one forward pass. That asymmetry is why deep learning is possible at all.

## 4.2 Partial Derivatives and the Gradient

### 🧭 The Problem First
A loss depends on *millions* of parameters at once. We need the sensitivity with respect to each one and a single combined direction to move.

### 💡 Intuition / Instinct
A **partial derivative** $\partial f/\partial w_i$ is the sensitivity to one knob while holding all others fixed. Stack them all and you get the **gradient** $\nabla f$, an arrow pointing in the direction of *steepest ascent*. Imagine standing on a foggy mountain: the gradient points straight uphill; you step the opposite way.

### 🖼️ Visual Mental Model

```text
  contour lines of loss L(w1, w2):
       ___________
     /  _______   \
    |  /  ___  \   |        ∇L points perpendicular to contours, outward (uphill)
    | |  ( • ) |   |  ◀──   -∇L points toward the minimum •
    |  \_______/   |
     \___________/
```

### 📐 The Math, Gently
$$\nabla f(w) = \left(\frac{\partial f}{\partial w_1}, \dots, \frac{\partial f}{\partial w_n}\right)$$
Why steepest? For a small step $\delta$, $f(w + \delta) \approx f(w) + \nabla f \cdot \delta$. Among steps of fixed length, the dot product is largest when $\delta \parallel \nabla f$ (Ch 3.2!).
Example: $f(w_1, w_2) = w_1^2 + 3w_2^2$ at $(1, 1)$ gives $\nabla f = (2, 6)$. The function is 3× more sensitive to $w_2$.

### 🛠️ Build It From Scratch

```python
import numpy as np
def f(w): return w[0]**2 + 3 * w[1]**2
def grad_f(w): return np.array([2 * w[0], 6 * w[1]])

def numeric_grad(f, w, h=1e-5):
    g = np.zeros_like(w)
    for i in range(len(w)):
        e = np.zeros_like(w); e[i] = h
        g[i] = (f(w + e) - f(w - e)) / (2 * h)
    return g

w = np.array([1.0, 1.0])
print(grad_f(w), numeric_grad(f, w))

# gradient descent path
path = [w.copy()]
for _ in range(20):
    w = w - 0.1 * grad_f(w)
    path.append(w.copy())
print(np.array(path)[[0, 1, 2, 5, 20]].round(4))
```

### 🔬 Experiment & Observe
- Plot the path: it zig-zags less on $w_1$ and shrinks $w_2$ much faster. With lr = 0.34 the $w_2$ coordinate oscillates, because the step factor $1 - 0.34·6 = -1.04$ has magnitude above 1, so it diverges. **Instinct:** the steepest direction limits the learning rate (the curvature problem that Adam addresses, Ch 8).

### ⚠️ Failure Modes & Debugging
- **Ill-conditioning:** very different curvatures in different directions give zig-zagging and slow progress.
- **Wrong gradient** from a manual derivation: always check against a numerical gradient.

### 🧠 Expert Insight
The **condition number** (ratio of largest to smallest curvature) governs how fast plain gradient descent converges. Normalization layers (Ch 10) and adaptive optimizers (Ch 8) exist largely to improve conditioning.

**Predict:** which coordinate converges first with lr = 0.1?

</details>

### 📌 Recap Card
- Gradient = vector of partial derivatives = steepest-ascent direction.
- Step along −∇ to descend.
- Unequal curvature → zig-zag; the max lr is set by the steepest direction.

> **Core intuition:** *The gradient is a compass that always points uphill.*

## 4.3 The Chain Rule as a Relay Race

### 🧭 The Problem First
A neural network is a *composition* of many functions: embed → attention → MLP → ... → loss. How does a change in an early weight affect the final loss through all those layers?

### 💡 Intuition / Instinct
**Sensitivities multiply along a chain.** If turning knob A by 1 moves gear B by 2, and moving B by 1 moves output C by 3, then turning A by 1 moves C by 6. It's a relay race: each runner (layer) only knows its *local* exchange rate, and multiplying them gives the global one.

If paths branch and rejoin, you **add** the contributions from each path.

### 🖼️ Visual Mental Model

```text
  x ──(×3)──▶ u = 3x ──(square)──▶ y = u² ──▶
  dy/dx = dy/du · du/dx = 2u · 3 = 18x

  branching:  x ──▶ a = x²  ─┐
              x ──▶ b = 3x  ─┴─▶ y = a + b      dy/dx = 2x + 3   (sum over paths)
```

### 📐 The Math, Gently
$$\frac{dy}{dx} = \frac{dy}{du}\cdot\frac{du}{dx}$$
Multivariate with branching: $\frac{\partial y}{\partial x} = \sum_{\text{paths}} \prod_{\text{edges}} (\text{local derivative})$.
Worked example: $y = \ln(1 + e^{2x})$ at x = 0. Let $u = 2x$, $v = 1 + e^u$, $y = \ln v$.
$dy/dv = 1/v = 1/2$, $dv/du = e^u = 1$, $du/dx = 2$, so $dy/dx = 0.5 · 1 · 2 = 1$.

### 🛠️ Build It From Scratch

```python
import math
x = 0.0
# forward, keeping intermediates
u = 2 * x
v = 1 + math.exp(u)
y = math.log(v)
# backward: local derivatives multiplied from the output back to the input
dy_dy = 1.0
dy_dv = dy_dy * (1 / v)
dy_du = dy_dv * math.exp(u)
dy_dx = dy_du * 2
print(dy_dx)                                                     # 1.0

num = (math.log(1 + math.exp(2e-5)) - math.log(1 + math.exp(-2e-5))) / 2e-5
print(num)                                                       # ~1.0

# branching: y = x^2 + 3x at x=2 -> 2*2+3 = 7
x = 2.0; a = x**2; b = 3*x; y = a + b
dy_da = 1; dy_db = 1
dy_dx = dy_da * 2 * x + dy_db * 3                                # sum over paths
print(dy_dx)                                                     # 7.0
```

### 🔬 Experiment & Observe
Build a chain of 50 functions, each $f(z) = 0.5z$, and compute the derivative: $0.5^{50} ≈ 10^{-15}$. With $f(z) = 1.5z$: $1.5^{50} ≈ 6×10^8$. **This is the vanishing/exploding gradient problem** (Ch 9, 14): long chains of multiplication either die or blow up. Residual connections (Ch 10) are the fix.

### ⚠️ Failure Modes & Debugging
- **Forgetting a path** when variables are reused. Autograd handles this by *accumulating* gradients, which is why `grad += ...` (Ch 6).
- **Evaluating local derivatives at the wrong point**: they must use forward-pass values, which is why frameworks store activations (and why training uses so much memory).

### 🧠 Expert Insight
Backpropagation (Rumelhart, Hinton & Williams, 1986) is just the chain rule applied in the efficient order (output → input) with caching. Linnainmaa (1970) described reverse-mode autodiff even earlier.

### ✅ Check Your Instinct
1. $d/dx\,\sigma(3x)$ where $\sigma' = \sigma(1-\sigma)$, at x = 0?
2. Why do we store forward activations?
3. *(Coding)* Hand-backprop $y = (2x + 1)^3$ at x = 1 and verify numerically.

**Predict:** derivative through 20 layers each multiplying by 0.9?

<details><summary>Answers</summary>

1. $\sigma(0)(1-\sigma(0)) · 3 = 0.75$.
2. Local derivatives depend on them.
3. $3(2x+1)^2 · 2 = 54$.

Predict: $0.9^{20} ≈ 0.12$.
</details>

### 📌 Recap Card
- Chain rule: multiply local derivatives along a path.
- Branches: sum over paths.
- Long products vanish or explode.
- Backprop = chain rule + caching, output to input.

> **Core intuition:** *Global sensitivity is the product of local sensitivities along every path.*

## 4.4 Jacobians, Vector–Jacobian Products, and Why Backprop Runs Backwards

### 🧭 The Problem First
Layers map vectors to vectors ($\mathbb{R}^n \to \mathbb{R}^m$). The "derivative" is now a matrix of all partials, the Jacobian. For a 4096→4096 layer that's 16M entries per layer per example. Storing them is impossible. How does backprop avoid it?

### 💡 Intuition / Instinct
Because the final loss is a **single number**, we never need full Jacobians. We only need a *row vector* (the gradient of the loss w.r.t. the layer's output) times the Jacobian. That **vector–Jacobian product (VJP)** can be computed directly without forming the matrix.

Going backwards, we always carry a vector the size of the activations. Going forwards (forward-mode) we'd need one pass *per input*. With 1 output and 10⁹ inputs, backwards wins by 10⁹×.

### 🖼️ Visual Mental Model

```text
 forward:   x ─f1─▶ h1 ─f2─▶ h2 ─f3─▶ L (scalar)
 backward:  ∂L/∂x ◀─VJP─ ∂L/∂h1 ◀─VJP─ ∂L/∂h2 ◀─ 1
            each VJP: (row vector) · J_f   computed without building J_f
```

### 📐 The Math, Gently
For $y = Wx$ ($W: m×n$), the Jacobian is $\partial y/\partial x = W$. Given $g = \partial L/\partial y$ (shape m):
- $\partial L/\partial x = W^T g$ (shape n)
- $\partial L/\partial W = g\,x^T$ (outer product, shape m×n)

Batched (rows are examples): $Y = XW^T$, so $\partial L/\partial X = G W$ and $\partial L/\partial W = G^T X$.
**Shape rule:** the gradient always has the same shape as the thing it is a gradient of. Use this to *derive* formulas by matching shapes.

Example: $W = [[1, 2]]$, $x = (3, 4)$, so $y = 11$. With $g = 1$: $\partial L/\partial x = (1, 2)$ and $\partial L/\partial W = [[3, 4]]$.

### 🛠️ Build It From Scratch

```python
import torch
torch.manual_seed(0)
B, n, m = 4, 3, 2
X = torch.randn(B, n, requires_grad=True)
W = torch.randn(m, n, requires_grad=True)
Y = X @ W.T                                  # (B, m)
L = (Y ** 2).sum()                           # scalar
L.backward()

G = 2 * Y.detach()                           # dL/dY, (B, m)
dX = G @ W.detach()                          # (B, m)@(m, n) -> (B, n)
dW = G.T @ X.detach()                        # (m, B)@(B, n) -> (m, n)
print(torch.allclose(dX, X.grad), torch.allclose(dW, W.grad))   # True True

# explicit Jacobian for one example vs VJP
x0 = X[0].detach()
J = torch.autograd.functional.jacobian(lambda x: x @ W.detach().T, x0)   # (m, n) == W
print(torch.allclose(J, W.detach()))
```

### 🔬 Experiment & Observe
Derive the gradient of $L = \text{sum}(\text{softmax}(z) \odot t)$ by shape reasoning, then check with autograd. Shape-matching gets you ~90% of the way to any derivation.

### ⚠️ Failure Modes & Debugging
- **Transposes wrong** in manual gradients: shapes won't match, so let the shape rule guide you.
- **Forgetting to sum over the batch** in $\partial L/\partial W$. The $G^T X$ product does it automatically.

### 🧠 Expert Insight
PyTorch's autograd is exactly a library of VJPs (`backward` formulas) for each op. JAX exposes `jax.vjp` and `jax.jvp` directly. Custom kernels like FlashAttention (Ch 29) implement their own hand-derived VJPs.

### 📌 Recap Card

- Backprop computes vector–Jacobian products.

- A gradient has the shape of its variable.

> **Core intuition:** *Backprop carries one "blame vector" backwards and never builds full Jacobians.*

## 4.5 Numerical Gradient Checking From Scratch

### 🧭 The Problem First
When you write your own backward functions (Ch 6, 29, 38), a wrong gradient does not crash. The model just learns badly or not at all. You need an automatic truth test.

### 💡 Intuition / Instinct
Compare the analytic gradient with the numerical "wiggle test" on a few random parameters. If they agree to about 1e-6 relative error (in float64), your backward pass is right.

### 🖼️ Visual Mental Model

```text
 analytic grad ──┐
                 ├─▶ relative error = |a - n| / max(|a|, |n|, tiny)  < 1e-6 ✓
 numeric  grad ──┘
```

### 📐 The Math, Gently
$$\text{rel\_err} = \frac{|g_a - g_n|}{\max(|g_a|, |g_n|, \epsilon)}$$
Thresholds (float64): < 1e-7 excellent; 1e-5 suspicious; > 1e-3 wrong.

### 🛠️ Build It From Scratch

```python
# nanoforge/mathutils.py (append)
import numpy as np

def grad_check(f, params, analytic_grads, n_checks=10, h=1e-5, seed=0):
    """f(): scalar loss using params (list of float64 arrays, modified in place)."""
    rng = np.random.default_rng(seed)
    worst = 0.0
    for p, g in zip(params, analytic_grads):
        for _ in range(n_checks):
            idx = tuple(rng.integers(0, s) for s in p.shape)
            old = p[idx]
            p[idx] = old + h; fp = f()
            p[idx] = old - h; fm = f()
            p[idx] = old
            num = (fp - fm) / (2 * h)
            rel = abs(num - g[idx]) / max(abs(num), abs(g[idx]), 1e-12)
            worst = max(worst, rel)
    return worst

if __name__ == "__main__":
    rng = np.random.default_rng(1)
    X = rng.normal(size=(5, 4)); W = rng.normal(size=(3, 4)); y = rng.normal(size=(5, 3))
    def loss(): return 0.5 * ((X @ W.T - y) ** 2).sum()
    G = X @ W.T - y                      # dL/dY
    dW = G.T @ X
    print("worst rel err:", grad_check(loss, [W], [dW]))       # ~1e-10
    print("buggy:", grad_check(loss, [W], [dW * 1.01]))         # ~1e-2
```

### 🔬 Experiment & Observe
Run the same check with float32 arrays: errors of ~1e-3 appear even for correct gradients. **Always gradient-check in float64.**

### ⚠️ Failure Modes & Debugging
- **Kinks** (ReLU near 0, max) can make correct gradients fail at a few points. Check several points.
- **Randomness inside f** (dropout) breaks the check. Fix the seed or disable it.

### 🧠 Expert Insight
`torch.autograd.gradcheck` does exactly this. Use it when you write custom `autograd.Function`s. Frontier kernel authors test backward kernels against a reference implementation in fp64.

### ✅ Check Your Instinct
1. Why float64?
2. What does a relative error of 0.5 tell you?
3. *(Coding)* Gradient-check a softmax + cross-entropy that you implement by hand.

<details><summary>Answers</summary>

1. Float32 roundoff in $f(x\pm h)$ dominates the tiny difference.
2. The analytic gradient is wrong (often a missing factor or transpose).
3. Use the analytic gradient `softmax(z) - onehot(y)`.
</details>

### 📌 Recap Card
- Gradient check = compare with central differences.
- Use float64 and relative error.
- Test every hand-written backward.

> **Core intuition:** *Trust your gradients only after the wiggle test agrees.*

## 4.6 Loss Landscapes: Convexity, Saddles, Flat vs Sharp Minima

### 🧭 The Problem First
Neural net losses are not simple bowls. Why does gradient descent work at all on such complicated, non-convex surfaces, and which solutions generalize?

### 💡 Intuition / Instinct
- **Convex** (a bowl): one minimum, and gradient descent always finds it. Neural nets are *not* convex.
- **Saddle points**: downhill in some directions, uphill in others. In high dimensions, most critical points are saddles, not bad local minima. Noise (SGD) helps escape them.
- **Flat vs sharp minima**: a flat valley means small parameter changes barely change the loss, which tends to generalize better. A sharp pit is fragile.

### 🖼️ Visual Mental Model

```text
   sharp minimum         flat minimum            saddle
      \    /           \_____________/         ↗  ↑  ↖
       \  /                                     ←  •  →   (up in one axis, down in another)
        \/
```

### 📐 The Math, Gently
Curvature is described by the second derivative (Hessian $H$). At a critical point ($\nabla f = 0$):
- all eigenvalues of $H$ > 0 → minimum;
- mixed signs → saddle.

Example: $f(x, y) = x^2 - y^2$ gives $H = \text{diag}(2, -2)$, a saddle at the origin.
The largest eigenvalue $\lambda_{max}$ (sharpness) limits the stable learning rate: $\text{lr} < 2/\lambda_{max}$ (you saw this in 4.2).

### 🛠️ Build It From Scratch

```python
import numpy as np
f = lambda w: w[0]**2 - w[1]**2
grad = lambda w: np.array([2*w[0], -2*w[1]])

w = np.array([1.0, 0.0])                # exactly on the saddle's ridge
for _ in range(50): w = w - 0.1 * grad(w)
print("no noise:", w.round(4))          # stuck at (0, 0), the saddle

rng = np.random.default_rng(0)
w = np.array([1.0, 0.0])
for _ in range(50): w = w - 0.1 * (grad(w) + 0.01 * rng.normal(size=2))
print("with noise:", w.round(4))        # escapes along y

# sharpness: estimate top Hessian eigenvalue via finite differences of the gradient
def hessian(gradf, w, h=1e-4):
    n = len(w); H = np.zeros((n, n))
    for i in range(n):
        e = np.zeros(n); e[i] = h
        H[:, i] = (gradf(w + e) - gradf(w - e)) / (2 * h)
    return H
print(np.linalg.eigvalsh(hessian(grad, np.zeros(2))))   # [-2, 2]
```

### 🔬 Experiment & Observe
Train the Ch 1 toy model with batch size 8 vs 1024 and compare the final *validation* loss. Small batches (noisier) often find flatter solutions (Keskar et al., 2017), though at LLM scale this interacts with the learning rate (Ch 26).

### ⚠️ Failure Modes & Debugging
- **Loss plateaus** are often saddles or flat regions, not "convergence". Patience, momentum, or LR warmup help.
- **Edge of stability:** in practice, sharpness rises until it hits $2/\text{lr}$ and hovers there (Cohen et al., 2021). Loss curves are non-monotone even when things are fine.

### 🧠 Expert Insight
- **Dauphin et al. (2014):** saddle points, not local minima, are the main obstacle in high dimensions.
- **Foret et al. (2020), SAM:** optimizes for flat minima explicitly.
- **Li et al. (2018), "Visualizing the Loss Landscape of Neural Nets":** residual connections make landscapes far smoother.

<details><summary>Answers</summary>

2. Stability requires lr < 2/λ_max.

Predict: lr > 0.02.
</details>

### 📌 Recap Card
- Neural losses are non-convex, but mostly saddles rather than bad minima.
- Noise helps escape saddles.
- Flat minima generalize better.
- Sharpness sets the max stable learning rate.

> **Core intuition:** *Training is a noisy ball rolling through a landscape of saddles toward wide valleys.*
