## 27.1 A Field Guide to Loss-Curve Shapes

### 🧭 The Problem First
Your loss curve looks "a bit odd". Is it fine, or a sign of a bug that invalidates the run?

### 💡 Intuition / Instinct
Learn the common shapes and what each means:

| Shape | Likely meaning |
|---|---|
| Starts ≈ ln V, falls fast, then slows (power-law-like) | Healthy ✓ |
| Starts far above ln V | Bad init / output scale |
| Flat at ln V | No learning: lr ≈ 0, grads not flowing, labels misaligned |
| Falls to ~0 quickly | Data leak (mask bug, target = input) or tiny dataset memorized |
| Train ↓, val ↑ | Overfitting (repetition, small data) |
| Plateau then sudden drop | Phase transition (e.g. induction heads forming, Ch 48) ✓ |
| Staircase drops at epoch boundaries | Multi-epoch memorization |
| Sharp drop at the end | LR decay (cosine tail / WSD decay) ✓ |
| Periodic bumps | Data-order artefacts (unshuffled shards, a bad shard) |
| Sudden spike, then recovery | Instability event (27.2) |
| Spike then NaN / never recovers | Divergence (27.2–27.3) |

### 🖼️ Visual Mental Model

```text
 healthy          leak             overfit           spike+recover     divergence
 \                \                \    val /        \   ∧              \   ∧  ∧/‾‾NaN
  \___             \_ ~0            \__/‾‾‾           \_/ \__            \_/ \/
      ‾‾──                           train ‾‾──               ‾──
```

### 📐 The Math, Gently
Smooth noisy losses with an EMA (β = 0.9–0.99) before judging them. The noise level is ≈ σ/√(tokens per step), so small batches are noisier.

### 🛠️ Build It From Scratch

```python
# scripts/diagnose_log.py
import json, sys, math
recs = [json.loads(l) for l in open(sys.argv[1]) if "loss" in l]
V = int(sys.argv[2]) if len(sys.argv) > 2 else None
ema, spikes = None, []
for r in recs:
    ema = r["loss"] if ema is None else 0.98 * ema + 0.02 * r["loss"]
    if r["loss"] > ema * 1.3 and r["step"] > 100: spikes.append((r["step"], round(r["loss"], 3), round(ema, 3)))
first = recs[0]["loss"]
if V: print(f"initial loss {first:.3f} vs ln V {math.log(V):.3f}", "OK" if abs(first - math.log(V)) < 0.5 else "CHECK INIT")
print("spikes (step, loss, ema):", spikes[:20])
print("NaN seen:", any(math.isnan(r["loss"]) for r in recs))
```

### 🔬 Experiment & Observe
Deliberately create each pathology on a micro run: (1) remove the causal mask (leak); (2) lr = 1e-1 (divergence); (3) train on 1% of TinyStories for many epochs (overfit + staircase); (4) sort the data by story length (periodic structure). Save the plots as your personal field guide.

### ⚠️ Failure Modes & Debugging
Don't over-interpret single-step noise; judge the EMA and the val loss.

### 🧠 Expert Insight
The OPT-175B logbook (Zhang et al., 2022) and the BLOOM training chronicles document dozens of real spikes, restarts and interventions. They are excellent reading about how messy real runs are.

## 27.2 Loss Spikes and Divergence: Causes

### 🧭 The Problem First
At step 43,000 the loss jumps from 2.3 to 4.8. Sometimes it recovers in 200 steps, sometimes it goes to NaN. What's happening inside?

### 💡 Intuition / Instinct
Most spikes come from a feedback loop in which some quantity grows until the softmax or optimizer breaks:
1. **Attention logit growth:** $q\cdot k$ grows, attention collapses to one-hot (entropy collapse), and the gradients become erratic.
2. **Output logit growth:** the LM-head logits drift large, so the softmax saturates.
3. **Adam's stale v:** a parameter's gradient was tiny for a long time (v ≈ 0), then suddenly becomes large, so the update $m/\sqrt v$ explodes. Common for rarely updated embeddings or after a data distribution shift.
4. **Bad data:** a batch of garbage (repeated characters, a corrupted shard) produces huge gradients.
5. **LR too high for the current sharpness** (edge of stability, Ch 4.6).

### 🖼️ Visual Mental Model

```text
 max attention logit ───────╱‾‾  rising for thousands of steps...
 attention entropy   ‾‾‾‾‾‾╲___  ...collapsing
 grad norm           ▁▁▁▁▁▁▁█▅▂
 loss                ‾‾‾‾‾‾╱╲__  spike
```

### 📐 The Math, Gently
Adam's per-coordinate update is $\frac{m}{\sqrt{v}+\epsilon}$. If $v$ has decayed to ~ε² (after many small gradients) and a gradient g arrives: $m ≈ (1-\beta_1)g$, $v ≈ (1-\beta_2)g^2$, so the update ≈ $\frac{0.1}{\sqrt{0.05}} ≈ 0.45$ × lr. That is larger than the typical steady-state per-coordinate update, and applied to *all* the stale coordinates at once. β₂ = 0.95 adapts faster than 0.999, which is one reason LLMs use it.

### 🛠️ Build It From Scratch

```python
# nanoforge/diagnostics.py (append): instability monitors for GPT
import torch, torch.nn.functional as F
@torch.no_grad()
def attention_stats(model, x):
    """Per-layer max attention logit and mean attention entropy (manual attention path)."""
    stats = []; tr = model.transformer
    h = tr.wte(x) + tr.wpe(torch.arange(x.size(1), device=x.device))
    for blk in tr.h:
        a = blk.attn; B, T, C = h.shape; H = a.n_head; D = C // H
        q, k, _ = a.c_attn(blk.ln_1(h)).split(C, dim=2)
        q = q.view(B, T, H, D).transpose(1, 2); k = k.view(B, T, H, D).transpose(1, 2)
        s = (q @ k.transpose(-2, -1)) / D ** 0.5
        s = s.masked_fill(~torch.tril(torch.ones(T, T, dtype=torch.bool, device=x.device)), float("-inf"))
        p = F.softmax(s.float(), -1)
        ent = -(p * p.clamp_min(1e-12).log()).sum(-1).mean().item()
        stats.append({"max_logit": s[s.isfinite()].max().item(), "entropy": ent})
        h = blk(h)
    return stats

@torch.no_grad()
def output_logit_stats(model, x):
    logits, _ = model(x, all_logits=True)
    return {"max_logit": logits.max().item(), "lse_mean": torch.logsumexp(logits.float(), -1).mean().item()}
```

### 🔬 Experiment & Observe
Train micro at a deliberately high lr (e.g. 3e-3 to 5e-3) and log `attention_stats` every 100 steps. Before the spike you'll typically see the max attention logit climbing and the entropy of some layer collapsing.

### ⚠️ Failure Modes & Debugging
- Treating every spike as a crisis: small spikes that recover within ~100 steps are normal at scale.
- Missing a slow logit growth because you only log the loss.

### 🧠 Expert Insight
- **Dehghani et al. (2023), ViT-22B:** attention-logit growth caused divergence; QK-norm fixed it.
- **Wortsman et al. (2023), "Small-scale proxies for large-scale Transformer training instabilities":** reproduced attention-logit growth and output-logit divergence in small models at high lr; QK-layernorm and z-loss mitigate them.
- **Molybog et al. (2023):** Adam-related instability analysis.

### ✅ Check Your Instinct
1. Why does attention entropy collapse precede spikes?
2. Why can stale Adam statistics cause spikes?

<details><summary>Answers</summary>

1. Growing logits saturate the softmax, making attention near one-hot and the gradients unstable.
2. When v is tiny and a real gradient arrives, the normalized update is large across many coordinates.
</details>

### 📌 Recap Card
- Spikes = runaway logits, stale Adam statistics, bad data, or lr vs sharpness.
- Monitor the max attention/output logits and the attention entropy.
- Small recovering spikes are normal.

> **Core intuition:** *Most blow-ups are slow growth that nobody was watching.*

## 27.3 Fixes: QK-Norm, Z-Loss, Lower LR, Skip Batches, Rewinding

### 🧭 The Problem First
You've diagnosed the cause. What are the levers, and which ones can you apply *mid-run*?

### 💡 Intuition / Instinct
**Architectural (set before training):**
- **QK-norm:** apply LayerNorm/RMSNorm to q and k (per head) before the dot product. This caps the logit magnitude directly.
- **Logit soft-capping:** $s \leftarrow c\cdot\tanh(s/c)$ for attention and/or output logits (Gemma 2 uses 50 for attention and 30 for the final logits).
- **z-loss:** add $10^{-4}\cdot\text{LSE}(\text{logits})^2$ to the loss, gently pushing the log-normalizer toward 0 so the output logits can't drift.

**Optimization:**
- A lower peak lr, longer warmup, β₂ = 0.95, a larger ε for bf16, and clipping.

**Operational (mid-run):**
- **Skip batches:** if the grad norm > k× its running median, skip that step.
- **Rewind:** reload a checkpoint from before the spike, skip or reshuffle the next data window, optionally lower the lr, and continue.

### 🖼️ Visual Mental Model

```text
 spike at step S:
   rewind to ckpt S-Δ ─▶ skip data [S-Δ, S+δ] ─▶ (optionally lr × 0.7) ─▶ continue
```

### 📐 The Math, Gently
z-loss: $\mathcal{L}_z = \lambda_z\cdot\frac{1}{BT}\sum\left(\log\sum_j e^{z_j}\right)^2$, with $\lambda_z = 10^{-4}$ (PaLM).
QK-norm: $s_{ij} = \frac{\text{RMSNorm}(q_i)\cdot\text{RMSNorm}(k_j)}{\sqrt D}$, with learnable per-dimension gains (or scaled by a learned or fixed temperature).

### 🛠️ Build It From Scratch

```python
# nanoforge/models/attention.py (append): QK-norm + soft-cap variant
import math, torch, torch.nn as nn, torch.nn.functional as F
from nanoforge.nn import RMSNorm

class StableCausalSelfAttention(nn.Module):
    def __init__(self, n_embd, n_head, block_size, qk_norm=True, softcap=None, bias=False):
        super().__init__()
        self.n_head, self.n_embd, self.softcap = n_head, n_embd, softcap
        D = n_embd // n_head
        self.c_attn = nn.Linear(n_embd, 3 * n_embd, bias=bias)
        self.c_proj = nn.Linear(n_embd, n_embd, bias=bias); self.c_proj.RESIDUAL_SCALE = True
        self.q_norm = RMSNorm(D) if qk_norm else nn.Identity()
        self.k_norm = RMSNorm(D) if qk_norm else nn.Identity()
    def forward(self, x):
        B, T, C = x.shape; H, D = self.n_head, C // self.n_head
        q, k, v = self.c_attn(x).split(C, dim=2)
        q = self.q_norm(q.view(B, T, H, D)).transpose(1, 2)
        k = self.k_norm(k.view(B, T, H, D)).transpose(1, 2)
        v = v.view(B, T, H, D).transpose(1, 2)
        if self.softcap is None:
            y = F.scaled_dot_product_attention(q, k, v, is_causal=True)
        else:
            s = (q @ k.transpose(-2, -1)) / math.sqrt(D)
            s = self.softcap * torch.tanh(s / self.softcap)
            s = s.masked_fill(~torch.tril(torch.ones(T, T, dtype=torch.bool, device=x.device)), float("-inf"))
            y = F.softmax(s.float(), -1).type_as(v) @ v
        return self.c_proj(y.transpose(1, 2).contiguous().view(B, T, C))

def z_loss(logits, coef=1e-4):
    return coef * torch.logsumexp(logits.float(), dim=-1).pow(2).mean()
# in GPT.forward when training: loss = ce + z_loss(logits)
```

Batch-skip logic in the training loop:

```python
# nanoforge/train.py: robust step with outlier skipping
import collections, statistics
class SpikeGuard:
    def __init__(self, window=200, factor=6.0): self.hist, self.factor = collections.deque(maxlen=window), factor
    def should_skip(self, grad_norm):
        if len(self.hist) >= 50 and grad_norm > self.factor * statistics.median(self.hist): return True
        self.hist.append(grad_norm); return False
# usage: compute the grad norm (clip returns it) BEFORE opt.step();
# if guard.should_skip(gn): opt.zero_grad(set_to_none=True); log "skipped"; continue
```

(With the stock `train_step`, split out the clip and step so you can decide between them.)

### 🔬 Experiment & Observe
At the high lr that diverged in 27.2, add QK-norm → the run survives. Add z-loss → the output-logit max stays bounded. Compare the final losses: the stabilized run can often use a *higher* lr, which is a win-win.

### ⚠️ Failure Modes & Debugging
- Skipping too many batches (a too-low factor) silently discards data. Log the skip count.
- Rewinding without changing anything often reproduces the same spike, since the same data hits the same weights. Skip the data window or perturb something.
- QK-norm changes the effective attention temperature. Initialize the norm gains so that the scores start at a reasonable scale.

### 🧠 Expert Insight
- **Chowdhery et al. (2022), PaLM:** z-loss; restarting ~100 steps before a spike and skipping 200–500 batches resolved spikes.
- **OLMo 2 (2024):** QK-norm, z-loss, and reordered norms for stability.
- **Gemma 2 (2024):** logit soft-capping.
- **Chameleon (2024):** QK-norm was essential for mixed-modal stability.

### ✅ Check Your Instinct
1. What does z-loss penalize?
2. Why might rewinding alone reproduce the spike?

<details><summary>Answers</summary>

1. The squared log-partition function (large output logit normalizers).
2. Deterministic data + weights → the same trajectory; you must change the data window or the hyperparameters.
</details>

### 📌 Recap Card
- Architecture: QK-norm, soft-capping, z-loss.
- Optimization: lower lr, β₂ = 0.95, clipping.
- Operations: skip outlier batches, rewind + skip data.

> **Core intuition:** *Put guardrails on the quantities that like to run away.*

## 27.4 Overtraining, Data Repetition and Multi-Epoch Effects

### 🧭 The Problem First
Your domain corpus is only 500M tokens, but your compute budget allows 5B. Train 10 epochs? A bigger model? What happens when data runs out?

### 💡 Intuition / Instinct
- **Repeating data** has diminishing value: epochs 2–4 are nearly as good as fresh data; by ~16 epochs, extra passes are almost worthless and overfitting risk grows.
- **Overtraining** (tokens/param ≫ 20) with *fresh* data keeps improving the loss, just slowly, and it's great for inference efficiency.
- When unique data is limited: favour a **smaller model** (fewer params to fit), **fewer repeats of the best data**, **data augmentation / synthetic data** (Ch 42), and **mixing in general data** so the domain data isn't over-repeated.

### 🖼️ Visual Mental Model

```text
 value of an extra epoch:
 1 ████████████
 2 ███████████▌
 4 ██████████
 8 ██████
 16 ██
 40 ▏ (≈ worthless / harmful)
```

### 📐 The Math, Gently
Muennighoff et al. (2023) model repeated data as an *effective* number of unique tokens: $D' = U + U R^*(1 - e^{-R/R^*})$, where U is the unique tokens, R the number of repetitions beyond the first, and $R^* ≈ 15$. With R = 3 extra epochs, $D' ≈ U(1 + 15(1 - e^{-0.2})) ≈ 3.72U$ vs 4U raw (≈ 93% of the value). With R = 15: $D' ≈ U(1 + 15·0.632) ≈ 10.5U$ vs 16U (66%).

### 🛠️ Build It From Scratch

```python
def effective_tokens(unique, epochs, R_star=15.4):
    R = max(epochs - 1, 0)
    return unique + unique * R_star * (1 - math.exp(-R / R_star))
import math
for ep in [1, 2, 4, 8, 16, 40]:
    print(ep, f"effective/raw = {effective_tokens(1.0, ep) / ep:.2f}")
```

### 🔬 Experiment & Observe
Take 20M tokens of TinyStories. Train micro for 1, 4 and 16 epochs (the same number of steps is impossible, so compare against a run with 16× *unique* data if you have it). Plot the val loss vs tokens seen. Repetition starts to hurt past ~4–8 epochs for this model size.

### ⚠️ Failure Modes & Debugging
- Val loss rising while train falls → stop, reduce the epochs, or add data.
- A small domain corpus heavily upsampled into a mixture (Ch 22.5) → memorization of domain documents. Check with verbatim extraction tests (prompt with document prefixes).

### 🧠 Expert Insight
- **Muennighoff et al. (2023), "Scaling Data-Constrained Language Models".**
- **Hernandez et al. (2022):** a small fraction of repeated data can disproportionately harm performance.
- Galactica trained ~4 epochs on curated scientific data and found it fine.

### ✅ Check Your Instinct
1. Roughly how valuable is the 4th epoch compared with fresh data?
2. Three strategies when unique data is scarce?

<details><summary>Answers</summary>

1. Nearly as valuable (≈ 90%+ of the effective tokens up to ~4 epochs).
2. A smaller model, synthetic/augmented data, and mixing with general data (plus careful early stopping).
</details>

### 📌 Recap Card
- Up to ~4 epochs: nearly free. Beyond ~16: little value.
- Overtraining with fresh data is fine (and inference-friendly).
- Scarce data → smaller model, synthesize, mix.

> **Core intuition:** *Rereading a good book helps a few times; after that you're just memorizing the page numbers.*
