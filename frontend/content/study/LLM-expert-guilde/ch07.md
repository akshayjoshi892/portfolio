## 7.1 A Neuron as a Weighted Vote Plus a Squash

### 🧭 The Problem First
A linear function $w\cdot x + b$ can only draw straight-line boundaries. Most real patterns (like "is this word a verb?") are not linearly separable in raw features.

### 💡 Intuition / Instinct
A neuron is a **committee vote**: each input casts a vote weighted by importance ($w_i x_i$), the bias sets the threshold, and a nonlinearity "squashes" or "gates" the result. Alone it's a single straight boundary. But many neurons *combined* can carve space into complicated regions, like bending a sheet of paper many times.

Geometrically: $w \cdot x + b = 0$ is a hyperplane; the neuron measures the *signed distance* from it (scaled by $\|w\|$) and then gates it.

### 🖼️ Visual Mental Model

```text
 x1 ──w1──┐
 x2 ──w2──┼──▶ Σ + b ──▶ φ(·) ──▶ output
 x3 ──w3──┘
 ReLU φ: "fire proportionally if the evidence is above threshold, else stay silent"
```

### 📐 The Math, Gently
$y = \phi(w^\top x + b)$.
Example: $w = (1, -1)$, $b = 0$, ReLU. For $x = (3, 1)$: $y = \max(0, 2) = 2$. For $x = (1, 3)$: $y = \max(0, -2) = 0$. This neuron detects "$x_1 > x_2$".

### 🛠️ Build It From Scratch

```python
import numpy as np
def neuron(x, w, b, phi=lambda z: np.maximum(0, z)):
    return phi(x @ w + b)
w, b = np.array([1., -1.]), 0.0
X = np.array([[3., 1.], [1., 3.], [2., 2.]])
print(neuron(X, w, b))                     # [2. 0. 0.]

# XOR: impossible for one neuron, easy for two + one
X = np.array([[0,0],[0,1],[1,0],[1,1]], dtype=float)
h1 = np.maximum(0, X @ np.array([1., 1.]) - 0.5)   # "at least one"
h2 = np.maximum(0, X @ np.array([1., 1.]) - 1.5)   # "both"
print(h1 - 2 * h2)                          # [0, 0.5, 0.5, 0] -> XOR pattern
```

### 🔬 Experiment & Observe
Plot the decision regions of 1, 3 and 10 random ReLU neurons summed together: more neurons give more "folds" and a more complex boundary.

### ⚠️ Failure Modes & Debugging
- **Dead ReLU:** if $w\cdot x + b < 0$ for all inputs, the gradient is always 0 and the neuron never recovers (Ch 9).
- **Forgetting the bias:** every boundary is forced through the origin.

### 🧠 Expert Insight
McCulloch & Pitts (1943) and Rosenblatt's perceptron (1958) started here. Minsky & Papert (1969) showed that a single layer can't do XOR, which contributed to the first AI winter; multi-layer nets + backprop (1986) resolved it.

### ✅ Check Your Instinct
1. What does the bias do geometrically?
2. Why can't one neuron solve XOR?

<details><summary>Answers</summary>

1. It shifts the hyperplane away from the origin.
2. XOR's classes can't be separated by a single line.
</details>

### 📌 Recap Card
- Neuron = weighted sum + bias + nonlinearity.
- One neuron = one hyperplane.
- Combining neurons gives complex boundaries.

> **Core intuition:** *A neuron asks one yes/no-ish question about its input.*

## 7.2 Layers and MLPs; Universal Approximation

### 🧭 The Problem First
How do we organize many neurons efficiently, and how powerful is the result?

### 💡 Intuition / Instinct
A **layer** is many neurons reading the same input in parallel, which is one matrix multiply: $h = \phi(xW^\top + b)$. An **MLP** stacks layers: each one re-represents the data so the next one's job is easier. The **universal approximation theorem** says one hidden layer with enough neurons can approximate any continuous function. *Depth* makes it efficient: deep nets reuse features compositionally (edges → shapes → objects; letters → words → meaning).

### 🖼️ Visual Mental Model

```text
 x (B, C_in) ─▶ Linear(C_in→H) ─▶ φ ─▶ Linear(H→H) ─▶ φ ─▶ Linear(H→C_out) ─▶ logits (B, C_out)

 Transformer FFN (Ch 19):  (B,T,C) ─▶ Linear(C→4C) ─▶ GELU ─▶ Linear(4C→C) ─▶ (B,T,C)
```

### 📐 The Math, Gently
Params of Linear(in→out) = in·out + out. The MLP 2→16→16→1 has $2·16+16 + 16·16+16 + 16+1 = 337$.
A ReLU MLP is a *piecewise-linear* function; the number of linear pieces can grow exponentially with depth.

### 🛠️ Build It From Scratch

```python
import torch, torch.nn as nn
torch.manual_seed(0)

class MLP(nn.Module):
    def __init__(self, sizes, act=nn.ReLU):
        super().__init__()
        layers = []
        for i in range(len(sizes) - 1):
            layers.append(nn.Linear(sizes[i], sizes[i + 1]))
            if i < len(sizes) - 2: layers.append(act())
        self.net = nn.Sequential(*layers)
    def forward(self, x):                   # x: (B, sizes[0])
        return self.net(x)                  # (B, sizes[-1])

# universal approximation demo: fit sin(3x) on [-2, 2]
x = torch.linspace(-2, 2, 400).unsqueeze(1)     # (400, 1)
y = torch.sin(3 * x)
for H in [2, 8, 64]:
    m = MLP([1, H, 1]); opt = torch.optim.Adam(m.parameters(), lr=1e-2)
    for _ in range(3000):
        loss = ((m(x) - y) ** 2).mean(); opt.zero_grad(); loss.backward(); opt.step()
    print(f"hidden={H:3d} params={sum(p.numel() for p in m.parameters()):4d} mse={loss.item():.5f}")
```

### 🔬 Experiment & Observe
- 2 hidden units can't fit sin(3x); 64 fit it well. **Predict**, then compare the width-64 depth-1 model against a width-16 depth-3 model with similar parameter counts.
- Try extrapolating to x ∈ [3, 4]: MLPs don't extrapolate periodic functions. They interpolate the training range.

### ⚠️ Failure Modes & Debugging
- Adding a nonlinearity after the final layer by mistake: logits squashed by ReLU can't be negative.
- Mismatched in/out features give "mat1 and mat2 shapes cannot be multiplied (B×a and b×c)".

### 🧠 Expert Insight
- **Cybenko (1989), Hornik (1991):** universal approximation.
- **Geva et al. (2021), "Transformer Feed-Forward Layers Are Key-Value Memories":** in LLMs, the FFN MLPs store much of the factual knowledge (Ch 19).

### ✅ Check Your Instinct
1. Params of Linear(768→3072)?
2. Why no activation after the last layer?
3. *(Coding)* Fit $y = |x|$ with a 1-hidden-unit ReLU MLP. Can it? What about 2 units?

<details><summary>Answers</summary>

1. 768·3072 + 3072 = 2,362,368.
2. Outputs are logits/real values that must be unconstrained.
3. One unit: no (it can make only one bend on one side). Two units: yes, since $|x| = \text{relu}(x) + \text{relu}(-x)$.
</details>

### 📌 Recap Card
- Layer = matmul + bias + nonlinearity.
- MLP = stacked re-representations.
- Width gives expressivity; depth gives efficiency.
- No activation on the output layer.

> **Core intuition:** *Each layer rewrites the data so the next question is easier to ask.*

## 7.3 Loss Functions: MSE, Cross-Entropy, NLL, and Why CE for LMs

### 🧭 The Problem First
Training needs a single number that says "how wrong". The wrong choice of loss causes slow learning or poor results, and with softmax outputs the difference is dramatic.

### 💡 Intuition / Instinct
- **MSE** (mean squared error): for real-valued outputs; it corresponds to MLE under Gaussian noise.
- **Cross-entropy/NLL**: for categories; it is MLE under a categorical distribution (Ch 5).

Why not MSE on softmax probabilities for classification? When the model is *confidently wrong*, the softmax is saturated and MSE's gradient becomes tiny, so it learns slowest exactly when it's most wrong. CE's gradient w.r.t. the logits is $p - y$: large when wrong, small when right. **The log undoes the exp.**

### 🖼️ Visual Mental Model

```text
 true prob of correct class →   0.01    0.1    0.5    0.9
 CE loss  (-ln p)          →   4.6     2.3    0.69   0.11     steep when wrong ✓
 MSE on probs (1-p)^2      →   0.98    0.81   0.25   0.01     flat when very wrong ✗
```

### 📐 The Math, Gently
- MSE: $\frac1N\sum(\hat y - y)^2$; gradient $\frac2N(\hat y - y)$.
- CE with logits z and target class c: $L = -z_c + \log\sum_j e^{z_j}$; $\partial L/\partial z_j = p_j - \mathbb{1}[j=c]$.
- MSE through softmax: $\partial L/\partial z_j$ includes the factor $p_j(1-p_j)$, which goes to 0 when saturated.

Example: z = [0, 5], c = 0, so p = [0.0067, 0.9933].
CE gradient: [−0.9933, 0.9933], strong. MSE gradient on z₀: ≈ −0.013, about 75× weaker.

### 🛠️ Build It From Scratch

```python
import torch, torch.nn.functional as F
z = torch.tensor([[0.0, 5.0]], requires_grad=True); c = torch.tensor([0])
F.cross_entropy(z, c).backward(); print("CE grad :", z.grad)
z.grad = None
p = F.softmax(z, -1); target = F.one_hot(c, 2).float()
((p - target) ** 2).sum().backward(); print("MSE grad:", z.grad)

# race: CE vs MSE on a tiny classification problem
torch.manual_seed(0)
X = torch.randn(512, 10); true_W = torch.randn(10, 5); Y = (X @ true_W).argmax(1)
for name in ["ce", "mse"]:
    W = torch.zeros(10, 5, requires_grad=True); W.data += 3 * torch.randn(10, 5)  # confident, wrong init
    opt = torch.optim.SGD([W], lr=0.5)
    for step in range(200):
        logits = X @ W
        loss = F.cross_entropy(logits, Y) if name == "ce" else ((F.softmax(logits, -1) - F.one_hot(Y, 5).float())**2).sum(1).mean()
        opt.zero_grad(); loss.backward(); opt.step()
    acc = ((X @ W).argmax(1) == Y).float().mean()
    print(f"{name}: acc={acc:.3f}")
```

### 🔬 Experiment & Observe
CE reaches much higher accuracy from a confident, wrong initialization. With a zero init the gap is smaller. **Instinct:** CE's strength is recovering from confident mistakes.

### ⚠️ Failure Modes & Debugging
- Passing *probabilities* into `F.cross_entropy` (it expects raw logits) applies softmax twice, so learning is weak and slow.
- `F.nll_loss` expects *log-probs*. Passing logits gives nonsense.
- The target dtype must be `long` and the shape `(B,)`, not one-hot (unless you use label smoothing / soft targets).

### 🧠 Expert Insight
- LLM pretraining uses token-level CE averaged over all positions: `F.cross_entropy(logits.view(-1, V), targets.view(-1))`.
- **Label smoothing** (Szegedy et al., 2016) mixes the target with uniform; common in translation, rarely in LLM pretraining.
- Reward models use a *pairwise* logistic loss (Ch 39), which is also CE in disguise.

### ✅ Check Your Instinct
1. Why is MSE bad with softmax?
2. The CE gradient w.r.t. logits?
3. *(Coding)* Implement label-smoothed CE (ε = 0.1) and compare with `F.cross_entropy(..., label_smoothing=0.1)`.

<details><summary>Answers</summary>

1. Saturation multiplies the gradient by p(1−p) ≈ 0 when confidently wrong.
2. softmax − one-hot.
3. `loss = (1-ε)*nll + ε*(-log_softmax.mean(-1))`.
</details>

### 📌 Recap Card
- MSE for regression, CE for categories.
- CE gradient = p − y: strong when wrong.
- `F.cross_entropy` takes logits and integer targets.

> **Core intuition:** *Cross-entropy's log cancels softmax's exp, so the signal is loudest exactly when the model is most wrong.*

## 7.4 Numerically Stable Softmax and Log-Softmax: the Log-Sum-Exp Trick

### 🧭 The Problem First
LLM logits can reach 50–100 in fp32 and overflow even earlier in fp16 (max ≈ 65,504, and $e^{12} ≈ 162,755$). A naive softmax gives `inf/inf = NaN` and training dies.

### 💡 Intuition / Instinct
Softmax only cares about logit *differences*, so shift all logits so the largest is 0. Then every $e^{z}$ is ≤ 1 and at least one equals 1. No overflow, and the result is mathematically identical.

### 🖼️ Visual Mental Model

```text
 z = [1000, 1001, 1002] ──(-max)──▶ [-2, -1, 0] ──exp──▶ [0.135, 0.368, 1] ──norm──▶ [0.09, 0.24, 0.67]
```

### 📐 The Math, Gently
$$\text{LSE}(z) = m + \log\sum_j e^{z_j - m}, \quad m = \max_j z_j$$
$$\log\text{softmax}(z)_i = z_i - \text{LSE}(z)$$
Example: LSE([1000, 1000]) = 1000 + log 2 = 1000.693.

### 🛠️ Build It From Scratch

```python
import numpy as np, torch
z = np.array([1000., 1001., 1002.])
with np.errstate(over="ignore", invalid="ignore"):
    print("naive:", np.exp(z) / np.exp(z).sum())        # [nan nan nan]
def lse(z): m = z.max(); return m + np.log(np.exp(z - m).sum())
print("stable:", np.exp(z - lse(z)))                     # [0.09 0.245 0.665]

# fp16 danger
zt = torch.tensor([12., 11.], dtype=torch.float16)
print(torch.exp(zt))                                     # inf for 12
print(torch.softmax(zt.float(), -1))                     # compute softmax in fp32
```

### 🔬 Experiment & Observe
Compare `torch.log(torch.softmax(z, -1))` vs `torch.log_softmax(z, -1)` for z = [0, −200]: the first gives −inf for the second entry, the second gives exactly −200.

### ⚠️ Failure Modes & Debugging
- NaN loss in mixed precision is very often a softmax/LSE computed in fp16. Upcast to fp32 for softmax and loss (PyTorch autocast does this for you).
- Masking attention with `-inf` on an entire row gives a NaN softmax (all −inf). Use a large negative value or guarantee at least one unmasked position.

### 🧠 Expert Insight
FlashAttention's key trick (Ch 29) is an **online** LSE: it computes softmax in chunks by keeping a running max and running sum, which lets attention never materialize the full T×T matrix.

### ✅ Check Your Instinct
1. Why subtract the max, not the mean?
2. *(Coding)* Implement an online (streaming) LSE that processes values one chunk at a time.

<details><summary>Answers</summary>

1. The max guarantees every exponent is ≤ 0 (no overflow) and one is exactly 0 (no underflow of all terms).
2. Keep `m` and `s`; for each new chunk x: `m_new = max(m, x.max()); s = s*exp(m-m_new) + exp(x-m_new).sum(); m = m_new`; result `m + log s`.
</details>

### 📌 Recap Card
- Subtract the max before exp.
- Use `log_softmax` / `cross_entropy`, never `log(softmax)`.
- Do softmax in fp32 under mixed precision.
- Online LSE is the heart of FlashAttention.

> **Core intuition:** *Only differences matter, so anchor the largest logit at zero.*

## 7.5 Training an MLP: Our Engine, Then Idiomatic PyTorch

### 🧭 The Problem First
We have all the pieces. Now we need the standard training structure that every later chapter reuses: `nn.Module`, parameters, `forward`, a training loop, evaluation mode, and train/val splits.

### 💡 Intuition / Instinct
Every training script has the same skeleton: **data → model → loss → optimizer → loop (forward, loss, zero_grad, backward, step) → evaluate on held-out data**. Master this skeleton once. It is the same in nanoGPT and in frontier codebases (just scaled up).

### 🖼️ Visual Mental Model

```text
 for step:
   xb, yb = get_batch("train")
   logits = model(xb)                 # forward
   loss = F.cross_entropy(logits, yb)
   opt.zero_grad(set_to_none=True)
   loss.backward()                    # autograd
   opt.step()                         # update
   if step % eval_every == 0: evaluate on "val" under torch.no_grad(), model.eval()
```

### 📐 The Math, Gently
Classification accuracy vs loss: the loss measures confidence calibration; accuracy only measures the argmax. The loss can improve while accuracy stays flat (the model gets more confident on already-correct answers).

### 🛠️ Build It From Scratch

```python
# nanoforge/nn.py  (first version — grows in Ch 9, 10)
import torch, torch.nn as nn, torch.nn.functional as F

class MLP(nn.Module):
    def __init__(self, n_in, n_hidden, n_out, n_layers=2, act=nn.ReLU):
        super().__init__()
        dims = [n_in] + [n_hidden] * (n_layers - 1) + [n_out]
        layers = []
        for i in range(len(dims) - 1):
            layers.append(nn.Linear(dims[i], dims[i + 1]))
            if i < len(dims) - 2: layers.append(act())
        self.net = nn.Sequential(*layers)
    def forward(self, x): return self.net(x)

@torch.no_grad()
def evaluate(model, X, Y):
    model.eval()
    logits = model(X)
    out = F.cross_entropy(logits, Y).item(), (logits.argmax(-1) == Y).float().mean().item()
    model.train()
    return out
```

```python
# scripts/train_mlp_spirals.py
import math, torch, torch.nn.functional as F
from nanoforge.nn import MLP, evaluate
from nanoforge.utils import set_seed
set_seed(0)

def spirals(n=1500, k=3, noise=0.2):
    X, Y = [], []
    for c in range(k):
        t = torch.linspace(0.0, 1, n // k)
        r = t * 4
        th = t * 4 * math.pi + c * 2 * math.pi / k + noise * torch.randn(n // k)
        X.append(torch.stack([r * torch.cos(th), r * torch.sin(th)], 1)); Y.append(torch.full((n // k,), c))
    X, Y = torch.cat(X), torch.cat(Y); p = torch.randperm(len(X))
    return X[p], Y[p]

X, Y = spirals()
n = int(0.8 * len(X)); Xtr, Ytr, Xva, Yva = X[:n], Y[:n], X[n:], Y[n:]
model = MLP(2, 64, 3, n_layers=3)
opt = torch.optim.Adam(model.parameters(), lr=3e-3)
for step in range(2001):
    ix = torch.randint(0, n, (128,))
    loss = F.cross_entropy(model(Xtr[ix]), Ytr[ix])
    opt.zero_grad(set_to_none=True); loss.backward(); opt.step()
    if step % 400 == 0:
        vl, va = evaluate(model, Xva, Yva)
        print(f"step {step:4d} train {loss.item():.3f} | val loss {vl:.3f} acc {va:.3f}")
```

### 🔬 Experiment & Observe
- `n_layers=1` (linear): accuracy ~40%. `n_layers=3`: >95%. **Predict first.**
- Hidden 8 vs 256: underfitting vs possible overfitting. Watch the gap between train and val loss.
- Plot the decision boundary on a grid (`torch.meshgrid`) to *see* what the MLP learned.

### ⚠️ Failure Modes & Debugging
- Forgetting `model.eval()` / `torch.no_grad()` during evaluation: dropout stays active and memory is wasted.
- Evaluating on training data only: you can't detect overfitting.
- **The first sanity check:** overfit a *single batch* to ~0 loss. If you can't, there's a bug.

### 🧠 Expert Insight
Karpathy's "A Recipe for Training Neural Networks" (2019): become one with the data, set up an end-to-end skeleton, verify the initial loss (ln K), overfit one batch, then regularize. Following this recipe prevents most wasted weeks.
