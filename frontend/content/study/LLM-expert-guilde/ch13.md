## 13.1 Greedy Decoding and Its Repetition Trap

### 🧭 The Problem First
The model gives a distribution. The obvious choice is to always pick the most likely token. Why doesn't that give the best text?

### 💡 Intuition / Instinct
Greedy picks the locally best step, but language is full of *high-probability loops*: "the the the", "I don't know. I don't know." Once in a loop, the context makes the loop even more probable, a self-reinforcing trap. And the most likely *sequence* isn't made of the most likely *tokens* at each step. Human text is actually *not* maximally probable; it has surprise in it.

### 🖼️ Visual Mental Model

```text
 greedy: "the king is the king is the king is ..."
 sampled: "the king is dead, and his crown lies cold..."
```

### 📐 The Math, Gently
Greedy: $x_t = \arg\max_v P(v\mid x_{<t})$. This is deterministic, so the same prompt always gives the same output.
Human text has per-token probabilities spread widely (Holtzman et al., 2019): the typical human token is *not* the argmax.

### 🛠️ Build It From Scratch

```python
import torch, torch.nn.functional as F
@torch.no_grad()
def greedy(model, ctx, n_new, n_ctx):
    for _ in range(n_new):
        logits, _ = model(ctx[:, -n_ctx:])
        nxt = logits.argmax(-1, keepdim=True)          # (B, 1)
        ctx = torch.cat([ctx, nxt], dim=1)
    return ctx
# using the MLP LM from Ch 12:
out = greedy(model, torch.zeros(1, 8, dtype=torch.long), 200, 8)
print("".join(itos[i] for i in out[0, 8:].tolist()))
```

### 🔬 Experiment & Observe
The greedy output from the MLP LM quickly enters a loop ("the the the" or a repeated line). Count the distinct 10-grams in 500 generated characters: greedy has very few.

### ⚠️ Failure Modes & Debugging
Greedy is right for tasks with a single correct answer (math, code with tests, extraction), and wrong for open-ended writing.

### 🧠 Expert Insight
**Holtzman et al. (2019), "The Curious Case of Neural Text Degeneration":** introduced nucleus sampling and documented greedy/beam degeneration.

### ✅ Check Your Instinct
1. Why does greedy loop?

<details><summary>Answers</summary>

1. Repetition raises the probability of further repetition (a self-reinforcing context).
</details>

### 📌 Recap Card
- Greedy = argmax each step; deterministic.
- Loops and bland text for open-ended generation.
- Good for single-answer tasks.

> **Core intuition:** *Always choosing the safest word leads you in circles.*

## 13.2 Temperature: Flattening and Sharpening

### 🧭 The Problem First
Pure sampling from the model distribution sometimes picks absurd low-probability tokens (the long tail), and one bad token derails everything after it.

### 💡 Intuition / Instinct
Divide the logits by the temperature τ before the softmax (Ch 5.2):
- τ < 1 → sharper: safer and more repetitive.
- τ > 1 → flatter: more creative and more errors.
- τ → 0 → greedy.

### 🖼️ Visual Mental Model

```text
 τ=0.3  █████████▇▁▁   focused
 τ=1.0  ██████▅▃▂▁▁▁   model's own belief
 τ=1.5  ████▄▄▃▃▂▂▂▁   adventurous
```

### 📐 The Math, Gently
$p_i(\tau) = \frac{e^{z_i/\tau}}{\sum_j e^{z_j/\tau}}$. The entropy increases monotonically with τ.
Example: z = [2, 1, 0]. At τ = 0.5: [0.867, 0.117, 0.016]. At τ = 2: [0.506, 0.307, 0.186].

### 🛠️ Build It From Scratch

```python
def entropy_bits(p): return -(p * p.clamp_min(1e-12).log2()).sum().item()
z = torch.tensor([2.0, 1.0, 0.0])
for tau in [0.1, 0.5, 1.0, 2.0, 10.0]:
    p = F.softmax(z / tau, -1); print(tau, p.numpy().round(3), f"H={entropy_bits(p):.2f} bits")
```

### 🔬 Experiment & Observe
Generate 300 characters from the MLP LM at τ ∈ {0.5, 0.8, 1.0, 1.3}. Low τ is repetitive; high τ is misspelled gibberish. For character models, ~0.8 is a good middle.

### ⚠️ Failure Modes & Debugging
τ = 0 → division by zero; route it to greedy. Apply the temperature to *logits*, not probabilities.

### 🧠 Expert Insight
Temperature is also used during *training*: in distillation (soft targets, Ch 42), in contrastive losses, and to generate diverse RL rollouts (Ch 41, often τ = 1.0).

### ✅ Check Your Instinct
1. Does temperature change the argmax?

<details><summary>Answers</summary>

1. No (for τ > 0); it only changes how peaked the distribution is.
</details>

### 📌 Recap Card
- Logits / τ, then softmax.
- τ < 1 focused, τ > 1 diverse, τ → 0 greedy.

> **Core intuition:** *Temperature sets how much the model trusts its own favourite.*

## 13.3 Top-k and Top-p (Nucleus) Sampling

### 🧭 The Problem First
Even at τ = 1, the tail of 50K tokens holds significant *total* mass (say 10%), so a nonsense token is sampled often. We want to cut the tail without becoming greedy.

### 💡 Intuition / Instinct
- **Top-k:** keep only the k most likely tokens, then renormalize. Simple, but k is fixed: when the model is confident, k = 50 includes junk; when it's uncertain, k = 50 may cut valid options.
- **Top-p (nucleus):** keep the smallest set of tokens whose cumulative probability ≥ p. The set adapts: 1–2 tokens when the model is confident, hundreds when it's unsure.

### 🖼️ Visual Mental Model

```text
 confident:  ██████████▂▁▁▁   top-p(0.9) keeps 1-2 tokens
 uncertain:  ▃▃▃▃▃▂▂▂▂▂▂▁▁▁   top-p(0.9) keeps many tokens
```

### 📐 The Math, Gently
Sort the probabilities in descending order: $p_{(1)} \ge p_{(2)} \ge\dots$. The nucleus is $\{1..m\}$ with $m = \min\{m: \sum_{i\le m} p_{(i)} \ge p\}$.
Example: [0.5, 0.3, 0.1, 0.05, 0.05] with p = 0.85 keeps the first 3 (0.9 ≥ 0.85), renormalized to [0.556, 0.333, 0.111].

### 🛠️ Build It From Scratch

```python
def top_k_filter(logits, k):                        # (B, V)
    if k is None or k <= 0 or k >= logits.size(-1): return logits
    kth = torch.topk(logits, k, dim=-1).values[..., -1:]
    return logits.masked_fill(logits < kth, float("-inf"))

def top_p_filter(logits, p):                        # (B, V)
    if p is None or p >= 1.0: return logits
    sorted_logits, idx = torch.sort(logits, descending=True, dim=-1)
    cum = F.softmax(sorted_logits, -1).cumsum(-1)
    remove = cum - F.softmax(sorted_logits, -1) >= p   # remove tokens whose preceding mass already ≥ p
    sorted_logits = sorted_logits.masked_fill(remove, float("-inf"))
    return torch.full_like(logits, float("-inf")).scatter(-1, idx, sorted_logits)

z = torch.log(torch.tensor([[0.5, 0.3, 0.1, 0.05, 0.05]]))
print(F.softmax(top_p_filter(z, 0.85), -1))   # [0.556 0.333 0.111 0 0]
print(F.softmax(top_k_filter(z, 2), -1))      # [0.625 0.375 0 0 0]
```

### 🔬 Experiment & Observe
Log the nucleus size at each generation step for p = 0.9. It varies wildly: 1 after "q" (→ "u"), and dozens at the start of a word.

### ⚠️ Failure Modes & Debugging
- Off-by-one in the top-p cutoff that removes *all* tokens: always keep at least the top-1 (the `cum - p_i >= p` formulation guarantees it).
- Applying top-k/top-p *before* temperature vs after: the convention (HF) is temperature first, then filter.

### 🧠 Expert Insight
Fan et al. (2018) top-k; Holtzman et al. (2019) top-p. Common production defaults: temperature 0.7–1.0, top-p 0.9–0.95.

### ✅ Check Your Instinct
1. Why is top-p more adaptive than top-k?
2. *(Coding)* Measure the average nucleus size over 500 generated steps.

<details><summary>Answers</summary>

1. The number of kept tokens depends on the model's confidence at each step.
2. Count the non-`-inf` entries after filtering.
</details>

### 📌 Recap Card
- Top-k: fixed count. Top-p: fixed mass (adaptive).
- Both cut the unreliable tail.
- Apply after temperature.

> **Core intuition:** *Only consider the options the model genuinely finds plausible.*

## 13.4 Repetition Penalties, Min-p, and Beam Search

### 🧭 The Problem First
Even with top-p, long generations drift into repetition, and for some tasks (translation, short exact answers) we want the most likely *sequence*, not a random one.

### 💡 Intuition / Instinct
- **Repetition/frequency/presence penalties:** reduce the logits of tokens already generated. Presence = a flat penalty if the token appeared; frequency = proportional to the count; the CTRL-style repetition penalty divides positive logits by θ.
- **Min-p:** keep tokens with $p \ge p_{min}\cdot p_{max}$. The cutoff scales with the top token's confidence (strong at high temperature).
- **Beam search:** keep the B best partial sequences by total log-probability, extend each, and keep the best B again. It approximates the argmax sequence. It's good for translation, bad for open-ended text (bland and repetitive).

### 🖼️ Visual Mental Model

```text
 beam B=2:
 step1: "the"(-0.5)  "a"(-0.9)
 step2: "the cat"(-1.2) "the dog"(-1.4) "a cat"(-1.6) ... keep top 2
```

### 📐 The Math, Gently
Frequency/presence (OpenAI-style): $z_v \leftarrow z_v - \alpha\,c_v - \beta\,\mathbb{1}[c_v > 0]$.
Beam score: $\sum_t \log p(x_t\mid x_{<t})$, often normalized by $\text{length}^\gamma$ to avoid favouring short outputs.

### 🛠️ Build It From Scratch

```python
def apply_penalties(logits, generated, freq=0.0, presence=0.0, rep=1.0):
    """logits: (B, V); generated: (B, L) token ids so far"""
    if generated.numel() == 0 or (freq == 0 and presence == 0 and rep == 1.0): return logits
    B, V = logits.shape
    counts = torch.zeros(B, V, device=logits.device).scatter_add_(1, generated, torch.ones_like(generated, dtype=torch.float))
    logits = logits - freq * counts - presence * (counts > 0).float()
    if rep != 1.0:
        seen = counts > 0
        logits = torch.where(seen & (logits > 0), logits / rep, torch.where(seen, logits * rep, logits))
    return logits

def min_p_filter(logits, min_p):
    if not min_p: return logits
    probs = F.softmax(logits, -1)
    thresh = min_p * probs.max(-1, keepdim=True).values
    return logits.masked_fill(probs < thresh, float("-inf"))

@torch.no_grad()
def beam_search(model, ctx, n_new, n_ctx, beam=4, len_pen=0.7):
    beams = [(ctx, 0.0)]
    for _ in range(n_new):
        cand = []
        for seq, score in beams:
            logits, _ = model(seq[:, -n_ctx:])              # (1, T, V) interface (see 13.5)
            logp = F.log_softmax(logits[:, -1].float(), -1)[0]  # (V,)
            top = logp.topk(beam)
            for lp, ix in zip(top.values, top.indices):
                cand.append((torch.cat([seq, ix.view(1, 1)], 1), score + lp.item()))
        L = cand[0][0].size(1) - ctx.size(1)
        beams = sorted(cand, key=lambda c: c[1] / (L ** len_pen), reverse=True)[:beam]
    return beams[0][0]
```

### 🔬 Experiment & Observe
- Generate with frequency penalty 0, 0.5, 1.5: repetition drops, but at high values the model avoids even necessary repeats (like "the"), and quality suffers.
- Beam search on the MLP LM: very likely, very boring text.

### ⚠️ Failure Modes & Debugging
- Penalizing the *prompt's* tokens too (usually unintended); pass only the generated tokens.
- Beam search without length normalization prefers short sequences / early EOS.

### 🧠 Expert Insight
- Keskar et al. (2019), CTRL: the repetition penalty.
- **Nguyen et al. (2024), min-p sampling:** popular in open-source inference engines.
- Beam search is still used in speech recognition and machine translation, and rarely in chat LLMs.

### ✅ Check Your Instinct
1. Why is min-p adaptive?
2. Why does beam search produce bland text?

<details><summary>Answers</summary>

1. The threshold scales with the top token's probability.
2. It maximizes likelihood, and high-likelihood text is generic.
</details>

### 📌 Recap Card
- Penalties reduce repetition; min-p is an adaptive tail cut.
- Beam search ≈ most likely sequence; good for constrained tasks.

> **Core intuition:** *Decoding is a policy: choose how much to explore, how much to repeat, how much to trust.*

## 13.5 A Reusable `generate()` for the Whole Book

### 🧭 The Problem First
Every model from here to the Capstone needs generation. One robust, tested function avoids a dozen buggy copies.

### 💡 Intuition / Instinct
Standardize the interface: the model takes `(B, T)` ids and returns `(B, T, V)` logits (all our sequence models will follow this). `generate` crops the context to the model's max length, takes the last position's logits, applies penalties → temperature → filters, samples, appends, and stops at EOS.

### 🖼️ Visual Mental Model

```text
 ids (B,T) → crop to block_size → model → logits[:, -1, :] (B,V)
   → penalties → /τ → top-k → top-p → min-p → softmax → multinomial → append → repeat
```

### 📐 The Math, Gently
Order of operations (convention): penalties → temperature → top-k → top-p → min-p → sample.

### 🛠️ Build It From Scratch

```python
# nanoforge/sampling.py
import torch, torch.nn.functional as F

def top_k_filter(logits, k):
    if not k or k >= logits.size(-1): return logits
    kth = torch.topk(logits, k, dim=-1).values[..., -1:]
    return logits.masked_fill(logits < kth, float("-inf"))

def top_p_filter(logits, p):
    if p is None or p >= 1.0: return logits
    s, idx = torch.sort(logits, descending=True, dim=-1)
    probs = F.softmax(s, -1)
    remove = (probs.cumsum(-1) - probs) >= p
    s = s.masked_fill(remove, float("-inf"))
    return torch.full_like(logits, float("-inf")).scatter(-1, idx, s)

def min_p_filter(logits, min_p):
    if not min_p: return logits
    probs = F.softmax(logits, -1)
    return logits.masked_fill(probs < min_p * probs.max(-1, keepdim=True).values, float("-inf"))

def apply_penalties(logits, generated, freq=0.0, presence=0.0):
    if generated is None or generated.numel() == 0 or (freq == 0 and presence == 0): return logits
    counts = torch.zeros_like(logits).scatter_add_(1, generated, torch.ones_like(generated, dtype=logits.dtype))
    return logits - freq * counts - presence * (counts > 0).to(logits.dtype)

@torch.no_grad()
def generate(model, idx, max_new_tokens, block_size, temperature=1.0, top_k=None, top_p=None,
             min_p=None, freq_penalty=0.0, presence_penalty=0.0, eos_id=None, generator=None):
    """idx: (B, T) prompt ids. model(idx) -> (logits (B,T,V), loss). Returns (B, T + new)."""
    was_training = model.training; model.eval()
    start = idx.size(1)
    finished = torch.zeros(idx.size(0), dtype=torch.bool, device=idx.device)
    for _ in range(max_new_tokens):
        logits, _ = model(idx[:, -block_size:])
        logits = logits[:, -1, :].float()                               # (B, V)
        logits = apply_penalties(logits, idx[:, start:], freq_penalty, presence_penalty)
        if temperature == 0:
            nxt = logits.argmax(-1, keepdim=True)
        else:
            logits = logits / temperature
            logits = min_p_filter(top_p_filter(top_k_filter(logits, top_k), top_p), min_p)
            nxt = torch.multinomial(F.softmax(logits, -1), 1, generator=generator)   # (B, 1)
        if eos_id is not None:
            nxt = torch.where(finished[:, None], torch.full_like(nxt, eos_id), nxt)
            finished |= nxt.squeeze(1) == eos_id
        idx = torch.cat([idx, nxt], dim=1)
        if eos_id is not None and finished.all(): break
    model.train(was_training)
    return idx
```

To use `generate` with the Ch 12 MLP LM, wrap it so it returns `(B, T, V)`:

```python
class WindowWrapper(torch.nn.Module):
    """Adapts a fixed-window model (B, n_ctx)->(B, V) to the (B,T)->(B,T,V) interface (last position only)."""
    def __init__(self, m, n_ctx): super().__init__(); self.m, self.n_ctx = m, n_ctx
    def forward(self, idx, targets=None):
        ctx = idx[:, -self.n_ctx:]
        if ctx.size(1) < self.n_ctx: ctx = F.pad(ctx, (self.n_ctx - ctx.size(1), 0))
        return self.m(ctx)[0][:, None, :], None
from nanoforge.sampling import generate
out = generate(WindowWrapper(model, 8), torch.zeros(1, 1, dtype=torch.long), 300, block_size=8, temperature=0.8, top_p=0.95)
print("".join(itos[i] for i in out[0].tolist()))
```
