## 22.1 Heuristic Filters (Gopher/C4 Rules)

### 🧭 The Problem First
Deduplicated web text still contains keyword spam, machine-generated gibberish, lists of product codes, pages of "lorem ipsum", and navigation fragments. We need cheap, transparent rules to remove the obvious junk.

### 💡 Intuition / Instinct
Good prose has recognizable statistics: reasonable word lengths, a normal ratio of symbols, lines that end with punctuation, little repetition, and common stop words ("the", "and", "of"). Spam and junk violate these. Each rule is a simple sanity check; together they remove a large fraction of junk with few false positives.

### 🖼️ Visual Mental Model

```text
 doc ─▶ [word count 50..100k] ─▶ [mean word len 3..10] ─▶ [symbol/word < 0.1]
     ─▶ [≥ 2 stop words] ─▶ [% lines ending in punct ≥ ...] ─▶ [dup-line fraction < 0.3] ─▶ keep
```

### 📐 The Math, Gently
Gopher (Rae et al., 2021) rules include: 50 ≤ words ≤ 100,000; mean word length in [3, 10]; symbol-to-word ratio < 0.1 for "#" and "…"; > 80% of words contain an alphabetic character; ≥ 2 of the stop words {the, be, to, of, and, that, have, with}; fraction of duplicate lines < 0.3; top-2-gram character fraction < 0.2.

### 🛠️ Build It From Scratch

```python
# nanoforge/data/filters.py
import re
from collections import Counter

STOP = {"the", "be", "to", "of", "and", "that", "have", "with"}

def gopher_quality(text):
    """Returns (keep: bool, reason: str)."""
    words = text.split(); n = len(words)
    if not 50 <= n <= 100_000: return False, "word_count"
    mean_len = sum(len(w) for w in words) / n
    if not 3 <= mean_len <= 10: return False, "mean_word_len"
    if (text.count("#") + text.count("...") + text.count("…")) / n > 0.1: return False, "symbol_ratio"
    if sum(bool(re.search(r"[a-zA-Z]", w)) for w in words) / n < 0.8: return False, "alpha_ratio"
    if len(STOP & {w.lower() for w in words}) < 2: return False, "stop_words"
    lines = [l for l in text.split("\n") if l.strip()]
    if lines:
        if sum(l.strip().startswith(("•", "-", "*")) for l in lines) / len(lines) > 0.9: return False, "bullets"
        if sum(l.rstrip().endswith("...") for l in lines) / len(lines) > 0.3: return False, "ellipsis"
        dup = sum(c - 1 for c in Counter(lines).values() if c > 1) / len(lines)
        if dup > 0.3: return False, "dup_lines"
    bigrams = Counter(zip(words, words[1:]))
    if bigrams:
        (top, c), = bigrams.most_common(1)
        if c * (len(top[0]) + len(top[1])) / max(1, len(text)) > 0.2: return False, "top_bigram"
    return True, "ok"

def c4_line_filter(text):
    """C4-style: keep lines ending in terminal punctuation, drop javascript/cookie/lorem lines."""
    keep = []
    for l in text.split("\n"):
        s = l.strip()
        if not s: continue
        low = s.lower()
        if any(k in low for k in ("javascript", "cookie", "lorem ipsum", "terms of use")): continue
        if s.endswith((".", "!", "?", '"', "'")) and len(s.split()) >= 3: keep.append(s)
    return "\n".join(keep)
```

### 🔬 Experiment & Observe
Run `gopher_quality` over 1,000 raw pages and count the rejections by reason. Read 10 rejected and 10 kept documents per reason, and adjust any thresholds that remove good content in *your* domain (e.g. code, where "#" and symbols are normal).

### ⚠️ Failure Modes & Debugging
- Heuristics built for English web prose can destroy code, math, poetry and non-English text. Apply filters **per domain/language**.
- C4's terminal-punctuation rule removes lists and code and is too aggressive for many domains.

### 🧠 Expert Insight
- **Raffel et al. (2019), C4.** **Rae et al. (2021), Gopher/MassiveText.**
- FineWeb added custom heuristics (e.g. the fraction of lines ending in punctuation, short-line ratios) validated by *training small models and measuring benchmarks*. That's the right way to tune filters: ablate them by training.

### ✅ Check Your Instinct
1. Why is the stop-word rule effective?
2. Why can't you apply these filters to code?

<details><summary>Answers</summary>

1. Natural prose nearly always contains common function words; spam and lists often don't.
2. Code has different statistics (symbols, short lines, no stop words).
</details>

### 📌 Recap Card
- Cheap statistical rules remove obvious junk.
- Inspect the rejections by reason; tune per domain.
- Validate filters by training small models.

> **Core intuition:** *Junk text has unnatural statistics, so check the vital signs.*

## 22.2 Model-Based Quality Classifiers (fastText-Style, Perplexity Filters)

### 🧭 The Problem First
Heuristics catch garbage but can't distinguish *mediocre* from *excellent*. Clickbait SEO articles pass every heuristic.

### 💡 Intuition / Instinct
Train a classifier to recognize "high-quality" text by example:
- **Positive** examples: text like the content you want (Wikipedia, textbooks, curated references; or documents that a strong LLM rated "educational").
- **Negative** examples: random web text.

Then score every document and keep the top X%. A second approach is **perplexity filtering**: score each document with a small LM trained on high-quality text and keep low-perplexity documents (they look like the good text).

### 🖼️ Visual Mental Model

```text
 positives: Wikipedia / textbooks / LLM-rated "educational"   negatives: random CC
            │                                                  │
            └──────────── train bag-of-ngrams logistic classifier ───────┘
 every doc → p(high quality) → keep top 10–30%
```

### 📐 The Math, Gently
A fastText-style classifier: average the embeddings of word unigrams and bigrams (hashed), then logistic regression. $p = \sigma(w^\top\bar e + b)$. Train with binary CE.
Perplexity filter: keep documents with $\text{PPL}_{\text{ref}}(d) < \tau$, or the lowest-PPL bucket.

### 🛠️ Build It From Scratch

```python
# nanoforge/data/quality_clf.py
import re, zlib, torch, torch.nn as nn, torch.nn.functional as F

class HashedNgramClassifier(nn.Module):
    """fastText-like: hashed unigram+bigram embeddings, mean-pooled, linear head."""
    def __init__(self, n_buckets=2**20, dim=64):
        super().__init__(); self.emb = nn.EmbeddingBag(n_buckets, dim, mode="mean"); self.head = nn.Linear(dim, 1)
        self.n = n_buckets
    def featurize(self, text):
        w = re.findall(r"\w+", text.lower())[:2000]
        grams = w + [a + " " + b for a, b in zip(w, w[1:])]
        return torch.tensor([zlib.crc32(g.encode()) % self.n for g in grams] or [0])
    def forward(self, texts):
        ids = [self.featurize(t) for t in texts]
        offsets = torch.tensor([0] + [len(i) for i in ids[:-1]]).cumsum(0)
        return self.head(self.emb(torch.cat(ids), offsets)).squeeze(-1)   # logits (B,)

def train_quality_clf(pos, neg, epochs=3, lr=0.05, bs=64):
    clf = HashedNgramClassifier(); opt = torch.optim.Adagrad(clf.parameters(), lr=lr)
    data = [(t, 1.0) for t in pos] + [(t, 0.0) for t in neg]
    for ep in range(epochs):
        perm = torch.randperm(len(data))
        for i in range(0, len(data), bs):
            batch = [data[j] for j in perm[i:i + bs]]
            logits = clf([t for t, _ in batch]); y = torch.tensor([l for _, l in batch])
            loss = F.binary_cross_entropy_with_logits(logits, y)
            opt.zero_grad(); loss.backward(); opt.step()
        print(f"epoch {ep} loss {loss.item():.3f}")
    return clf

@torch.no_grad()
def perplexity_score(model, tok, text, block_size=256, device="cpu"):
    ids = torch.tensor([tok.encode_ordinary(text)[: block_size + 1]], device=device)
    if ids.size(1) < 2: return float("inf")
    _, loss = model(ids[:, :-1], ids[:, 1:])
    return float(torch.exp(loss))
```

### 🔬 Experiment & Observe
Train the classifier with Wikipedia paragraphs as positives vs your raw crawl as negatives. Sort the crawl by score and read the top 10 and bottom 10. Then train two micro GPTs, one on the top 30% and one on random 30%, at equal tokens, and compare their val loss on a *clean* held-out set (e.g. Wikipedia). **This is exactly how DCLM/FineWeb-Edu validated their filters.**

### ⚠️ Failure Modes & Debugging
- **Homogenization:** strict filtering toward Wikipedia-like text removes dialects, informal registers and minority perspectives. Keep some diversity (sample by score rather than a hard threshold, or mix in unfiltered data).
- Perplexity filters favour repetitive/simple text (low PPL). Combine them with other signals.

### 🧠 Expert Insight
- **FineWeb-Edu (2024):** Llama-3-70B rated 450K samples for educational value (0–5); a small classifier trained on those ratings was used to filter 15T tokens, with big MMLU/ARC gains.
- **DCLM (2024):** a fastText classifier (OpenHermes/ELI5 positives) was the best filter tested.
- **Wenzek et al. (2019), CCNet:** perplexity filtering with Wikipedia-trained KenLM.

### ✅ Check Your Instinct
1. What's the risk of an overly strict quality filter?
2. How should you validate a filter?

<details><summary>Answers</summary>

1. Loss of diversity and bias toward one register or demographic of text.
2. Train small models on filtered vs unfiltered data at equal tokens and compare benchmarks/val loss.
</details>

### 📌 Recap Card
- Classifier: positives = what you want, negatives = random web.
- Perplexity filtering with a reference LM.
- Validate by training small models; keep diversity.

> **Core intuition:** *Teach a cheap model to recognize the text you wish you had more of.*

## 22.3 PII Detection and Redaction

### 🧭 The Problem First
Web text contains emails, phone numbers, addresses, ID numbers and credentials. Models can memorize and regurgitate them (Carlini et al., 2021 extracted verbatim personal data from GPT-2).

### 💡 Intuition / Instinct
Detect PII with patterns (regexes for emails, phones, IPs, credit cards with Luhn checks, API keys) plus, optionally, a named-entity model for names and addresses. Then **replace it with typed placeholders** (`<EMAIL>`, `<PHONE>`) rather than deleting the whole document, which preserves the text's structure. Deduplication *also* reduces memorization risk dramatically.

### 🖼️ Visual Mental Model

```text
 "Contact john.doe@acme.com or +1 (555) 123-4567"
   → "Contact <EMAIL> or <PHONE>"
```

### 📐 The Math, Gently
Luhn checksum for card numbers: double every second digit from the right, subtract 9 if > 9, sum; valid iff the sum ≡ 0 (mod 10). This removes most random 16-digit false positives.

### 🛠️ Build It From Scratch

```python
# nanoforge/data/pii.py
import re
PATTERNS = {
    "EMAIL": re.compile(r"\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}\b"),
    "PHONE": re.compile(r"(?<!\w)(?:\+?\d{1,3}[\s.-]?)?(?:\(\d{2,4}\)[\s.-]?)?\d{3,4}[\s.-]\d{3,4}(?:[\s.-]\d{2,4})?(?!\w)"),
    "IPV4":  re.compile(r"\b(?:(?:25[0-5]|2[0-4]\d|1?\d?\d)\.){3}(?:25[0-5]|2[0-4]\d|1?\d?\d)\b"),
    "KEY":   re.compile(r"\b(?:sk|pk|api|key|token)[-_][A-Za-z0-9]{16,}\b|\bAKIA[0-9A-Z]{16}\b"),
}
CARD = re.compile(r"\b(?:\d[ -]?){13,19}\b")

def luhn_ok(num):
    d = [int(c) for c in re.sub(r"\D", "", num)][::-1]
    s = sum(d[0::2]) + sum(sum(divmod(2 * x, 10)) for x in d[1::2])
    return len(d) >= 13 and s % 10 == 0

def redact_pii(text):
    counts = {}
    for name, pat in PATTERNS.items():
        text, n = pat.subn(f"<{name}>", text); counts[name] = n
    def card_sub(m):
        if luhn_ok(m.group()): counts["CARD"] = counts.get("CARD", 0) + 1; return "<CARD>"
        return m.group()
    text = CARD.sub(card_sub, text)
    return text, counts
```

```python
print(redact_pii("Mail jane@x.org, call +1 (555) 123-4567, card 4111 1111 1111 1111, server 10.0.0.1, key sk_live_ABCDEF1234567890abcd"))
```

### 🔬 Experiment & Observe
Run the redactor on 1,000 documents and inspect the *false positives* (version numbers matched as IPs, dates matched as phones). Tune the patterns; precision matters, since over-redaction damages the data.

### ⚠️ Failure Modes & Debugging
- Regex phone patterns match dates and product codes. Test on real data.
- Names and addresses need NER (e.g. spaCy, Presidio). Regexes can't catch them.
- Redact consistently in both training data and eval data, or the model learns placeholder artefacts.

### 🧠 Expert Insight
- **Carlini et al. (2021), "Extracting Training Data from Large Language Models"**; **Carlini et al. (2023):** memorization grows with model size and duplication.
- **StarCoder** trained a dedicated PII model for code (keys, emails, IPs).
- **Microsoft Presidio** is a common open-source PII toolkit.

### ✅ Check Your Instinct
1. Why redact rather than drop documents?
2. What else besides redaction reduces memorization?

<details><summary>Answers</summary>

1. It keeps the useful content and structure while removing the sensitive spans.
2. Deduplication (repeated text is memorized most), and fewer epochs.
</details>

### 📌 Recap Card
- Regex + checksums for structured PII; NER for names.
- Replace with typed placeholders.
- Measure false positives; dedup reduces memorization.

> **Core intuition:** *Keep the knowledge, remove the people.*

## 22.4 Toxicity Filtering and Its Trade-offs

### 🧭 The Problem First
Web text contains hate speech, harassment and explicit content. A model trained on it reproduces it. But aggressive filtering has costs.

### 💡 Intuition / Instinct
Score each document with a toxicity classifier (or wordlists as a crude first pass) and remove or down-weight the highly toxic ones. **Trade-off:** filtering removes the model's ability to *recognize* toxicity (hurting moderation and safety classifiers) and disproportionately removes text by or about marginalized groups (wordlists flag reclaimed terms and identity mentions). Modern practice: filter only the most extreme content in pretraining, and teach behaviour in post-training (Ch 42).

### 🖼️ Visual Mental Model

```text
 toxicity score distribution:  ▇▇▇▇▇▅▃▂▁▁▁ ▏ ← drop only the extreme tail (e.g. > 0.9)
 behaviour (refusing, being polite) ← taught later by SFT/RLHF, not by starving the model of knowledge
```

### 📐 The Math, Gently
Soft down-weighting: sample document d with probability $\propto (1 - s_d)^\gamma$ rather than a hard cut, which preserves some exposure.

### 🛠️ Build It From Scratch

```python
# nanoforge/data/toxicity.py
import re
def wordlist_score(text, bad_words):
    toks = re.findall(r"\w+", text.lower())
    return sum(t in bad_words for t in toks) / max(1, len(toks))
def keep_prob(score, gamma=4.0, hard_cut=0.9):
    if score >= hard_cut: return 0.0
    return (1 - score) ** gamma
# For a real classifier: train HashedNgramClassifier (22.2) on a labelled toxicity dataset
# (e.g. Jigsaw Toxic Comments) and use its sigmoid output as `score`.
```

### 🔬 Experiment & Observe
Apply a wordlist filter to a sample and read the flagged documents. You'll find medical texts, discussions *about* discrimination, and literature being flagged. That is the bias problem made concrete.

### ⚠️ Failure Modes & Debugging
- Wordlist filters have high false-positive rates on identity terms.
- Over-filtering yields models that can't discuss sensitive topics helpfully.

### 🧠 Expert Insight
- **Dodge et al. (2021):** C4's blocklist disproportionately removed text about LGBTQ+ people and in African American English.
- **Longpre et al. (2023), "A Pretrainer's Guide to Training Data":** toxicity filtering reduced toxic generation but hurt toxicity *identification*.
- **Korbak et al. (2023):** "pretraining with human feedback", where conditioning on control tokens (good/bad) can beat filtering.

### ✅ Check Your Instinct
1. Why might you keep some toxic data?

<details><summary>Answers</summary>

1. So the model can recognize, classify and discuss harmful content; behaviour is shaped later in post-training.
</details>

### 📌 Recap Card
- Filter only the extreme tail; down-weight the rest.
- Beware wordlist bias.
- Teach behaviour in post-training.

> **Core intuition:** *Remove the poison, but let the model learn what poison looks like.*

## 22.5 Domain Mixing, Upsampling and Data Schedules

### 🧭 The Problem First
You have 500B web tokens, 50B code, 5B math and 2B textbook tokens. Training on the natural proportions under-weights small, high-value sources. How much of each should the model see, and when?

### 💡 Intuition / Instinct
- **Mixture weights:** decide the fraction of each domain in the training stream. Upsample small high-quality sources (repeat them 2–4 epochs; Ch 10.5 says ~4 epochs is nearly free), and downsample huge noisy ones.
- **Temperature sampling** (as for languages, Ch 16.5): $p_d \propto n_d^\alpha$.
- **Learned mixtures (DoReMi):** train a small proxy model and increase the weights of domains where it lags a reference model the most.
- **Curriculum / annealing:** at the end of training (during the LR decay), switch to a higher-quality mix. Late tokens have an outsized effect on the final model.

### 🖼️ Visual Mental Model

```text
 tokens ─────────────────────────────────────────────────────▶
 [ phase 1: broad mix (web-heavy)              ][ anneal: high-quality mix, LR→0 ]
```

### 📐 The Math, Gently
Epochs of domain d = $\frac{w_d \cdot D_{total}}{n_d}$. Keep this ≤ ~4 for most sources.
Example: 100B total tokens, math weight 10%, math corpus 5B → 2 epochs ✓. Textbooks weight 5% with 1B → 5 epochs (borderline).
DoReMi update: $w_d \leftarrow w_d\cdot\exp(\eta\cdot\text{excess\_loss}_d)$, then renormalize.

### 🛠️ Build It From Scratch

```python
# nanoforge/data/mixture.py
import numpy as np

def temperature_weights(sizes: dict, alpha=0.5):
    w = {k: v ** alpha for k, v in sizes.items()}; z = sum(w.values())
    return {k: v / z for k, v in w.items()}

def epochs_per_domain(weights, sizes, total_tokens):
    return {k: weights[k] * total_tokens / sizes[k] for k in weights}

def doremi_step(weights, proxy_loss, ref_loss, eta=1.0, smoothing=1e-3):
    ex = {k: max(proxy_loss[k] - ref_loss[k], 0.0) for k in weights}
    w = {k: weights[k] * np.exp(eta * ex[k]) for k in weights}; z = sum(w.values())
    K = len(w)
    return {k: (1 - smoothing) * v / z + smoothing / K for k, v in w.items()}

class MixtureSampler:
    """Yields domain names according to weights; switch weights for annealing phase."""
    def __init__(self, weights, seed=0): self.set(weights); self.rng = np.random.default_rng(seed)
    def set(self, weights): self.names, self.p = list(weights), np.array(list(weights.values())) / sum(weights.values())
    def __iter__(self):
        while True: yield self.names[self.rng.choice(len(self.names), p=self.p)]

sizes = {"web": 500e9, "code": 50e9, "math": 5e9, "books": 2e9}
w = temperature_weights(sizes, 0.5); print({k: round(v, 3) for k, v in w.items()})
print({k: round(v, 2) for k, v in epochs_per_domain(w, sizes, 100e9).items()})
```

### 🔬 Experiment & Observe
With your Capstone corpus plus TinyStories/web data, train three micro models with domain weights of 10%, 30% and 60% for your domain. Evaluate on (a) held-out domain text and (b) general text. You'll see the trade-off curve: more domain data means better domain loss and worse general loss.

### ⚠️ Failure Modes & Debugging
- Upsampling tiny sources too much (> 10 epochs) → memorization and overfitting.
- Mixture weights defined in *documents* vs *tokens* differ hugely. Always use tokens.

### 🧠 Expert Insight
- **Xie et al. (2023), DoReMi:** learned mixtures improved downstream accuracy and speed.
- **Llama 3 (2024):** annealing on high-quality data at the end of training improved GSM8K/MATH significantly for 8B.
- **OLMo 2 (2024)** "mid-training": a high-quality mixture during the LR decay.

### ✅ Check Your Instinct
1. Why anneal on high-quality data at the end?
2. Epochs for a 2B-token source at weight 5% of 200B training tokens?

<details><summary>Answers</summary>

1. As the LR decays, the final tokens strongly shape the converged model; high-quality data there improves final capabilities.
2. 0.05 × 200 / 2 = 5 epochs.
</details>

### 📌 Recap Card
- Mixture weights in tokens; keep epochs ≤ ~4.
- Temperature sampling or DoReMi to set the weights.
- Anneal on the best data at the end.

> **Core intuition:** *What the model sees, how often, and when, shapes who it becomes.*
