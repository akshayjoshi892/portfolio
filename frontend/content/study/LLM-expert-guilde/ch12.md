## 12.1 One-Hot Vectors and Their Failure

### 🧭 The Problem First
We fed the bigram a one-hot vector: a V-length vector with a single 1. With a context of 8 characters, that's 8V inputs. And every token is equally different from every other one.

### 💡 Intuition / Instinct
One-hot vectors are *orthogonal*: the dot product between "cat" and "dog" is 0, the same as between "cat" and "democracy". They carry **identity but no similarity**. Anything learned about "cat" transfers nothing to "dog". With 50K words, that's 50K isolated islands of knowledge.

### 🖼️ Visual Mental Model

```text
 one-hot:  cat = [0 0 1 0 0 ... 0]     dog = [0 0 0 0 1 ... 0]     cat·dog = 0
 embedding: cat = [0.8, 0.1, -0.3]      dog = [0.7, 0.2, -0.2]      cat·dog high
```

### 📐 The Math, Gently
$\text{onehot}(i)^\top W = W_i$: multiplying a one-hot by a matrix just selects a row. So "one-hot then linear" = "look up row i", and an embedding table is exactly that, done efficiently.

### 🛠️ Build It From Scratch

```python
import torch, torch.nn.functional as F
V, C = 10, 4
W = torch.randn(V, C)
i = torch.tensor([3, 7])
print(torch.allclose(F.one_hot(i, V).float() @ W, W[i]))    # True: embedding == one-hot matmul
emb = torch.nn.Embedding(V, C); emb.weight.data = W
print(torch.allclose(emb(i), W[i]))
```

### 🔬 Experiment & Observe
Time `F.one_hot(i, 50000).float() @ W` vs `W[i]` for 4096 indices. The lookup is orders of magnitude faster and uses no giant one-hot matrix.

### ⚠️ Failure Modes & Debugging
An index ≥ V gives "index out of range" (on GPU, a cryptic device-side assert). Check `idx.max() < V` when debugging tokenizer/vocab mismatches.

### 🧠 Expert Insight
The embedding matrix is often the biggest single matrix in small LLMs (GPT-2 small: 50257×768 = 38.6M of its 124M params). This matters for vocabulary-size choices (Ch 16) and weight tying (Ch 19).

### ✅ Check Your Instinct
1. Why can't one-hot vectors express similarity?
2. What is `nn.Embedding` mathematically?

<details><summary>Answers</summary>

1. All pairs are orthogonal and equidistant.
2. One-hot × weight matrix, implemented as a row gather.
</details>

### 📌 Recap Card
- One-hot = identity without similarity.
- Embedding lookup = one-hot × matrix.
- Embeddings are dense, learned vectors.

> **Core intuition:** *One-hot names things; embeddings place them.*

## 12.2 Embeddings as Learned Coordinates of Meaning

### 🧭 The Problem First
How do we get vectors where similar tokens are close, without hand-labelling features?

### 💡 Intuition / Instinct
**Let the prediction task decide.** Start with random vectors. If "cat" and "dog" appear in similar contexts ("the ___ ran", "feed the ___"), the gradients that improve prediction push their vectors in similar directions. Over time, the geometry organizes by *usage*, which is the **distributional hypothesis**: "you shall know a word by the company it keeps" (Firth, 1957).

Directions become meaningful: e.g. a "plural" direction, a "gender" direction. The famous example: king − man + woman ≈ queen (Mikolov et al., 2013).

### 🖼️ Visual Mental Model

```text
 before training: points scattered randomly
 after training:   vowels cluster ●●●●     digits cluster ■■■
                   punctuation ▲▲          uppercase ○○○ near their lowercase
```

### 📐 The Math, Gently
The gradient w.r.t. an embedding row $E_i$ only arrives when token i is used, and equals the sum of upstream gradients at those positions: $\partial L/\partial E_i = \sum_{t: x_t = i} \partial L/\partial e_t$. Tokens used in similar contexts receive similar gradients and therefore drift similarly.

### 🛠️ Build It From Scratch
The training happens in 12.3. Here is the analysis function we'll use after training:

```python
def nearest(E, itos, token_id, k=5):
    En = F.normalize(E, dim=-1)
    sims = En @ En[token_id]
    top = sims.topk(k + 1).indices[1:]
    return [(itos[i.item()], round(sims[i].item(), 3)) for i in top]
```

### 🔬 Experiment & Observe
After 12.3, check `nearest(E, itos, stoi['a'])`: expect other vowels. For `stoi['A']`, expect other uppercase letters or 'a'.

### ⚠️ Failure Modes & Debugging
Rare tokens get few updates and their embeddings stay near random init. This is a real issue for rare-token behaviour in LLMs ("glitch tokens", Ch 16).

### 🧠 Expert Insight
- **Mikolov et al. (2013), word2vec.** **Pennington et al. (2014), GloVe.**
- In LLMs, the input embeddings are only the *starting point*; meaning is refined in the residual stream by later layers (Ch 19).

### ✅ Check Your Instinct
1. Why do tokens used in similar contexts get similar embeddings?

<details><summary>Answers</summary>

1. They receive similar gradients from the prediction loss, so they move in similar directions.
</details>

### 📌 Recap Card
- Embeddings are learned from the prediction objective.
- Similar usage → similar vectors (the distributional hypothesis).
- Directions encode attributes.

> **Core intuition:** *A token's meaning is where prediction pushes it in space.*

## 12.3 The Bengio MLP Language Model, Step by Step

### 🧭 The Problem First
We need a model that uses *several* previous tokens without a $V^{n}$ table, and that generalizes across similar contexts.

### 💡 Intuition / Instinct
Take the last n tokens, look up each embedding, **concatenate** them into one vector, pass it through an MLP, and output logits over the vocabulary. The parameter count is *linear* in n (not exponential), and similar contexts give similar concatenated vectors, so similar predictions follow. That is generalization for free.

### 🖼️ Visual Mental Model

```text
 context ids (B, n) ─▶ E lookup ─▶ (B, n, d) ─▶ flatten ─▶ (B, n·d)
      ─▶ Linear(n·d → H) ─▶ tanh/GELU ─▶ Linear(H → V) ─▶ logits (B, V)
```

### 📐 The Math, Gently
$h = \tanh([e_{t-n};\dots;e_{t-1}]W_1 + b_1)$, logits $= hW_2 + b_2$.
Params: $Vd + (nd)H + H + HV + V$. For V = 65, d = 24, n = 8, H = 256: 1,560 + 49,152 + 256 + 16,640 + 65 ≈ 67.7K.

### 🛠️ Build It From Scratch

```python
# nanoforge/models/mlp_lm.py
import torch, torch.nn as nn, torch.nn.functional as F

class MLPLM(nn.Module):
    """Bengio et al. 2003 style: fixed window of n previous tokens -> next token."""
    def __init__(self, V, n_ctx=8, d_emb=24, hidden=256):
        super().__init__()
        self.n_ctx = n_ctx
        self.emb = nn.Embedding(V, d_emb)
        self.net = nn.Sequential(
            nn.Linear(n_ctx * d_emb, hidden), nn.LayerNorm(hidden), nn.GELU(),
            nn.Linear(hidden, V),
        )
        with torch.no_grad():
            self.net[-1].weight.mul_(0.1); self.net[-1].bias.zero_()   # near-uniform start
    def forward(self, ctx, targets=None):           # ctx: (B, n_ctx)
        e = self.emb(ctx)                           # (B, n_ctx, d)
        logits = self.net(e.flatten(1))             # (B, V)
        loss = F.cross_entropy(logits, targets) if targets is not None else None
        return logits, loss

def build_windows(data, n_ctx):
    """All (context, next) pairs: X (N, n_ctx), Y (N,). Pads the start with token 0."""
    pad = torch.zeros(n_ctx, dtype=torch.long)
    d = torch.cat([pad, data])
    X = d.unfold(0, n_ctx, 1)[:-1]                  # (N, n_ctx) sliding windows
    Y = data
    return X, Y
```

```python
# scripts/train_mlp_lm.py
import torch
from nanoforge.models.mlp_lm import MLPLM, build_windows
from nanoforge.utils import set_seed
set_seed(0)
text = open("data/raw/shakespeare.txt", encoding="utf-8").read()
chars = sorted(set(text)); V = len(chars); stoi = {c: i for i, c in enumerate(chars)}; itos = {i: c for c, i in stoi.items()}
data = torch.tensor([stoi[c] for c in text]); n = int(0.9 * len(data))
Xtr, Ytr = build_windows(data[:n], 8); Xva, Yva = build_windows(data[n:], 8)

model = MLPLM(V); opt = torch.optim.AdamW(model.parameters(), lr=3e-3, weight_decay=0.01)
for step in range(20001):
    ix = torch.randint(0, len(Xtr), (256,))
    _, loss = model(Xtr[ix], Ytr[ix])
    opt.zero_grad(set_to_none=True); loss.backward(); opt.step()
    if step == 15000:
        for g in opt.param_groups: g["lr"] = 3e-4          # simple step decay
    if step % 2500 == 0:
        with torch.no_grad():
            vi = torch.randint(0, len(Xva), (20000,))
            print(f"step {step:5d} train {loss.item():.3f} val {model(Xva[vi], Yva[vi])[1].item():.3f}")
```

### 🔬 Experiment & Observe
- Val loss ≈ 2.0–2.05 vs the bigram's 2.47. **Context helps.**
- Sweep `n_ctx` ∈ {1, 3, 8, 16}: n = 1 ≈ bigram; gains diminish past ~8–16 because the MLP struggles to use far-away tokens (the concatenation treats each position independently).

### ⚠️ Failure Modes & Debugging
- `unfold` windows misaligned by one with Y: the model sees the answer. Check `X[k, -1]` equals `data[k-1]`.
- An initial loss far above ln V: shrink the output layer init (done above).

### 🧠 Expert Insight
**Bengio, Ducharme, Vincent & Jauvin (2003), "A Neural Probabilistic Language Model"**: the founding paper of neural LMs. It beat smoothed trigrams even with 2003 compute. Karpathy's *makemore* part 2 follows the same design.

### ✅ Check Your Instinct
1. How do the parameters scale with the context length n?
2. Why does this generalize better than n-grams?
3. *(Coding)* Add a direct embedding→output skip connection (as in Bengio's paper) and compare.

<details><summary>Answers</summary>

1. Linearly (the first Linear grows as n·d·H).
2. Similar contexts map to similar dense vectors and share parameters.
3. Add `nn.Linear(n*d, V)` to the logits; the effect is small.
</details>

### 📌 Recap Card
- Concatenate the context embeddings → MLP → logits.
- Linear params in context length; generalizes across similar contexts.
- Beats the bigram substantially.

> **Core intuition:** *Dense vectors let the model treat new contexts like familiar ones.*

## 12.4 Mini-batching, the LR Finder, Training Diagnostics

### 🧭 The Problem First
You have a model and don't know the right learning rate or batch size. Guessing wastes hours.

### 💡 Intuition / Instinct
**LR range test:** start with a tiny lr, multiply it by a constant each step, and record the loss. The loss falls, flattens, then explodes. Pick an lr about an order of magnitude below the explosion point (where the loss is still decreasing steeply). Batch size: as large as memory allows for throughput, while keeping enough update steps.

### 🖼️ Visual Mental Model

```text
 loss
  │‾‾‾‾\
  │     \___
  │         \__      /  ← explodes
  │            \___/
  └─────────────────────── log lr
    1e-5     1e-3  ↑1e-2  1e-1
                   pick ~here (or a bit lower)
```

### 📐 The Math, Gently
Exponential schedule: $\text{lr}_k = \text{lr}_{min}\cdot(\text{lr}_{max}/\text{lr}_{min})^{k/K}$. Smooth the loss with an EMA (β = 0.98) before reading it.

### 🛠️ Build It From Scratch

```python
# nanoforge/utils.py (append)
import copy, math

def lr_finder(model, make_opt, get_batch_fn, lr_min=1e-6, lr_max=1.0, steps=300, beta=0.98):
    state = copy.deepcopy(model.state_dict())
    opt = make_opt(model.parameters(), lr_min)
    lrs, losses, avg, best = [], [], 0.0, float("inf")
    for k in range(steps):
        lr = lr_min * (lr_max / lr_min) ** (k / (steps - 1))
        for g in opt.param_groups: g["lr"] = lr
        x, y = get_batch_fn(); _, loss = model(x, y)
        opt.zero_grad(); loss.backward(); opt.step()
        avg = beta * avg + (1 - beta) * loss.item(); sm = avg / (1 - beta ** (k + 1))
        lrs.append(lr); losses.append(sm); best = min(best, sm)
        if sm > 4 * best or math.isnan(sm): break
    model.load_state_dict(state)
    return lrs, losses
```

```python
import torch, matplotlib.pyplot as plt
from nanoforge.utils import lr_finder
m = MLPLM(V)
lrs, losses = lr_finder(m, lambda p, lr: torch.optim.AdamW(p, lr=lr),
                        lambda: (lambda ix: (Xtr[ix], Ytr[ix]))(torch.randint(0, len(Xtr), (256,))))
plt.semilogx(lrs, losses); plt.xlabel("lr"); plt.ylabel("smoothed loss"); plt.savefig("lr_finder.png")
```

### 🔬 Experiment & Observe
For the MLP LM with AdamW, the explosion point is typically around 1e-1 to 3e-1 and the steepest descent around 3e-3 to 1e-2. Compare with the 3e-3 we used.

### ⚠️ Failure Modes & Debugging
- Forgetting to restore the weights after the LR finder.
- The LR finder picks a *starting* point; long runs usually need a lower peak lr plus warmup and decay (Ch 24).

### 🧠 Expert Insight
Smith (2017), "Cyclical Learning Rates". At LLM scale, people use small-scale sweeps plus scaling rules (µP, Ch 26) instead of per-run LR finders.

### ✅ Check Your Instinct
1. Why pick an lr below the explosion point?

<details><summary>Answers</summary>

1. Near the edge, training is unstable over long runs; you need a margin.
</details>

### 📌 Recap Card
- LR finder: exponential lr ramp, smoothed loss.
- Pick ~10× below the blow-up.
- Restore the weights afterwards.

> **Core intuition:** *Let the model tell you how big a step it can take.*

## 12.5 Visualizing Embeddings (PCA / t-SNE)

### 🧭 The Problem First
We claim the embeddings encode meaning. Let's *see* it.

### 💡 Intuition / Instinct
Project the d-dimensional embeddings to 2D. PCA keeps the directions of largest variance (a linear projection, Ch 3.6); t-SNE preserves local neighbourhoods (nonlinear, good for clusters, but distances between clusters aren't meaningful).

### 🖼️ Visual Mental Model

```text
      ● a e i o u          ■ 0-9 digits (not in Shakespeare, but punctuation clusters)
   ○ A E I O U   ▲ , . ; :     ◆ \n
```

### 📐 The Math, Gently
PCA: $E_c = E - \bar E$, $E_c = U\Sigma V^\top$, 2D coordinates $= E_c V_{:,:2}$.

### 🛠️ Build It From Scratch

```python
import matplotlib.pyplot as plt, torch
E = model.emb.weight.detach()
Ec = E - E.mean(0)
U, S, Vh = torch.linalg.svd(Ec, full_matrices=False)
xy = Ec @ Vh[:2].T
plt.figure(figsize=(8, 8))
for i in range(len(E)):
    plt.scatter(xy[i, 0], xy[i, 1], s=200, c="lightblue")
    plt.text(xy[i, 0], xy[i, 1], repr(itos[i])[1:-1], ha="center", va="center")
plt.title("MLP LM character embeddings (PCA)"); plt.savefig("embeddings_pca.png")
print("nearest to 'a':", nearest(E, itos, stoi['a']))
```

### 🔬 Experiment & Observe
Vowels usually cluster together, and uppercase letters cluster apart from lowercase. For t-SNE: `from sklearn.manifold import TSNE; TSNE(perplexity=10).fit_transform(E.numpy())`.

### ⚠️ Failure Modes & Debugging
- Reading too much into t-SNE distances between clusters.
- 2D PCA may capture only ~20% of the variance; check the explained-variance ratio.

### 🧠 Expert Insight
Visualization is a starting point. Rigorous interpretability uses probes and causal interventions (Ch 48).

### ✅ Check Your Instinct
1. What's one pitfall of t-SNE?

<details><summary>Answers</summary>

1. Global distances and cluster sizes aren't meaningful; it can also invent clusters.
</details>

### 📌 Recap Card
- PCA for linear structure; t-SNE for neighbourhoods.
- Learned embeddings cluster by usage.

> **Core intuition:** *Seeing the geometry confirms the model learned meaning, not magic.*

## 12.6 Scaling the MLP LM, and Hitting Its Wall

### 🧭 The Problem First
If context helps, why not n = 256 and a huge hidden layer?

### 💡 Intuition / Instinct
Concatenation assigns **separate weights to each position**: what the model learns about "the" at position −3 doesn't transfer to "the" at position −7. Parameters grow with n, data per parameter shrinks, and the model can't learn *position-independent* patterns like "look back for the matching quote". There is also no way to **decide dynamically** which past tokens matter.

We need:
1. weight sharing across positions (RNNs, Ch 14; attention, Ch 17);
2. content-based selection of relevant context (attention).

### 🖼️ Visual Mental Model

```text
 MLP LM:   pos-8 weights | pos-7 weights | ... | pos-1 weights   (no sharing, no selection)
 wanted:   one shared "reader" that looks at all positions and picks the relevant ones
```

### 📐 The Math, Gently
The first-layer params are $n\cdot d\cdot H$: n = 256, d = 64, H = 1024 gives 16.8M params in one layer, most seeing rare signal.

### 🛠️ Build It From Scratch

```python
for n_ctx in [8, 32, 128]:
    Xtr_n, Ytr_n = build_windows(data[:n], n_ctx); Xva_n, Yva_n = build_windows(data[n:], n_ctx)
    set_seed(0); m = MLPLM(V, n_ctx=n_ctx, d_emb=24, hidden=512)
    opt = torch.optim.AdamW(m.parameters(), lr=2e-3, weight_decay=0.05)
    for step in range(8000):
        ix = torch.randint(0, len(Xtr_n), (256,)); _, l = m(Xtr_n[ix], Ytr_n[ix])
        opt.zero_grad(); l.backward(); opt.step()
    with torch.no_grad():
        vi = torch.randint(0, len(Xva_n), (20000,)); tl = m(Xtr_n[vi], Ytr_n[vi])[1].item(); vl = m(Xva_n[vi], Yva_n[vi])[1].item()
    print(f"n_ctx={n_ctx:4d} params={sum(p.numel() for p in m.parameters()):8d} train {tl:.3f} val {vl:.3f}")
```

### 🔬 Experiment & Observe
Longer contexts help a bit, then the train–val gap widens (overfitting) and the val loss stalls. **The wall.** The transformer (Ch 20) with the same data will reach ~1.5 val loss.

### ⚠️ Failure Modes & Debugging
Large windows × many examples use a lot of memory (`unfold` creates views, but indexing copies). Generate batches on the fly for large n.

### 🧠 Expert Insight
This wall is historically why the field moved to RNNs (2010–2017), then to transformers (2017–). The **MLP-Mixer**-style LMs revisited position-mixing MLPs, but they don't handle variable-length causal context as well as attention.

### ✅ Check Your Instinct
1. Two things the MLP LM lacks?

<details><summary>Answers</summary>

1. Weight sharing across positions and dynamic, content-based selection of context.
</details>

### 📌 Recap Card
- Concatenation = per-position weights = no sharing.
- No dynamic selection of relevant context.
- Motivates RNNs and attention.

> **Core intuition:** *A good reader uses the same eyes for every word and decides where to look.*
