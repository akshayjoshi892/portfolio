## 10.1 BatchNorm: The Idea, and Why It Fails for Sequences

### 🧭 The Problem First
Even with good init, activation distributions drift during training (weights change → each layer's input distribution shifts), making optimization fragile.

### 💡 Intuition / Instinct
**Force each feature to have mean 0 and std 1**, then let the network rescale with learnable γ, β. BatchNorm computes these statistics *across the batch*. It's like grading on a curve per question, across all students.

Why it fails for LLMs:
1. Statistics depend on the *other examples* in the batch, and the batch composition differs between training and inference.
2. In autoregressive models, batch statistics leak information across sequences and positions.
3. Small or variable batches (and padding) make the statistics noisy.
4. Inference needs running averages, a train/test mismatch.

### 🖼️ Visual Mental Model

```text
          features →
 batch  ┌───────────────┐
   ↓    │ x x x x x x x │   BatchNorm: normalize each COLUMN (over batch)
        │ x x x x x x x │   LayerNorm: normalize each ROW    (over features)
        └───────────────┘
```

### 📐 The Math, Gently
$\mu_j = \frac1B\sum_i x_{ij}$, $\sigma_j^2 = \frac1B\sum_i(x_{ij}-\mu_j)^2$, $\hat x_{ij} = \frac{x_{ij}-\mu_j}{\sqrt{\sigma_j^2+\epsilon}}$, $y = \gamma_j\hat x_{ij} + \beta_j$.

### 🛠️ Build It From Scratch

```python
import torch
class BatchNorm1d(torch.nn.Module):
    def __init__(self, C, eps=1e-5, momentum=0.1):
        super().__init__()
        self.gamma, self.beta = torch.nn.Parameter(torch.ones(C)), torch.nn.Parameter(torch.zeros(C))
        self.register_buffer("run_mean", torch.zeros(C)); self.register_buffer("run_var", torch.ones(C))
        self.eps, self.m = eps, momentum
    def forward(self, x):                           # (B, C)
        if self.training:
            mu, var = x.mean(0), x.var(0, unbiased=False)
            with torch.no_grad():
                self.run_mean.lerp_(mu, self.m); self.run_var.lerp_(x.var(0, unbiased=True), self.m)
        else:
            mu, var = self.run_mean, self.run_var
        return self.gamma * (x - mu) / torch.sqrt(var + self.eps) + self.beta

bn, ref = BatchNorm1d(8), torch.nn.BatchNorm1d(8)
x = torch.randn(32, 8) * 3 + 1
print(torch.allclose(bn(x), ref(x), atol=1e-5))
# the output for example 0 depends on the other examples:
print(bn(x)[0, :3], bn(torch.cat([x[:1], torch.randn(31, 8)]))[0, :3])
```

### 🔬 Experiment & Observe
The last line shows that example 0's output changes when the *other* batch members change. For a language model predicting the next token, that dependence is unacceptable.

### ⚠️ Failure Modes & Debugging
- Forgetting `model.eval()` means inference with a batch of 1 uses that single example's statistics → garbage.
- Batch sizes of 1–2 give degenerate statistics.

### 🧠 Expert Insight
**Ioffe & Szegedy (2015)** BatchNorm revolutionized CNNs. Transformers adopted **LayerNorm** (Ba et al., 2016) instead; every major LLM uses LayerNorm or RMSNorm.

<details><summary>Answers</summary>

1. The batch axis, per feature.
2. Cross-example dependence and train/inference mismatch (plus padding and variable lengths).
</details>

### 📌 Recap Card

- It creates cross-example dependence and train/test mismatch.
- Great for CNNs, wrong for LLMs.

> **Core intuition:** *BatchNorm grades each token on a curve set by strangers.*

## 10.2 LayerNorm and RMSNorm From Scratch

### 🧭 The Problem First
We want normalization without batch dependence: each token normalized on its own.

### 💡 Intuition / Instinct
**LayerNorm:** for each token vector, subtract its own mean and divide by its own std (over the C features), then apply the learnable γ, β.
**RMSNorm:** skip the mean subtraction; just divide by the root-mean-square. It's cheaper, and empirically just as good. The *scale* control was what mattered, not the centering.

Geometric view: RMSNorm projects every token vector onto a sphere of radius √C, then γ stretches each axis. It keeps representation magnitudes controlled, whatever happens upstream.

### 🖼️ Visual Mental Model

```text
 token vector x (C,) ─▶ /rms(x) ─▶ on sphere radius √C ─▶ ⊙ γ ─▶ out
```

### 📐 The Math, Gently
LayerNorm: $y = \gamma\odot\frac{x - \mu}{\sqrt{\sigma^2+\epsilon}} + \beta$, with $\mu, \sigma$ over the features of one token.
RMSNorm: $y = \gamma\odot\frac{x}{\sqrt{\frac1C\sum_i x_i^2 + \epsilon}}$.
Example: x = (1, 2, 3, 4): rms = √7.5 = 2.739, so RMSNorm gives (0.365, 0.730, 1.095, 1.461). LayerNorm: μ = 2.5, σ = 1.118, giving (−1.342, −0.447, 0.447, 1.342).

### 🛠️ Build It From Scratch

```python
# nanoforge/nn.py (append)
import torch, torch.nn as nn

class LayerNorm(nn.Module):
    def __init__(self, C, eps=1e-5, bias=True):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(C))
        self.bias = nn.Parameter(torch.zeros(C)) if bias else None
        self.eps = eps
    def forward(self, x):                                   # (..., C)
        mu = x.mean(-1, keepdim=True)
        var = x.var(-1, keepdim=True, unbiased=False)
        y = (x - mu) * torch.rsqrt(var + self.eps) * self.weight
        return y + self.bias if self.bias is not None else y

class RMSNorm(nn.Module):
    def __init__(self, C, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(C)); self.eps = eps
    def forward(self, x):                                   # (..., C)
        xf = x.float()                                      # compute in fp32 for stability
        y = xf * torch.rsqrt(xf.pow(2).mean(-1, keepdim=True) + self.eps)
        return (y * self.weight.float()).type_as(x)
```

```python
x = torch.randn(2, 5, 16) * 4 + 3
print(torch.allclose(LayerNorm(16)(x), nn.LayerNorm(16)(x), atol=1e-5))
r = RMSNorm(16)(x); print(r.pow(2).mean(-1)[0])            # ~1 for every token
print(RMSNorm(4)(torch.tensor([[1., 2., 3., 4.]])))         # [0.365 0.730 1.095 1.461]
```

### 🔬 Experiment & Observe
Scale the input by 1000: LayerNorm/RMSNorm outputs are unchanged (scale invariance). **Instinct:** norms make each layer's input scale-independent, which stabilizes training and allows higher learning rates.

### ⚠️ Failure Modes & Debugging
- Computing norms in fp16/bf16: the sum of squares overflows or loses precision. Upcast to fp32 (as above).
- ε differences (1e-5 vs 1e-6) matter when loading pretrained weights: match the original.
- Normalizing over the wrong axis (T instead of C) mixes tokens and leaks the future.

### 🧠 Expert Insight
- **Ba et al. (2016)** LayerNorm; **Zhang & Sennrich (2019)** RMSNorm.
- GPT-2/3 use LayerNorm; Llama, Mistral, Qwen, Gemma use RMSNorm.
- **QK-Norm** applies RMSNorm to queries and keys to prevent attention-logit growth (Ch 27).

1. What does RMSNorm drop compared with LayerNorm?
2. Is LayerNorm scale invariant? Shift invariant?
3. *(Coding)* Verify your RMSNorm against `torch.nn.RMSNorm` (PyTorch ≥ 2.4).

<details><summary>Answers</summary>

1. Mean subtraction and bias.
2. Both, per token (RMSNorm is only scale invariant).
3. `torch.allclose(RMSNorm(C)(x), torch.nn.RMSNorm(C, eps=1e-6)(x), atol=1e-5)`.
</details>

### 📌 Recap Card
- LayerNorm: per-token mean/std normalize + γ, β.
- RMSNorm: per-token RMS normalize + γ (cheaper; the modern default).
- Compute in fp32; match ε when loading weights.

> **Core intuition:** *Normalize each token by its own size so no layer can blow up the next.*

## 10.3 Residual Connections: The Gradient Highway

### 🧭 The Problem First
Even with good init and norms, very deep plain networks train *worse* than shallow ones (He et al., 2015): gradients must pass through every layer's Jacobian, and any weakness compounds.

### 💡 Intuition / Instinct
Instead of $x_{l+1} = f(x_l)$, use $x_{l+1} = x_l + f(x_l)$. Each layer *adds a correction* to a shared stream instead of replacing it. Two consequences:
1. **The gradient highway:** $\partial x_{l+1}/\partial x_l = I + \partial f/\partial x_l$. The identity term carries the gradient straight back to early layers, unattenuated.
2. **Easy to be harmless:** a layer can learn f ≈ 0 and do no damage, so depth never hurts.

In transformers this becomes the **residual stream**: a shared bus that every attention and MLP layer reads from and writes to (Ch 19).

### 🖼️ Visual Mental Model

```text
 x ──┬──────────────────(+)──▶ x + f(x)
     └──▶ norm ─▶ f ─────┘
 backward: gradient flows through the "+" untouched ─▶ early layers always hear the loss
```

### 📐 The Math, Gently
Across L blocks: $\frac{\partial x_L}{\partial x_0} = \prod_{l}(I + J_l) = I + \sum_l J_l + \dots$. The identity term guarantees the gradient reaches $x_0$ even if every $J_l$ is small.
Variance: each block adds variance, so $\text{Var}(x_L) \approx \text{Var}(x_0) + \sum_l \text{Var}(f_l)$. This is why GPT-2 scales the residual-branch init by $1/\sqrt{2L}$.

### 🛠️ Build It From Scratch

```python
import torch, torch.nn as nn
class Block(nn.Module):
    def __init__(self, C, residual=True):
        super().__init__()
        self.norm = nn.LayerNorm(C); self.f = nn.Sequential(nn.Linear(C, C), nn.GELU(), nn.Linear(C, C))
        self.residual = residual
    def forward(self, x):
        return x + self.f(self.norm(x)) if self.residual else self.f(self.norm(x))

def first_layer_grad(depth, residual):
    torch.manual_seed(0)
    net = nn.Sequential(*[Block(64, residual) for _ in range(depth)])
    x = torch.randn(32, 64); net(x).pow(2).mean().backward()
    return net[0].f[0].weight.grad.norm().item()
for d in [2, 8, 32, 64]:
    print(f"depth {d:2d}: first-layer grad  plain={first_layer_grad(d, False):.2e}  residual={first_layer_grad(d, True):.2e}")
```

### 🔬 Experiment & Observe
The plain network's first-layer gradient collapses with depth; the residual network's stays healthy. Train both on the spirals at depth 32: only the residual one learns.

### ⚠️ Failure Modes & Debugging
- The residual stream's norm grows with depth unless the branches are scaled. Monitor the per-layer residual RMS.
- Putting a norm *after* the addition (post-norm) at great depth leads to instability without warmup (Ch 19).

### 🧠 Expert Insight
- **He et al. (2015), ResNet.** **Srivastava et al. (2015), Highway Networks.**
- **Veit et al. (2016):** residual nets behave like ensembles of shallower paths.
- **Elhage et al. (2021), "A Mathematical Framework for Transformer Circuits":** the residual stream view (Ch 19, 48).

### ✅ Check Your Instinct
1. Why does the identity term help the gradient flow?
2. Why scale the residual-branch init by $1/\sqrt{2L}$?

<details><summary>Answers</summary>

1. It adds a direct path whose Jacobian is I, independent of how weak the layer Jacobians are.
2. Each of the 2L branches (attention + MLP per block) adds variance; the scaling keeps the total bounded.
</details>

### 📌 Recap Card
- $x + f(x)$: layers add corrections to a stream.
- Identity path = gradient highway.
- Residual variance grows with depth, so scale the init.

> **Core intuition:** *Residuals let every layer whisper edits into a shared stream without blocking the signal.*

## 10.4 Dropout as Ensemble Training

### 🧭 The Problem First
Networks can memorize training data by building fragile co-adaptations: neuron A only works if neuron B is exactly right.

### 💡 Intuition / Instinct
During training, randomly zero each activation with probability p (and scale the survivors by 1/(1−p) to keep the expectation). Every step trains a different "thinned" sub-network, so no neuron can rely on any specific other neuron. At test time, use the full network, which approximates averaging an ensemble of exponentially many sub-networks.

### 🖼️ Visual Mental Model

```text
 train step 1: ● ○ ● ● ○ ●     (○ dropped)
 train step 2: ○ ● ● ○ ● ●
 inference:    ● ● ● ● ● ●     (all on; expectation matched by 1/(1-p) scaling)
```

### 📐 The Math, Gently
Inverted dropout: $y = \frac{m \odot x}{1-p}$ with $m_i \sim \text{Bernoulli}(1-p)$, so $\mathbb{E}[y] = x$.
Example: p = 0.1 gives survivors ×1.111.

### 🛠️ Build It From Scratch

```python
import torch
class Dropout(torch.nn.Module):
    def __init__(self, p=0.1): super().__init__(); self.p = p
    def forward(self, x):
        if not self.training or self.p == 0: return x
        mask = (torch.rand_like(x) > self.p).to(x.dtype)
        return x * mask / (1 - self.p)
d = Dropout(0.5); x = torch.ones(100000)
print(d(x).mean().item(), (d(x) == 0).float().mean().item())   # ~1.0, ~0.5
d.eval(); print(d(x).mean().item())                             # 1.0 exactly
```

### 🔬 Experiment & Observe
Train a big MLP on a *small* subset of the spirals (100 points) with p ∈ {0, 0.1, 0.3, 0.5}. p = 0 overfits (train loss ≈ 0, val loss rises); moderate dropout gives a better validation loss.

### ⚠️ Failure Modes & Debugging
- Forgetting `model.eval()` at inference gives random, degraded outputs.
- Dropout during RL/DPO log-prob computation causes inconsistent log-probs. Disable it for post-training (Ch 39–40).

### 🧠 Expert Insight
- **Srivastava et al. (2014), Dropout.**
- GPT-2 used p = 0.1. **Most modern LLM pretraining uses dropout = 0**: with trillions of tokens and < 1 epoch, overfitting isn't the concern, and dropout wastes capacity. Fine-tuning on small data may re-enable it.

### ✅ Check Your Instinct
1. Why scale by 1/(1−p)?
2. Why do modern LLMs skip dropout in pretraining?

<details><summary>Answers</summary>

1. To keep the expected activation the same between train and test.
2. Single-epoch training on huge data rarely overfits; dropout only slows learning.
</details>

### 📌 Recap Card
- Randomly zero units in training; scale the survivors.
- Approximates an ensemble; prevents co-adaptation.
- Off at inference; usually 0 in LLM pretraining.

> **Core intuition:** *Train every neuron to be useful even when its teammates are missing.*

## 10.5 Overfitting, Bias–Variance, and Double Descent

### 🧭 The Problem First
Training loss keeps falling, but performance on new data gets worse. How do we recognize and reason about this?

### 💡 Intuition / Instinct
- **Underfitting (high bias):** the model is too simple, so both train and val loss are high.
- **Overfitting (high variance):** the model memorizes noise, so train loss is low and val loss is high.
- **Double descent:** past the point where the model can exactly memorize the data, making it *even bigger* can improve test performance again. Huge models find smoother interpolating solutions.

For LLMs the practical rule: if you see each token only ~once, you are **data-limited**, not overfitting. Overfitting appears with repeated epochs on small or domain datasets and in fine-tuning.

### 🖼️ Visual Mental Model

```text
 test error
   │\             classic U           ╲       double descent
   │ \        ___/                     ╲   /╲___
   │  \______/                          ╲_/      ‾‾‾──── keeps improving
   └──────────────▶ model size          └─── interpolation threshold ───▶
```

### 📐 The Math, Gently
Expected test error = bias² + variance + irreducible noise. The generalization gap = val loss − train loss. Track it every eval.

### 🛠️ Build It From Scratch

```python
import numpy as np
rng = np.random.default_rng(0)
x = np.sort(rng.uniform(-1, 1, 20)); y = np.sin(3 * x) + 0.2 * rng.normal(size=20)
xt = np.linspace(-1, 1, 200); yt = np.sin(3 * xt)
for deg in [1, 3, 9, 15, 19]:
    c = np.polyfit(x, y, deg)
    tr = np.mean((np.polyval(c, x) - y) ** 2); te = np.mean((np.polyval(c, xt) - yt) ** 2)
    print(f"degree {deg:2d}: train {tr:.4f}  test {te:.4f}")
```

### 🔬 Experiment & Observe
The test error falls, then shoots up near degree 19 (interpolation). For the double-descent curve, use random-features regression with the minimum-norm solution (`np.linalg.pinv`) and sweep the features past N. The test error peaks at features = N, then falls again.

### ⚠️ Failure Modes & Debugging
- Val data leaking into train (duplicates!) hides overfitting. Dedup across splits (Ch 21).
- Early-stopping on the *test* set means your reported number is optimistic.

### 🧠 Expert Insight
- **Belkin et al. (2019)** and **Nakkiran et al. (2019), "Deep Double Descent".**
- **Muennighoff et al. (2023), "Scaling Data-Constrained Language Models":** repeating data up to ~4 epochs is nearly as good as fresh data; beyond that, returns diminish quickly.

### ✅ Check Your Instinct
1. Train loss 0.1, val loss 2.5: diagnosis?
2. Why are LLMs rarely overfit in pretraining?

<details><summary>Answers</summary>

1. Severe overfitting.
2. They typically see each token about once; there is too much data to memorize.
</details>

### 📌 Recap Card
- Watch the generalization gap.
- Underfit = both high; overfit = gap large.
- Double descent: bigger can be better past interpolation.
- Repeated epochs are where LLM overfitting appears.

> **Core intuition:** *Memorizing is easy; generalizing requires the model to learn the rule, not the examples.*

## 10.6 Weight Decay, Early Stopping, and Data Augmentation for Text

### 🧭 The Problem First
When overfitting does appear (fine-tuning, small domain corpora), what practical levers do you have?

### 💡 Intuition / Instinct
1. **Weight decay:** prefer small weights, i.e. simpler functions (Ch 8.6).
2. **Early stopping:** stop when val loss stops improving and keep the best checkpoint.
3. **More / augmented data:** for text: back-translation, paraphrasing, synonym swaps, random span masking, or synthetic data generated by a stronger model (Ch 42).
4. **Smaller model / fewer epochs / LoRA** (Ch 38).

### 🖼️ Visual Mental Model

```text
 val loss
   │\
   │ \___  ← best checkpoint (stop here, patience = N evals)
   │     \_/‾‾‾‾‾ rising = overfitting
   └────────────── steps
```

### 📐 The Math, Gently
Early stopping with patience P: stop if val loss hasn't improved by at least δ for P consecutive evaluations. For gradient descent on a quadratic, early stopping is equivalent to L2 regularization (the stopping time acts like $1/\lambda$).

### 🛠️ Build It From Scratch

```python
# nanoforge/utils.py (append)
class EarlyStopping:
    def __init__(self, patience=5, min_delta=1e-3):
        self.patience, self.min_delta, self.best, self.bad = patience, min_delta, float("inf"), 0
    def step(self, val_loss):
        """returns (should_stop, is_best)"""
        if val_loss < self.best - self.min_delta:
            self.best, self.bad = val_loss, 0
            return False, True
        self.bad += 1
        return self.bad >= self.patience, False

import random
def augment_text(s, p_drop=0.1, p_swap=0.1, rng=random):
    """Tiny word-level augmentation: random deletion and adjacent swaps."""
    w = [t for t in s.split() if rng.random() > p_drop] or s.split()[:1]
    for i in range(len(w) - 1):
        if rng.random() < p_swap: w[i], w[i + 1] = w[i + 1], w[i]
    return " ".join(w)
```

### 🔬 Experiment & Observe
Fine-tune the spiral MLP on 100 points with early stopping (patience 5) and weight decay 0.1. Compare its best val loss with training for a fixed 5,000 steps.

### ⚠️ Failure Modes & Debugging
- Patience that's too short with a noisy val loss stops too early. Smooth it, or evaluate on more data.
- Naive augmentation can change meaning ("not good" → "good"). Be careful with labels.

### 🧠 Expert Insight
In LLM fine-tuning, the most effective regularizers are usually **fewer epochs (1–3)**, a **low lr**, **LoRA**, and **data quality/diversity**, not dropout tricks.

### 📌 Recap Card
- Weight decay, early stopping, augmentation, smaller updates (LoRA).
- Keep the best checkpoint by val loss.
- Data quality and diversity beat tricks.

> **Core intuition:** *Regularization is a bias toward simple explanations.*
