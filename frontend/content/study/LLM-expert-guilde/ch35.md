## 35.1 Perplexity Done Right: Bits-per-Byte Across Tokenizers

### 🧭 The Problem First
Your Llama with an 8K domain tokenizer has val loss 2.1; a baseline with a 50K tokenizer has 2.9. Which is better? You can't tell: the tokens are different sizes.

### 💡 Intuition / Instinct
Normalize by something tokenizer-independent: **bytes** of the original text. Bits-per-byte (BPB) = the total information (in bits) the model needs to encode the text, divided by its size in bytes. Lower is better, and it's comparable across *any* tokenizers. Also evaluate on long, clean, held-out documents with a **sliding window** so every token has as much context as possible.

### 🖼️ Visual Mental Model

```text
 text (N bytes) → tokenizer A (n_A tokens), total NLL_A nats → BPB_A = NLL_A / (N ln 2)
               → tokenizer B (n_B tokens), total NLL_B nats → BPB_B = NLL_B / (N ln 2)   comparable ✓
```

### 📐 The Math, Gently
$\text{BPB} = \frac{\sum_t -\ln p(x_t\mid x_{<t})}{N_{bytes}\ln 2}$; $\text{PPL}_{token} = e^{\text{NLL}/n_{tokens}}$.
Worked: loss 2.1 nats/token at 4.5 bytes/token gives BPB = 2.1/(4.5·0.693) = 0.673. Loss 2.9 at 3.8 bytes/token gives 2.9/(3.8·0.693) = 1.101. The first model is much better.
Sliding window with stride S < T: score only the last S tokens of each window, so that every scored token has ≥ T − S tokens of context.

### 🛠️ Build It From Scratch

```python
# nanoforge/eval/perplexity.py
import math, torch

@torch.no_grad()
def sliding_window_nll(model, ids, block_size, stride=None, device="cpu"):
    """ids: 1D LongTensor for a long text. Returns (total_nll_nats, n_scored_tokens)."""
    stride = stride or block_size // 2
    total, count, prev_end = 0.0, 0, 0
    model.eval()
    for start in range(0, len(ids) - 1, stride):
        end = min(start + block_size, len(ids) - 1)
        x = ids[start:end].unsqueeze(0).to(device); y = ids[start + 1:end + 1].unsqueeze(0).to(device)
        logits, _ = model(x, all_logits=True)
        nll = torch.nn.functional.cross_entropy(logits[0].float(), y[0], reduction="none")
        new = end - max(prev_end, start)                     # only score tokens not scored before
        total += nll[-new:].sum().item(); count += new; prev_end = end
        if end == len(ids) - 1: break
    return total, count

def bits_per_byte(model, tok, texts, block_size, device="cpu"):
    nll, nbytes, ntok = 0.0, 0, 0
    for t in texts:
        ids = torch.tensor(tok.encode_ordinary(t))
        if len(ids) < 2: continue
        n, c = sliding_window_nll(model, ids, block_size, device=device)
        nll += n; ntok += c; nbytes += len(t.encode("utf-8"))
    return {"bpb": nll / (nbytes * math.log(2)), "token_ppl": math.exp(nll / ntok), "bytes_per_token": nbytes / ntok}
```

### 🔬 Experiment & Observe
Compute the BPB of your GPT-2 (Ch 20.5, 50K vocab) and of your Llama-micro (4K vocab) on the same TinyStories validation texts. Only BPB is a fair comparison. Also compare stride = block_size (no overlap) vs block_size/2: the overlapping evaluation gives a lower (better, more honest about the model's ability) number.

### ⚠️ Failure Modes & Debugging
- Scoring the first token of every non-overlapping window with no context inflates the perplexity.
- Counting special tokens (EOT) in the byte denominator but not the numerator, or vice versa.

### 🧠 Expert Insight
- The Pile and GPT-NeoX papers popularized BPB.
- **Huang et al. (2024), "Compression Represents Intelligence Linearly":** BPB on held-out corpora correlates strongly with benchmark scores across models.
- Many labs track "held-out loss on curated sets" as their primary pretraining metric.

### ✅ Check Your Instinct

2. What does a sliding window with stride < block_size fix?

<details><summary>Answers</summary>

1. Tokens cover different amounts of text; per-token uncertainty scales with the token size.
2. It ensures every scored token has substantial context.
</details>

### 📌 Recap Card
- BPB = total nats / (bytes × ln 2), tokenizer-independent.
- Sliding window for fair context.
- Held-out, clean, long documents.

> **Core intuition:** *Measure the model's information cost per byte of reality, not per arbitrary chunk.*

## 35.2 Multiple-Choice Evaluation by Log-Likelihood (MMLU, HellaSwag)

### 🧭 The Problem First
A base model doesn't "answer" questions reliably in free text. How do you measure knowledge and reasoning with multiple-choice benchmarks?

### 💡 Intuition / Instinct
Two standard approaches:
1. **Cloze / completion scoring (HellaSwag-style):** for each candidate ending, compute the (length-normalized) log-likelihood of the ending given the context; predict the most likely one. This works for base models without instruction following.
2. **Letter scoring (MMLU-style):** format the question with options "A. … B. … C. … D. …" + "Answer:", and compare the model's probability of the tokens " A", " B", " C", " D". It needs a model that has learned the format (few-shot examples help).

### 🖼️ Visual Mental Model

```text
 context: "A man is sitting on a roof. He"
 endings: [ "starts pulling up roofing on a roof.",  logP/len = -1.9  ✓
            "is using wrap to wrap a pair of skis.", -3.4
            ... ]
```

### 📐 The Math, Gently
Score(ending) = $\frac{1}{|e|}\sum_{t\in e}\log p(e_t\mid \text{ctx}, e_{<t})$ (normalized by tokens, or by characters/bytes as in lm-eval-harness's `acc_norm`).
Random baselines: 4-way = 25%. MMLU with 57 subjects: report the macro average.

### 🛠️ Build It From Scratch

```python
# nanoforge/eval/multiple_choice.py
import torch, torch.nn.functional as F

@torch.no_grad()
def continuation_logprob(model, tok, context, continuation, device="cpu"):
    ctx = tok.encode_ordinary(context); cont = tok.encode_ordinary(continuation)
    ids = torch.tensor([ctx + cont], device=device)
    logits, _ = model(ids[:, :-1], all_logits=True)
    logp = F.log_softmax(logits.float(), -1)[0]
    tgt = ids[0, 1:]
    lp = logp[torch.arange(len(tgt)), tgt][-len(cont):]          # only continuation tokens
    return lp.sum().item(), len(cont), len(continuation.encode())

def score_mc(model, tok, examples, norm="byte", device="cpu"):
    """examples: [{"context": str, "endings": [str], "label": int}]"""
    correct = 0
    for ex in examples:
        scores = []
        for e in ex["endings"]:
            s, ntok, nbyte = continuation_logprob(model, tok, ex["context"], " " + e.strip(), device)
            scores.append(s / (nbyte if norm == "byte" else ntok if norm == "token" else 1))
        correct += int(max(range(len(scores)), key=scores.__getitem__) == ex["label"])
    return correct / len(examples)

def mmlu_prompt(q, choices, shots=()):
    fmt = lambda q, c, a=None: q + "\n" + "\n".join(f"{L}. {x}" for L, x in zip("ABCD", c)) + "\nAnswer:" + (f" {a}\n\n" if a else "")
    return "".join(fmt(*s) for s in shots) + fmt(q, choices)

@torch.no_grad()
def score_letter(model, tok, prompt, device="cpu"):
    ids = torch.tensor([tok.encode_ordinary(prompt)], device=device)
    logits, _ = model(ids)                                          # last position
    letter_ids = [tok.encode_ordinary(f" {L}")[-1] for L in "ABCD"]
    return int(torch.argmax(logits[0, -1, letter_ids]).item())
```

### ⚠️ Failure Modes & Debugging

- Unnormalized sums favour shorter endings.
- Letter scoring on a tiny base model is basically random. Use cloze scoring for small models.

### 🧠 Expert Insight
- **Hendrycks et al. (2020), MMLU.** **Zellers et al. (2019), HellaSwag.**
- **EleutherAI lm-evaluation-harness** is the standard implementation; small formatting differences move MMLU scores by several points (Alzahrani et al., 2024, "When Benchmarks are Targets").

2. Why does letter scoring need a capable or few-shot-prompted model?

<details><summary>Answers</summary>

1. Longer continuations accumulate more negative log-probability regardless of correctness.
2. The model must understand the Q/A format to map knowledge onto the letter tokens.
</details>

### 📌 Recap Card
- Cloze scoring: compare the normalized log-likelihoods of the endings.
- Letter scoring: compare P(" A"...) after a formatted prompt.
- Formatting and normalization choices matter; be consistent.

> **Core intuition:** *Ask which answer the model finds least surprising.*

## 35.3 Generative Evaluation: GSM8K, HumanEval, pass@k

### 🧭 The Problem First
Math and coding ability can't be scored by likelihood over fixed options. The model must *generate* a solution that is then checked.

### 💡 Intuition / Instinct
- **GSM8K (math word problems):** generate a solution (often chain-of-thought), extract the final number, and compare it with the reference (exact match).
- **HumanEval / MBPP (code):** generate a function body and **execute unit tests** in a sandbox. Pass = all tests pass.
- **pass@k:** sample n ≥ k solutions per problem; pass@k = the probability that at least one of k random samples passes. Use the unbiased estimator (not just "any of the first k").

### 🖼️ Visual Mental Model

```text
 problem → model generates n=20 samples → run tests → c=7 pass
 pass@1 = 1 - C(13,1)/C(20,1) = 0.35;   pass@10 = 1 - C(13,10)/C(20,10) ≈ 0.998
```

### 📐 The Math, Gently
Unbiased estimator (Chen et al., 2021): $\text{pass@}k = 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}$, averaged over problems. Compute it as a stable product: $1 - \prod_{i=n-c+1}^{n}\left(1 - \frac{k}{i}\right)$.

### 🛠️ Build It From Scratch

```python
# nanoforge/eval/generative.py
import re, subprocess, sys, tempfile, os, numpy as np

def pass_at_k(n, c, k):
    if n - c < k: return 1.0
    return 1.0 - float(np.prod(1.0 - k / np.arange(n - c + 1, n + 1)))

def extract_last_number(text):
    nums = re.findall(r"-?\d[\d,]*\.?\d*", text.replace("$", ""))
    return nums[-1].replace(",", "").rstrip(".") if nums else None

def gsm8k_correct(generation, reference_answer):
    ref = reference_answer.split("####")[-1].strip().replace(",", "")
    pred = extract_last_number(generation.split("\n\n")[0] if "####" not in generation else generation.split("####")[-1])
    try: return pred is not None and abs(float(pred) - float(ref)) < 1e-6
    except ValueError: return False

def run_code_tests(program: str, timeout=5.0) -> bool:
    """Execute untrusted model code in a separate process with a timeout. For real use: containers/sandboxes!"""
    with tempfile.NamedTemporaryFile("w", suffix=".py", delete=False) as f:
        f.write(program); path = f.name
    try:
        r = subprocess.run([sys.executable, path], capture_output=True, timeout=timeout)
        return r.returncode == 0
    except subprocess.TimeoutExpired:
        return False
    finally:
        os.unlink(path)

def humaneval_program(problem, completion):
    return problem["prompt"] + completion + "\n\n" + problem["test"] + f"\ncheck({problem['entry_point']})\n"
```

⚠️ **Security:** model-generated code is untrusted. Run it in an isolated container or VM with no network and resource limits; a subprocess alone is **not** a sandbox.

### 🔬 Experiment & Observe
Compute pass@1 and pass@10 from 20 samples per problem at temperature 0.8 on 20 HumanEval problems with a small open code model (or GPT-2, near 0%). Note how pass@10 ≫ pass@1: sampling diversity matters, which motivates best-of-n and RL (Ch 41).

### ⚠️ Failure Modes & Debugging
- The biased estimator ("any of the first k passed") has high variance. Use the formula.
- Answer extraction bugs (commas, units, trailing periods) swing GSM8K by many points. Inspect the failures manually.
- Stop sequences: generation continues into a new "Question:", so truncate at the stop strings.

### 🧠 Expert Insight
- **Cobbe et al. (2021), GSM8K.** **Chen et al. (2021), Codex/HumanEval** (pass@k estimator). **Austin et al. (2021), MBPP.**
- Frontier evals have moved to harder sets (MATH, AIME, GPQA, SWE-bench, LiveCodeBench) as the older ones saturated.

## 35.4 Contamination Detection With N-gram Overlap

### 🧭 The Problem First
If benchmark questions (or their answers) appear in the training data, the scores measure memorization, not ability. Web-scale data often contains benchmark copies.

### 💡 Intuition / Instinct
Check for overlapping long n-grams (e.g. 13-grams of words) between each benchmark example and the training corpus. Examples with significant overlap are "contaminated"; report scores on the clean subset too. Other signals: the model assigns abnormally high likelihood to the exact benchmark text vs paraphrases, or it completes a question verbatim from a prefix.

### 🖼️ Visual Mental Model

```text
 benchmark item → 13-grams {g1, g2, ...} → lookup in training n-gram index (Bloom filter / hash set)
 overlap ratio > 0.5 → contaminated
```

### 📐 The Math, Gently
Overlap ratio = |ngrams(item) ∩ ngrams(train)| / |ngrams(item)|. For huge corpora, use a Bloom filter: memory ≈ $-\frac{n\ln p}{(\ln 2)^2}$ bits for n items at false-positive rate p (1B n-grams at p = 1% ≈ 1.2 GB).

### 🛠️ Build It From Scratch

```python
# nanoforge/eval/contamination.py
import re, hashlib
def word_ngrams(text, n=13):
    w = re.findall(r"\w+", text.lower())
    return {" ".join(w[i:i + n]) for i in range(len(w) - n + 1)}

class NgramIndex:
    """Hashed n-gram set (use a Bloom filter at scale)."""
    def __init__(self, n=13): self.n, self.h = n, set()
    def _hash(self, g): return hashlib.blake2b(g.encode(), digest_size=8).digest()
    def add_document(self, text):
        for g in word_ngrams(text, self.n): self.h.add(self._hash(g))
    def overlap(self, text):
        grams = word_ngrams(text, self.n)
        return (sum(self._hash(g) in self.h for g in grams) / len(grams)) if grams else 0.0

def contamination_report(index, items, threshold=0.5):
    flags = [index.overlap(it) >= threshold for it in items]
    return {"contaminated_frac": sum(flags) / len(items), "flags": flags}

def verbatim_completion_test(model, tok, text, prefix_frac=0.5, max_new=50, device="cpu"):
    """Prompt with the first half of a benchmark item; check whether greedy continuation matches the true rest."""
    import torch
    from nanoforge.sampling import generate
    ids = tok.encode_ordinary(text); k = int(len(ids) * prefix_frac)
    out = generate(model, torch.tensor([ids[:k]], device=device), min(max_new, len(ids) - k), block_size=1024, temperature=0)
    gen = out[0, k:].tolist(); ref = ids[k:k + len(gen)]
    return sum(a == b for a, b in zip(gen, ref)) / max(1, len(ref))
```

### ⚠️ Failure Modes & Debugging
- Short items (< 13 words) can't be checked with 13-grams. Use smaller n with care (false positives).
- Paraphrased contamination escapes n-gram checks. Use embedding similarity or LLM judges as a complement.

### 🧠 Expert Insight

- **Sainz et al. (2023)** and **Golchin & Surdeanu (2023):** contamination detection via guided prompting.
- **LiveBench / LiveCodeBench:** continuously refreshed, post-cutoff questions to avoid contamination.

## 35.5 What the Numbers Actually Mean: Variance, Error Bars, Saturation

### 🧭 The Problem First
Model A scores 62.1% on a 500-question benchmark, and model B scores 60.8%. Is A better?

### 💡 Intuition / Instinct
Benchmarks are *samples* of questions, so scores have sampling error. For accuracy p on n items, the standard error is $\sqrt{p(1-p)/n}$. At n = 500 and p = 0.6, that's ±2.2%, so a 1.3-point gap is noise. Use **paired** comparisons (the same questions for both models), which cancel the per-question difficulty and are much more sensitive. Also beware: **saturated** benchmarks (models near the ceiling or near the label-noise floor), prompt sensitivity, and seed variance across training runs.

### 🖼️ Visual Mental Model

```text
 A: 62.1 ± 2.2      B: 60.8 ± 2.2      → overlapping intervals; need a paired test
 paired: per-question (A right, B wrong) vs (A wrong, B right) counts → McNemar / bootstrap
```

### 📐 The Math, Gently
Paired bootstrap: resample the question indices with replacement 10,000 times, compute acc_A − acc_B each time, and take the 2.5–97.5 percentiles. If the interval excludes 0, the difference is significant at ~5%.
Clustered questions (many items from the same passage) need clustered standard errors (Miller, 2024, "Adding Error Bars to Evals").

### 🛠️ Build It From Scratch

```python
# nanoforge/eval/stats.py
import numpy as np
def accuracy_ci(correct, alpha=0.05):
    c = np.asarray(correct, float); p = c.mean(); se = np.sqrt(p * (1 - p) / len(c))
    return p, (p - 1.96 * se, p + 1.96 * se)

def paired_bootstrap(correct_a, correct_b, iters=10000, seed=0):
    a, b = np.asarray(correct_a, float), np.asarray(correct_b, float); rng = np.random.default_rng(seed)
    idx = rng.integers(0, len(a), (iters, len(a)))
    diffs = a[idx].mean(1) - b[idx].mean(1)
    return float((a - b).mean()), (float(np.percentile(diffs, 2.5)), float(np.percentile(diffs, 97.5)))

rng = np.random.default_rng(1)
base = rng.random(500) < 0.6
a = base | (rng.random(500) < 0.05); b = base.copy()
print(accuracy_ci(a), accuracy_ci(b), paired_bootstrap(a, b))
```

### 🧠 Expert Insight
- **Miller (2024), "Adding Error Bars to Evals: A Statistical Approach to Language Model Evaluations".**
- **Madaan et al. (2024), "Quantifying Variance in Evaluation Benchmarks":** seed variance in small models can exceed the gains claimed in papers.
- **Schaeffer et al. (2023):** "emergent abilities" are sometimes artefacts of discontinuous metrics.

> **Core intuition:** *Every benchmark score is an estimate with a margin of error. Report both.*
