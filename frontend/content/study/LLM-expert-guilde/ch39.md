## 39.1 Preference Data and the Bradley–Terry Model

### 🧭 The Problem First
Writing the ideal response to every prompt is hard, even for experts. But given two responses, people can reliably say which one is better. How do we turn pairwise judgments into a training signal?

### 💡 Intuition / Instinct
Assume each response has a hidden "quality score" r. The chance a person prefers A over B depends on the *difference* of the scores through a logistic curve: equal scores → 50/50; a much higher score → almost always preferred. This is the Bradley–Terry model (the same one behind chess Elo and Chatbot Arena, Ch 36.2). Learning r from comparisons is **logistic regression on score differences**.

### 🖼️ Visual Mental Model

```text
 prompt x ─▶ response y_w (chosen)  ─▶ r(x, y_w) = 2.1 ┐
          ─▶ response y_l (rejected)─▶ r(x, y_l) = 0.4 ┴─▶ P(y_w ≻ y_l) = σ(2.1 − 0.4) = 0.85
```

### 📐 The Math, Gently
$P(y_w \succ y_l\mid x) = \sigma(r(x, y_w) - r(x, y_l))$.
Loss: $\mathcal{L}_{RM} = -\mathbb{E}\left[\log\sigma(r_w - r_l)\right]$.
Note: only differences matter, so r is defined up to a constant (per prompt). Normalize the rewards before RL.

### 🛠️ Build It From Scratch

```python
# preference record format (data/prefs/*.jsonl)
# {"prompt": [{"role":"user","content":"..."}], "chosen": "...", "rejected": "..."}
import json, random
def make_preferences_from_judge(prompts, sample_fn, judge_pair_fn, n_samples=2):
    """Generate 2 responses per prompt with the SFT model; a judge (Ch 36) picks the winner."""
    out = []
    for msgs in prompts:
        a, b = sample_fn(msgs), sample_fn(msgs)
        v = judge_pair_fn(msgs[-1]["content"], a, b)      # +1 a wins, -1 b wins, 0 tie/inconsistent
        if v == 0: continue
        out.append({"prompt": msgs, "chosen": a if v > 0 else b, "rejected": b if v > 0 else a})
    return out
```

### 🔬 Experiment & Observe
Create ~2,000 preference pairs for your domain: sample 2 responses per prompt from your SFT model (temperature 0.8–1.0), and label them with verifiable checks where possible (a correct answer beats an incorrect one) plus a judge for the open-ended ones. Check a random 50 by hand.

### ⚠️ Failure Modes & Debugging
- Label noise: humans agree only ~65–80% on subtle comparisons. Include clear-cut pairs.
- Length bias: if longer responses usually win, the RM learns "longer = better". Balance or control for length.

- **Stiennon et al. (2020), "Learning to Summarize from Human Feedback".**
- **Bai et al. (2022), Anthropic HH-RLHF:** helpful/harmless preference data.
- Open preference datasets: UltraFeedback, HelpSteer2, and others.

## 39.2 Training a Reward Model

### 🧭 The Problem First
We need a function r(x, y) that scores *any* response, including ones never labelled, to use as the RL objective.

### 💡 Intuition / Instinct
Take the SFT model, replace the LM head with a **scalar head**, feed (prompt + response), and read the score at the last token. Train it with the Bradley–Terry loss on the preference pairs. The RM inherits the SFT model's understanding of language and the domain, so it can generalize from a few thousand pairs.

### 🖼️ Visual Mental Model

```text
 [prompt tokens][response tokens][<|im_end|>] ─▶ transformer ─▶ hidden at last token ─▶ Linear(C,1) ─▶ r
```

### 📐 The Math, Gently
Batch the chosen and rejected completions together: $\mathcal{L} = -\frac{1}{B}\sum\log\sigma(r_w^{(i)} - r_l^{(i)})$.
Accuracy = the fraction of pairs where $r_w > r_l$ (typically 65–80% on held-out human data). Optionally add a small regularizer $\mu(r_w + r_l)^2$ to keep the rewards centred.

### 🛠️ Build It From Scratch

```python
# nanoforge/posttrain/reward.py
import json, random, torch, torch.nn as nn, torch.nn.functional as F
from torch.nn.utils.rnn import pad_sequence

class RewardModel(nn.Module):
    def __init__(self, backbone):                          # backbone: Llama (Ch 32), lm_head unused
        super().__init__(); self.backbone = backbone
        self.v_head = nn.Linear(backbone.cfg.n_embd, 1, bias=False); nn.init.zeros_(self.v_head.weight)
    def hidden(self, idx):
        bb = self.backbone; x = bb.tok_emb(idx)
        for layer in bb.layers: x = layer(x, bb.rope_cos, bb.rope_sin)
        return bb.norm(x)                                  # (B, T, C)
    def forward(self, idx, last_idx):                      # last_idx: (B,) index of final real token
        h = self.hidden(idx)
        return self.v_head(h[torch.arange(idx.size(0)), last_idx]).squeeze(-1)   # (B,)

def encode_pair(fmt, rec):
    p = fmt.prompt_for_generation(rec["prompt"])
    end = [fmt.end]
    return p + fmt.tok.encode_ordinary(rec["chosen"]) + end, p + fmt.tok.encode_ordinary(rec["rejected"]) + end

def rm_batches(pairs, B, pad_id):
    while True:
        random.shuffle(pairs)
        for i in range(0, len(pairs) - B + 1, B):
            seqs = [s for c, r in pairs[i:i + B] for s in (c, r)]          # interleave chosen/rejected
            lens = torch.tensor([len(s) - 1 for s in seqs])
            x = pad_sequence([torch.tensor(s) for s in seqs], batch_first=True, padding_value=pad_id)
            yield x, lens

def train_reward_model(rm, pairs, pad_id, device, lr=1e-5, steps=500, B=8):
    opt = torch.optim.AdamW([p for p in rm.parameters() if p.requires_grad], lr=lr, weight_decay=0.0)
    it = rm_batches(pairs, B, pad_id)
    for step in range(steps):
        x, last = next(it); x, last = x.to(device), last.to(device)
        with torch.autocast("cuda", dtype=torch.bfloat16, enabled=device == "cuda"):
            r = rm(x, last).float()
        rw, rl = r[0::2], r[1::2]
        loss = -F.logsigmoid(rw - rl).mean() + 1e-3 * ((rw + rl) ** 2).mean()
        opt.zero_grad(); loss.backward(); torch.nn.utils.clip_grad_norm_(rm.parameters(), 1.0); opt.step()
        if step % 50 == 0: print(f"rm step {step} loss {loss.item():.3f} acc {(rw > rl).float().mean().item():.2f}")
    return rm
```

(Right padding with causal attention is safe here because we read the hidden state at the last *real* token.)

### 🔬 Experiment & Observe
Hold out 10% of the pairs and track the held-out accuracy. Then probe the biases: score the same answer padded with filler text, or with markdown formatting added. Does the reward go up? That is what RL will exploit.

### ⚠️ Failure Modes & Debugging
- Reading the score at a padding position (wrong `last_idx`) → nonsense rewards.
- Overfitting: train accuracy 100%, held-out 60%. Use 1 epoch, a low lr, or LoRA.
- Rewards drifting to huge values → the centring regularizer or normalization.

- **Ouyang et al. (2022):** a 6B RM for the 175B policy.
- **Lambert et al. (2024), RewardBench:** evaluating RMs.
- **Process reward models (PRMs)** score each reasoning step rather than the final answer (Lightman et al., 2023, "Let's Verify Step by Step").

## 39.3 Policy Gradients From Scratch (REINFORCE)

### 🧭 The Problem First
The reward is computed on *sampled* text. Sampling is discrete and non-differentiable. How do we get gradients that increase the expected reward?

### 💡 Intuition / Instinct
**Make good samples more likely, bad samples less likely.** For each sampled response, push up its log-probability in proportion to how good it was. Because we're weighting log-probabilities of things the model *actually generated*, we never need to differentiate through the sampling. Subtracting a **baseline** (the average reward) reduces the variance: we only reinforce responses that are *better than usual*.

### 🖼️ Visual Mental Model

```text
 sample y ~ π(·|x) → reward R(y) → advantage A = R − baseline
 loss = −A · log π(y|x)     A>0: make y more likely   A<0: less likely
```

### 📐 The Math, Gently
Policy gradient theorem (log-derivative trick):
$\nabla_\theta\mathbb{E}_{y\sim\pi_\theta}[R(y)] = \mathbb{E}_{y\sim\pi_\theta}[R(y)\nabla_\theta\log\pi_\theta(y)]$.
Proof: $\nabla\sum_y\pi(y)R(y) = \sum_y\pi(y)\frac{\nabla\pi(y)}{\pi(y)}R(y)$.
For a sequence, $\log\pi(y\mid x) = \sum_t\log\pi(y_t\mid x, y_{<t})$.
A baseline b doesn't bias the gradient because $\mathbb{E}[\nabla\log\pi] = 0$.

### 🛠️ Build It From Scratch

```python
# toy REINFORCE: teach a policy over 5 "responses" to prefer the one with highest reward
import torch
torch.manual_seed(0)
logits = torch.zeros(5, requires_grad=True); rewards = torch.tensor([0.1, 0.5, 1.0, 0.2, -0.5])
opt = torch.optim.Adam([logits], lr=0.1); baseline = 0.0
for step in range(300):
    dist = torch.distributions.Categorical(logits=logits)
    y = dist.sample((32,))                                  # 32 samples
    R = rewards[y]; baseline = 0.9 * baseline + 0.1 * R.mean().item()
    loss = -((R - baseline) * dist.log_prob(y)).mean()
    opt.zero_grad(); loss.backward(); opt.step()
print(torch.softmax(logits, 0).detach().round(decimals=3))  # mass concentrates on index 2
```

For language models, the policy is the LM, `y` is a generated sequence, and log π(y) = the sum of the token log-probs (computed with one forward pass over prompt + response).

```python
# nanoforge/posttrain/rl_utils.py
import torch, torch.nn.functional as F
def sequence_logprobs(model, input_ids, response_mask):
    """input_ids: (B, T) prompt+response; response_mask: (B, T) 1 on response tokens (aligned to targets).
       Returns per-token logprobs (B, T-1) and the mask shifted to targets."""
    logits, _ = model(input_ids[:, :-1], all_logits=True)
    logp = F.log_softmax(logits.float(), -1)
    tok_logp = logp.gather(-1, input_ids[:, 1:, None]).squeeze(-1)
    return tok_logp, response_mask[:, 1:].float()
```

### 🔬 Experiment & Observe
Remove the baseline in the toy example and compare the variance of the learning curves across 5 seeds: without a baseline, learning is much noisier. That is variance reduction you can see.

### ⚠️ Failure Modes & Debugging
- Huge variance with sparse rewards (only at the end of long sequences).
- Taking too many gradient steps on the same samples: REINFORCE is *on-policy*, so reusing samples breaks it (PPO fixes this).

### 🧠 Expert Insight
- **Williams (1992), REINFORCE.**
- **Ahmadian et al. (2024), "Back to Basics: Revisiting REINFORCE Style Optimization for Learning from Human Feedback":** RLOO (a leave-one-out baseline) matches PPO for LLMs with less complexity. GRPO (Ch 41) is in this family.

1. Why can we get gradients without differentiating through the sampling?
2. Why does a baseline not bias the gradient?

<details><summary>Answers</summary>

1. The log-derivative trick weights ∇ log π of the sampled outputs by their reward.
2. $\mathbb{E}_\pi[\nabla\log\pi] = \nabla\sum\pi = \nabla 1 = 0$.
</details>

### 📌 Recap Card
- ∇E[R] = E[(R − b)∇log π(y)].
- Sequence log-prob = the sum of the token log-probs.
- The baseline reduces variance; on-policy only.

> **Core intuition:** *Do more of what worked better than expected, less of what worked worse.*

## 39.4 PPO: Clipped Objective, Value Head, GAE, KL Penalty

### 🧭 The Problem First
REINFORCE is noisy and sample-inefficient: each batch of expensive generations is used for one gradient step. Large steps can collapse the policy. And an RL-optimized LM drifts into gibberish that happens to fool the reward model.

### 💡 Intuition / Instinct
PPO adds four stabilizers:
1. **Reuse samples for a few epochs, but clip:** the probability ratio $\rho = \pi_\theta/\pi_{old}$ is clipped to [1−ε, 1+ε], so no single update moves any token's probability too far from the sampling policy.
2. **Value head (critic):** predicts the expected future reward at each token, giving *per-token* advantages instead of one sequence-level number.
3. **GAE:** blends multi-step returns to trade bias for variance.
4. **KL penalty to the reference (SFT) model:** a per-token penalty $-\beta(\log\pi_\theta - \log\pi_{ref})$ added to the reward keeps the policy close to the fluent SFT model. It's the leash against reward hacking (Ch 5.5: reverse KL).

### 🖼️ Visual Mental Model

```text
 rollout: prompts → policy samples → RM score at the end → per-token rewards: r_t = −β·KL_t (+ RM at last token)
 critic V(s_t) → GAE advantages A_t → returns
 update (several epochs over the batch):
   L_policy = −min(ρA, clip(ρ, 1−ε, 1+ε)A)     L_value = (V − returns)²
```

### 📐 The Math, Gently
Per-token reward: $r_t = -\beta\left(\log\pi_{old}(y_t) - \log\pi_{ref}(y_t)\right) + \mathbb{1}[t = T]\cdot R_{RM}$.
TD error: $\delta_t = r_t + \gamma V_{t+1} - V_t$; GAE: $A_t = \sum_{l\ge0}(\gamma\lambda)^l\delta_{t+l}$ (usually γ = 1, λ = 0.95 for LLMs).
Clipped objective: $\mathcal{L}^{clip} = -\mathbb{E}_t\left[\min(\rho_tA_t,\ \text{clip}(\rho_t, 1-\epsilon, 1+\epsilon)A_t)\right]$, with ε = 0.2.
Why the min? If A > 0, the ratio's benefit stops above 1 + ε; if A < 0, it stops below 1 − ε, so there is no incentive to move further.

### 🛠️ Build It From Scratch

```python
# nanoforge/posttrain/ppo.py
import copy, torch, torch.nn as nn, torch.nn.functional as F

class PolicyWithValue(nn.Module):
    def __init__(self, lm):
        super().__init__(); self.lm = lm
        self.value = nn.Linear(lm.cfg.n_embd, 1); nn.init.zeros_(self.value.weight); nn.init.zeros_(self.value.bias)
    def forward(self, idx):
        bb = self.lm; x = bb.tok_emb(idx)
        for layer in bb.layers: x = layer(x, bb.rope_cos, bb.rope_sin)
        h = bb.norm(x)
        return bb.lm_head(h), self.value(h).squeeze(-1)                 # logits (B,T,V), values (B,T)

def gather_logp(logits, ids):
    return F.log_softmax(logits.float(), -1).gather(-1, ids[..., None]).squeeze(-1)

@torch.no_grad()
def gae(rewards, values, mask, gamma=1.0, lam=0.95):
    """rewards/values/mask: (B, L) over response positions. Returns advantages, returns."""
    B, L = rewards.shape; adv = torch.zeros_like(rewards); last = torch.zeros(B, device=rewards.device)
    zeros = torch.zeros(B, device=rewards.device)
    for t in reversed(range(L)):
        next_v = values[:, t + 1] if t + 1 < L else zeros
        next_m = mask[:, t + 1] if t + 1 < L else zeros          # 0 after the final response token
        delta = rewards[:, t] + gamma * next_v * next_m - values[:, t]
        last = delta + gamma * lam * next_m * last
        adv[:, t] = last * mask[:, t]
    return adv, adv + values

def masked_mean(x, m): return (x * m).sum() / m.sum().clamp_min(1)
def masked_whiten(x, m):
    mu = masked_mean(x, m); var = masked_mean((x - mu) ** 2, m)
    return (x - mu) * torch.rsqrt(var + 1e-8) * m

class PPOTrainer:
    def __init__(self, policy: PolicyWithValue, ref_lm, reward_fn, tok_fmt, device,
                 lr=1e-6, vf_lr=1e-5, beta=0.05, clip=0.2, vf_clip=0.2, epochs=2, max_new=128, temperature=1.0):
        self.pi, self.ref, self.reward_fn, self.fmt, self.dev = policy, ref_lm.eval(), reward_fn, tok_fmt, device
        for p in self.ref.parameters(): p.requires_grad_(False)
        self.opt = torch.optim.AdamW([{"params": policy.lm.parameters(), "lr": lr},
                                      {"params": policy.value.parameters(), "lr": vf_lr}], weight_decay=0.0)
        self.beta, self.clip, self.vf_clip, self.epochs, self.max_new, self.temp = beta, clip, vf_clip, epochs, max_new, temperature

    @torch.no_grad()
    def rollout(self, prompts):
        from nanoforge.sampling import generate
        batch = []
        for msgs in prompts:
            p_ids = self.fmt.prompt_for_generation(msgs)
            out = generate(self.pi.lm, torch.tensor([p_ids], device=self.dev), self.max_new, self.pi.lm.cfg.block_size,
                           temperature=self.temp, eos_id=self.fmt.end)[0].tolist()
            batch.append((p_ids, out[len(p_ids):]))
        return batch

    def step(self, prompts):
        samples = self.rollout(prompts)
        seqs = [torch.tensor(p + r) for p, r in samples]
        ids = nn.utils.rnn.pad_sequence(seqs, batch_first=True, padding_value=0).to(self.dev)
        B, T = ids.shape
        resp = torch.zeros(B, T, device=self.dev)                          # 1 on response tokens
        for i, (p, r) in enumerate(samples): resp[i, len(p):len(p) + len(r)] = 1
        m = resp[:, 1:]                                                     # aligned to targets
        with torch.no_grad():
            logits, values = self.pi(ids[:, :-1]); old_logp = gather_logp(logits, ids[:, 1:])
            ref_logits, _ = self.ref(ids[:, :-1], all_logits=True); ref_logp = gather_logp(ref_logits, ids[:, 1:])
            scores = torch.tensor([self.reward_fn(prompts[i], self.fmt.tok.decode(r)) for i, (_, r) in enumerate(samples)],
                                  device=self.dev, dtype=torch.float)
            kl = (old_logp - ref_logp) * m
            rewards = -self.beta * kl
            last = (m.cumsum(1) == m.sum(1, keepdim=True)) & (m > 0)       # final response token
            rewards = rewards + last.float() * scores[:, None]
            adv, ret = gae(rewards, values * m, m)
            adv = masked_whiten(adv, m)
        for _ in range(self.epochs):
            logits, v = self.pi(ids[:, :-1]); logp = gather_logp(logits, ids[:, 1:])
            ratio = torch.exp(logp - old_logp)
            pg = -torch.min(ratio * adv, ratio.clamp(1 - self.clip, 1 + self.clip) * adv)
            v_clipped = values + (v - values).clamp(-self.vf_clip, self.vf_clip)
            vf = 0.5 * torch.max((v - ret) ** 2, (v_clipped - ret) ** 2)
            loss = masked_mean(pg, m) + 0.1 * masked_mean(vf, m)
            self.opt.zero_grad(); loss.backward(); nn.utils.clip_grad_norm_(self.pi.parameters(), 1.0); self.opt.step()
        return {"reward": scores.mean().item(), "kl": (kl.sum(1)).mean().item(),
                "resp_len": m.sum(1).mean().item(), "clipfrac": ((ratio - 1).abs() > self.clip).float().mul(m).sum().item() / m.sum().item()}
```

(Simplifications for clarity: one generation per call, no mini-batching within the rollout, padding id 0. Production implementations (TRL, OpenRLHF, veRL) batch the generation with a fast inference engine, shard the models, and run mini-batch epochs.)

### 🔬 Experiment & Observe
Log per iteration: the mean reward, the KL to the reference, the response length, the clip fraction and the value loss. A healthy run: the reward rises, the KL rises slowly (a few nats per sequence), the clip fraction stays ~0.05–0.2.

### ⚠️ Failure Modes & Debugging
- KL exploding and gibberish outputs → β too small or lr too high.
- Reward flat → an lr that's too low, a bad RM signal, or too little sampling diversity (temperature).
- The value head initialized randomly and dominating early → zero-init (done) and a separate lr.
- Memory: the policy, value, reference and reward models all at once. Share backbones or use LoRA (only the adapters differ from the reference!).

### 🧠 Expert Insight
- **Schulman et al. (2017), PPO.** **Schulman et al. (2015), GAE.**
- **Ziegler et al. (2019), "Fine-Tuning Language Models from Human Preferences":** the per-token KL penalty.
- **Huang et al. (2024), "The N+ Implementation Details of RLHF with PPO":** the many small details that matter.

## 39.5 A Minimal RLHF Loop; Reward Hacking

### 🧭 The Problem First
Put it all together: SFT model → RM → PPO. Then watch for the policy "succeeding" in ways you didn't intend.

### 💡 Intuition / Instinct
**Goodhart's law:** "When a measure becomes a target, it ceases to be a good measure." The RM is an imperfect proxy for human preference. Optimize it hard enough and the policy finds its blind spots: excessive length, flattery, hedging, repeated keywords, formatting tricks. The true quality first rises, then *falls* while the RM score keeps climbing.

Defences: the KL penalty (β), early stopping by *held-out* evals (a judge or humans, not the training RM), RM ensembles, length penalties, fresh preference data on the current policy's outputs (iterated RLHF), and verifiable rewards where possible (Ch 41).

### 🖼️ Visual Mental Model

```text
 score
  │           RM reward ────────────────────╱
  │                                     ╱
  │     true quality ╱‾‾‾‾‾‾‾‾‾‾╲___            ← overoptimization
  │               ╱
  └────────────────────────────────────── KL from reference (√KL)
```

### 📐 The Math, Gently
Gao et al. (2022) found that the gold reward vs $d = \sqrt{KL}$ follows $R_{gold}(d) = d(\alpha - \beta d)$ for RL: it rises, then falls. The peak shifts outward with larger RMs and more RM data.

### 🛠️ Build It From Scratch

```python
# scripts/rlhf.py (outline wiring all pieces)
import copy, json, random, torch
from nanoforge.posttrain.ppo import PolicyWithValue, PPOTrainer
from nanoforge.posttrain.reward import RewardModel
from nanoforge.posttrain.chat import ChatFormatter

def build_reward_fn(rm, fmt, device, length_penalty=0.0, target_len=150):
    @torch.no_grad()
    def fn(prompt_msgs, response_text):
        ids = fmt.prompt_for_generation(prompt_msgs) + fmt.tok.encode_ordinary(response_text) + [fmt.end]
        x = torch.tensor([ids], device=device)
        r = rm(x, torch.tensor([len(ids) - 1], device=device)).item()
        n = len(fmt.tok.encode_ordinary(response_text))
        return r - length_penalty * max(0, n - target_len) / target_len
    return fn

def rlhf(sft_model, rm, fmt, prompts, device, iters=200, batch=16, eval_fn=None):
    policy = PolicyWithValue(copy.deepcopy(sft_model)).to(device)
    ref = copy.deepcopy(sft_model).to(device)
    trainer = PPOTrainer(policy, ref, build_reward_fn(rm, fmt, device, length_penalty=0.1), fmt, device)
    for it in range(iters):
        stats = trainer.step(random.sample(prompts, batch))
        print(it, stats)
        if eval_fn and it % 20 == 0: print("held-out eval:", eval_fn(policy.lm))   # judge win-rate vs SFT
    return policy.lm
```
